# 1. Мета аудиту

W43 досліджує коректність структурного кодування та декодування дерев у SUBIT-WARP.

Центральне питання:

> Чи є кодування дерева в позиційний код і декодування такого коду взаємно оберненими операціями, які зберігають структуру, порядок, типи вузлів, відсутні позиції та властивості нескінченного продовження?

Самої наявності двох функцій недостатньо. Для повної коректності необхідно встановити:

1. однозначність структурного представлення;
2. відповідність між вузлами дерева та позиціями коду;
3. збереження типів вузлів;
4. збереження порядку дочірніх позицій;
5. коректну семантику відсутніх позицій;
6. оборотність на всьому допустимому домені;
7. сумісність із нескінченними гілками та граничним відображенням.

Аудит розрізняє три рівні результатів:

- **доведено в межах зафіксованих означень**;
- **умовно доведено за додаткових припущень**;
- **відкрито — потрібне джерельне звірення або окремий доказ**.

Це розрізнення принципове: текстовий доказ не є автоматично Lean-доказом, а структурна відповідність не означає автоматично метричну або спектральну сумісність.

# 2. Базові множини та нотація

Нехай:

- b ≥ 2 — скінченний branching factor;
- B_b = {1, …, b} — алфавіт дочірніх позицій;
- Pos_b = B_b^{<ω} — множина скінченних адрес;
- ε — порожня адреса, тобто корінь;
- Σ_b = B_b^ℕ — простір нескінченних адрес.

Для адрес u, v ∈ Pos_b запис:

u ⊑ v

означає, що u є префіксом v.

Конкатенацію адреси u із символом i позначаємо:

u·i, де i ∈ B_b.

Для множини листових значень A визначимо алфавіт станів:

S_A = {ABSENT, INTERNAL} ∪ {LEAF(a) : a ∈ A}.

Кодовий простір:

Code_b(A) = S_A^{Pos_b}.

Отже, код — це функція:

t : Pos_b → S_A.

Кодова метрика:

d_code(t,s) = 2^(−r_code(t,s)),

де r_code(t,s) — мінімальна глибина адреси, на якій t і s відрізняються. Для однакових кодів r_code(t,t)=∞ і d_code(t,t)=0.

Це означення відповідає метричній архітектурі W39.1.

# 3. Структурна модель дерева

## 3.1. Тип дерева

Для фіксованих A та b розглядаємо коіндуктивний тип часткового впорядкованого дерева:

PartialTree∞_A^(b) := νX. None ⊔ Leaf(A) ⊔ Node(X^b).

Його конструктори:

- None — відсутній вузол;
- Leaf(a) — лист із значенням a ∈ A;
- Node(c₁,…,c_b) — внутрішній вузол із b впорядкованими дочірніми позиціями.

Кожна дочірня позиція може містити None, Leaf або Node.

Тут Node має рівно b позицій, але не обов'язково b наявних дочірніх вузлів.

Це розрізнення усуває неоднозначність між:

- повним розгалуженням;
- частковим розгалуженням;
- відсутнім дочірнім вузлом.

## 3.2. Rooted-підтип

Визначимо:

RootedPartialTree∞_A^(b)
= {x ∈ PartialTree∞_A^(b) : root(x) ≠ None}.

Корінь може бути:

- Leaf(a);
- Node(c₁,…,c_b).

Кореневий None не належить rooted-підтипу.

## 3.3. Скінченні та нескінченні структури

Коіндуктивне означення дозволяє представляти як скінченні, так і нескінченні дерева.

Скінченне дерево має скінченну множину наявних вузлів.

Нескінченне дерево має нескінченну множину наявних вузлів або нескінченну гілку.

Водночас нескінченна кількість вузлів не обов'язково означає існування нескінченної гілки: нескінченне дерево з нескінченною кількістю скінченних гілок можливе за нескінченного branching factor, але в цій специфікації b скінченний. За скінченного branching factor лема Кеніга дає нескінченну гілку для нескінченного локально скінченного дерева.

Ця відмінність важлива для подальшої сумісності з Tω_P.

# 4. Канонічне кодування

## 4.1. Означення Enc_sub

Визначимо:

Enc_sub : RootedPartialTree∞_A^(b) → Code_b(A).

Для дерева x та адреси u:

Enc_sub(x)(u) =
- ABSENT, якщо вузол за адресою u відсутній;
- LEAF(a), якщо вузол за адресою u є листом зі значенням a;
- INTERNAL, якщо вузол за адресою u є внутрішнім.

Адреси визначаються послідовністю індексів дочірніх позицій від кореня.

Для відсутньої або листової позиції всі її нащадки кодуються як ABSENT.

Отже:

1. корінь має бути не ABSENT;
2. кожний INTERNAL має рівно b адресованих дочірніх слотів;
3. кожний слот має стан ABSENT, LEAF(a) або INTERNAL;
4. після ABSENT усі нащадки ABSENT;
5. після LEAF(a) усі нащадки ABSENT.

## 4.2. Інваріанти кодування

Для t = Enc_sub(x) мають виконуватися:

**ENC-01 — Root preservation**

t(ε) ≠ ABSENT.

**ENC-02 — Absence closure**

∀u,v ∈ Pos_b:

u ⊑ v ∧ t(u)=ABSENT ⇒ t(v)=ABSENT.

**ENC-03 — Leaf closure**

∀u,v ∈ Pos_b:

u ⊑ v ∧ t(u)=LEAF(a) ⇒ t(v)=ABSENT,

якщо v є строгим нащадком u.

**ENC-04 — Ordered branching**

Для кожного INTERNAL-вузла дочірні позиції мають фіксовані індекси 1,…,b.

**ENC-05 — Label preservation**

Якщо вузол x за адресою u є Leaf(a), тоді t(u)=LEAF(a).

**ENC-06 — Internal-node preservation**

Якщо вузол x за адресою u є внутрішнім, тоді t(u)=INTERNAL.

**ENC-07 — Address preservation**

Кожний наявний вузол має одну адресу; різні вузли не можуть мати однакову адресу.

**ENC-08 — No implicit permutation**

Перестановка дочірніх позицій змінює код, якщо вона змінює розташування вузлів за адресами.

# 5. Простір допустимих кодів

Визначимо локально допустимий код як t ∈ Code_b(A), для якого виконуються ABSENT closure та LEAF closure.

Позначимо:

C_Partial^all(A,b).

Цей простір допускає код із коренем ABSENT.

Rooted-коди:

C_Partial(A,b)
= {t ∈ C_Partial^all(A,b) : t(ε) ≠ ABSENT}.

Повні коди:

C_Full(A,b)
= {t ∈ C_Partial(A,b) :
∀u, t(u)=INTERNAL ⇒ ∀i∈B_b, t(u·i)≠ABSENT}.

Отже:

C_Full(A,b) ⊆ C_Partial(A,b).

Важливо: C_Full не означає, що всі листи мають бути однаковими або що всі гілки мають однакову глибину. Він означає лише, що кожний внутрішній вузол має всі b дочірніх позицій зайнятими.

## 5.1. Відсутність та невідомість

ABSENT не є UNKNOWN.

ABSENT означає, що дочірня позиція структурно не зайнята.

UNKNOWN означало б, що стан позиції невідомий або не визначений у поточному контексті.

Якщо майбутня версія SUBIT потребуватиме UNKNOWN, його слід додати як окремий стан із власною семантикою.

Не можна ототожнювати:

- відсутній слот;
- невідомий слот;
- неотримане спостереження;
- суперечливе спостереження.

Це відповідає принципу DO NOT COLLAPSE — CONTEXTUALIZE.

# 6. Канонічне декодування

## 6.1. Означення Dec_sub

Визначимо:

Dec_sub : C_Partial(A,b) → RootedPartialTree∞_A^(b).

Декодування здійснюється за станом у кореневій позиції.

Для адреси u:

- якщо t(u)=ABSENT, результат — None;
- якщо t(u)=LEAF(a), результат — Leaf(a);
- якщо t(u)=INTERNAL, результат — Node(c₁,…,c_b), де cᵢ декодується з підкоду, що починається в u·i.

Формально дочірній підкод t_uᵢ визначається:

t_uᵢ(v) = t(u·i·v).

Для кожного INTERNAL-вузла декодування викликає себе на всіх b дочірніх підкодах.

Оскільки дерево коіндуктивне, визначення Dec_sub має бути реалізоване як ко-рекурсивна конструкція або через еквівалентну структурну семантику.

## 6.2. Коректність домену

Dec_sub не визначається для довільного t ∈ Code_b(A).

Наприклад, код:

t(ε)=LEAF(a),  
t(1)=INTERNAL

порушує LEAF closure.

Так само код:

t(ε)=ABSENT,  
t(1)=INTERNAL

не є rooted-кодом і порушує ABSENT closure.

Отже, декодування має працювати не з довільним масивом символів, а лише з C_Partial(A,b).

# 7. Перша властивість оборотності

## 7.1. Теорема W43-T1 — Dec ∘ Enc = id

Для кожного x ∈ RootedPartialTree∞_A^(b):

Dec_sub(Enc_sub(x)) = x.

### Доказова схема

Доказ проводиться коіндукцією за структурою дерева.

**Випадок 1: x = Leaf(a).**

Кодування дає:

Enc_sub(x)(ε)=LEAF(a),

а всі строгі нащадки кореня отримують ABSENT.

Декодування кореня повертає Leaf(a).

Отже:

Dec_sub(Enc_sub(Leaf(a))) = Leaf(a).

**Випадок 2: x = Node(x₁,…,x_b).**

Кодування дає:

Enc_sub(x)(ε)=INTERNAL.

Для кожного i ∈ B_b підкод за адресою i дорівнює Enc_sub(xᵢ), включно з випадком xᵢ=None.

За коіндуктивним припущенням:

Dec_sub(Enc_sub(xᵢ))=xᵢ.

Отже, декодування повертає:

Node(x₁,…,x_b).

Тому:

Dec_sub(Enc_sub(x))=x.

### Статус

**ДОВЕДЕНО В МЕЖАХ КАНОНІЧНОЇ МОДЕЛІ**, за умови, що Enc_sub та Dec_sub реалізовані саме з наведеними означеннями й зберігають порядок дочірніх позицій.

# 8. Друга властивість оборотності

## 8.1. Теорема W43-T2 — Enc ∘ Dec = id

Для кожного t ∈ C_Partial(A,b):

Enc_sub(Dec_sub(t)) = t.

### Доказова схема

Доведемо рівність покоординатно.

Нехай u ∈ Pos_b.

Розглянемо три випадки.

**Випадок 1: t(u)=ABSENT.**

За ABSENT closure всі нащадки u також ABSENT.

Декодування створює None у цій позиції.

Повторне кодування None повертає ABSENT у u та всіх її нащадках.

**Випадок 2: t(u)=LEAF(a).**

За LEAF closure всі строгі нащадки u мають ABSENT.

Декодування створює Leaf(a).

Повторне кодування повертає LEAF(a) у u та ABSENT у всіх нащадках.

**Випадок 3: t(u)=INTERNAL.**

Декодування створює Node із b дочірніми піддеревами.

За означенням кожний підкод відновлюється з відповідної дочірньої позиції.

Повторне кодування повертає INTERNAL у u та відновлює всі b дочірніх підкодів.

Отже, для кожного u:

Enc_sub(Dec_sub(t))(u)=t(u).

Тому:

Enc_sub(Dec_sub(t))=t.

### Статус

**ДОВЕДЕНО В МЕЖАХ КАНОНІЧНОЇ МОДЕЛІ**, за умови ABSENT closure, LEAF closure та фіксованої адресації.

# 9. Результат взаємної оборотності

За теоремами W43-T1 і W43-T2:

Dec_sub ∘ Enc_sub = id_RootedPartialTree∞,

Enc_sub ∘ Dec_sub = id_C_Partial.

Отже, маємо бієкцію:

RootedPartialTree∞_A^(b) ≅ C_Partial(A,b).

Це не просто відповідність між множинами. Це структурна ізоморфність, яка зберігає:

- тип вузла;
- значення листа;
- адресу;
- порядок дочірніх позицій;
- відсутність дочірнього вузла;
- скінченні та нескінченні підструктури.

Однак ця бієкція залежить від конкретної домовленості: дерево є впорядкованим, а кожний вузол має b адресованих дочірніх слотів.

Для невпорядкованих дерев або структур із незафіксованими адресами висновок не переноситься автоматично.

# 10. Нескінченна глибина та коіндуктивна коректність

## 10.1. Чому скінченної індукції недостатньо

Скінченна індукція дозволяє довести властивості на деревах обмеженої висоти.

Але SUBIT-WARP використовує:

- нескінченні адреси;
- нескінченні гілки;
- граничні множини;
- коіндуктивні структури.

Тому повний доказ має використовувати коіндукцію або бісимуляцію.

## 10.2. Бісимуляційна умова

Визначимо відношення R між структурними деревами та кодами:

R(x,t), якщо:

1. кореневий стан x відповідає t(ε);
2. Leaf(a) відповідає LEAF(a);
3. None відповідає ABSENT;
4. Node(x₁,…,x_b) відповідає INTERNAL;
5. для кожного i ∈ B_b відповідні дочірні структури перебувають у R.

Якщо R є бісимуляцією, то структурна рівність відновлюється коіндуктивно.

Потрібні дві властивості:

**R-Forth:** кожний структурний перехід має відповідний кодовий перехід.

**R-Back:** кожний допустимий кодовий перехід має відповідний структурний перехід.

Це сильніше за перевірку скінченної кількості рівнів.

## 10.3. Збереження нескінченної гілки

Нехай ξ ∈ Σ_b.

ξ є нескінченною INTERNAL-гілкою коду t, якщо:

∀k ≥ 0, t(ξ|k)=INTERNAL.

Тоді за структурною відповідністю:

ξ є нескінченною гілкою дерева x  
⇔  
ξ є нескінченною INTERNAL-гілкою Enc_sub(x).

Звідси випливає:

x має нескінченну гілку  
⇔  
Enc_sub(x) має нескінченну INTERNAL-гілку.

Це твердження потребує, щоб адреси структурного дерева та адреси коду використовували той самий алфавіт B_b.

# 11. Сумісність із Tω_P

Нагадаємо означення W39/W39.1:

IB(u,t) ⇔
t(u)=INTERNAL ∧
∃ξ ∈ Σ_b,
u ⊑ ξ ∧
∀k ≥ |u|, t(ξ|k)=INTERNAL.

Далі:

Tω_P =
{t ∈ C_Partial(A,b) :
∀u, t(u)=INTERNAL ⇒ IB(u,t)}.

І:

Tω_P⁺ =
{t ∈ Tω_P : t(ε)=INTERNAL}.

## 11.1. Збереження умови нескінченного продовження

За теоремою збереження нескінченних гілок:

IB(u,Enc_sub(x))

еквівалентне існуванню нескінченного структурного продовження від відповідного вузла x_u.

Тому можна визначити структурний підпростір:

Treeω_P =
{x ∈ RootedPartialTree∞ :
кожний INTERNAL-вузол має нескінченне INTERNAL-продовження}.

Тоді:

Enc_sub(Treeω_P)=Tω_P.

А для кореневих INTERNAL-дерев:

Enc_sub(Treeω_P⁺)=Tω_P⁺,

де:

Treeω_P⁺ =
{x ∈ Treeω_P : root(x)=Node(…)}.

Це твердження є наслідком структурної бієкції та збереження адресованих нескінченних гілок.

## 11.2. Важливе обмеження

Не кожне rooted partial tree належить Treeω_P.

Наприклад, корінь може бути INTERNAL, але всі його дочірні вузли — листи або None.

Таке дерево структурно коректне, але не має нескінченної INTERNAL-гілки.

Отже:

RootedPartialTree∞ ≠ Treeω_P.

Так само:

C_Partial ≠ Tω_P.

Ці простори не можна ототожнювати.

# 12. Сумісність із boundary map

W41 визначає:

∂t =
{ξ ∈ Σ_b :
∀k ≥ 0, t(ξ|k)=INTERNAL},

для t ∈ Tω_P⁺.

Для структурного дерева x визначимо:

∂_Tree(x) =
{ξ ∈ Σ_b :
усі вузли на адресах ξ|k є INTERNAL}.

За збереженням адрес і типів вузлів:

∂(Enc_sub(x)) = ∂_Tree(x).

Отже, маємо комутативну відповідність:

Treeω_P⁺  --Enc_sub-->  Tω_P⁺  
     |                         |  
  ∂_Tree                    ∂  
     |                         |  
     v                         v  
   K(Σ_b)  ================ K(Σ_b)

Ця діаграма є комутативною в межах зафіксованих означень.

## 12.1. Що саме доведено

Кодування зберігає граничну множину, оскільки не змінює:

- адреси;
- INTERNAL-статус;
- нескінченну послідовність дочірніх індексів.

Тому:

∂(Enc_sub(x))=∂_Tree(x).

## 12.2. Чого цей результат не доводить

Він не доводить автоматично:

- сумісність із будь-якою історичною метрикою d_F;
- сумісність із усіма попередніми означеннями Tω;
- еквівалентність невпорядкованої та впорядкованої реконструкції;
- збереження спектральних операторів;
- ізометричність між усіма просторами дерев.

Для цих висновків потрібні окремі твердження.

# 13. Ін'єктивність, сюр'єктивність та неоднозначність

## 13.1. Ін'єктивність

Enc_sub є ін'єктивним на RootedPartialTree∞ за умови:

- фіксованого A;
- фіксованого b;
- фіксованого порядку дочірніх позицій;
- канонічної адресації;
- точного збереження типів вузлів.

Якщо два дерева мають однаковий код, то вони мають однаковий корінь, однакові дочірні підструктури та однакові листові значення. Коіндуктивна рівність дає рівність дерев.

## 13.2. Сюр'єктивність

Enc_sub є сюр'єктивним на C_Partial(A,b), якщо кожний код у цьому просторі задовольняє ABSENT closure, LEAF closure і rooted-умову.

Це саме те, що забезпечує визначеність Dec_sub.

На всьому Code_b(A) сюр'єктивності немає.

Приклад:

t(ε)=LEAF(a),  
t(1)=INTERNAL.

Такий код не може бути результатом Enc_sub, оскільки лист не має нащадків.

## 13.3. Неоднозначність невпорядкованих дерев

Якщо порядок дочірніх позицій не входить до структури дерева, кодування стає неоднозначним.

Нехай b=2, A={a}.

Розглянемо два невпорядковані дерева:

- корінь із листом a та відсутньою позицією;
- корінь із відсутньою позицією та листом a.

Як невпорядковані структури вони еквівалентні.

Але їхні впорядковані коди різні:

t₁(1)=LEAF(a), t₁(2)=ABSENT;

t₂(1)=ABSENT, t₂(2)=LEAF(a).

Тому для невпорядкованих дерев потрібна окрема нормалізація або факторизація за групою перестановок дочірніх позицій.

Не можна заявляти ін'єктивність кодування невпорядкованих дерев без такого додаткового механізму.

## 13.4. Мінімальні контрприклади

**CE-01 — Некоректний корінь**

t(ε)=ABSENT.

Не належить C_Partial.

**CE-02 — Нащадок після листа**

t(ε)=LEAF(a), t(1)=INTERNAL.

Порушує LEAF closure.

**CE-03 — Нащадок після ABSENT**

t(ε)=INTERNAL, t(1)=ABSENT, t(1·1)=LEAF(a).

Порушує ABSENT closure.

**CE-04 — Втрата порядку**

Перестановка двох дочірніх піддерев змінює код, хоча невпорядкована структура може залишитися тією самою.

**CE-05 — UNKNOWN ≠ ABSENT**

Якщо невідомий слот кодується як ABSENT, декодування перетворює невизначеність на твердження про структурну відсутність.

Це втрата інформації, а не нейтральне спрощення.

# 14. Скінченні та нескінченні регресійні тести

Наведені тести є специфікацією для реалізації. Їх виконання не заявляється.

## 14.1. Rootedness

**RT-001:** кореневий Leaf(a) кодується як LEAF(a).

**RT-002:** кореневий Node кодується як INTERNAL.

**RT-003:** кореневий None відхиляється для rooted encoding.

## 14.2. Leaf та ABSENT closure

**RT-004:** Leaf(a) має лише ABSENT-нащадків.

**RT-005:** None має лише ABSENT-нащадків.

**RT-006:** код із INTERNAL після LEAF(a) відхиляється.

**RT-007:** код із наявним нащадком після ABSENT відхиляється.

## 14.3. Branching factor

**RT-008:** кожний INTERNAL має рівно b адресованих дочірніх слотів.

**RT-009:** часткове дерево може мати ABSENT у деяких слотах.

**RT-010:** повне дерево не має ABSENT безпосередньо під INTERNAL.

**RT-011:** unary occupied branching допускається у C_Partial, якщо рівно один дочірній слот зайнятий.

## 14.4. Round-trip

**RT-012:** Dec_sub(Enc_sub(x))=x для кореневого листа.

**RT-013:** Dec_sub(Enc_sub(x))=x для внутрішнього вузла з усіма відсутніми дочірніми слотами.

**RT-014:** Dec_sub(Enc_sub(x))=x для змішаного часткового дерева.

**RT-015:** Enc_sub(Dec_sub(t))=t для кожного допустимого коду.

## 14.5. Нескінченне продовження

**RT-016:** нескінченний INTERNAL-ланцюг зберігається після round-trip.

**RT-017:** дерево без нескінченного INTERNAL-продовження не повинно помилково потрапити до Tω_P.

**RT-018:** нескінченна гілка за адресою ξ зберігається без зміни ξ.

## 14.6. Boundary preservation

**RT-019:** ∂(Enc_sub(x))=∂_Tree(x).

**RT-020:** дерево з непорожньою межею має непорожню межу після round-trip.

**RT-021:** скінченне rooted leaf-дерево має порожню межу.

## 14.7. Невизначеність

**RT-022:** UNKNOWN не може неявно декодуватися як ABSENT.

**RT-023:** розширення алфавіту UNKNOWN потребує окремої семантики та окремих round-trip властивостей.

# 17. Виявлені ризики та обмеження

**R-001 — Коіндуктивна реалізація.**  
Текстова рекурсія Dec_sub не гарантує автоматично прийнятної Lean-реалізації. Потрібно перевірити guardedness та структурну коректність ко-рекурсії.

**R-002 — Неоднозначність невпорядкованих структур.**  
Бієкція доведена для впорядкованої моделі, а не для класів невпорядкованих дерев.

**R-003 — Невизначеність.**  
UNKNOWN не входить до поточного алфавіту. Його додавання змінить тип кодового простору та вимагатиме нових теорем.

**R-004 — Історичні означення.**  
Сумісність із W23′/W30/W34 не підтверджена прямим source cross-check.

**R-005 — Метрична відповідність.**  
Структурна бієкція не доводить автоматично ізометрію для d_code, d_F або інших метрик.

**R-006 — Спектральна відповідність.**  
Збереження дерева не означає автоматичного збереження спектральних операторів.

**R-007 — Межа.**  
Boundary preservation спирається на однаковий алфавіт адрес і однакову інтерпретацію INTERNAL-гілки.

# 19. Підсумковий висновок

RootedPartialTree∞_A^(b) ≅ C_Partial(A,b).

Вона ґрунтується на двох властивостях:

Dec_sub(Enc_sub(x))=x;

Enc_sub(Dec_sub(t))=t.

Відповідність зберігає типи вузлів, значення листів, адреси, порядок дочірніх позицій, відсутні слоти та нескінченні гілки.
