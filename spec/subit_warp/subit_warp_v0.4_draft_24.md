# SUBIT-WARP v0.4

## W33 — Release Stabilization & Stable Release Protocol

**Статус:** RELEASE PREPARATION  
**Версія:** v0.4  
**Дата:** 4 листопада 2026 року  
**Базова система:** SUBIT-∞ v6.13.39 Stable  
**Призначення:** завершення математичної, обчислювальної та документаційної стабілізації SUBIT-WARP v0.4.

**Принцип:** DO NOT COLLAPSE — CONTEXTUALIZE.

---

## 1. Мета

W33 переводить SUBIT-WARP v0.4 від MATHEMATICALLY CONSOLIDATED DRAFT до контрольованого процесу підготовки STABLE RELEASE.

Мета — не розширювати теорію новими гіпотезами, а забезпечити:

1. єдину канонічну математичну специфікацію;
2. повну узгодженість означень і теорем;
3. інтеграцію виправлень W29;
4. узгодження реєстру теорем W30;
5. відтворювану чисельну перевірку;
6. незалежний аудит обчислювальної реалізації;
7. однозначні критерії прийняття релізу;
8. документовані межі формальної верифікації.

W33 не змінює фундаментальну математичну модель без окремого обґрунтування.

## 2. Політика стабілізації

На етапі W33 діють такі правила:

**S-01. Canonical Definitions**

Кожне математичне поняття має одне канонічне означення.

**S-02. No Silent Corrections**

Жодна зміна формули, області визначення або припущення не вноситься без запису в Change Log.

**S-03. Proof Completeness**

Твердження без повного доведення не отримує статус PROVED.

**S-04. Independent Verification**

Аналітична, чисельна, формальна та програмна перевірки мають незалежні статуси.

**S-05. Endpoint Completeness**

Усі параметричні граничні випадки повинні бути розглянуті окремо.

**S-06. Reproducibility**

Кожен чисельний результат повинен мати відтворюваний протокол.

**S-07. Scope Control**

Нові дослідницькі гіпотези не включаються до стабільного ядра без окремого аудиту.

## 4. Обов'язкові виправлення C-11…C-15

**C-11 — Zero-power convention**

Для параметричного ядра:

q⁰ = 1, q ∈ [0,1].

Це локальна домовленість визначення ядра.

**C-12 — Fingerprint separation**

Дві різні теореми:

Unordered Structural Reconstruction:

F(T) = (L,h,a).

Ordered SUBIT Reconstruction:

F_ordered(T) = (L,h,a,p).

Необхідно явно вказати, що перший fingerprint не відновлює порядок дочірніх гілок.

**C-13 — Trace separation**

Розрізняти:

Tr(T_q⁽ⁿ⁾)

і

Tr(T_q).

Скінченний слід проєкції не є автоматично слідом нескінченновимірного оператора.

**C-14 — Endpoint separation**

Окремо довести твердження для:

q = 0;

0 < q < 1;

q = 1.

Для q = 1:

T₁ = P_const.

**C-15 — Kernel threshold separation**

Для зростаючого ядра:

K₊(ξ,η) = exp(α_w ℓ(ξ,η))

окремо розглядати:

- обмеженість;
- належність до класу Гільберта—Шмідта;
- компактність;
- слідовий клас.

Не переносити висновки одного критерію на інший.

## 5. Регресійна перевірка

W20 повинен бути виконаний як повний набір тестів.

Обов'язкові групи:

| Група | Об'єкт |
|---|---|
| R-TREE | Типи дерев та структурні інваріанти |
| R-METRIC | Метрики та ультраметричність |
| R-GEOMETRY | Компактність, grafting, boundary |
| R-DIMENSION | Hausdorff dimension |
| R-KERNEL | Спадні та зростаючі ядра |
| R-SPECTRUM | Власні значення, кратності, спектр |
| R-NORMS | Operator, HS, trace norms |
| R-FINITE | Скінченні матриці та апроксимації |
| R-ENDPOINT | q=0 та q=1 |
| R-STRUCTURE | Fingerprint та реконструкція |

Для кожного тесту зберігати:

- Test ID;
- математичне твердження;
- вхідні параметри;
- очікуваний результат;
- фактичний результат;
- чисельну похибку;
- статус;
- версію середовища.

Успішне виконання частини тестів не дозволяє присвоювати статус FULL REGRESSION PASSED.

## 6. Implementation Audit

Обчислювальна реалізація повинна пройти незалежну перевірку.

Перевірити:

1. відповідність типів математичним означенням;
2. коректність адресного кодування;
3. обробку граничних випадків;
4. побудову скінченних матриць;
5. симетричність матриць;
6. спектральні обчислення;
7. обчислення норм;
8. точність наближень;
9. обробку помилкових вхідних даних;
10. відтворюваність результатів.

Результат оформити окремим Implementation Audit Report.

## 7. Lean Boundary

W31 залишається канонічним планом формалізації.

Для стабільної математичної специфікації необхідно:

- зберегти чіткі межі формалізації;
- не заявляти Lean verification без перевірених файлів;
- не підміняти Lean чисельними тестами;
- визначити версії Lean і Mathlib перед початком реалізації.

Lean implementation може бути наступним окремим проєктним етапом.

## 8. Release Gates

### GATE A — Mathematical Integrity

- усі означення однозначні;
- усі теореми мають припущення;
- залежності не містять циклів;
- C-11…C-15 інтегровані;
- немає суперечностей між канонічними розділами.

### GATE B — Proof Integrity

- усі твердження зі статусом PROVED мають повні доведення;
- невирішені твердження позначені OPEN;
- граничні випадки розглянуті;
- структурна реконструкція має правильну область застосування.

### GATE C — Numerical Integrity

- W20 виконаний повністю;
- усі тести мають результати;
- звіт відтворюється;
- похибки документовані.

### GATE D — Implementation Integrity

- реалізація зіставлена зі специфікацією;
- граничні випадки перевірені;
- незалежний аудит завершений.

### GATE E — Documentation Integrity

- є один канонічний документ;
- README відповідає фактичному стану;
- реєстр теорем синхронізований;
- відкриті проблеми задокументовані;
- версія та дата релізу узгоджені.

### GATE F — Formalization Integrity

- межі Lean-формалізації визначені;
- неперевірені твердження не позначені LEAN VERIFIED;
- аксіоматичні залежності документовані.

## 10. Умови Stable Release

SUBIT-WARP v0.4 може отримати статус STABLE лише за таких умов:

1. GATE A — PASS;
2. GATE B — PASS;
3. GATE C — PASS;
4. GATE D — PASS;
5. GATE E — PASS;
6. GATE F — PASS.

Lean implementation не є обов'язковою умовою математичного STABLE, якщо межі формалізації чітко визначені, а статус Lean verification не перебільшується.

STABLE означає стабільність математичної специфікації та її заявленого обчислювального шару, а не завершення всіх майбутніх формальних досліджень.

## 11. Заборонені твердження в релізі

- аудит реалізації без окремого звіту;
- фізичне підтвердження гравітаційної моделі;
- універсальність результатів за межами доведених припущень.
