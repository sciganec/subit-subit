## 0. Призначення та межі

Цей patch закриває математичну неоднозначність між тотальними кодами W34.1.3 та рекурсивними деревними типами W23′ настільки, наскільки це можливо без непомітної зміни вже наявного канону.

Ключове рішення: запровадити **окремий явно коіндуктивний тип** `PartialTree∞_A^(b)`. Не приписувати заднім числом коіндуктивну семантику старому запису `PartialTree_A^(b)` у W23′.1.5, оскільки там fixed-point-полярність не зазначена.

Patch встановлює ізоморфізм між `PartialTree∞_A^(b)` з коренем, відмінним від None, та `C_Partial`; аналогічно встановлює ізоморфізм `FullTree_A^(b)` та `C_Full`.

Це математична специфікація та proof sketch. Вона **не** означає, що Lean-код або kernel proof уже існують.

## 1. Алфавіти та простір адрес

Нехай b∈ℕ, b≥2, `B_b={1,…,b}`, `A={00,01,10,11}` (або довільний фіксований скінченний алфавіт міток).

`Pos_b=B_b^{<ω}` — множина скінченних адрес; ε — корінь; ui — i-й дочірній вузол адреси u.

Алфавіт станів:

`S_A={ABSENT, INTERNAL} ⊔ {LEAF(a) : a∈A}`.

Усі коди є тотальними функціями:

`t:Pos_b→S_A`.

TC-01–TC-05 залишаються такими, як визначено у W34.1.3:
- TC-01: t(ε)≠ABSENT;
- TC-02: ABSENT успадковується всіма нащадками;
- TC-03: LEAF(a) має лише ABSENT-дітей;
- TC-04: у C_Full кожна дитина INTERNAL-вузла не-ABSENT;
- TC-05: у C_Partial діти INTERNAL-вузла можуть бути ABSENT.

---

## 2. Явно коіндуктивні типи

### 2.1. Часткове коіндуктивне дерево

Визначимо greatest-fixed-point тип:

`PartialTree∞_A^(b) := νX. None ⊔ Leaf(A) ⊔ Node(X^b)`.

Конструктори:
- `None`;
- `Leaf(a)`, a∈A;
- `Node(p₁,…,p_b)`, де pᵢ∈PartialTree∞_A^(b).

Це **коіндуктивний**, а не індуктивний тип. Він допускає нескінченні послідовності Node-конструкторів.

Кореневий тип:

`PartialTree∞_{A,root}^(b)={p∈PartialTree∞_A^(b): root(p)≠None}`.

Він не містить дерева з коренем None, бо TC-01 вимагає наявного кореня.

### 2.2. Повне коіндуктивне дерево

`FullTree_A^(b) := νX. Leaf(A) ⊔ Node(X^b)`.

Це відповідає типу W23′.1.4, де FullTree прямо названо коіндуктивним.

### 2.3. Розмежування старого PartialTree

Запис W23′.1.5
`PartialTree_A^(b) ≅ None ⊔ Leaf(A) ⊔ Node(PartialTree_A^(b))^b`
не містить позначення μ чи ν. Отже, він не визначає, чи мається на увазі least fixed point, чи greatest fixed point.

Цей patch не змінює старий символ мовчки. До окремої редакції W23′:
- `PartialTree_A^(b)` — legacy notation із невизначеною fixed-point семантикою;
- `PartialTree∞_A^(b)` — новий явно коіндуктивний тип;
- усі твердження про нескінченні часткові дерева стосуються `PartialTree∞_A^(b)`.

## 3. Кодування Enc

Для кожного `p∈PartialTree∞_{A,root}^(b)` визначимо тотальний код `Enc_P(p):Pos_b→S_A` коіндуктивною рекурсією за адресою.

Для будь-якої адреси u, якщо піддерево p|u має конструктор:
- None, то `Enc_P(p)(u)=ABSENT`;
- Leaf(a), то `Enc_P(p)(u)=LEAF(a)`;
- Node(p₁,…,p_b), то `Enc_P(p)(u)=INTERNAL`, а для кожного i код у позиції ui дорівнює коду відповідного піддерева pᵢ.

Для None та Leaf усі строгі нащадки кодуються ABSENT. Це робить Enc тотальним на всьому Pos_b.

### Лема 3.1 — локальна допустимість

Для кожного p∈PartialTree∞_{A,root}^(b), `Enc_P(p)∈C_Partial`.

**Доказ.**
Корінь не None, тому TC-01. Якщо стан у u є None, усі піддерева під ним відсутні, тому TC-02. Якщо стан Leaf(a), усі діти ABSENT, тому TC-03. Якщо стан Node, його діти кодуються відповідними станами None/Leaf/Node, отже TC-05. □

### 3.2. Повне кодування

Обмеження Enc на `FullTree_A^(b)` визначає:

`Enc_F:FullTree_A^(b)→C_Full`.

Leaf(a) кодується LEAF(a), Node — INTERNAL із b не-ABSENT дочірніми кодами. Локальні умови TC-01–TC-04 виконуються.

---

## 4. Декодування Dec

Для `t∈C_Partial` визначимо `Dec_P(t)` як коіндуктивний об'єкт:
- якщо t(ε)=ABSENT, кореневий результат None;
- якщо t(ε)=LEAF(a), результат Leaf(a);
- якщо t(ε)=INTERNAL, результат Node(Dec_P(t₁),…,Dec_P(t_b)), де tᵢ є зсувом коду до дочірнього піддерева i.

Оскільки C_Partial вимагає TC-01, перший випадок не виникає для кореневого коду. Він залишений у загальному рекурсивному правилі для дочірніх підкодів.

TC-02 гарантує, що ABSENT-позиція декодується в None з усіма відсутніми нащадками. TC-03 гарантує, що LEAF(a) не має дочірніх вузлів. TC-05 гарантує, що кожен INTERNAL має рівно b позицій дітей, кожна з яких декодується як None, Leaf або Node.

Для повного класу:

`Dec_F:C_Full→FullTree_A^(b)`

визначається аналогічно; TC-04 виключає None безпосередньо під INTERNAL-вузлом.

## 5. Теореми відповідності

### Теорема 5.1 — Enc/Dec для часткових дерев

`Dec_P(Enc_P(p))=p` для кожного p∈PartialTree∞_{A,root}^(b).

`Enc_P(Dec_P(t))=t` для кожного t∈C_Partial.

Отже:

`PartialTree∞_{A,root}^(b) ≅ C_Partial`.

**Доказова схема.**
Обидві рівності доводяться коіндукцією / бісимуляцією за кореневим конструктором. У кожному випадку None, Leaf(a), Node(children) кодування та декодування відновлюють той самий стан кореня; для Node гіпотеза бісимуляції застосовується до кожної з b дочірніх пар. Скінченна глибина довільна, тому всі координати Pos_b збігаються. □

**Статус:** MATHEMATICAL PROOF SKETCH; повний формальний доказ не виконано.

### Теорема 5.2 — Enc/Dec для повних дерев

`Dec_F(Enc_F(f))=f` для кожного f∈FullTree_A^(b), а `Enc_F(Dec_F(t))=t` для кожного t∈C_Full.

Отже:

`FullTree_A^(b) ≅ C_Full`.

Доведення аналогічне, але Node завжди має b наявних дочірніх дерев.

**Статус:** MATHEMATICAL PROOF SKETCH; повний формальний доказ не виконано.

## 6. Метрика та ізометрія

На кожному кодованому класі визначено:

`r_F(t,s)=min{|u|:t(u)≠s(u)}`, якщо t≠s; `r_F(t,t)=∞`.

`d_F(t,s)=2^(−r_F(t,s))`.

На коіндуктивних деревах визначимо:

`r_P(p,q)=min{|u|:state(p|u)≠state(q|u)}`

та `d_P(p,q)=2^(−r_P(p,q))`; аналогічно d_Full.

### Теорема 6.1 — ізометричність

`d_P(p,q)=d_F(Enc_P(p),Enc_P(q))`.

`d_Full(f,g)=d_F(Enc_F(f),Enc_F(g))`.

Це випливає з того, що Enc зберігає стан у кожній адресі, а тому перша адреса відмінності зберігається точно.

**Наслідок.** Ізоморфізми §5 є ізометричними щодо метрик першої відмінності.

**Уточнення.** Метрика d_F у W23′ первинно задана на функціональному просторі дерев. Цей patch показує, як її можна інтерпретувати на кодах; канонічне перенесення позначення до W23′ потребує окремого інтеграційного commit.

## 7. Перенесення Tω та Tω⁺

Для `p∈PartialTree∞_{A,root}^(b)` і коду `t=Enc_P(p)` нескінченна гілка від внутрішнього вузла u — це адреса ξ∈[u], для якої кожен префікс ξ|k, k≥|u|, має стан INTERNAL.

Визначимо:

`Tω_P={p∈PartialTree∞_{A,root}^(b): кожен Node-вузол p|u має нескінченну Node-гілку}`.

За означенням Enc зберігає стан INTERNAL/Node на кожній адресі, отже:

### Теорема 7.1

`Enc_P(Tω_P)=C_ω`.

Це не нове незалежне твердження про існування гілок; це перенесення одного й того самого предиката через покоординатне кодування.

### Теорема 7.2 — непорожня межа

Для кожного `t∈C_ω`:

`∂t≠∅ ⇔ t(ε)=INTERNAL`.

**Доказ.**
Якщо t(ε)=INTERNAL, означення C_ω застосоване до ε дає нескінченну INTERNAL-гілку, тобто елемент межі. Якщо t(ε)=LEAF(a), нескінченної гілки з кореня немає; TC-01 виключає ABSENT. □

Тому:

`Enc_P(Tω_P^+)=C_ω^+=C_ω∩{t:t(ε)=INTERNAL}`,

де `Tω_P^+={p∈Tω_P:∂p≠∅}`.

Це узгоджується зі змістом W23′.7 та W23′.5.2, але не проголошує старий legacy-тип PartialTree автоматично ізоморфним новому коіндуктивному типу.

## 8. Компактність та топологічний наслідок

Оскільки C_Partial і C_Full компактні за W34.1.3, а Enc/Dec є ізометричними бієкціями, відповідні коіндуктивні типи з метриками d_P та d_Full компактні.

Оскільки C_ω замкнений у C_Partial, Tω_P також компактний. Обмеження кореневого стану INTERNAL є clopen, тому Tω_P^+ компактний.

Це твердження стосується саме введеного `PartialTree∞`, а не неуточненого legacy-символу W23′.
