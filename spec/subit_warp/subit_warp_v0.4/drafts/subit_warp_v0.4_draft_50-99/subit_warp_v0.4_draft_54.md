## 0. Executive determination

W50 перевіряє не лише правильність запропонованих у W49.1 означень, а й логічну необхідність кожної аксіоми.

Основний результат:

1. Система UFP-01…UFP-11 є достатньою для реконструкції rooted tree, але містить надлишкові умови.
2. UFP-03, UFP-09, UFP-10 та UFP-11 можна вивести з компактнішої базової системи.
3. UFP-10 — властивість вкладеності рівневих класів, яка випливає з еквівалентності `E_k` та унікальності представника кожного класу.
4. UFP-11 — властивість точного відновлення спільної глибини, яка також випливає з базових умов.
5. Реконструйоване дерево не обов’язково є скінченно-гіллястим або b-арним. Обмеження на branching factor потрібно задавати окремо.
6. T-021 потребує чіткого розділення між:
   - заданими позитивними та негативними спостереженнями;
   - множиною допустимих повних дерев;
   - статусами PRESENT / ABSENT / UNKNOWN, які виводяться з цієї множини.
7. `UNKNOWN` не можна трактувати як просту відсутність інформації у вхідному записі. Це точний семантичний статус: існують допустимі completions з обома можливими значеннями.
8. T-021B є коректною класифікаційною лемою за умови непорожності множини completions. Вона не доводить, що довільний partial fingerprint має хоча б одне completion.

**Загальний висновок:** T-020 можна спростити до компактної аксіоматичної системи з подальшим доведенням властивостей UFP-10 та UFP-11 як теорем. T-021 слід переформулювати через completion semantics, а не через незалежне призначення трьох статусів кожній позиції.

# PART I. T-020 — UNORDERED FINGERPRINT RECONSTRUCTION

## 1. Мета реконструкції

Нехай задано fingerprint:

`F_rec = (L, h, a)`

де:

- `L` — множина вузлів;
- `h : L → ℕ₀` — функція глибини;
- `a : L × L → ℕ₀` — симетрична функція спільної глибини.

Мета — відновити rooted tree, у якому:

- вузол `x` має глибину `h(x)`;
- `a(x,y)` дорівнює глибині найглибшого спільного предка вузлів `x` та `y`;
- кожен вузол, крім кореня, має рівно одного безпосереднього батька;
- кожен вузол має скінченний шлях до кореня.

Тут не передбачається порядок дочірніх вузлів.

## 2. Початкова система UFP-01…UFP-11

У W49.1 було запропоновано одинадцять умов.

### Базові умови

**UFP-01 — Nonempty node set**

`L ≠ ∅`.

**UFP-02 — Depth function**

`h : L → ℕ₀`.

**UFP-03 — Unique root level**

Існує рівно один вузол `r ∈ L`, для якого:

`h(r) = 0`.

**UFP-04 — Symmetry**

`a(x,y) = a(y,x)`.

**UFP-05 — Self-depth**

`a(x,x) = h(x)`.

**UFP-06 — Depth bound**

`0 ≤ a(x,y) ≤ min(h(x),h(y))`.

**UFP-07 — Equivalence at each level**

Для кожного `k ∈ ℕ₀` відношення

`x ≡ₖ y ⇔ a(x,y) ≥ k`

є відношенням еквівалентності на:

`L_≥k = {x ∈ L : h(x) ≥ k}`.

### Умови представників та узгодженості

**UFP-08 — Unique level representative**

Кожен клас еквівалентності `E_k` містить рівно один вузол рівня `k`.

**UFP-09 — Root compatibility**

Для кожного `x ∈ L`:

`π₀(x) = r`.

**UFP-10 — Nested ancestry**

Для `0 ≤ j ≤ k ≤ h(x)`:

`πⱼ(πₖ(x)) = πⱼ(x)`.

**UFP-11 — Exact common-depth**

`a(x,y) = max{k : πₖ(x) = πₖ(y)}`.

Тут `πₖ(x)` позначає єдиного представника рівня `k` у класі еквівалентності, що містить `x`.

## 3. Скорочена базова аксіоматична система

W50 пропонує не вилучати умови механічно, а замінити початкову систему її компактнішою основою.

### UFP-M01 — Nonempty domain

`L ≠ ∅`.

### UFP-M02 — Natural depth

`h : L → ℕ₀`.

### UFP-M03 — Symmetric common-depth function

`a : L × L → ℕ₀`.

Для всіх `x,y ∈ L`:

`a(x,y) = a(y,x)`,

`a(x,x) = h(x)`,

`0 ≤ a(x,y) ≤ min(h(x),h(y))`.

### UFP-M04 — Level equivalence

Для кожного `k ∈ ℕ₀` відношення

`x Eₖ y ⇔ a(x,y) ≥ k`

є еквівалентністю на `L_≥k`.

### UFP-M05 — Unique level representative

Для кожного `k ∈ ℕ₀` кожен клас `Eₖ` містить рівно один елемент множини:

`L_k = {x ∈ L : h(x)=k}`.

Це п’ять базових груп умов. UFP-M01…M05 є достатніми для реконструкції rooted tree.

Важливо: ця система не накладає обмеження на кількість дітей одного вузла.

---

## 4. Перевірка існування та єдиності рівневого представника

Для кожного `x ∈ L` та кожного `k ≤ h(x)` клас еквівалентності `Eₖ(x)` існує, оскільки:

`a(x,x) = h(x) ≥ k`.

За UFP-M04 це коректний клас еквівалентності.

За UFP-M05 цей клас містить рівно один вузол рівня `k`.

Позначимо його:

`πₖ(x)`.

Отже, функція:

`πₖ : L_≥k → L_k`

визначена однозначно.

### Лема 4.1 — Identity at own level

Для кожного `x ∈ L`:

`πₕ₍ₓ₎(x) = x`.

**Доведення.**

Нехай `k = h(x)`.

Тоді:

`a(x,x) = h(x) = k`.

Отже, `x Eₖ x`.

Вузол `x` належить рівню `L_k` і є елементом власного класу еквівалентності.

За UFP-M05 цей клас має рівно одного представника рівня `k`.

Оскільки `x` вже є таким представником:

`πₖ(x)=x`.

Доведено.

Цей крок є необхідним для коректного визначення безпосереднього батька.

## 5. Root uniqueness як наслідок базових умов

Початкова UFP-03 вимагає існування рівно одного кореня.

Однак її можна вивести.

Розглянемо `k=0`.

Оскільки:

`a(x,y) ≥ 0`

для всіх `x,y ∈ L`, маємо:

`x E₀ y`

для будь-якої пари вузлів.

Отже, `E₀` має рівно один клас — усю множину `L`.

За UFP-M05 цей клас містить рівно один елемент рівня `0`.

Тому існує рівно один:

`r ∈ L₀`.

Отже:

**Theorem 5.1 — Unique root**

За UFP-M01…M05 існує рівно один корінь.

`∃! r ∈ L : h(r)=0`.

UFP-03 є надлишковою.

### Root compatibility

Для кожного `x ∈ L` клас `E₀(x)` дорівнює всій множині `L`.

Його єдиний представник рівня 0 — це `r`.

Тому:

`π₀(x)=r`.

Отже, UFP-09 також є наслідком базових умов.

## 6. Чи випливає UFP-10 із вкладеності еквівалентностей?

Це центральна перевірка W50.

Потрібно довести:

`πⱼ(πₖ(x)) = πⱼ(x)`

для всіх:

`0 ≤ j ≤ k ≤ h(x)`.

### Лема 6.1 — Monotonicity of equivalence

Якщо:

`x Eₖ y`

і:

`j ≤ k`,

то:

`x Eⱼ y`.

**Доведення.**

За визначенням:

`a(x,y) ≥ k`.

Оскільки `j ≤ k`, маємо:

`a(x,y) ≥ j`.

Отже:

`x Eⱼ y`.

### Теорема 6.2 — Nested representative identity

Для кожного `x ∈ L` та `0 ≤ j ≤ k ≤ h(x)`:

`πⱼ(πₖ(x)) = πⱼ(x)`.

**Доведення.**

Позначимо:

`z = πₖ(x)`.

За визначенням `πₖ`:

`z Eₖ x`.

За лемою 6.1:

`z Eⱼ x`.

Тепер:

- `πⱼ(z)` — єдиний представник рівня `j` у класі `Eⱼ(z)`;
- `πⱼ(x)` — єдиний представник рівня `j` у класі `Eⱼ(x)`.

Оскільки `z Eⱼ x`, ці класи збігаються.

За унікальністю представника:

`πⱼ(z)=πⱼ(x)`.

Підставляючи `z=πₖ(x)`, отримуємо:

`πⱼ(πₖ(x))=πⱼ(x)`.

Доведено.

**Результат:** UFP-10 не є незалежною аксіомою. Вона випливає з UFP-M04 та UFP-M05.

### Інтерпретація

Вкладеність ancestry не потрібно додатково постулювати.

Вона вже закладена у монотонності порогових відношень:

`Eₖ ⊆ Eⱼ` для `j ≤ k`

на відповідних областях визначення.

Це важливий результат для SUBIT-WARP: ієрархія спільних предків виникає з узгодженої системи рівневих еквівалентностей, а не додається як окреме структурне припущення.

## 7. Чи випливає UFP-11 із визначення представників?

Потрібно довести:

`a(x,y)=max{k : πₖ(x)=πₖ(y)}`.

### Лема 7.1 — Equality of representatives implies equivalence

Для `k ≤ min(h(x),h(y))`:

`πₖ(x)=πₖ(y) ⇒ x Eₖ y`.

**Доведення.**

Нехай:

`πₖ(x)=πₖ(y)=z`.

За визначенням представника:

`x Eₖ z` та `y Eₖ z`.

За симетричністю:

`z Eₖ y`.

За транзитивністю:

`x Eₖ y`.

Доведено.

### Лема 7.2 — Equivalence implies equality of representatives

Якщо:

`x Eₖ y`,

то:

`πₖ(x)=πₖ(y)`.

**Доведення.**

Відношення еквівалентності означає, що `x` і `y` належать одному класу `Eₖ`.

За UFP-M05 цей клас має рівно одного представника рівня `k`.

Тому представники збігаються.

### Теорема 7.3 — Exact common-depth

Для будь-яких `x,y ∈ L`:

`a(x,y)=max{k : πₖ(x)=πₖ(y)}`.

**Доведення.**

Нехай:

`m=a(x,y)`.

За UFP-M03:

`m ≤ min(h(x),h(y))`.

Для кожного `k ≤ m`:

`a(x,y) ≥ k`.

Отже:

`x Eₖ y`.

За лемою 7.2:

`πₖ(x)=πₖ(y)`.

Для кожного `k > m`:

`a(x,y)<k`.

Тому:

`x Eₖ y`

не виконується.

За лемою 7.1 рівність представників також не може виконуватися.

Отже, множина рівнів, на яких представники збігаються, має найбільший елемент `m`.

Тому:

`max{k : πₖ(x)=πₖ(y)}=a(x,y)`.

Доведено.

**Результат:** UFP-11 є теоремою, а не незалежною аксіомою.

## 8. Побудова parent relation

Визначимо:

`parent(x)=π₍ₕ₍ₓ₎₋₁₎(x)`

для всіх `x`, для яких:

`h(x)>0`.

Для кореня parent не визначається.

### Теорема 8.1 — Parent existence

Для кожного `x` із `h(x)>0` існує батько.

**Доведення.**

Нехай:

`n=h(x)>0`.

Тоді:

`n−1≤h(x)`.

За UFP-M05 клас `E_(n−1)(x)` містить рівно одного представника рівня `n−1`.

Це і є:

`parent(x)=π_(n−1)(x)`.

Отже, батько існує.

### Теорема 8.2 — Parent uniqueness

Для кожного вузла ненульової глибини батько єдиний.

Це безпосередньо випливає з умови унікальності представника в UFP-M05.

### Теорема 8.3 — Depth decrement

Для кожного `x` із `h(x)>0`:

`h(parent(x))=h(x)−1`.

Це випливає з того, що `parent(x)` належить рівню `L_(h(x)−1)`.

## 9. Доведення rooted-tree structure

Побудуємо граф:

`G=(L,E_parent)`,

де ребро з'єднує кожен вузол із його parent.

Потрібно показати:

1. існування кореня;
2. єдиність кореня;
3. єдиність батька кожного некореневого вузла;
4. зв'язність;
5. відсутність циклів.

Перші три властивості вже доведені.

### 9.1. Скінченний шлях до кореня

Для вузла `x` із глибиною `n` послідовно застосовуємо parent:

`xₙ → xₙ₋₁ → … → x₁ → x₀`.

На кожному кроці глибина зменшується рівно на одиницю.

Оскільки `h(x)=n∈ℕ₀`, після рівно `n` кроків отримуємо вузол глибини 0.

За теоремою 5.1 це єдиний корінь `r`.

Отже, кожен вузол має скінченний шлях до кореня.

### 9.2. Відсутність циклів

При кожному переході до parent глибина строго зменшується.

Тому неможливо повернутися до початкового вузла, не порушивши монотонність глибини.

Отже, циклів немає.

### 9.3. Зв'язність

Кожен вузол з'єднаний із коренем своїм parent-шляхом.

Отже, граф зв'язний.

### Теорема 9.4 — Reconstruction existence

За UFP-M01…M05 структура:

`T_rec=(L,parent,r,h)`

є rooted tree.

Доведено.

## 10. Єдиність реконструкції

Потрібно показати, що fingerprint визначає не лише деяке дерево, а й єдине дерево з точністю до ізоморфізму.

Нехай існують два rooted trees:

`T₁=(L₁,parent₁,r₁,h₁)`

та

`T₂=(L₂,parent₂,r₂,h₂)`

із відповідними fingerprint-структурами, що задовольняють ті самі умови та відтворюють однакові дані.

Якщо вузли fingerprint уже є ідентифікованими елементами `L`, то:

`parent(x)=π_(h(x)−1)(x)`

визначає parent однозначно.

Отже, обидві реконструкції мають однакове parent relation на `L`.

Тотожне відображення:

`id_L : L → L`

є ізоморфізмом rooted trees.

Якщо ж реконструкції побудовані на різних множинах вузлів, але мають ізоморфні fingerprint-дані через бієкцію `φ`, то ця бієкція зберігає:

- глибини;
- функцію `a`;
- класи `Eₖ`;
- єдиних представників `πₖ`;
- parent relation.

Тому `φ` є ізоморфізмом rooted trees.

### Теорема 10.1 — Reconstruction uniqueness

Fingerprint `F_rec=(L,h,a)` визначає rooted tree з точністю до ізоморфізму, за умови UFP-M01…M05.

Доведено.

## 11. Крайові випадки T-020

### 11.1. Єдиний корінь без дітей

Нехай:

`L={r}`, `h(r)=0`, `a(r,r)=0`.

Усі умови виконуються.

Реконструкція дає дерево з одним вузлом.

**Статус:** PASS.

### 11.2. Unary chain

Нехай:

`L={x₀,x₁,…,x_n}`,

`h(x_i)=i`,

`a(x_i,x_j)=min(i,j)`.

Реконструюється ланцюг:

`x₀ → x₁ → … → x_n`.

**Статус:** PASS.

### 11.3. Finite leaves

Вузол із глибиною `n` може не мати дітей.

Це не порушує жодної умови.

Fingerprint реконструює parent relation, але не вимагає, щоб кожен вузол мав нащадка.

**Статус:** PASS.

### 11.4. Infinite branches

Нескінченна гілка:

`x₀ → x₁ → x₂ → …`

може бути присутня.

Кожен її вузол має скінченну глибину, тому parent-реконструкція залишається коректною.

**Статус:** PASS.

### 11.5. Empty levels

Множина:

`L_k={x:h(x)=k}`

може бути порожньою для окремого `k`.

Однак якщо існує вузол глибини `n>k`, то його клас `E_k` повинен містити рівно одного представника рівня `k`.

Тому порожній рівень `k` неможливий, якщо існує хоча б один вузол глибини `n≥k`.

Інакше кажучи:

`L_≥k ≠ ∅ ⇒ L_k ≠ ∅`.

Звідси випливає, що множина зайнятих рівнів є початковим відрізком `ℕ₀` або всім `ℕ₀`.

Це не додаткова аксіома, а наслідок UFP-M05.

**Статус:** PASS.

### 11.6. Unbounded height

Можливе:

`sup{h(x):x∈L}=∞`.

Це означає, що висоти вузлів не мають скінченної верхньої межі.

Реконструкція залишається коректною: кожен окремий вузол має скінченну глибину.

**Статус:** PASS.

### 11.7. Uncountable node set

UFP-M01…M05 не вимагають зліченності `L`.

Отже, можливі незліченні множини вузлів і незліченна кількість дітей одного вузла.

Це не порушує доведення rooted-tree structure.

Однак якщо SUBIT-WARP потребує скінченної або обмеженої гіллястості, таке обмеження необхідно вводити окремо.

**Статус:** PASS, але клас дерев ширший за finite-branching trees.

## 12. Branching factor: окреме структурне обмеження

Початкова unordered reconstruction не визначає максимальну кількість дітей.

Тому не можна автоматично робити висновок:

`deg⁺(x) ≤ b`.

Для b-арного дерева потрібна окрема умова:

`∀x∈L : |Child(x)| ≤ b`.

Для повного b-арного дерева потрібна сильніша умова:

`∀x∈L : |Child(x)| = b`.

Для скінченно-гіллястого дерева:

`∀x∈L : |Child(x)| < ∞`.

Ці умови не є еквівалентними.

### Рекомендація

Не включати branching constraint до загальної теореми T-020.

Натомість визначити окремі класи:

- `Tree_rooted` — довільні rooted trees;
- `Tree_finitely_branching` — скінченно-гіллясті rooted trees;
- `Tree_bounded(b)` — дерева з branching factor не більшим за `b`;
- `Tree_full(b)` — повні b-арні дерева.

Таке розділення не дозволяє непомітно переносити властивості b-арних дерев на загальну unordered reconstruction.

---

## 13. Контрприклади та необхідність базових умов

Тут перевіряється, що базові групи UFP-M01…M05 не є довільними.

### 13.1. Вилучення UFP-M01

Якщо дозволити:

`L=∅`,

то існує порожня структура без кореня.

Вона не є rooted tree у звичайному визначенні.

**Висновок:** nonempty domain потрібний.

### 13.2. Вилучення UFP-M02

Якщо `h` не має значень у `ℕ₀`, то може виникнути структура з від'ємними або нецілими рівнями.

Тоді операція:

`h(x)−1`

не обов'язково визначає попередній дискретний рівень.

**Висновок:** натуральна дискретна глибина потрібна для цієї конструкції.

### 13.3. Вилучення self-depth

Нехай:

`L={r,x}`, `h(r)=0`, `h(x)=1`.

Визначимо:

`a(r,r)=0`, `a(x,x)=0`, `a(r,x)=a(x,r)=0`.

Тоді `a` симетрична, невід'ємна й обмежена зверху глибинами.

Усі `E_k` можуть бути еквівалентностями на відповідних областях, а представник рівня 0 існує.

Проте:

`a(x,x) ≠ h(x)`.

Для рівня 1 не існує класу `E₁(x)`, який містив би `x`, тому вузол `x` не має власного рівневого представника.

Реконструкція руйнується.

**Висновок:** self-depth потрібна.

### 13.4. Вилучення symmetry

Якщо `a` несиметрична, то `E_k` може бути несиметричним і не бути відношенням еквівалентності.

Тоді поняття класу еквівалентності та єдиного представника втрачає підставу.

**Висновок:** симетрія потрібна, якщо `a` інтерпретується як спільна глибина.

### 13.5. Вилучення depth bound

Якщо дозволити:

`a(x,y)>min(h(x),h(y))`,

то спільна глибина може перевищувати глибину одного з вузлів.

Це суперечить інтерпретації `a` як глибини спільного предка.

Наприклад, якщо `h(x)=1`, `h(y)=2`, але `a(x,y)=2`, то вузол `x` нібито має спільного предка на рівні 2, хоча сам знаходиться на рівні 1.

**Висновок:** depth bound потрібна.

### 13.6. Вилучення equivalence transitivity

Нехай на рівні `k` задано три вузли `x,y,z` і:

`a(x,y)≥k`,  
`a(y,z)≥k`,  
`a(x,z)<k`.

Тоді:

`x Eₖ y`,  
`y Eₖ z`,  
але не `x Eₖ z`.

Не існує коректного розбиття на класи спільних предків.

**Висновок:** транзитивність потрібна.

### 13.7. Вилучення unique representative

Нехай на рівні `k` один клас `Eₖ` містить два різні вузли `u` та `v`, обидва з глибиною `k`.

Тоді для вузла `x` цього класу:

`πₖ(x)` не визначається однозначно.

Parent relation стає неоднозначним.

**Висновок:** унікальність представника потрібна.

---

## 14. Точний статус UFP-01…UFP-11

Після перевірки маємо:

- **UFP-01:** необхідна; зберегти.
- **UFP-02:** необхідна; зберегти.
- **UFP-03:** надлишкова; випливає з UFP-01, UFP-06, UFP-07, UFP-08.
- **UFP-04:** необхідна як частина визначення common-depth function.
- **UFP-05:** необхідна.
- **UFP-06:** необхідна.
- **UFP-07:** необхідна.
- **UFP-08:** необхідна.
- **UFP-09:** надлишкова; випливає з єдиного класу `E₀` та UFP-08.
- **UFP-10:** теорема; випливає з монотонності `Eₖ` та унікальності представників.
- **UFP-11:** теорема; випливає з відповідності між `Eₖ` та рівністю представників.

**Рішення:** UFP-03, UFP-09, UFP-10 та UFP-11 не повинні залишатися незалежними аксіомами.

# PART II. T-021 — ORDERED PARTIAL FINGERPRINT AND COMPLETION SEMANTICS

## 15. Проблема попереднього визначення

У W49.1 було запропоновано три статуси:

- PRESENT;
- ABSENT;
- UNKNOWN.

Водночас UNKNOWN визначався як існування двох completions, одне з яких містить позицію, а інше — ні.

Це визначення правильне за умови непорожньої множини completions.

Однак воно створює проблему, якщо статуси спочатку задаються як вхідні дані, а потім використовуються для побудови самої множини completions.

Наприклад:

- вузол `u` позначено як ABSENT;
- дочірню позицію `u·i` позначено як UNKNOWN.

Але prefix closure означає, що якщо `u` відсутній, то `u·i` також обов'язково відсутній.

Отже, UNKNOWN у цьому випадку не є коректним статусом.

Потрібно відокремити обмеження від результату семантичної класифікації.

---

## 16. Простір адрес

Нехай:

`B_b={1,…,b}`,

де `b≥1`.

Позначимо:

`B_b*`

множину всіх скінченних слів над алфавітом `B_b`, включно з порожнім словом:

`ε`.

Конкатенацію адрес позначимо:

`u·i`.

Адреса `v` є префіксом `u`, якщо існує слово `w`, для якого:

`u=v·w`.

### Definition 16.1 — Ordered tree

`T ⊆ B_b*` є ordered tree, якщо:

1. `ε∈T`;
2. `u∈T` і `v` є префіксом `u` ⇒ `v∈T`.

Тобто дерево містить корінь і є prefix-closed.

Це визначення не вимагає, щоб кожен вузол мав усі можливі дочірні позиції.

Для `u∈T` його дочірні позиції мають вигляд:

`u·i`, де `i∈B_b`.

Якщо `u·i∈T`, ця позиція зайнята.

---

## 17. Простір допустимих completions

Потрібно визначити клас дерев, серед яких відбувається реконструкція.

Позначимо його:

`𝒯_allowed`.

Це може бути:

- клас усіх prefix-closed дерев над `B_b*`;
- клас лише скінченних дерев;
- клас дерев із заданою максимальною глибиною;
- клас дерев із додатковими структурними обмеженнями;
- клас нескінченних або змішаних дерев, якщо це дозволено конкретною моделлю.

Важливо: `𝒯_allowed` є частиною контексту задачі.

Не можна непомітно змінювати цей клас між двома fingerprint-записами, якщо їхні completion semantics мають бути порівнюваними.

### Definition 17.1 — Positive constraints

Нехай:

`P ⊆ B_b*`

— множина адрес, які мають бути присутніми.

### Definition 17.2 — Negative constraints

Нехай:

`A ⊆ B_b*`

— множина адрес, які мають бути відсутніми.

Ці множини задають спостереження, а не остаточну класифікацію всіх позицій.

---

## 18. Prefix closure of positive constraints

Якщо позиція `u` обов'язково присутня, усі її префікси також обов'язково присутні.

Визначимо:

`P* = {v : ∃u∈P, v є префіксом u} ∪ {ε}`.

Це prefix closure позитивних спостережень.

Навіть якщо `P=∅`, корінь має бути присутнім у кожному допустимому дереві.

Тому `ε` включається до `P*` незалежно від вхідного набору.

### Наслідок

Для кожного:

`u∈P*`

будь-яке допустиме completion повинно містити `u`.

---

## 19. Downward propagation of negative constraints

Якщо позиція `u` відсутня, жоден її нащадок не може бути присутнім через prefix closure.

Визначимо:

`A* = {v : ∃u∈A, u є префіксом v}`.

Тобто `A*` містить усі адреси, які лежать під негативно позначеними позиціями.

### Наслідок

Для кожного:

`v∈A*`

будь-яке допустиме completion повинно не містити `v`.

---

## 20. Completion set

### Definition 20.1 — Completion set

Визначимо:

`Comp(P,A;𝒯_allowed)`

як множину:

`{T∈𝒯_allowed : P*⊆T ∧ T∩A*=∅}`.

Тобто completion:

- належить дозволеному класу дерев;
- містить усі обов'язкові позитивні адреси;
- не містить жодної обов'язково відсутньої адреси та її нащадків.

### Definition 20.2 — Consistency

Fingerprint є completion-consistent тоді й лише тоді, коли:

`Comp(P,A;𝒯_allowed) ≠ ∅`.

Це принципова умова.

Самої перевірки:

`P*∩A*=∅`

недостатньо в усіх можливих моделях.

Вона гарантує відсутність прямого конфлікту позитивних і негативних обмежень, але не гарантує існування дерева в довільному `𝒯_allowed`.

Наприклад, якщо `𝒯_allowed` обмежений деревами глибини не більше 3, а `P` містить адресу глибини 5, множина completions порожня, навіть якщо `P*∩A*=∅`.

Тому:

`P*∩A*=∅`

є необхідною умовою сумісності, але загальна умова — це непорожність `Comp`.

---

## 21. Статуси PRESENT / ABSENT / UNKNOWN

Тепер статуси визначаються не як довільні вхідні позначки, а як результат аналізу completion set.

Для кожної адреси:

`u∈B_b*`

визначимо:

### PRESENT

`σ(u)=PRESENT`

тоді й лише тоді, коли:

`∀T∈Comp : u∈T`.

Позиція присутня в усіх допустимих completions.

### ABSENT

`σ(u)=ABSENT`

тоді й лише тоді, коли:

`∀T∈Comp : u∉T`.

Позиція відсутня в усіх допустимих completions.

### UNKNOWN

`σ(u)=UNKNOWN`

тоді й лише тоді, коли:

`∃T₁,T₂∈Comp : u∈T₁ ∧ u∉T₂`.

Позиція присутня в деяких допустимих completions і відсутня в інших.

Це визначення робить UNKNOWN точним семантичним статусом.

UNKNOWN не означає:

- що дані не завантажені;
- що алгоритм ще не обчислив значення;
- що користувач не вказав статус;
- що позиція просто не згадується у fingerprint.

UNKNOWN означає реальну варіативність між допустимими реконструкціями.

---

## 22. Теорема тристатусної класифікації

### Theorem 22.1 — Completion trichotomy

Нехай:

`Comp ≠ ∅`.

Для кожної адреси `u` рівно один із трьох статусів виконується:

1. PRESENT;
2. ABSENT;
3. UNKNOWN.

### Доведення

Розглянемо два випадки.

**Випадок A.**

Для всіх `T∈Comp`:

`u∈T`.

Тоді статус PRESENT.

Оскільки `Comp` непорожня, одночасно не може бути істинним ABSENT або UNKNOWN.

**Випадок B.**

Не всі completions містять `u`.

Тоді існує:

`T₀∈Comp`, для якого `u∉T₀`.

Тепер:

- якщо жодне completion не містить `u`, статус ABSENT;
- якщо існує `T₁∈Comp`, для якого `u∈T₁`, статус UNKNOWN.

Ці випадки взаємовиключні.

Отже, рівно один статус виконується.

Доведено.

### Обмеження теореми

Теорема не доводить:

`Comp ≠ ∅`.

Вона починає працювати лише після того, як непорожність completion set встановлена.

Тому T-021B не може використовуватися як доказ загальної консистентності довільного partial fingerprint.

---

## 23. Наслідки prefix closure

### Теорема 23.1 — Absent-prefix propagation

Якщо:

`σ(u)=ABSENT`,

то для кожного нащадка `v` адреси `u`:

`σ(v)=ABSENT`.

**Доведення.**

За визначенням ABSENT:

`∀T∈Comp : u∉T`.

Оскільки кожне `T∈𝒯_allowed` є prefix-closed, якщо `v` є нащадком `u`, то:

`v∈T ⇒ u∈T`.

Але `u∉T` для всіх completions.

Отже:

`v∉T`

для всіх completions.

Тому `σ(v)=ABSENT`.

Доведено.

### Теорема 23.2 — Present-prefix propagation

Якщо:

`σ(u)=PRESENT`,

то кожен префікс `v` адреси `u` також має:

`σ(v)=PRESENT`.

**Доведення.**

Кожне completion містить `u`.

За prefix closure кожне completion містить усі префікси `u`.

Отже, кожен префікс присутній у всіх completions.

Доведено.

### Важливе уточнення

Якщо:

`σ(u)=UNKNOWN`,

то статус нащадка не визначається автоматично.

Нащадок може бути:

- ABSENT;
- UNKNOWN.

Він не може бути PRESENT, якщо його префікс `u` не є PRESENT.

Це уточнення важливе для коректної реалізації локальних правил поширення невизначеності.

---

## 24. Чому UNKNOWN у батька не означає UNKNOWN у дитини

Розглянемо позиції:

`u`, `u·i`.

Нехай є два допустимі completions:

- `T₁` не містить `u`;
- `T₂` містить `u`, але не містить `u·i`.

Тоді:

`σ(u)=UNKNOWN`.

Але:

`σ(u·i)=ABSENT`.

Отже, невизначеність батьківської позиції не передається автоматично всім дочірнім позиціям.

Це спростовує просту рекурсивну інтерпретацію:

`UNKNOWN(parent) ⇒ UNKNOWN(child)`.

Правильне правило:

`UNKNOWN(child)` визначається тільки тоді, коли існують допустимі completions з обома значеннями дочірньої позиції.

---

## 25. Приклад 1 — Однозначне completion

Нехай:

`P={ε,1,1·2}`,

`A={2}`.

Тоді:

`P*={ε,1,1·2}`.

`A*` містить адресу `2` та всі її нащадки.

Якщо `𝒯_allowed` дозволяє таке дерево, completion set може містити кілька дерев через невизначеність інших позицій.

Але для адрес:

- `ε`;
- `1`;
- `1·2`;
- `2`;

статуси однозначні:

- `ε`: PRESENT;
- `1`: PRESENT;
- `1·2`: PRESENT;
- `2`: ABSENT.

Інші адреси класифікуються за всіма допустимими completions.

Цей приклад показує, що позитивні й негативні спостереження не повинні визначати статуси невідомих позицій без аналізу completion set.

---

## 26. Приклад 2 — UNKNOWN як реальна варіативність

Нехай:

`P={ε}`,

`A={}`.

Нехай `𝒯_allowed` містить усі prefix-closed дерева над `B_b*`.

Для будь-якої непорожньої адреси `u`:

- існує completion, у якому `u` відсутня;
- існує completion, у якому `u` присутня разом з усіма її префіксами.

Тому:

`σ(u)=UNKNOWN`.

Водночас:

`σ(ε)=PRESENT`.

Це коректний partial fingerprint із великою кількістю невизначених позицій.

---

## 27. Приклад 3 — Неможливий partial fingerprint

Нехай:

`P={1·2}`,

`A={1}`.

Тоді:

`P*={ε,1,1·2}`.

`A*` містить `1` та всі його нащадки, зокрема `1·2`.

Отже:

`P*∩A* ≠ ∅`.

Тому:

`Comp(P,A;𝒯_allowed)=∅`.

Це не UNKNOWN.

Це суперечливий fingerprint.

### Розмежування

- UNKNOWN — існують альтернативні допустимі completions.
- INCONSISTENT — не існує жодного допустимого completion.

Ці статуси не можна змішувати.

---

## 28. Скінченні та нескінченні completions

Поняття completion залежить від обраного класу `𝒯_allowed`.

### 28.1. Усі prefix-closed дерева

Якщо дозволені всі prefix-closed дерева, то можна включати як скінченні, так і нескінченні дерева.

### 28.2. Лише скінченні дерева

Якщо:

`𝒯_allowed=𝒯_fin`,

то completion має бути скінченним.

У такому випадку деякі позиції можуть бути невизначеними, але нескінченні гілки не є допустимими completions.

### 28.3. Лише нескінченні дерева

Якщо:

`𝒯_allowed=𝒯_inf`,

то completion має задовольняти додаткову умову нескінченності.

Не кожен partial fingerprint матиме таке completion.

### 28.4. WARP relevance

Для SUBIT-WARP потрібно не змішувати:

- множину скінченних адрес;
- множину повних дерев;
- множину нескінченних гілок;
- boundary space.

Адреса є скінченним словом.

Нескінченна гілка є послідовністю сумісних адрес.

Boundary не тотожна множині всіх адрес і не тотожна множині всіх вузлів.

Відповідно, completion semantics має задаватися на просторі дерев, а boundary визначатися окремо для кожного повного дерева.

---

## 29. Ordered complete trie — T-021A

Нехай:

`F_ord=(L,p,h)`,

де:

- `L` — множина вузлів;
- `p : L → B_b*` — адресна функція;
- `h : L → ℕ₀` — глибина.

Умови:

**OT-01 — Injectivity**

`p(x)=p(y) ⇒ x=y`.

**OT-02 — Root**

Існує єдиний вузол `r`, для якого:

`p(r)=ε`.

**OT-03 — Prefix closure**

Для кожного `x∈L` і кожного префікса `v` адреси `p(x)` існує вузол `y∈L`, для якого:

`p(y)=v`.

**OT-04 — Depth consistency**

`h(x)=|p(x)|`.

Тоді:

`T=p(L)`

є єдиним occupied trie, сумісним із fingerprint.

### Теорема 29.1 — Unique ordered trie

За OT-01…OT-04 множина `T=p(L)` є prefix-closed деревом, яке однозначно визначається `F_ord`.

**Доведення.**

Корінь належить `T` за OT-02.

Для кожного елемента `p(x)∈T` усі його префікси належать `T` за OT-03.

Отже, `T` є prefix-closed.

Оскільки `p` ін'єктивна, кожна адреса відповідає не більше ніж одному вузлу.

Оскільки `T` безпосередньо визначається образом `p`, іншого occupied trie з тим самим fingerprint бути не може.

Доведено.

**Статус:** PROVED.

---

## 30. Перевірка PC-01…PC-10

Попередній список локальних правил потрібно інтерпретувати як перевірки узгодженості спостережень із completion semantics.

Після уточнення W50:

- **PC-01 — Root certainty:** корінь має бути PRESENT.
- **PC-02 — Prefix dependency:** PRESENT-позиція має PRESENT-префікси.
- **PC-03 — Absence propagation:** ABSENT-позиція має ABSENT-нащадків.
- **PC-04 — Present-child validity:** дочірня позиція не може бути PRESENT, якщо її батько не PRESENT.
- **PC-05 — Absent-child exclusion:** якщо батько ABSENT, дитина ABSENT.
- **PC-06 — Unknown variability:** UNKNOWN означає існування двох completions з різними значеннями позиції.
- **PC-07 — Address consistency:** адреси належать `B_b*`.
- **PC-08 — Depth consistency:** глибина дорівнює довжині адреси.
- **PC-09 — Known-prefix consistency:** кожна позитивно підтверджена адреса має підтверджені префікси.
- **PC-10 — Nonempty completion:** множина допустимих completions непорожня.

Ці правила мають різний логічний статус.

PC-01…PC-05 та PC-09 є наслідками prefix closure і семантики PRESENT / ABSENT.

PC-06 є визначенням UNKNOWN.

PC-07 та PC-08 є структурними обмеженнями адресного представлення.

PC-10 є окремою умовою консистентності.

**Важливо:** виконання локальних правил PC-01…PC-09 не замінює перевірки PC-10, якщо `𝒯_allowed` містить додаткові глобальні обмеження.

# PART III. REVISED THEOREM REGISTRY

## 31. T-020 — Unordered reconstruction

**Назва:** Unordered Fingerprint Reconstruction

**Формулювання:** За UFP-M01…M05 fingerprint `F_rec=(L,h,a)` визначає rooted tree з точністю до ізоморфізму.

**Статус:** PROVED MATHEMATICALLY IN THIS AUDIT.

**Залежності:**
- UFP-M01 Nonempty domain;
- UFP-M02 Natural depth;
- UFP-M03 Symmetric common-depth function;
- UFP-M04 Level equivalence;
- UFP-M05 Unique level representative.

**Необхідні застереження:**
- не доводить finite branching;
- не доводить b-ary structure;
- не доводить обмежену кількість вузлів;
- не доводить компактність простору дерев;
- не є Lean-верифікацією.

## 32. T-020A — Fingerprint consistency verification

**Назва:** Parent-LCA Consistency Verification

**Вхід:**

`F_ver=(L,h,a,p)`.

**Перевірки:**

1. кожен некореневий вузол має рівно одного parent;
2. parent має глибину на одиницю меншу;
3. parent iteration приводить до єдиного root;
4. `a(x,y)` дорівнює глибині LCA у заданому parent tree.

**Статус:** PROVED BY DIRECT VERIFICATION, якщо всі умови перевірені.

**Принципове розмежування:**

T-020A перевіряє відповідність уже заданого дерева fingerprint.

T-020 реконструює parent relation із fingerprint.

Це різні задачі.

## 33. T-021 — Ordered partial reconstruction

**Назва:** Ordered Partial Fingerprint Completion Semantics

**Вхід:**

`F_partial=(P,A,𝒯_allowed)`.

**Визначення:**

`Comp(P,A;𝒯_allowed)`.

**Умова коректності:**

`Comp ≠ ∅`.

**Статус:** DEFINITIONALLY WELL-POSED, за умови явного визначення `𝒯_allowed`.

## 34. T-021A — Complete ordered trie reconstruction

**Формулювання:** Ін'єктивне адресне відображення з root, prefix closure та depth consistency визначає єдиний occupied trie.

**Статус:** PROVED.

## 35. T-021B — Completion trichotomy

**Формулювання:** Якщо `Comp ≠ ∅`, кожна адреса має рівно один статус PRESENT, ABSENT або UNKNOWN відповідно до квантифікації по всіх completions.

**Статус:** PROVED.

**Обмеження:** не доводить непорожність `Comp`.

## 36. T-021C — Prefix propagation

**Формулювання:**
- PRESENT поширюється до всіх префіксів;
- ABSENT поширюється до всіх нащадків;
- UNKNOWN не має автоматичного статусного поширення до дітей.

**Статус:** PROVED.

# PART IV. INTEGRATION CONSEQUENCES

## 37. Наслідки для SUBIT-WARP v0.4

Результати W50 мають обмежений, але важливий вплив на архітектуру WARP.

### 37.1. Reconstruction layer

Unordered fingerprint reconstruction може бути окремим математичним модулем:

`Fingerprint → RootedTree`.

Його результат не повинен автоматично вважатися b-арним деревом.

### 37.2. Ordered address layer

Ordered reconstruction має іншу природу:

`AddressFingerprint → OrderedTrie`.

Вона залежить від алфавіту `B_b` та prefix closure.

Не слід змішувати її з unordered reconstruction без явного перетворення.

### 37.3. Partial knowledge layer

Partial fingerprint не є неповним повним деревом у простому сенсі.

Це система обмежень на множину можливих повних дерев:

`F_partial → Comp(F_partial)`.

Тому знання про позицію є властивістю всієї множини completions.

### 37.4. Boundary layer

Boundary повинна будуватися з конкретного повного дерева або чітко визначеного класу повних дерев.

Не можна без додаткового доведення ототожнювати:

- UNKNOWN у fingerprint;
- відсутність вузла;
- нескінченну гілку;
- boundary point.

Це чотири різні поняття.

# PART V. ACCEPTANCE CRITERIA

## 39. T-020 acceptance criteria

T-020 може бути прийнята до наступного етапу лише після підтвердження:

1. Базова система UFP-M01…M05 використовується замість одинадцяти незалежних аксіом.
2. UFP-03, UFP-09, UFP-10 та UFP-11 позначені як наслідки або теореми.
3. Доведено існування та єдиність `πₖ(x)`.
4. Доведено `πₕ₍ₓ₎(x)=x`.
5. Доведено єдиність root.
6. Доведено nested representative identity.
7. Доведено exact common-depth identity.
8. Доведено існування та єдиність parent.
9. Доведено rooted-tree structure.
10. Доведено uniqueness up to isomorphism.
11. Branching constraints винесені в окремий рівень специфікації.

## 40. T-021 acceptance criteria

T-021 може бути прийнята до наступного етапу лише після підтвердження:

1. `𝒯_allowed` визначено явно.
2. Позитивні й негативні обмеження відокремлено від статусів.
3. `P*` визначено як prefix closure.
4. `A*` визначено як closure негативних обмежень нащадками.
5. Completion set визначено через обидва обмеження.
6. Непорожність completion set є явною умовою.
7. PRESENT визначено через універсальну квантифікацію.
8. ABSENT визначено через універсальну квантифікацію.
9. UNKNOWN визначено через існування двох completions із протилежними значеннями.
10. Доведено тристатусну класифікацію.
11. Доведено propagation для PRESENT та ABSENT.
12. Не використовується некоректне правило автоматичного поширення UNKNOWN до дітей.
13. Скінченні й нескінченні completions розмежовано.
14. T-021B не подається як доказ існування completion.
