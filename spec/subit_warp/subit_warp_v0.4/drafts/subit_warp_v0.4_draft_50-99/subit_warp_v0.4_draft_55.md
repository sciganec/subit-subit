# 0. Executive determination

W51 продовжує W50, але ставить суворіше питання: чи є UFP-M01…M05 справді мінімальною системою, чи лише зручним скороченим набором?

Результати:

1. Умову еквівалентності UFP-M04 можна переписати через одну нерівність сильної транзитивності:
   `a(x,z) ≥ min(a(x,y),a(y,z))`.
2. Унікальність рівневого представника можна частково розкласти на дві незалежні властивості:
   - існування предка на кожному проміжному рівні;
   - унікальність вузла цього рівня в одному класі спільної глибини.
3. Унікальність кореня випливає з цих умов і не потребує окремої аксіоми.
4. UFP-10 та UFP-11 залишаються теоремами, а не аксіомами.
5. Для класу всіх prefix-closed дерев completion існує тоді й лише тоді, коли позитивні та негативні обмеження не конфліктують після closure.
6. Для класу скінченних дерев потрібна додаткова умова скінченності позитивного prefix closure.
7. Для класів дерев із глобальними обмеженнями — наприклад, повних дерев, дерев із нескінченними гілками або спеціальною структурою — проста перевірка локального конфлікту може бути недостатньою.
8. Визначення UNKNOWN через множину completions є семантично коректним, але обчислення цього статусу може бути нерозв'язним або неефективним для необмежених класів дерев.

**Головний висновок:** T-020 має компактне формулювання через strong similarity inequality та рівневу ancestral completeness. T-021 потребує параметризованого простору допустимих дерев. Не можна визначати completion semantics без фіксації цього простору.

# PART I. T-020 — FURTHER AXIOM MINIMIZATION

## 1. Вихідна структура

Нехай:

`F_rec=(L,h,a)`,

де:

- `L` — непорожня множина вузлів;
- `h:L→ℕ₀` — глибина;
- `a:L×L→ℕ₀` — функція спільної глибини.

Бажана реконструкція:

`T=(L,parent,r,h)`.

Для кожного `x∈L` та `k≤h(x)` потрібно визначити єдиного предка:

`πₖ(x)`.

Parent визначається через:

`parent(x)=π₍ₕ₍ₓ₎₋₁₎(x)`

для `h(x)>0`.

У W50 було встановлено, що система UFP-M01…M05 достатня.

W51 перевіряє, чи можна переформулювати її так, щоб відокремити:

- властивості функції спільної глибини;
- існування предків;
- унікальність предків.

---

## 2. Еквівалентність рівневих класів і сильна транзитивність

У W50 для кожного `k` було визначено:

`x Eₖ y ⇔ a(x,y)≥k`.

Вимагалося, щоб `Eₖ` було еквівалентністю на:

`L_≥k={x∈L:h(x)≥k}`.

Рефлексивність випливає з:

`a(x,x)=h(x)`.

Симетричність випливає з:

`a(x,y)=a(y,x)`.

Отже, єдиною нетривіальною властивістю є транзитивність.

### Лема 2.1 — Threshold transitivity

Для кожного `k` відношення `Eₖ` є транзитивним тоді й лише тоді, коли для всіх `x,y,z∈L`:

`a(x,z)≥min(a(x,y),a(y,z))`.

### Доведення напрямку A

Припустімо, що всі `Eₖ` транзитивні.

Нехай:

`m=min(a(x,y),a(y,z))`.

Оскільки значення `a` належать `ℕ₀`, `m` також належить `ℕ₀`.

Маємо:

`a(x,y)≥m`,

`a(y,z)≥m`.

Отже:

`x Eₘ y` та `y Eₘ z`.

За транзитивністю:

`x Eₘ z`.

Тому:

`a(x,z)≥m`.

Отже:

`a(x,z)≥min(a(x,y),a(y,z))`.

### Доведення напрямку B

Припустімо:

`a(x,z)≥min(a(x,y),a(y,z))`.

Нехай:

`x Eₖ y` та `y Eₖ z`.

Тоді:

`a(x,y)≥k`,

`a(y,z)≥k`.

Отже:

`min(a(x,y),a(y,z))≥k`.

За сильною нерівністю:

`a(x,z)≥k`.

Тому:

`x Eₖ z`.

Доведено.

### Наслідок

Замість сімейства вимог транзитивності для кожного `Eₖ` можна використовувати одну глобальну умову:

**SIM-TR — Strong similarity transitivity**

`a(x,z)≥min(a(x,y),a(y,z))`.

Це еквівалентне формулювання, а не послаблення.

## 3. Компактна система SIM-01…SIM-05

W51 пропонує наступну систему.

### SIM-01 — Nonempty domain

`L≠∅`.

### SIM-02 — Natural depth

`h:L→ℕ₀`.

### SIM-03 — Common-depth bounds and self-depth

Для всіх `x,y∈L`:

`a(x,y)=a(y,x)`,

`a(x,x)=h(x)`,

`0≤a(x,y)≤min(h(x),h(y))`.

### SIM-04 — Strong similarity transitivity

Для всіх `x,y,z∈L`:

`a(x,z)≥min(a(x,y),a(y,z))`.

### SIM-05 — Ancestral completeness and uniqueness

Для кожних `x∈L` та `k≤h(x)` існує рівно один вузол `u∈L`, для якого:

`h(u)=k`

і:

`a(x,u)=k`.

Цей вузол позначається:

`πₖ(x)`.

SIM-05 об'єднує існування та унікальність рівневого представника.

### Зв'язок із UFP-M01…M05

- SIM-01 відповідає UFP-M01.
- SIM-02 відповідає UFP-M02.
- SIM-03 відповідає UFP-M03.
- SIM-04 є еквівалентним формулюванням UFP-M04.
- SIM-05 відповідає UFP-M05, але без необхідності спочатку визначати класи еквівалентності.

Отже, SIM-01…SIM-05 — не нова математична структура, а більш пряме аксіоматичне представлення попередньої.

## 4. Еквівалентність SIM-05 та unique level representative

### Теорема 4.1

За SIM-03 та SIM-04 умова SIM-05 еквівалентна вимозі:

Кожен клас відношення:

`x Eₖ y ⇔ a(x,y)≥k`

на `L_≥k` містить рівно один вузол рівня `k`.

### Доведення напрямку A

Нехай SIM-05 виконується.

Розглянемо `x∈L_≥k`.

За SIM-05 існує рівно один `u` з:

`h(u)=k` та `a(x,u)=k`.

Тому:

`a(x,u)≥k`.

Отже, `u` належить класу `Eₖ(x)`.

Якщо інший вузол `v` рівня `k` також належить цьому класу, то:

`a(x,v)≥k`.

За depth bound:

`a(x,v)≤h(v)=k`.

Тому:

`a(x,v)=k`.

За унікальністю SIM-05:

`v=u`.

Отже, клас містить рівно одного представника рівня `k`.

### Доведення напрямку B

Нехай кожен клас `Eₖ` містить рівно одного вузла рівня `k`.

Для `x∈L_≥k` клас `Eₖ(x)` існує, оскільки:

`a(x,x)=h(x)≥k`.

За умовою він містить рівно одного вузла `u` рівня `k`.

Тоді:

`a(x,u)≥k`.

За depth bound:

`a(x,u)≤h(u)=k`.

Отже:

`a(x,u)=k`.

Унікальність випливає з унікальності представника класу.

Доведено.

## 5. Чи можна скоротити SIM-05 ще більше?

SIM-05 містить дві властивості:

1. для кожного вузла існує предок на кожному нижчому рівні;
2. такий предок єдиний.

Ці властивості логічно незалежні.

### 5.1. Відсутність існування

Нехай:

`L={r,x}`,

`h(r)=0`, `h(x)=2`.

Задамо:

`a(r,r)=0`,

`a(x,x)=2`,

`a(r,x)=a(x,r)=0`.

Функція симетрична, задовольняє self-depth та depth bound.

Вона також задовольняє SIM-TR.

Однак для `x` немає вузла рівня 1 із:

`a(x,u)=1`.

Тому предок проміжного рівня не існує.

Це не rooted tree із дискретною ancestry chain.

Отже, умова існування проміжних предків потрібна.

### 5.2. Відсутність унікальності

Нехай:

`L={r,u,v,x}`,

`h(r)=0`,

`h(u)=h(v)=1`,

`h(x)=2`.

Задамо:

- `a(x,x)=2`;
- `a(u,u)=a(v,v)=1`;
- `a(r,r)=0`;
- `a(x,u)=a(u,x)=1`;
- `a(x,v)=a(v,x)=1`;
- `a(u,v)=a(v,u)=1`;
- усі значення між `r` та іншими вузлами дорівнюють 0.

Ця структура задовольняє SIM-TR, симетрію, self-depth та depth bound.

Для `x` існують два різні вузли рівня 1 із common-depth 1:

`a(x,u)=a(x,v)=1`.

Тому предок рівня 1 неоднозначний.

Отже, унікальність також потрібна.

### Висновок

SIM-05 не можна вилучити або замінити лише умовою SIM-TR.

Сильна транзитивність гарантує узгодженість класів, але сама по собі не гарантує наявність рівневих представників.

## 6. Мінімальність системи: що саме доведено

Термін «мінімальна система» може мати два значення:

1. мінімальна кількість записаних формул;
2. логічно незалежна система, у якій кожна група умов потрібна.

W51 не стверджує, що SIM-01…SIM-05 має абсолютну мінімальну кількість символів або формул.

Натомість перевіряється структурна незалежність груп умов.

| Умова | Функція | Результат вилучення |
|---|---|---|
| SIM-01 | Непорожність | Можлива порожня структура без root |
| SIM-02 | Дискретна глибина | Втрачається дискретний parent-рівень |
| SIM-03 symmetry | Симетрія common-depth | Втрачається симетрична ancestry relation |
| SIM-03 self-depth | Вузол має власну глибину | Може не існувати власний рівневий представник |
| SIM-03 depth bound | Спільний предок не глибший за вузли | Руйнується інтерпретація common-depth |
| SIM-04 | Узгодженість рівневих класів | Порушується транзитивність ancestry |
| SIM-05 existence | Існування всіх проміжних предків | Можливі пропуски рівнів |
| SIM-05 uniqueness | Єдиність предка | Parent relation стає неоднозначним |

**Висновок:** SIM-01…SIM-05 є структурно достатньою та групово незалежною аксіоматичною системою в межах обраної моделі. Абсолютна синтаксична мінімальність не доведена й не заявляється.

# PART II. T-020 — FORMAL THEOREM DEPENDENCY

## 7. Рекомендована послідовність доведень

Для формальної реалізації не слід доводити T-020 одним монолітним theorem statement.

Рекомендована послідовність:

### Lemma 7.1 — Level representative existence

Для `x∈L` та `k≤h(x)` існує `πₖ(x)`.

Залежність: SIM-05.

### Lemma 7.2 — Level representative uniqueness

Для кожних `x,k` та будь-яких `u,v`:

якщо:

`h(u)=h(v)=k`,

`a(x,u)=k`,

`a(x,v)=k`,

то:

`u=v`.

Залежність: SIM-05.

### Lemma 7.3 — Identity at own level

`πₕ₍ₓ₎(x)=x`.

Залежність: SIM-03, SIM-05.

### Lemma 7.4 — Root uniqueness

Існує рівно один `r` із:

`h(r)=0`.

Залежність: SIM-01, SIM-03, SIM-05.

### Lemma 7.5 — Root compatibility

Для всіх `x`:

`π₀(x)=r`.

Залежність: Lemma 7.4, SIM-05.

### Lemma 7.6 — Nested ancestry

Для `j≤k≤h(x)`:

`πⱼ(πₖ(x))=πⱼ(x)`.

Залежність: SIM-04, SIM-05.

### Lemma 7.7 — Exact common-depth

`a(x,y)=max{k:πₖ(x)=πₖ(y)}`.

Залежність: SIM-03, SIM-04, SIM-05.

### Lemma 7.8 — Parent existence

Для кожного `x` з `h(x)>0` існує `parent(x)`.

Залежність: SIM-05.

### Lemma 7.9 — Parent uniqueness

Parent єдиний.

Залежність: SIM-05.

### Lemma 7.10 — Parent depth decrement

`h(parent(x))=h(x)−1`.

Залежність: визначення `πₖ`.

### Theorem 7.11 — Rooted tree existence

`(L,parent,r,h)` є rooted tree.

Залежність: Lemmas 7.4, 7.8–7.10.

### Theorem 7.12 — Reconstruction uniqueness

Fingerprint визначає parent relation однозначно.

Залежність: визначення parent та унікальність `πₖ`.

Ця послідовність забезпечує локалізацію помилок і не дозволяє приховувати пропущені кроки в одному великому доведенні.

## 8. Крайові випадки SIM-системи

### 8.1. Root-only tree

`L={r}`, `h(r)=0`, `a(r,r)=0`.

Усі умови виконуються.

Результат — дерево з одним вузлом.

### 8.2. Unary chain

`L={x₀,…,x_n}`,

`h(x_i)=i`,

`a(x_i,x_j)=min(i,j)`.

Для кожного вузла існує рівно один предок на кожному нижчому рівні.

Реконструюється ланцюг.

### 8.3. Branching tree

Нехай два вузли `u,v` мають одного предка `r`, але різні parent paths після певного рівня.

Їхня common-depth дорівнює глибині останнього спільного предка.

SIM-TR гарантує узгодженість цієї функції.

### 8.4. Infinite height

Можлива необмежена множина глибин:

`sup h(L)=∞`.

Кожен окремий вузол має скінченну глибину.

Реконструкція не потребує глобальної верхньої межі.

### 8.5. Uncountable branching

SIM-система не обмежує кількість дітей.

Для переходу до b-арного дерева потрібна додаткова умова.

### 8.6. Infinite descending ancestry

Неможлива, оскільки глибина є натуральним числом і кожен parent зменшує її рівно на одиницю.

Це важливе розмежування: нескінченна висхідна гілка можлива, але нескінченний parent-шлях від конкретного вузла до кореня — ні.

# PART III. T-021 — COMPLETION-SPACE VERIFICATION

## 9. Загальна модель

Нехай:

`B_b={1,…,b}`,

`B_b*` — множина скінченних адрес над `B_b`.

`ε` — порожня адреса, корінь.

Нехай:

`P⊆B_b*`

— позитивні спостереження,

`A⊆B_b*`

— негативні спостереження.

Визначимо:

`P* = Pref(P) ∪ {ε}`,

де `Pref(P)` — множина всіх префіксів адрес із `P`.

Визначимо:

`A* = Desc(A)`,

де `Desc(A)` — множина всіх адрес, для яких деяка адреса з `A` є префіксом.

Отже:

- `P*` — множина обов'язково присутніх адрес;
- `A*` — множина обов'язково відсутніх адрес.

---

## 10. Універсальний клас prefix-closed trees

Визначимо:

`𝒯_all = {T⊆B_b* : ε∈T ∧ T prefix-closed}`.

До цього класу входять:

- скінченні дерева;
- нескінченні дерева;
- дерева необмеженої глибини;
- дерева з кінцевими вузлами;
- дерева з нескінченними гілками.

Не накладається умова повноти branching.

### Definition 10.1 — Universal completion set

`Comp_all(P,A) = {T∈𝒯_all : P*⊆T ∧ T∩A*=∅}`.

### Теорема 10.2 — Universal completion existence

Для `𝒯_all`:

`Comp_all(P,A)≠∅`

тоді й лише тоді, коли:

`P*∩A*=∅`.

### Доведення необхідності

Нехай існує:

`T∈Comp_all(P,A)`.

Тоді:

`P*⊆T`.

І:

`T∩A*=∅`.

Якби існувала адреса:

`u∈P*∩A*`,

то з першої умови:

`u∈T`.

З другої:

`u∉T`.

Суперечність.

Отже:

`P*∩A*=∅`.

### Доведення достатності

Нехай:

`P*∩A*=∅`.

Візьмемо:

`T₀=P*`.

За визначенням prefix closure:

`T₀` є prefix-closed.

Оскільки `ε∈P*`, корінь належить `T₀`.

Отже:

`T₀∈𝒯_all`.

Також:

`P*⊆T₀`.

І:

`T₀∩A*=P*∩A*=∅`.

Тому:

`T₀∈Comp_all(P,A)`.

Отже:

`Comp_all(P,A)≠∅`.

Доведено.

### Важливий результат

Для універсального класу всіх prefix-closed дерев completion existence має простий точний критерій:

**Completion exists ⇔ positive closure and negative closure are disjoint.**

Цей результат сильніший за загальну умову W50, але діє лише для конкретно визначеного класу `𝒯_all`.

---

## 11. Простір completions як інтервал включення

За умови:

`P*∩A*=∅`

маємо:

`Comp_all(P,A) = {T∈𝒯_all : P*⊆T⊆B_b*\A*}`.

Отже, completion space є сімейством prefix-closed множин між нижньою та верхньою межами:

`P* ⊆ T ⊆ U`,

де:

`U=B_b*\A*`.

`P*` є найменшим completion.

`U` є найбільшою допустимою множиною адрес, але не обов'язково саме completion: вона має бути prefix-closed.

Оскільки `A*` є замкненою щодо нащадків, `U` є prefix-closed.

Отже:

`U∈𝒯_all`.

Тому `Comp_all` має і найменший, і найбільший елементи за включенням.

### Теорема 11.1 — Extremal completions

Якщо:

`P*∩A*=∅`,

то:

`T_min=P*`,

`T_max=B_b*\A*`

є відповідно найменшим і найбільшим елементами `Comp_all(P,A)`.

### Наслідок для UNKNOWN

Для кожної адреси `u`:

- PRESENT, якщо `u∈T_min`;
- ABSENT, якщо `u∉T_max`;
- UNKNOWN, якщо `u∈T_max\T_min`.

Тобто для універсального класу prefix-closed дерев:

`PRESENT ⇔ u∈P*`,

`ABSENT ⇔ u∈A*`,

`UNKNOWN ⇔ u∉P* ∧ u∉A*`.

Це важливе спрощення.

Для `𝒯_all` не потрібно шукати два completions окремо для кожної адреси: їхнє існування гарантують екстремальні дерева `T_min` і `T_max`.

---

## 12. Обмеження цього спрощення

Формула:

`UNKNOWN ⇔ u∉P* ∧ u∉A*`

коректна лише для `𝒯_all`.

Якщо дозволений клас дерев має додаткові обмеження, екстремальні дерева можуть перестати бути допустимими.

Наприклад:

- повне b-арне дерево;
- дерево фіксованої висоти;
- дерево з обов'язковою нескінченною гілкою;
- дерево з точно заданою кількістю дітей;
- дерево з додатковими глобальними властивостями.

Тому загальне визначення UNKNOWN залишається:

`∃T₁,T₂∈Comp : u∈T₁ ∧ u∉T₂`.

Просте локальне правило є спеціальним наслідком універсальної completion universe.

---

## 13. Лише скінченні дерева

Нехай:

`𝒯_fin={T∈𝒯_all : T скінченне}`.

Тоді:

`Comp_fin(P,A)={T∈𝒯_fin : P*⊆T ∧ T∩A*=∅}`.

### Теорема 13.1 — Finite completion existence

Для `𝒯_fin` completion існує тоді й лише тоді, коли:

1. `P*∩A*=∅`;
2. `P*` є скінченним.

### Доведення необхідності

Якщо `T` є скінченним completion, то:

`P*⊆T`.

Отже, `P*` скінченне.

Також позитивне й негативне обмеження не можуть перетинатися.

### Доведення достатності

Якщо `P*` скінченне та:

`P*∩A*=∅`,

то:

`T=P*`

є скінченним prefix-closed деревом, яке задовольняє всі обмеження.

Доведено.

### Висновок

Для скінченних дерев позитивні спостереження можуть самі по собі унеможливити completion, якщо їхнє prefix closure нескінченне.

---

## 14. Дерева з обмеженою висотою

Нехай:

`𝒯_H={T∈𝒯_all : ∀u∈T, |u|≤H}`.

Тоді completion існує тоді й лише тоді, коли:

1. `P*∩A*=∅`;
2. кожна адреса з `P*` має довжину не більшу за `H`.

Оскільки `P*` є prefix-closed, умова висоти на всі його елементи еквівалентна:

`∀u∈P : |u|≤H`.

### Наслідок

Для фіксованого `H` та скінченного `b` адресний простір:

`B_b^{≤H}`

скінченний.

Completion existence і статуси всіх позицій можна перевірити скінченним алгоритмом.

---

## 15. Повні b-арні дерева

Потрібно розрізняти два поняття.

### 15.1. Повне дерево фіксованої висоти

У кожного вузла глибини меншої за `H` присутні всі `b` дітей, а вузли глибини `H` не мають дітей.

У такому класі множина вузлів визначена однозначно:

`T=B_b^{≤H}`.

Completion існує тоді й лише тоді, коли:

- усі позитивні обмеження належать `T`;
- жодне негативне обмеження не належить `T`.

У цьому класі UNKNOWN відсутній: кожна адреса або обов'язково присутня, або обов'язково відсутня через межі простору.

### 15.2. Нескінченне повне b-арне дерево

Усі скінченні адреси присутні:

`T=B_b*`.

Тоді completion існує тоді й лише тоді, коли:

`A=∅`.

Позитивні обмеження завжди задовольняються.

Негативне обмеження на будь-яку адресу суперечить повноті.

Цей приклад демонструє, наскільки сильно вибір `𝒯_allowed` впливає на completion semantics.

# PART IV. COMPUTABILITY AND DECIDABILITY

## 16. Три різні рівні перевірки

Необхідно розділити:

1. математичну визначеність;
2. алгоритмічну перевірюваність;
3. ефективну обчислюваність.

Те, що статус математично визначений, не означає, що його можна завжди обчислити за скінченний час.

---

## 17. Випадок A — Універсальний клас `𝒯_all`

Нехай:

- `b` скінченне;
- `P` і `A` скінченні набори адрес.

Тоді:

1. `P*` скінченне;
2. `A*` може бути нескінченним;
3. перевірка `P*∩A*=∅` скінченна.

Для кожного `p∈P` достатньо перевірити, чи не є якийсь елемент `A` префіксом `p`, і чи не міститься `p` під негативним обмеженням.

Еквівалентно:

`P*∩A*=∅`

тоді й лише тоді, коли жодна позитивна адреса не лежить під негативною адресою та жодна негативна адреса не є префіксом позитивної адреси.

Для скінченних `P,A` це перевіряється скінченним числом порівнянь.

Статуси довільної адреси `u` визначаються перевірками:

- чи є `u` префіксом деякого `p∈P`;
- чи є деякий `a∈A` префіксом `u`.

Отже, у цьому класі всі три статуси ефективно обчислювані для кожної заданої адреси.

---

## 18. Випадок B — Скінченна висота

Для скінченного `b` та скінченного `H` множина:

`B_b^{≤H}`

скінченна.

Можна:

1. перелічити всі допустимі адреси;
2. побудувати всі prefix-closed subsets;
3. відфільтрувати ті, що задовольняють обмеження;
4. перевірити непорожність completion set;
5. класифікувати кожну адресу.

Цей підхід експоненційно дорогий, але математично скінченний.

Для практичної реалізації потрібні ефективніші алгоритми.

---

## 19. Випадок C — Довільні глобальні обмеження

Якщо `𝒯_allowed` задається не лише prefix closure, а й довільними глобальними властивостями, перевірка може стати значно складнішою.

Приклади:

- обов'язкова нескінченна гілка;
- заборона певних конфігурацій на всіх рівнях;
- умови регулярності;
- умови періодичності;
- обмеження на кількість нескінченних гілок;
- властивості, що залежать від усіх рівнів одночасно.

У такому випадку:

`P*∩A*=∅`

не гарантує completion existence.

Потрібен окремий алгоритм або математичне доведення для конкретного класу.

### Важливе застереження

Не можна заявляти, що completion existence є алгоритмічно розв'язною для довільного `𝒯_allowed`.

Без опису класу це твердження не має визначеного змісту.

# PART V. UNKNOWN AS AN INFORMATIONAL SEMANTICS

## 20. Відсутність спостереження та UNKNOWN — різні речі

Нехай позиція `u` не згадується ні в `P`, ні в `A`.

Для `𝒯_all` це означає UNKNOWN.

Але для іншого `𝒯_allowed` позиція може бути PRESENT або ABSENT через глобальні правила.

Отже, відсутність локального спостереження сама по собі не визначає статус.

Статус є функцією:

`σ(u;P,A,𝒯_allowed)`.

Не лише:

`σ(u;P,A)`.

Це принципова вимога до SUBIT-WARP.

---

## 21. Три рівні невизначеності

Рекомендується розрізняти:

### Level 1 — Unobserved

Позиція не згадується у вхідних даних.

Це властивість запису, а не семантичний статус.

### Level 2 — UNKNOWN

Позиція має різні значення в різних допустимих completions.

Це властивість completion space.

### Level 3 — INCONSISTENT

Множина completions порожня.

Це властивість несумісності обмежень.

Не можна кодувати ці три ситуації одним значенням.

---

## 22. Відношення до Belnap FOUR

Для подальшої інтеграції із SUBIT-логікою потрібно уникати автоматичного ототожнення трьох completion statuses із чотиризначною логікою Белнапа.

Completion semantics має три класи:

- PRESENT;
- ABSENT;
- UNKNOWN.

Belnap FOUR має чотири інформаційні стани:

- `N=00`;
- `F=01`;
- `T=10`;
- `B=11`.

Вони відповідають іншій структурі: наявності або відсутності підтримки твердження та його заперечення.

Можливе відображення completion information у Belnap FOUR, але воно потребує окремого визначення джерел позитивної та негативної підтримки.

Наприклад:

- PRESENT може відповідати позитивній підтримці;
- ABSENT — негативній підтримці;
- UNKNOWN — відсутності обох підтримок;
- INCONSISTENT — одночасній наявності обох підтримок.

Однак це відображення не є автоматичним доказом еквівалентності двох систем.

**Рішення:** не включати Belnap mapping до T-021 без окремої теореми.

# PART VI. LEAN FORMALIZATION BLUEPRINT

## 23. Мета

Наступна структура є планом формалізації, а не Lean-кодом із підтвердженим kernel acceptance.

Необхідно розділити математичні об'єкти так, щоб кожна теорема мала прозорі залежності.

## 24. Module A — Similarity fingerprint

Очікувані об'єкти:

- `Node`
- `Depth : Node → ℕ`
- `CommonDepth : Node → Node → ℕ`

Умови:

- `commonDepth_symm`;
- `commonDepth_self`;
- `commonDepth_bound`;
- `commonDepth_strong_trans`.

## 25. Module B — Ancestral completeness

Визначити предка рівня `k` через існування вузла `u`, для якого:

- `Depth u = k`;
- `CommonDepth x u = k`.

Окремо довести:

- existence;
- uniqueness;
- representative function;
- identity at own level.

Не використовувати неявний choice як заміну доказу унікальності.

Якщо застосовується `Classical.choose`, його використання має відбуватися лише після доведення існування та унікальності.

## 26. Module C — Rooted tree reconstruction

Визначити:

- `root`;
- `parent`;
- `parent_depth`;
- `parent_unique`;
- `ancestor`.

Далі довести:

- root uniqueness;
- parent existence;
- parent uniqueness;
- finite descent to root;
- acyclicity;
- connectedness;
- reconstruction uniqueness.

## 27. Module D — Ordered addresses

Визначити тип адрес як скінченні списки елементів скінченного алфавіту.

Не змішувати адресу та вузол.

Окремі об'єкти:

- `Address`;
- `Prefix`;
- `PrefixClosure`;
- `DescendantClosure`;
- `PrefixClosedTree`.

## 28. Module E — Completion space

Визначити:

- `AllowedTree`;
- `PositiveConstraints`;
- `NegativeConstraints`;
- `Completion`;
- `CompletionSet`.

Після цього довести:

- `completion_iff_disjoint` для `𝒯_all`;
- `finite_completion_iff` для `𝒯_fin`;
- `height_bounded_completion_iff` для `𝒯_H`;
- `completion_trichotomy`;
- `present_prefix`;
- `absent_descendant`.

## 29. Module F — Decidability

Окремо формалізувати decidable propositions для:

- finite address equality;
- prefix relation;
- finite positive closure;
- finite constraint conflict;
- finite-height completion.

Не заявляти загальної decidability для довільного `AllowedTree`.
