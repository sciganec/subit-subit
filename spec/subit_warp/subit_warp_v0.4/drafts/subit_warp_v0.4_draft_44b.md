# 0. Анотація

Цей документ встановлює математичні умови коректності структурного кодування та декодування деревоподібних структур SUBIT-WARP.

Основна мета — довести відповідність між двома представленнями одного математичного об'єкта:

1. структурним представленням дерева, у якому вузли мають тип INTERNAL або LEAF, а дочірні позиції можуть бути присутніми чи відсутніми;
2. тотальним адресним кодуванням, у якому кожна адреса з простору Pos_b має один зі станів ABSENT, INTERNAL або LEAF(a).

Розглядаються два відображення:

**Enc_sub** — структурне кодування дерева у тотальну функцію адресних станів.

**Dec_sub** — відновлення структурного дерева з допустимого тотального коду.

Головний результат W43 полягає в тому, що за точно визначених доменів і кодоменів ці відображення є взаємно оберненими. Для адресно-індексованого представлення оберненість доводиться як точна рівність структур. Для альтернативного коіндуктивного представлення оберненість формулюється через бісимуляцію або рівність у відповідному фактор-просторі.

Додатково встановлюється:

- збереження кореня;
- збереження типів вузлів;
- збереження міток листків;
- збереження порядку дочірніх позицій;
- збереження branching factor b;
- збереження семантики ABSENT;
- сумісність із C_Partial та C_Full;
- відповідність нескінченного продовження умові Tω_P;
- відповідність області Tω_P⁺ структурному підкласу дерев із INTERNAL-коренем;
- комутативність encoding/decoding із boundary map ∂.

Окремо доводиться, що **ABSENT не може використовуватися як синонім UNKNOWN**.

У документі розділено математичні результати, умовні результати, відкриті питання, Lean 4 proof obligations та регресійні вимоги.

**Важливе обмеження:** W43 є текстовим математичним аудитом. Він не засвідчує компіляцію Lean 4, kernel verification, виконання автоматизованих тестів або інтеграцію до канонічних файлів репозиторію.

# 1. Математичні передумови та позначення

Нехай:

- b ∈ ℕ;
- b ≥ 2;
- B_b = {1, …, b};
- Pos_b = B_b^{<ω};
- Σ_b = B_b^ℕ;
- ε — порожня адреса;
- ui — конкатенація адреси u з дочірнім індексом i;
- |u| — довжина скінченної адреси u;
- ξ|k — префікс нескінченної адреси ξ довжини k.

Алфавіт значень листків позначимо A.

Алфавіт кодових станів:

S_A = {ABSENT, INTERNAL} ∪ {LEAF(a) : a ∈ A}.

Простір усіх тотальних кодів:

Code_b(A) = S_A^{Pos_b}.

Тобто кожен код є функцією:

t : Pos_b → S_A.

Тотальність означає, що кожна скінченна адреса має визначений стан. Зокрема, позиції під листками та під відсутніми вузлами також мають стан.

## 1.1. Важливе розрізнення

Тут необхідно відділити три поняття:

**ABSENT** — позиція структурно відсутня.

**INTERNAL** — позиція містить внутрішній вузол.

**LEAF(a)** — позиція містить листок із міткою a.

UNKNOWN не входить до базового алфавіту S_A.

Це свідоме обмеження: базове структурне кодування не повинно непомітно перетворювати невідомість на відсутність.

## 1.2. Конкатенація адрес

Для адрес u,v ∈ Pos_b позначимо їхню конкатенацію через uv.

Умова ABSENT-closure у сильній формі:

∀u,v ∈ Pos_b,

t(u)=ABSENT ⇒ t(uv)=ABSENT.

Ця форма еквівалентна послідовному застосуванню локальної умови:

t(u)=ABSENT ⇒ t(ui)=ABSENT

для кожного i ∈ B_b.

Еквівалентність доводиться індукцією за довжиною v.

# 2. Простір допустимих кодів

## 2.1. Rooted partial codes

Визначимо:

C_Partial = {t ∈ Code_b(A) : Root(t) ∧ AbsentClosure(t) ∧ LeafClosure(t)}.

Де:

**Root(t):**

t(ε) ≠ ABSENT.

**AbsentClosure(t):**

∀u,v ∈ Pos_b,

t(u)=ABSENT ⇒ t(uv)=ABSENT.

**LeafClosure(t):**

∀u ∈ Pos_b, ∀i ∈ B_b,

t(u)=LEAF(a) ⇒ t(ui)=ABSENT.

Це означення встановлює локальну структурну допустимість.

Воно не встановлює існування нескінченного продовження.

## 2.2. Повні коди

Визначимо:

C_Full = {t ∈ C_Partial :

∀u ∈ Pos_b,  
t(u)=INTERNAL ⇒ ∀i ∈ B_b, t(ui)≠ABSENT}.

Отже:

C_Full ⊆ C_Partial.

Повний код вимагає, щоб кожен INTERNAL-вузол мав усі b дочірніх позицій.

Це не означає, що кожен дочірній вузол також є INTERNAL. Дитина може бути LEAF(a).

## 2.3. Відсутність вимоги нескінченності

C_Partial дозволяє INTERNAL-вузол без жодної наявної дитини.

Наприклад:

t(ε)=INTERNAL,

t(i)=ABSENT для всіх i ∈ B_b,

а всі глибші позиції також ABSENT.

Це допустимий partial code.

Але він не належить Tω_P, оскільки кореневий INTERNAL не має нескінченного INTERNAL-продовження.

Отже, необхідно розрізняти:

- локальну допустимість C_Partial;
- повноту розгалуження C_Full;
- глобальну умову нескінченного продовження Tω_P.

Це розмежування узгоджується з доступним W34.1.3 Corrected Canonical Integration Patch, який окремо визначає C_Full, C_Partial та C_ω і застерігає від автоматичного ототожнення цих класів з історичним Tree∞. Водночас сам patch має статус пропозиції інтеграції, а не канонічно об'єднаного джерела. W32_BRANCH_HEAD

# 3. Структурне представлення дерева

Для точного визначення Enc_sub та Dec_sub спочатку необхідно зафіксувати незалежну структурну модель дерева.

## 3.1. Адресно-індексоване дерево

Визначимо множину структурних міток:

NodeLabel_A = {INTERNAL} ∪ {LEAF(a) : a ∈ A}.

Структурне дерево T є парою:

T = (V, λ),

де:

- V ⊆ Pos_b — множина наявних адрес;
- ε ∈ V;
- V є prefix-closed;
- λ : V → NodeLabel_A;
- листки не мають дочірніх вузлів.

Точніше, виконуються такі умови.

**ST-01 — Root**

ε ∈ V.

**ST-02 — Prefix closure**

Якщо uv ∈ V, то u ∈ V.

**ST-03 — Leaf closure**

Якщо λ(u)=LEAF(a), то:

∀i ∈ B_b, ui ∉ V.

**ST-04 — Internal branching**

Якщо λ(u)=INTERNAL, кількість наявних дітей може бути будь-якою від 0 до b.

Усі дочірні позиції індексуються елементами B_b.

Відповідно, порядок дітей є частиною структури.

## 3.2. Семантика дерева

Множина V містить усі наявні вузли.

Вузол поза V структурно відсутній.

Функція λ визначає тип кожного наявного вузла.

Звідси випливає:

- якщо u ∉ V, то жодне продовження uv не належить V;
- якщо λ(u)=LEAF(a), то жодна дитина ui не належить V;
- якщо λ(u)=INTERNAL, то його дочірні позиції можуть бути як наявними, так і відсутніми.

Отже, структура дерева повністю визначена парою (V,λ).

Позначимо простір таких дерев через:

Tree_b(A).

Це адресно-індексоване представлення, яке допускає як скінченні, так і нескінченні дерева.

## 3.3. Індуктивний та коіндуктивний погляд

Ту саму структуру можна розглядати через два способи спостереження.

### Індуктивне представлення

Скінченне дерево утворюється з двох конструкторів:

Leaf(a),

Node(c),

де:

c : Fin(b) → Option(FinTree_b(A)).

Тут Option має структурний зміст:

- None — дочірня позиція відсутня;
- Some(T) — дочірня позиція містить дерево T.

Оскільки FinTree є індуктивним типом, кожне таке дерево має скінченну глибину.

### Коіндуктивне представлення

Для дерев довільної, зокрема нескінченної, глибини використовується коіндуктивна інтерпретація:

Tree_b(A) ≅ νX. A + (Fin(b) → Option(X)).

Цей запис є математичним описом структури, а не заявою про готову Lean-реалізацію.

Він означає:

- Leaf(a) завершує гілку;
- Node(c) створює внутрішній вузол;
- кожна з b позицій може містити відсутність або наступне дерево;
- послідовне спостереження Node може тривати нескінченно.

Для формалізації W43 рекомендує спочатку використовувати адресно-індексовану модель Tree_b(A), а коіндуктивний інтерфейс розглядати як окремий шар.

Це дозволяє уникнути підміни нескінченного дерева скінченним inductive-типом.

# 4. Визначення Enc_sub та Dec_sub

## 4.1. Enc_sub — структурне кодування

Визначимо:

Enc_sub : Tree_b(A) → C_Partial.

Нехай T=(V,λ).

Для кожної адреси u ∈ Pos_b:

Enc_sub(T)(u) =

- LEAF(a), якщо u ∈ V та λ(u)=LEAF(a);
- INTERNAL, якщо u ∈ V та λ(u)=INTERNAL;
- ABSENT, якщо u ∉ V.

Це тотальне кодування.

Кожна позиція отримує рівно один кодовий стан.

## 4.2. Dec_sub — структурне декодування

Визначимо:

Dec_sub : C_Partial → Tree_b(A).

Для коду t визначимо:

V_t = {u ∈ Pos_b : t(u) ≠ ABSENT}.

Для кожного u ∈ V_t:

λ_t(u) =

- INTERNAL, якщо t(u)=INTERNAL;
- LEAF(a), якщо t(u)=LEAF(a).

Тоді:

Dec_sub(t) = (V_t, λ_t).

Необхідно довести, що ця пара справді є допустимим структурним деревом.

Це буде зроблено в наступному розділі.

## 4.3. Область застосування

Enc_sub визначений для всіх rooted partial trees.

Dec_sub визначений для всіх кодів із C_Partial.

Вони не визначені як взаємно обернені відображення між довільним простором Code_b(A) та довільним простором дерев.

Саме обмеження доменів є необхідною умовою коректності.

# 5. Структурні інваріанти кодування

## 5.1. Інваріант кореня

Для будь-якого T ∈ Tree_b(A):

ε ∈ V.

Тому:

Enc_sub(T)(ε) ≠ ABSENT.

Отже:

Enc_sub(T) ∈ Rooted.

**Лема 5.1.** Enc_sub зберігає кореневу структуру.

Доведення безпосередньо випливає з ST-01 та означення Enc_sub.

## 5.2. Інваріант ABSENT-closure

Нехай:

Enc_sub(T)(u)=ABSENT.

За означенням це означає u ∉ V.

Припустімо, що для деякого v ∈ Pos_b:

uv ∈ V.

Тоді за prefix closure маємо u ∈ V.

Суперечність.

Отже:

∀v, uv ∉ V.

Тому:

Enc_sub(T)(uv)=ABSENT.

**Лема 5.2.**

AbsentClosure(Enc_sub(T)).

## 5.3. Інваріант LEAF-closure

Нехай:

Enc_sub(T)(u)=LEAF(a).

Тоді:

u ∈ V,

λ(u)=LEAF(a).

За ST-03:

∀i ∈ B_b, ui ∉ V.

Тому:

Enc_sub(T)(ui)=ABSENT.

**Лема 5.3.**

LeafClosure(Enc_sub(T)).

## 5.4. Наслідок: коректність Enc_sub

З лем 5.1–5.3:

Enc_sub(T) ∈ C_Partial.

Отже, Enc_sub є коректно визначеним відображенням:

**Enc_sub : Tree_b(A) → C_Partial.**

Цей висновок доведений на рівні математичних означень.

## 5.5. Збереження типів вузлів

Для будь-якої адреси u:

- структурний INTERNAL переходить у кодовий INTERNAL;
- структурний LEAF(a) переходить у LEAF(a);
- структурна відсутність переходить у ABSENT.

Жоден тип вузла не змінюється.

Особливо:

LEAF(a) не може перетворитися на INTERNAL.

INTERNAL не може перетворитися на LEAF(a).

ABSENT не може перетворитися на LEAF(a) або INTERNAL.

Це безпосередній наслідок означення Enc_sub.

## 5.6. Збереження порядку дітей

У структурному дереві кожна дочірня позиція індексується:

i ∈ B_b.

У коді вона відповідає адресі:

ui.

Отже, дочірня позиція i переходить саме в адресу ui.

Перестановка дітей змінює код, якщо переставлені структури не є тотожними за позиціями.

**Висновок:** Enc_sub зберігає не лише дерево як неупорядкований граф, а саме впорядковану b-арну адресну структуру.

Якщо вихідне дерево є неупорядкованим, для застосування Enc_sub спочатку потрібне окреме правило призначення дочірніх індексів.

Без нього канонічне кодування не визначене.

## 5.7. Збереження branching factor

Оскільки:

B_b={1,…,b},

кожен INTERNAL-вузол має рівно b можливих позицій.

Enc_sub не додає і не вилучає адресні індекси.

Тому branching factor зберігається.

При цьому необхідно розрізняти:

- кількість можливих дочірніх позицій — b;
- кількість фактично наявних дітей — від 0 до b.

Для C_Full фактична кількість дітей INTERNAL-вузла дорівнює b.

Для C_Partial вона може бути меншою.

# 6. Коректність Dec_sub

## 6.1. Rootedness

Нехай t ∈ C_Partial.

За означенням:

t(ε) ≠ ABSENT.

Тому:

ε ∈ V_t.

Отже, Dec_sub(t) має корінь.

## 6.2. Prefix closure

Нехай:

uv ∈ V_t.

Тоді:

t(uv) ≠ ABSENT.

Припустімо, що u ∉ V_t.

Тоді:

t(u)=ABSENT.

За AbsentClosure:

t(uv)=ABSENT.

Суперечність.

Отже:

u ∈ V_t.

Тому V_t є prefix-closed.

## 6.3. Leaf closure

Нехай:

λ_t(u)=LEAF(a).

Тоді:

t(u)=LEAF(a).

За LeafClosure:

t(ui)=ABSENT

для кожного i ∈ B_b.

Отже:

ui ∉ V_t.

Тому відновлене дерево задовольняє ST-03.

## 6.4. Наслідок

За 6.1–6.3:

Dec_sub(t) ∈ Tree_b(A).

Отже, Dec_sub є коректно визначеним відображенням:

**Dec_sub : C_Partial → Tree_b(A).**

# 7. Дві обернені властивості

Це центральний розділ W43.

## 7.1. Перша обернена властивість

### Теорема W43-T001

Для кожного T ∈ Tree_b(A):

**Dec_sub(Enc_sub(T)) = T.**

Тобто декодування після кодування відновлює початкове структурне дерево.

### Доведення

Нехай:

T=(V,λ).

Позначимо:

t=Enc_sub(T).

За означенням Enc_sub:

t(u)≠ABSENT ⇔ u∈V.

Отже:

V_t=V.

Тепер розглянемо мітки.

Для кожного u∈V:

- якщо λ(u)=INTERNAL, то t(u)=INTERNAL, тому λ_t(u)=INTERNAL;
- якщо λ(u)=LEAF(a), то t(u)=LEAF(a), тому λ_t(u)=LEAF(a).

Отже:

λ_t=λ.

Таким чином:

Dec_sub(Enc_sub(T))=(V_t,λ_t)=(V,λ)=T.

Теорему доведено.

**Статус:** TEXT-LEVEL PROOF COMPLETE.

## 7.2. Друга обернена властивість

### Теорема W43-T002

Для кожного t ∈ C_Partial:

**Enc_sub(Dec_sub(t)) = t.**

Тобто кодування після декодування відновлює початковий код.

### Доведення

Нехай:

T=Dec_sub(t).

Тоді:

V_T={u : t(u)≠ABSENT}.

Розглянемо довільну адресу u ∈ Pos_b.

Можливі три випадки.

**Випадок 1: t(u)=ABSENT.**

Тоді u ∉ V_T.

За означенням Enc_sub:

Enc_sub(T)(u)=ABSENT=t(u).

**Випадок 2: t(u)=INTERNAL.**

Тоді u ∈ V_T та:

λ_T(u)=INTERNAL.

Отже:

Enc_sub(T)(u)=INTERNAL=t(u).

**Випадок 3: t(u)=LEAF(a).**

Тоді u ∈ V_T та:

λ_T(u)=LEAF(a).

Отже:

Enc_sub(T)(u)=LEAF(a)=t(u).

Усі можливі значення t(u) розглянуто.

Тому для кожної адреси u:

Enc_sub(Dec_sub(t))(u)=t(u).

Отже, за екстенсіональністю функцій:

Enc_sub(Dec_sub(t))=t.

Теорему доведено.

**Статус:** TEXT-LEVEL PROOF COMPLETE.

## 7.3. Основний наслідок

З W43-T001 та W43-T002:

Dec_sub ∘ Enc_sub = id_Tree,

Enc_sub ∘ Dec_sub = id_C_Partial.

Отже:

**Tree_b(A) ≅ C_Partial.**

Це ізоморфізм структурного та тотального адресного представлень rooted partial trees.

Він не встановлює автоматичного ізоморфізму з історичним Tree∞, FiniteTree_A або будь-якою іншою раніше визначеною структурою без окремого доказу відповідності.

# 8. Leaf та Node: індуктивний і коіндуктивний випадки

Обернені властивості мають бути перевірені не лише як загальна екстенсіональна рівність, але й на рівні структурних спостережень.

## 8.1. Leaf

Нехай:

T=Leaf(a).

Тоді:

V={ε},

λ(ε)=LEAF(a).

Кодування:

t(ε)=LEAF(a),

t(u)=ABSENT для кожної непорожньої адреси u.

Декодування відновлює:

V_t={ε},

λ_t(ε)=LEAF(a).

Тому:

Dec_sub(Enc_sub(Leaf(a)))=Leaf(a).

Це індуктивний базовий випадок.

## 8.2. Node

Нехай:

T=Node(c),

де:

c : B_b → Option(Tree_b(A)).

Для кожної дочірньої позиції i:

- якщо c(i)=None, то вся підгілка i відсутня;
- якщо c(i)=Some(T_i), то підгілка i містить дерево T_i.

Кодування:

t(ε)=INTERNAL.

Для адреси iv:

- якщо c(i)=None, то t(iv)=ABSENT;
- якщо c(i)=Some(T_i), то t(iv)=Enc_sub(T_i)(v).

Декодування визначає:

c_t(i)=

- None, якщо t(i)=ABSENT;
- Some(Dec_sub(t_i)), якщо t(i)≠ABSENT,

де:

t_i(v)=t(iv).

За першою оберненою властивістю кожна наявна дочірня підгілка відновлюється.

За другою оберненою властивістю весь код відновлюється.

Отже, Node-структура зберігається.

## 8.3. Нескінченна глибина

Для нескінченного дерева не можна застосовувати звичайну структурну індукцію за висотою, оскільки скінченна висота не визначена.

Тому використовується адресне спостереження.

Кожна скінченна адреса u визначає скінченний шлях від кореня.

Enc_sub та Dec_sub зберігають тип вузла на кожній такій адресі.

Отже, для кожного n:

усі структурні спостереження на глибинах ≤ n зберігаються.

Оскільки адресне дерево повністю визначається своїми скінченними адресними спостереженнями, це забезпечує відновлення всієї структури, включно з нескінченною глибиною.

Для коіндуктивного constructor-представлення відповідний доказ повинен бути сформульований через бісимуляцію.

## 8.4. Бісимуляційне формулювання

Для коіндуктивного дерева визначимо відношення:

T ≈ U,

якщо:

1. обидва дерева є Leaf з однаковою міткою; або
2. обидва дерева є Node, і для кожної дочірньої позиції i їхні слоти збігаються:
   - None відповідає None;
   - Some(T_i) відповідає Some(U_i), де T_i ≈ U_i.

Leaf не може бути бісимілярним Node.

None не може бути бісимілярним Some.

Тоді для коіндуктивної реалізації очікуються твердження:

Dec_sub(Enc_sub(T)) ≈ T,

Enc_sub(Dec_sub(t)) = t.

Друге твердження є рівністю тотальних кодів.

Перше є бісимуляцією структурних дерев.

Якщо простір дерев визначити як фактор за ≈, перше твердження переходить у точну рівність класів еквівалентності.

**Важливо:** W43 не стверджує, що відповідний коіндуктивний Lean-тип уже реалізовано. Доведення вище встановлено на рівні адресно-індексованої моделі; коіндуктивний Lean-доказ залишається окремим proof obligation.

# 9. Скінченні та нескінченні дерева

## 9.1. Скінченна підтримка

Визначимо підтримку коду:

Supp(t)={u∈Pos_b : t(u)≠ABSENT}.

Скінченне дерево має скінченну множину наявних адрес:

|Supp(t)|<∞.

Позначимо відповідний підклас через:

C_Fin ⊆ C_Partial.

Скінченне структурне дерево має скінченну множину вузлів V.

Для нього:

Enc_sub(T) ∈ C_Fin.

Навпаки, якщо t ∈ C_Fin, то Dec_sub(t) має скінченну множину вузлів.

Отже:

Tree_fin(A) ≅ C_Fin.

Цей ізоморфізм є обмеженням основного ізоморфізму W43.

## 9.2. Скінченні дерева та Tω_P

Важливий крайовий випадок:

Rooted LEAF tree належить Tω_P.

Причина: умова

∀u, t(u)=INTERNAL ⇒ IB(u,t)

виконується вакуумно, оскільки INTERNAL-вузлів немає.

Водночас:

Rooted LEAF tree ∉ Tω_P⁺.

Для будь-якого скінченного rooted дерева, яке містить хоча б один INTERNAL-вузол, відповідний INTERNAL не може мати нескінченного INTERNAL-продовження.

Тому:

**Скінченне rooted дерево з INTERNAL-вузлом не належить Tω_P.**

Це уточнення є необхідним для регресійної сумісності з W44.

## 9.3. Нескінченні дерева

Нескінченне адресне дерево може мати нескінченну множину наявних вузлів.

За скінченного branching factor b та prefix closure нескінченна множина вузлів має необмежену глибину.

За лемою Кеніга існує нескінченна гілка наявних вузлів.

Оскільки LEAF не має нащадків, кожен вузол на такій нескінченній гілці має бути INTERNAL.

Отже, нескінченна підтримка дає принаймні одну нескінченну INTERNAL-гілку від кореня.

Але цього недостатньо для належності Tω_P.

## 9.4. Контрприклад: нескінченне дерево не обов'язково належить Tω_P

Нехай корінь INTERNAL.

Він має дві наявні дочірні позиції:

- перша містить INTERNAL без дітей;
- друга містить нескінченний ланцюг INTERNAL.

Усе дерево має нескінченну глибину.

Корінь має нескінченне продовження через другу дитину.

Але перший дочірній INTERNAL не має нескінченного продовження.

Тому:

t ∉ Tω_P.

Цей приклад показує, що:

**існування нескінченної гілки від кореня ≠ умова нескінченного продовження кожного INTERNAL-вузла.**

W43 зберігає саме сильнішу умову Tω_P.

# 10. Full branching та partial branching

## 10.1. Збереження C_Full

Визначимо структурний підклас:

Tree_full(A)={T∈Tree_b(A) :

кожен INTERNAL-вузол має всі b наявних дітей}.

Тоді:

Enc_sub(T) ∈ C_Full ⇔ T ∈ Tree_full(A).

### Доведення

Нехай T має всі b дітей у кожному INTERNAL-вузлі.

За означенням Enc_sub кожна така дитина кодується станом, відмінним від ABSENT.

Тому Enc_sub(T) задовольняє full-branching умову.

У зворотному напрямку, якщо код має всі b дітей на кожному INTERNAL-вузлі, то кожна дочірня позиція належить V_t.

Отже, відновлене дерево має повне розгалуження.

Твердження доведено.

## 10.2. Full branching не означає Tω_P

Мінімальний приклад:

- корінь INTERNAL;
- усі b дітей присутні;
- усі b дітей є LEAF.

Код належить C_Full.

Але root INTERNAL не має нескінченного INTERNAL-продовження.

Отже:

C_Full ⊄ Tω_P.

## 10.3. Tω_P не означає C_Full

Нехай b≥2.

Побудуємо нескінченний ланцюг INTERNAL, у якому кожен INTERNAL має лише одну INTERNAL-дитину, а решта дочірніх позицій ABSENT.

Кожен INTERNAL має нескінченне продовження.

Тому:

t ∈ Tω_P⁺.

Але branching не є повним.

Отже:

Tω_P ⊄ C_Full.

## 10.4. Висновок

C_Full та Tω_P є різними структурними обмеженнями.

Жодне з них не можна вивести з іншого.

# 11. ABSENT проти UNKNOWN

Це окремий семантичний інваріант.

## 11.1. Базова семантика

У базовому просторі:

S_A={ABSENT,INTERNAL}∪{LEAF(a)}.

ABSENT означає, що дочірня позиція структурно відсутня.

Наприклад:

t(u)=INTERNAL,

t(ui)=ABSENT.

Це означає, що дитина i у вузла u відсутня.

За ABSENT-closure усі продовження цієї позиції також відсутні.

## 11.2. UNKNOWN

UNKNOWN означав би інше:

інформація про позицію не встановлена або не отримана.

Це не твердження про відсутність вузла.

Наприклад:

- у структурі дитина може існувати, але її тип невідомий;
- джерело даних може не містити відомостей про певний слот;
- спостереження може бути неповним.

Ці ситуації не еквівалентні ABSENT.

## 11.3. Формальне розділення

Якщо потрібна епістемічна модель, необхідно ввести окремий тип:

SlotKnowledge_A =

- KnownAbsent;
- KnownInternal;
- KnownLeaf(a);
- Unknown.

Цей тип не є S_A.

Перехід від SlotKnowledge_A до S_A дозволений лише за наявності достатньої інформації.

Зокрема:

Unknown ↛ ABSENT.

Без окремого правила розв'язання UNKNOWN кодування Enc_sub не повинно приймати такий слот як структурно визначений.

## 11.4. Наслідок для декодування

Dec_sub відновлює структурне дерево, а не епістемічний стан джерела.

Тому:

Dec_sub(ABSENT)=відсутня позиція,

а не:

Dec_sub(ABSENT)=невідомий вузол.

Якщо в майбутньому SUBIT-WARP потребуватиме кодування неповних спостережень, необхідно створити окремий модуль, наприклад:

SUBIT-WARP-EPISTEMIC-CODE.

Не можна розширювати базовий C_Partial шляхом мовчазної зміни семантики ABSENT.

# 12. Ін'єктивність, сюр'єктивність та неоднозначність

## 12.1. Ін'єктивність Enc_sub

Нехай:

Enc_sub(T₁)=Enc_sub(T₂).

Тоді для кожної адреси u:

- u належить V₁ тоді й лише тоді, коли u належить V₂;
- якщо u наявна, її мітка в T₁ і T₂ збігається.

Отже:

V₁=V₂,

λ₁=λ₂.

Тому:

T₁=T₂.

**Теорема W43-T003.**

Enc_sub є ін'єктивним на Tree_b(A).

Цей результат стосується екстенсіонального адресно-індексованого представлення.

Для сирого коіндуктивного синтаксису ін'єктивність має формулюватися modulo bisimulation.

## 12.2. Сюр'єктивність Enc_sub

Нехай:

t ∈ C_Partial.

За коректністю Dec_sub:

Dec_sub(t) ∈ Tree_b(A).

За W43-T002:

Enc_sub(Dec_sub(t))=t.

Отже, кожен допустимий partial code є образом деякого структурного дерева.

**Теорема W43-T004.**

Enc_sub є сюр'єктивним на C_Partial.

## 12.3. Бієктивність

З W43-T003 та W43-T004:

Enc_sub : Tree_b(A) → C_Partial є бієкцією.

Dec_sub є її оберненим відображенням.

Це один із головних результатів W43.

## 12.4. Чому не можна розширити кодомен до Code_b(A)

Enc_sub не є сюр'єктивним на весь простір Code_b(A).

Контрприклади:

**Контрприклад 1 — ABSENT root**

t(ε)=ABSENT.

Такий код не може бути образом rooted tree.

**Контрприклад 2 — LEAF із наявною дитиною**

t(ε)=LEAF(a),

t(1)=INTERNAL.

Такий код порушує LeafClosure.

**Контрприклад 3 — наявний нащадок під ABSENT**

t(ε)=INTERNAL,

t(1)=ABSENT,

t(11)=INTERNAL.

Такий код порушує AbsentClosure.

Усі три приклади належать Code_b(A), але не C_Partial.

Тому:

Enc_sub(Tree_b(A))=C_Partial,

а не Code_b(A).

## 12.5. Неоднозначність неупорядкованих дерев

Enc_sub є канонічним лише за умови, що дочірні позиції вже впорядковані та індексовані.

Якщо дерево задане як неупорядкований граф, то різні призначення дітей індексам B_b можуть дати різні коди.

Наприклад, нехай корінь має двох різних дітей:

- одна дитина — LEAF(a);
- друга — INTERNAL без дітей.

Якщо поміняти їхні індекси місцями, код зміниться.

Обидва коди можуть представляти одне й те саме неупорядковане дерево, але різні впорядковані дерева.

Отже, для неупорядкованого представлення потрібне додаткове правило:

- канонічне впорядкування дітей;
- або факторизація за групою перестановок;
- або окреме відображення в unordered tree space.

W43 не вводить такого правила.

Тому Enc_sub визначено лише для ordered b-ary trees.

## 12.6. Канонічність

За зафіксованих:

- B_b;
- порядку дочірніх індексів;
- міток A;
- семантики ABSENT;
- умов rootedness та closure,

кодування є канонічним.

Жодної додаткової нормалізації не потрібно.

# 13. Сумісність із Tω_P та Tω_P⁺

## 13.1. Умова нескінченного продовження

Для t ∈ C_Partial:

IB(u,t) означає:

t(u)=INTERNAL

та існує нескінченна адреса ξ ∈ Σ_b, яка продовжує u, така що:

∀k ≥ |u|,

t(ξ|k)=INTERNAL.

Визначимо:

Tω_P={t∈C_Partial :

∀u, t(u)=INTERNAL ⇒ IB(u,t)}.

І:

Tω_P⁺={t∈Tω_P : t(ε)=INTERNAL}.

## 13.2. Структурна умова

Для T=(V,λ) визначимо:

Treeω(A)={T∈Tree_b(A) :

кожен INTERNAL-вузол має нескінченне INTERNAL-продовження}.

Формально, для кожного u ∈ V з λ(u)=INTERNAL існує ξ ∈ Σ_b, що продовжує u, і всі відповідні префікси належать V та мають мітку INTERNAL.

## 13.3. Збереження нескінченного продовження

### Теорема W43-T005

Для кожного T ∈ Tree_b(A):

T ∈ Treeω(A) ⇔ Enc_sub(T) ∈ Tω_P.

### Доведення

За означенням Enc_sub:

- u ∈ V ⇔ Enc_sub(T)(u)≠ABSENT;
- λ(u)=INTERNAL ⇔ Enc_sub(T)(u)=INTERNAL.

Тому для кожної нескінченної адреси ξ:

усі її префікси є INTERNAL у T тоді й лише тоді, коли відповідні кодові стани дорівнюють INTERNAL.

Отже, існування нескінченного INTERNAL-продовження у структурному дереві еквівалентне існуванню такого продовження в коді.

Оскільки це твердження застосовується до кожного INTERNAL-вузла, отримуємо еквівалентність.

Теорему доведено.

**Статус:** TEXT-LEVEL PROOF COMPLETE.

## 13.4. Збереження Tω_P⁺

Корінь структурного дерева є INTERNAL тоді й лише тоді, коли:

Enc_sub(T)(ε)=INTERNAL.

Тому:

T ∈ Treeω⁺ ⇔ Enc_sub(T) ∈ Tω_P⁺,

де:

Treeω⁺={T∈Treeω : λ(ε)=INTERNAL}.

Отже, Enc_sub обмежується до бієкції:

Enc_sub : Treeω⁺ ≃ Tω_P⁺.

## 13.5. Leaf/root edge case

Якщо корінь є LEAF(a):

- дерево належить Treeω за вакуумним виконанням умови для INTERNAL-вузлів;
- код належить Tω_P;
- boundary порожня;
- дерево не належить Treeω⁺;
- код не належить Tω_P⁺.

Це узгоджується з означеннями W41 та W34.1.3.

# 14. Boundary map та її збереження

## 14.1. Межа кодованого дерева

Для t ∈ Tω_P⁺:

∂t={ξ∈Σ_b :

∀k≥0, t(ξ|k)=INTERNAL}.

Це множина нескінченних INTERNAL-гілок.

## 14.2. Межа структурного дерева

Для T=(V,λ) визначимо:

∂_T(T)={ξ∈Σ_b :

∀k≥0, ξ|k∈V  
і λ(ξ|k)=INTERNAL}.

Це множина нескінченних шляхів, які проходять лише через INTERNAL-вузли.

## 14.3. Теорема збереження межі

### Теорема W43-T006

Для кожного T ∈ Treeω⁺:

**∂_T(T)=∂(Enc_sub(T)).**

### Доведення

Нехай ξ ∈ Σ_b.

За означенням:

ξ ∈ ∂_T(T)

тоді й лише тоді, коли кожен префікс ξ|k:

- належить V;
- має мітку INTERNAL.

За означенням Enc_sub це еквівалентно:

Enc_sub(T)(ξ|k)=INTERNAL

для кожного k≥0.

А це саме означення:

ξ ∈ ∂(Enc_sub(T)).

Отже, множини рівні.

Теорему доведено.

## 14.4. Збереження межі при декодуванні

Оскільки:

Enc_sub(Dec_sub(t))=t,

то:

∂(Enc_sub(Dec_sub(t)))=∂t.

Отже, декодування та повторне кодування не змінюють boundary.

Так само структурна межа Dec_sub(t) дорівнює кодованій межі t.

## 14.5. Непорожність та компактність

Для t ∈ Tω_P⁺:

- корінь INTERNAL;
- за означенням Tω_P корінь має нескінченне INTERNAL-продовження;
- тому ∂t непорожня.

Межа замкнена в Σ_b, оскільки її визначають умови на скінченні префікси.

Оскільки Σ_b компактний, ∂t компактна.

Цей аргумент сумісний із текстовим математичним закриттям T-007 у W41.

Водночас W41 не був перевірений ядром Lean, і W43 не змінює цього статусу.

## 14.6. Метрика та перенесення оцінки W41

Визначимо кодову метрику:

d_code(t,s)=2^(−r_code(t,s)),

де r_code — мінімальна глибина адреси, на якій t та s відрізняються.

Якщо t=s, то:

d_code(t,t)=0.

На структурному просторі введемо індуковану метрику:

d_T^code(T,U)=d_code(Enc_sub(T),Enc_sub(U)).

Тоді Enc_sub є ізометрією за означенням цієї метрики.

Якщо застосовується текстова оцінка W41:

d_H,Σ(∂t,∂s)≤2d_code(t,s),

то для T,U ∈ Treeω⁺ отримуємо:

d_H,Σ(∂_T(T),∂_T(U))  
≤ 2d_T^code(T,U).

Це є коректним перенесенням оцінки на структурне представлення.

**Обмеження:** це не доводить еквівалентність d_code з історичною d_F або метрикою d_S SUBIT-∞.

Згідно з корекцією W39.1, d_code є базовою метрикою кодового простору, тоді як d_F потребує окремого джерельного звірення.

Тому жодна рівність:

d_code=d_F

у W43 не постулюється.

# 15. Відкриті питання щодо метрик та історичних представлень

## 15.1. d_F

Доступний W34.1.3 patch використовує позначення d_F для метрики першої відмінності.

W39.1 рекомендує не ототожнювати d_F з d_code без окремого обґрунтування.

W43 використовує d_code як базову метрику.

Потрібно встановити:

- чи є d_F історичною назвою тієї самої метрики;
- чи має вона інше джерельне означення;
- чи є між ними ізометрія;
- чи існує лише бі-ліпшицевий зв'язок;
- чи потребують вони різних доменів.

**Статус: OPEN — SOURCE CROSS-CHECK REQUIRED.**

## 15.2. Історичний Tree∞

W43 визначає Tree_b(A) як адресно-індексоване представлення rooted partial trees.

Це не є автоматичним ототожненням із Tree∞ SUBIT-∞.

Для такого ототожнення потрібні:

1. точний тип Tree∞;
2. відповідність адрес;
3. відповідність станів;
4. відповідність кореневих умов;
5. відповідність метрик;
6. доказ ізоморфізму або іншої точно визначеної еквівалентності.

**Статус: OPEN.**

## 15.3. Fingerprint reconstruction

W34.1.3 містить окремі пропозиції T-020′ та T-021′ для реконструкції за fingerprint.

W43 не використовує fingerprint як джерело кодування.

Зокрема, множина листків не визначає сама по собі стан кожного відсутнього слота.

Тому:

Fingerprint reconstruction ≠ Enc_sub.

Ці механізми можуть бути пов'язані лише через окремий доказ, який встановлює повноту та однозначність fingerprint.

**Статус: OPEN — NOT PART OF THE PRESENT BIJECTION.**

# 16. Мінімальні контрприклади та крайові випадки

Нижче наведено мінімальні приклади, які повинні бути присутні в математичній і програмній регресії.

## CE-001 — Відсутній корінь

t(ε)=ABSENT.

Результат:

- t ∉ C_Partial;
- Dec_sub(t) не визначено.

## CE-002 — Leaf із дочірнім вузлом

t(ε)=LEAF(a),

t(1)=INTERNAL.

Результат:

- порушено LeafClosure;
- t ∉ C_Partial.

## CE-003 — Наявний нащадок під ABSENT

t(ε)=INTERNAL,

t(1)=ABSENT,

t(11)=INTERNAL.

Результат:

- порушено AbsentClosure;
- t ∉ C_Partial.

## CE-004 — INTERNAL без дітей

t(ε)=INTERNAL,

усі діти ABSENT.

Результат:

- t ∈ C_Partial;
- t ∉ Tω_P;
- t ∉ C_Full.

## CE-005 — Rooted LEAF

t(ε)=LEAF(a),

усі інші позиції ABSENT.

Результат:

- t ∈ C_Partial;
- t ∈ Tω_P;
- t ∉ Tω_P⁺;
- ∂t=∅.

## CE-006 — Unary partial branching

Нехай b≥2.

Корінь INTERNAL має рівно одну наявну дитину, решта дітей ABSENT.

Результат:

- t ∈ C_Partial;
- t ∉ C_Full.

Якщо дерево скінченне, воно не належить Tω_P.

## CE-007 — Повне, але скінченне розгалуження

Корінь INTERNAL має всі b дітей, і всі вони LEAF.

Результат:

- t ∈ C_Full;
- t ∉ Tω_P.

Це демонструє незалежність full branching та infinite continuation.

## CE-008 — Нескінченний ланцюг

Кожен INTERNAL має одну INTERNAL-дитину, яка продовжує нескінченний ланцюг.

Результат:

- t ∈ Tω_P⁺;
- t ∈ C_Partial;
- t ∉ C_Full.

Межа складається з однієї нескінченної адреси.

## CE-009 — Нескінченна гілка плюс скінченна leaf-гілка

Корінь INTERNAL має:

- одну нескінченну INTERNAL-гілку;
- одну дочірню LEAF-гілку.

Результат:

- t ∈ Tω_P⁺;
- скінченна leaf-гілка не входить до ∂t;
- boundary містить нескінченну INTERNAL-гілку.

## CE-010 — Нескінченне дерево з dead INTERNAL-вузлом

Корінь має нескінченне продовження, але одна з його дочірніх позицій містить INTERNAL без нескінченного продовження.

Результат:

- дерево має нескінченну глибину;
- корінь має нескінченне продовження;
- t ∉ Tω_P.

## CE-011 — Перестановка дітей

Корінь має двох різних дітей.

Їхня перестановка змінює адресні позиції.

Результат:

- код змінюється;
- unordered tree може залишитися ізоморфним;
- ordered tree не зберігає тотожність.

## CE-012 — UNKNOWN

Позиція має невідомий стан, а не підтверджену відсутність.

Результат:

- базовий Enc_sub не повинен автоматично відображати UNKNOWN у ABSENT;
- потрібне окреме епістемічне представлення.

# 17. Lean 4: точні proof obligations

Цей розділ є формалізаційною специфікацією.

Наведені сигнатури є blueprint, а не перевіреним Lean-кодом.

## 17.1. Basic types

Рекомендовані абстрактні типи:

```lean
abbrev Branch (b : Nat) := Fin b
abbrev Address (b : Nat) := List (Fin b)

inductive CodeState (A : Type u)
  | absent
  | internal
  | leaf (a : A)

abbrev RawCode (b : Nat) (A : Type u) :=
  Address b → CodeState A
```

Усі основні теореми мають працювати в контексті:

```lean
variable (b : Nat)
variable (hb : 2 ≤ b)
variable (A : Type u)
```

Доказ hb повинен бути доступний у твердженнях, які потребують щонайменше двох дочірніх позицій.

## 17.2. PartialCode

Потрібно визначити:

```lean
def Rooted (t : RawCode b A) : Prop := ...

def AbsentClosure (t : RawCode b A) : Prop := ...

def LeafClosure (t : RawCode b A) : Prop := ...

def PartialCode (b : Nat) (A : Type u) :=
  {t : RawCode b A //
    Rooted t ∧ AbsentClosure t ∧ LeafClosure t}
```

Окремо визначити:

```lean
def FullCode (t : PartialCode b A) : Prop := ...
```

Необхідно довести еквівалентність локальної та сильної форми ABSENT-closure.

## 17.3. AddressTree

Рекомендовано спочатку реалізувати:

```lean
structure AddressTree (b : Nat) (A : Type u) where
  support : Set (Address b)
  root_mem : [] ∈ support
  prefix_closed : ...
  label : ...
  leaf_closed : ...
```

Це схематична сигнатура.

Конкретна Lean-структура повинна використовувати тип міток INTERNAL/LEAF та доказ того, що label визначена для кожної адреси з support.

# 24. Фінальний висновок

W43 встановлює точну відповідність між структурним представленням rooted partial tree та його тотальним адресним кодуванням.

За визначеними доменами:

Enc_sub : Tree_b(A) → C_Partial,

Dec_sub : C_Partial → Tree_b(A),

і виконуються:

Dec_sub ∘ Enc_sub = id,

Enc_sub ∘ Dec_sub = id.

Отже, структурне дерево та його код є двома взаємно однозначними представленнями одного математичного об'єкта.

Цей результат не залежить від припущення, що всі дерева є скінченними.

Адресно-індексована модель зберігає довільну глибину, а коіндуктивна інтерпретація забезпечує відповідне розуміння нескінченних структур через бісимуляцію.

Водночас W43 не ототожнює:

- C_Partial із C_Full;
- C_Full із Tω_P;
- Tω_P із Tω_P⁺;
- ABSENT із UNKNOWN;
- ordered tree з unordered tree;
- d_code з d_F;
- адресно-індексоване Tree_b(A) з історичним Tree∞;
- текстовий доказ із Lean kernel verification.

Найважливіший результат для архітектури SUBIT-WARP полягає в тому, що кодування не втрачає структурної інформації, якщо його домен і кодомен визначені точно.

**Кодування є оборотним не тому, що будь-яка інформація може бути закодована будь-яким способом, а тому, що структурні умови допустимості усувають неоднозначність між відсутністю, листком і внутрішнім вузлом.**

Саме тому ABSENT-closure, LEAF-closure та rootedness є не другорядними технічними обмеженнями, а необхідними умовами структурної оборотності.
