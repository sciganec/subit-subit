# 1. Мета W31

W31 визначає стратегію перенесення математичного ядра SUBIT-WARP до формальної системи Lean.

Завдання:

1. визначити математичні конструкції, які підлягають формалізації;
2. відокремити фундаментальні типи від похідних конструкцій;
3. визначити залежності між Lean-модулями;
4. визначити порядок формального доведення теорем;
5. відокремити аналітичні твердження від обчислювальних перевірок;
6. мінімізувати використання додаткових аксіом;
7. визначити критерії прийняття формалізованого результату.

W31 не є Lean-реалізацією. Це архітектурний план, який передує написанню коду.

## 1.1. Що вважатиметься формально доведеним

Теорема SUBIT-WARP отримує статус LEAN VERIFIED лише тоді, коли:

- її формулювання присутнє у вихідному коді Lean;
- усі залежності доступні в межах формальної системи;
- доведення успішно перевіряється Lean kernel;
- немає прихованих неперевірених припущень;
- використання аксіом задокументоване;
- версії Lean та Mathlib зафіксовані.

Чисельна перевірка, символьне обчислення або аналітичний текст самі по собі не надають статусу LEAN VERIFIED.

# 2. Межі формалізації

У SUBIT-WARP необхідно розділити чотири рівні.

## LAYER A — Foundational Structures

Формалізуються:

- скінченні алфавіти;
- адреси;
- дерева;
- типи листків і внутрішніх вершин;
- метрики;
- нескінченні гілки;
- компактні простори.

Це фундаментальна частина. Вона має бути незалежною від спектральної теорії.

## LAYER B — Analysis

Формалізуються:

- міри;
- інтеграли;
- простори L²;
- оператори;
- обмеженість;
- самоспряженість;
- компактність операторів;
- спектральні твердження.

Цей рівень залежить від LAYER A.

## LAYER C — Operator Approximation

Формалізуються:

- циліндричні підпростори;
- ортогональні проєкції;
- скінченні матриці;
- спектри скінченних апроксимацій;
- операторні оцінки;
- границі.

Цей рівень залежить від LAYER B.

## LAYER D — Structural and Computational Extensions

Формалізуються або перевіряються окремо:

- структурна реконструкція дерев;
- параметрична неперервність;
- спеціальні ядра;
- чисельні регресійні тести;
- відповідність програмної реалізації математичній моделі.

Цей рівень не повинен змінювати фундаментальні визначення попередніх рівнів.

# 4. Модуль Basic

## 4.1. Alphabet.lean

Визначити:

A = {00, 01, 10, 11}

B_b = Fin b

Для основної моделі:

b = 3.

Потрібно зберегти можливість параметризації через b, але основний тернарний випадок повинен бути перевірений окремо.

Базові вимоги:

- скінченність A;
- скінченність B_b;
- умова b ≥ 2;
- явне розрізнення елементів алфавіту та адресних символів.

**Ціль:** LEAN-001 — формалізація базових алфавітів.

## 4.2. Address.lean

Адреса визначається як скінченна послідовність елементів B_b.

Концептуально:

Pos_b = List B_b.

Нескінченна адреса:

Σ_b = N → B_b.

Необхідно формалізувати:

- конкатенацію;
- довжину скінченної адреси;
- префікс;
- відношення префіксності;
- найдовший спільний префікс;
- циліндричні множини.

**Ціль:** LEAN-002 — адресна алгебра.

## 4.3. Tree.lean

Для повних дерев рекомендовано індуктивно-рекурсивну структуру:

FullTree A b

з двома конструкторами:

- Leaf(a), де a ∈ A;
- Node(children), де children індексовані елементами B_b.

Концептуальна форма:

FullTree A b ≅ A ⊕ (B_b → FullTree A b).

Точний Lean-синтаксис і вибір між рекурсивним типом, коіндуктивною конструкцією та функціональним поданням мають бути перевірені на цільовій версії Lean.

### Важливе архітектурне рішення

Не слід використовувати один тип для:

- повних нескінченних дерев;
- часткових дерев;
- скінченних дерев.

Рекомендовано три окремі типи.

**Ціль:** LEAN-003 — тип повного дерева.

**Ціль:** LEAN-004 — тип часткового дерева.

**Ціль:** LEAN-005 — тип скінченного дерева.

# 5. Модуль Metric

## 5.1. AddressMetric.lean

Для нескінченних адрес:

d_Σ(ξ,η) = 2^−ℓ(ξ,η).

Потрібно довести:

1. невід'ємність;
2. тотожність нерозрізнюваних елементів;
3. симетричність;
4. ультраметричну нерівність.

Ультраметрична нерівність:

d_Σ(x,z) ≤ max(d_Σ(x,y), d_Σ(y,z)).

**Ціль:** LEAN-006 — ультраметричний простір адрес.

## 5.2. TreeMetric.lean

Формалізувати d_F окремо від d_Σ.

Потрібно уникнути повторного використання символу d_S для різних просторів.

Для метрики дерев:

- визначити першу адресу, на якій дерева відрізняються;
- визначити вагу відповідної глибини;
- довести метричні властивості;
- довести повноту або компактність відповідного простору.

**Ціль:** LEAN-007 — метричний простір дерев.

## 5.3. HausdorffMetric.lean

Стандартна метрика Гаусдорфа визначається на непорожніх компактних множинах.

Для порожньої множини потрібна окрема конструкція.

Рекомендована архітектура:

- основний простір — непорожні компактні підмножини;
- розширений простір — окремий тип із доданим елементом ∅;
- відстань до ∅ визначається спеціально.

Не можна без пояснення називати довільне спеціальне розширення стандартною метрикою Гаусдорфа.

**Ціль:** LEAN-008 — метрика Гаусдорфа на непорожніх компактах.

**Ціль:** LEAN-009 — спеціальне розширення на K₀.

# 6. Модуль Geometry

## 6.1. Compactness.lean

Формалізувати компактність:

- простору нескінченних адрес;
- простору повних дерев;
- необхідних підпросторів.

Бажано використовувати загальні математичні результати Lean/Mathlib там, де вони відповідають визначенням SUBIT-WARP.

Не слід дублювати вже наявні загальні теореми без необхідності.

**Ціль:** LEAN-010 — компактність Σ_b.

**Ціль:** LEAN-011 — компактність FullTree.

## 6.2. Grafting.lean

Визначити:

ρ_a(f) = Node(f, Leaf(a), Leaf(a))

для основного тернарного випадку.

Довести:

d_F(ρ_a(f),ρ_a(g)) = 1/2 · d_F(f,g).

Після цього застосувати загальну теорему Банаха про нерухому точку.

Важливо: доведення контрактності має передувати використанню теореми Банаха.

**Ціль:** LEAN-012 — точний коефіцієнт контрактності.

**Ціль:** LEAN-013 — єдиність нерухомої точки.

## 6.3. BoundaryMap.lean

Формалізувати:

∂f = {ξ ∈ Σ_b : кожний скінченний префікс ξ відповідає внутрішній вершині f}.

Використовувати Tω⁺, а не Tω без додаткової умови.

Потрібно довести:

- компактність ∂f;
- непорожність ∂f;
- коректність відображення f ↦ ∂f.

Далі:

d_H(∂f,∂g) ≤ 2d_F(f,g).

Це одне з найважливіших тверджень геометричного ядра.

**Ціль:** LEAN-014 — коректність межі.

**Ціль:** LEAN-015 — ліпшицевість boundary map.

# 7. Модуль HausdorffDimension

Цей модуль має бути відокремлений від базової геометрії.

Потрібно формалізувати:

1. рівномірну бернуллівську міру;
2. міру циліндрів;
3. діаметр циліндрів;
4. верхню оцінку хаусдорфової розмірності;
5. нижню оцінку через принцип розподілу маси.

Канонічна формула:

dim_H(Σ_b,d_v) = ln(b)/α_v.

Де:

d_v(ξ,η) = exp(−α_vℓ(ξ,η)).

### Критична вимога

Нижня оцінка не повинна зводитися до перевірки лише циліндрів.

Необхідно формально обґрунтувати перехід від циліндричної оцінки міри до оцінки для довільних достатньо малих множин або куль.

**Ціль:** LEAN-016 — міра циліндрів.

**Ціль:** LEAN-017 — верхня оцінка dimension.

**Ціль:** LEAN-018 — нижня оцінка dimension.

**Ціль:** LEAN-019 — рівність розмірності.

# 8. Модуль Measure

## 8.1. BernoulliMeasure.lean

Визначити рівномірну добуткову міру на:

Σ_b = B_b^N.

Потрібно забезпечити:

μ(C_w) = b^−|w|.

Де C_w — циліндр адреси w.

Важливо не плутати:

- скінченну кількість адрес;
- нескінченні послідовності;
- циліндричні множини;
- ймовірнісну міру.

## 8.2. L2Space.lean

Визначити:

H = L²(Σ_b,μ_b).

Далі:

- циліндричні функції;
- скінченновимірні підпростори H_n;
- ортогональні проєкції P_n;
- ієрархічні підпростори W_j.

**Ціль:** LEAN-020 — простір L².

**Ціль:** LEAN-021 — циліндричні підпростори.

**Ціль:** LEAN-022 — ортогональна ієрархічна декомпозиція.

# 9. Модуль Operators

## 9.1. Kernel.lean

Загальна інтегральна конструкція:

(Tf)(x) = ∫ K(x,y)f(y)dμ(y).

Формалізувати загальні умови:

- вимірність ядра;
- інтегровність;
- симетричність;
- обмеженість оператора.

## 9.2. HierarchicalKernel.lean

Спадне ядро:

K_q(x,y) = q^ℓ(x,y).

Для діагоналі:

K_q(x,x) = 1.

Обов'язкова домовленість:

q⁰ = 1 для q ∈ [0,1].

Окремо визначити:

- q=0;
- 0<q<1;
- q=1.

Не можна приховувати граничні випадки за загальним припущенням 0<q<1.

## 9.3. IntegralOperator.lean

Побудувати T_q на H.

Довести:

- лінійність;
- обмеженість;
- самоспряженість;
- компактність через властивість Гільберта—Шмідта за відповідних умов.

**Ціль:** LEAN-023 — інтегральний оператор.

**Ціль:** LEAN-024 — самоспряженість.

**Ціль:** LEAN-025 — компактність.

# 10. Модуль Spectrum

Це найбільш математично складний модуль.

Спектральні формули не слід вводити як неперевірені константи.

Необхідний порядок:

1. довести ортогональність H₀, W₁, W₂, …;
2. довести повноту ієрархічного розкладу;
3. визначити дію T_q на H₀;
4. визначити дію T_q на W_j;
5. отримати c_q та λ_j;
6. довести, що інших спектральних значень немає.

Канонічні формули:

c_q = (b−1)/(b−q).

λ_j = −(1−q)q^(j−1)/[b^(j−1)(b−q)].

m_j = (b−1)b^(j−1).

### Окрема увага

Для 0<q<1:

0 — гранична точка спектра, але не власне значення.

Для q=0:

0 має нескінченну кратність.

Для q=1:

T₁ = P_const.

Ці твердження повинні мати окремі леми.

**Ціль:** LEAN-026 — ієрархічні власні простори.

**Ціль:** LEAN-027 — спектральні значення.

**Ціль:** LEAN-028 — повнота спектрального опису.

**Ціль:** LEAN-029 — граничний випадок q=0.

**Ціль:** LEAN-030 — граничний випадок q=1.

# 11. Модуль OperatorApproximation

Після завершення спектрального ядра можна формалізувати скінченні апроксимації.

Визначити:

T_q^(n) = P_nT_qP_n|H_n.

Потрібно довести:

- формулу матричних елементів;
- суму рядка;
- скінченний слід;
- скінченний спектр;
- операторну похибку;
- збіжність центрованих апроксимацій.

Канонічні формули:

Для i ≠ j:

M_n(i,j) = b^−n q^ℓ(i,j).

Для i = j:

M_n(i,i) = b^−n q^n c_q.

Слід:

Tr(T_q^(n)) = q^n c_q.

Похибка:

||T_q − P_nT_qP_n|| = (1−q)q^n/[b^n(b−q)].

Окремо перевірити два види центрованого продовження:

P_nT_qP_n − c_qP_n

та

P_nT_qP_n − c_qI.

Вони мають різні режими збіжності.

**Ціль:** LEAN-031 — скінченна матриця.

**Ціль:** LEAN-032 — скінченний спектр.

**Ціль:** LEAN-033 — операторна похибка.

**Ціль:** LEAN-034 — центрована збіжність.

# 12. Модуль ParametricContinuity

Формалізувати:

||T_q − T_r|| ≤ |q−r|.

Це твердження залежить від спільної ієрархічної декомпозиції.

Необхідні кроки:

1. формально визначити сімейство T_q;
2. довести спільність спектральних підпросторів;
3. отримати формули власних значень;
4. довести оцінку різниць власних значень;
5. перейти до операторної норми.

**Ціль:** LEAN-035 — параметрична ліпшицевість.

Не слід доводити цей результат лише чисельною перевіркою вибраних пар q,r.

# 13. Модуль Structure

Структурна реконструкція повинна бути незалежною від спектральної теорії.

Розділити:

**Unordered fingerprint**

F(T) = (L,h,a).

**Ordered fingerprint**

F_ordered(T) = (L,h,a,p).

Де p зберігає адреси листків.

Потрібно довести:

- коректність fingerprint;
- реконструкцію неупорядкованого дерева;
- реконструкцію упорядкованого дерева;
- окреме врахування unary-вузлів;
- граничний випадок дерева, що складається лише з кореня.

**Ціль:** LEAN-036 — неупорядкована реконструкція.

**Ціль:** LEAN-037 — упорядкована реконструкція.

# 14. Модуль Verification

Lean і чисельні тести мають різні завдання.

## 14.1. Lean

Lean перевіряє:

- математичні визначення;
- логічні залежності;
- аналітичні теореми;
- коректність доведень;
- типову узгодженість конструкцій.

## 14.2. Python / Rust

Обчислювальний шар перевіряє:

- скінченні матриці;
- чисельні власні значення;
- операторні апроксимації;
- регресійні приклади;
- стабільність реалізації;
- відповідність програмного результату математичним формулам.

## 14.3. Заборонене змішування статусів

Не допускається:

NUMERICALLY VERIFIED ⇒ LEAN VERIFIED.

Так само:

LEAN VERIFIED ⇒ IMPLEMENTATION VERIFIED.

Формальне доведення математичної теореми не гарантує, що програмна реалізація використовує саме цю теорему правильно.

**Ціль:** LEAN-038 — формалізація математичних специфікацій регресійних тестів.

Вона не замінює виконання тестів у Python або Rust.

# 15. Політика аксіом

Формалізація має використовувати мінімально необхідну аксіоматичну базу.

Для кожного модуля необхідно фіксувати:

- використані аксіоми;
- залежність від стандартної логіки Lean;
- залежність від Mathlib;
- додаткові припущення;
- статус theorem versus axiom.

Не допускається маскувати відсутнє доведення оголошенням потрібного результату як axiom.

Якщо певний результат тимчасово заданий як припущення, він повинен бути позначений:

**PROVISIONAL ASSUMPTION — NOT PROVED.**

Окремо необхідно контролювати використання класичних принципів, вибору та функціональної екстенсіональності там, де це важливо для інтерпретації результату.

# 16. Порядок формалізації

Не рекомендовано починати зі спектральної теорії.

Пропонується така послідовність.

## PHASE 1 — Foundations

LEAN-001–LEAN-009.

Результат:

- алфавіти;
- адреси;
- типи дерев;
- метрики.

Критерій завершення: базові конструкції не потребують тимчасових аксіом для власних визначень.

## PHASE 2 — Geometry

LEAN-010–LEAN-019.

Результат:

- компактність;
- grafting;
- boundary map;
- хаусдорфова розмірність.

Критерій завершення: усі геометричні твердження мають повні доведення.

## PHASE 3 — Measure and L²

LEAN-020–LEAN-022.

Результат:

- бернуллівська міра;
- циліндричні підпростори;
- ортогональна декомпозиція.

Критерій завершення: ієрархічні простори формально визначені та їхня повнота доведена.

## PHASE 4 — Operator Theory

LEAN-023–LEAN-030.

Результат:

- інтегральні оператори;
- компактність;
- спектр;
- граничні випадки.

Критерій завершення: спектральні формули отримані з визначень, а не введені як припущення.

## PHASE 5 — Approximation and Parameters

LEAN-031–LEAN-035.

Результат:

- скінченні матриці;
- апроксимації;
- операторні оцінки;
- параметрична ліпшицевість.

Критерій завершення: формальні результати узгоджені з W25 чисельними перевірками.

## PHASE 6 — Reconstruction

LEAN-036–LEAN-037.

Результат:

- неупорядкована реконструкція;
- упорядкована реконструкція.

Критерій завершення: доведено, які саме структурні дані визначають дерево.

## PHASE 7 — Verification Interface

LEAN-038.

Результат:

- формальні специфікації;
- інтерфейси тестування;
- узгоджена матриця статусів.

# 18. Критерії прийняття Lean-реалізації

Формалізація може бути прийнята лише після проходження таких перевірок.

**F-01.** Зафіксовані версії Lean та Mathlib.

**F-02.** Проєкт збирається з чистого середовища.

**F-03.** Усі фундаментальні визначення мають однозначну семантику.

**F-04.** FullTree, PartialTree і FiniteTree розділені.

**F-05.** Метрики d_F, d_Σ, d_T та d_H не змішані.

**F-06.** Теореми мають явні припущення.

**F-07.** Усі додаткові аксіоми задокументовані.

**F-08.** Спектральні формули доведені через ієрархічну декомпозицію.

**F-09.** Випадки q=0 та q=1 перевірені окремо.

**F-10.** Скінченний слід не ототожнений зі слідом нескінченного оператора.

**F-11.** Ordered та unordered reconstruction розділені.

**F-12.** CI перевіряє повну збірку.

**F-13.** Усі регресійні тести мають окремий статус виконання.

**F-14.** Жодне чисельне підтвердження не видається за формальне доведення.

# 19. Що не слід формалізувати передчасно

Не потрібно починати з:

- повної загальної теорії всіх можливих дерев;
- універсальної нестаціонарної спектральної теорії;
- довільних ядер без необхідних умов інтегровності;
- повного SUBIT-∞;
- фізичних інтерпретацій;
- експериментальних гіпотез;
- програмної реалізації CPU.

Спершу потрібно формально закрити обмежене математичне ядро SUBIT-WARP.

Це зменшує ризик того, що надмірно загальна абстракція ускладнить доведення конкретних теорем.

W31 визначає архітектуру формалізації SUBIT-WARP.

1. формалізувати адреси та дерева;
