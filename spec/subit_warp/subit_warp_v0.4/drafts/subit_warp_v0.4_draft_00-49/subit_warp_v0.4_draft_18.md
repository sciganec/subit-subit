# W28.1. Мета та межі

W28 встановлює єдину систему перевірки для математичного ядра SUBIT-WARP.

Він розділяє чотири рівні:

1. **Mathematical validity** — коректність визначень і теорем.
2. **Analytical verification** — незалежні математичні виведення.
3. **Numerical verification** — скінченні обчислювальні перевірки.
4. **Formal verification** — машинне доведення формалізованих тверджень.

Позитивний результат на одному рівні не означає автоматичного проходження інших.

Зокрема:

`NUMERICALLY VERIFIED ≠ FORMALLY VERIFIED`.

Так само:

`ANALYTICALLY VERIFIED ≠ IMPLEMENTATION VERIFIED`.

# W28.2. Канонічна карта математичних об'єктів

## W28.2.1. Множини та типи

Базові алфавіти:

`A={00,01,10,11}`

`B={1,2,3}`

`Pos=B^{<ω}`

Простір нескінченних адрес:

`Σ=B^N`.

Канонічні типи:

| Тип | Визначення | Призначення |
|---|---|---|
| FullTree_A | `A ⊔ FullTree_A³` | Повні коіндуктивні дерева |
| PartialTree_A | `None ⊔ A ⊔ PartialTree_A³` | Часткові дерева |
| FiniteTree_A | Скінченні кореневі дерева | Структурна реконструкція |
| Σ | `B^N` | Нескінченні адреси |
| K(Σ) | Непорожні компактні підмножини Σ | Межі дерев |

Забороняється використовувати один тип як неявний синонім іншого.

## W28.2.2. Карта залежностей

```text
A, B
 │
 ├── FullTree_A
 │     ├── d_F
 │     ├── Tω
 │     │     └── Tω⁺
 │     │           └── ∂:Tω⁺ → K(Σ)
 │     └── Grafting ρ_a
 │
 ├── Σ
 │     ├── d_Σ
 │     ├── μ_b
 │     └── K(Σ), d_H
 │
 ├── FiniteTree_A
 │     └── Structural Fingerprint
 │
 └── L²(Σ,μ_b)
       ├── T_q
       ├── L_q
       ├── H_n
       └── Finite Spectral Approximation
```

Ця схема є архітектурною картою залежностей, а не доказом коректності кожного переходу.

# W28.3. Канонічні метричні структури

## W28.3.1. Метрика дерев

`d_F(f,g)=2^{-r(f,g)}`.

Властивості:

- невід'ємність;
- симетричність;
- тотожність нерозрізнених;
- ультраметрична нерівність.

`d_F(f,h)≤max(d_F(f,g),d_F(g,h))`.

## W28.3.2. Метрика адрес

`d_Σ(ξ,η)=exp(−α_vℓ(ξ,η))`.

За `α_v=ln2`:

`d_Σ(ξ,η)=2^{-ℓ(ξ,η)}`.

Це ультраметрика на компактному просторі Σ.

## W28.3.3. Метрика скінченного дерева

`d_T(ξ,η)=h(ξ)+h(η)−2ℓ(ξ,η)`.

Це шляхова метрика на множині вершин або листків скінченного кореневого дерева, залежно від обраної області.

## W28.3.4. Метрика Гаусдорфа

Для `X,Y∈K(Σ)`:

`d_H(X,Y)=max{sup_{x∈X}dist(x,Y), sup_{y∈Y}dist(y,X)}`.

Порожні множини не входять до K(Σ).

Якщо потрібно працювати з порожньою межею, використовується окремо визначений простір `K₀(Σ)` зі спеціальною метрикою. Цю метрику не можна називати стандартною метрикою Гаусдорфа без уточнення.

# W28.4. Регресійна група R-TREE

## R-TREE-001 — Типізація

Перевірити, що:
- FullTree не приймає `None` як окрему мітку;
- PartialTree допускає `None`;
- FiniteTree є скінченним;
- адреси належать `B^{<ω}` або `B^N` відповідно до типу.

Очікування: жодна операція не змішує ці типи без явного перетворення.

## R-TREE-002 — Метрика

Для довільних дерев f,g,h перевірити:

`d_F(f,g)=d_F(g,f)`,

`d_F(f,g)≥0`,

`d_F(f,g)=0 ⇔ f=g`,

`d_F(f,h)≤max(d_F(f,g),d_F(g,h))`.

Очікування: PASS.

## R-TREE-003 — Компактність

Для повного простору повних дерев перевірити:
- скінченність алфавіту міток;
- компактність простору конфігурацій;
- замкненість умов повного розгалуження.

Це не скінченний чисельний тест. Потрібне окреме аналітичне або формальне доведення.

## R-TREE-004 — Grafting

Для:

`ρ_a(f)=Node(f,Leaf(a),Leaf(a))`

перевірити:

`d_F(ρ_a(f),ρ_a(g))=½d_F(f,g)`.

Очікування: точна рівність.

## R-TREE-005 — Фіксована точка

Перевірити:

`ρ_a(f*)=f*`.

Для гілки, що продовжується через першу дитину:

`∂f*={1111…}`.

Очікування: одна нерухома точка для кожного фіксованого grafting-оператора.

## R-TREE-006 — Boundary domain

Перевірити:

`f∈Tω⁺ ⇒ ∂f∈K(Σ)`.

Перевірити окремо:
- корінь — Leaf;
- корінь — Node;
- нескінченна гілка;
- кілька нескінченних гілок;
- нескінченна множина межових адрес.

Очікування:
- Leaf не належить Tω⁺;
- Node із властивістю Tω належить Tω⁺;
- межа кожного елемента Tω⁺ непорожня і компактна.

## R-TREE-007 — Boundary Lipschitz

Перевірити теорему:

`d_H(∂f,∂g)≤2d_F(f,g)`.

Для тестових пар:
- однакова структура;
- відмінність на глибині 0;
- відмінність на глибині 1;
- відмінність на великій глибині;
- зміна гілки, що забезпечує нескінченне продовження.

Чисельні тести можуть знаходити контрприклади, але не замінюють аналітичного доведення.

# W28.5. Регресійна група R-GEOMETRY

## R-GEO-001 — Ультраметрична нерівність

Для адрес ξ,η,ζ перевірити:

`d_Σ(ξ,ζ)≤max(d_Σ(ξ,η),d_Σ(η,ζ))`.

## R-GEO-002 — Зміна масштабу

Перевірити:

`d_v=d_Σ^γ`,

де:

`γ=α_v/ln2`.

Очікування: топологія не змінюється для будь-якого `α_v>0`.

## R-GEO-003 — Циліндрична міра

Для кожного циліндра довжини n:

`μ_b([σ])=b^{-n}`.

Перевірити:
- `μ_b(Σ)=1`;
- адитивність при розбитті циліндра;
- рівномірність дочірніх циліндрів.

## R-GEO-004 — Hausdorff dimension

Перевірити аналітичну формулу:

`dim_H(Σ_b)=ln(b)/α_v`.

У тестовій реалізації чисельна оцінка розмірності може бути лише допоміжною перевіркою.

# W28.6. Регресійна група R-KERNEL

## R-KERNEL-001 — Спадне ядро

`K_q(ξ,η)=q^{ℓ(ξ,η)}`, діагональ визначена як 0.

Перевірити:
- симетричність;
- вимірність;
- інтегровність;
- незалежність оператора від значень ядра на діагоналі, оскільки діагональ має нульову міру μ_b×μ_b.

## R-KERNEL-002 — Зростаюче ядро

`K_+(ξ,η)=exp(α_wℓ(ξ,η))`.

Перевірити пороги:

`α_w<ln b` — обмеженість оператора;

`α_w<(ln b)/2` — умова Гільберта—Шмідта.

Значення на діагоналі фіксується окремою конвенцією.

## R-KERNEL-003 — Параметричні режими

Тестувати:
- `q=0`;
- `q→0⁺`;
- `q=0.5`;
- `q→1⁻`;
- `q=1`.

Не застосовувати формули для відкритого інтервалу без окремої перевірки на кінцях.

# W28.7. Регресійна група R-SPECTRUM

## R-SPEC-001 — Власні значення

Перевірити:

`c_q=(b−1)/(b−q)`,

`λ_j=−(1−q)q^{j−1}/[b^{j−1}(b−q)]`.

Кратності:

`m_j=(b−1)b^{j−1}`.

## R-SPEC-002 — Спектр

Для `0<q<1` перевірити:

`Spec(T_q)={c_q}∪{λ_j:j≥1}∪{0}`.

Окремо перевірити, що 0 є точкою накопичення, але не власним значенням.

## R-SPEC-003 — Граничний q=0

Перевірити:

`c₀=(b−1)/b`,

`λ₁=−1/b`,

`λ_j=0`, `j≥2`.

Нуль має нескінченну кратність.

## R-SPEC-004 — Граничний q=1

Перевірити:

`T₁=P_const`.

Спектр:

`Spec(T₁)={0,1}`.

## R-SPEC-005 — Норми

Для `0≤q<1`:

`||T_q||=c_q`.

`||T_q||²_HS=(b−1)/(b−q²)`.

`||T_q||₁=2c_q`.

`Tr(T_q)=0`.

Для q=1:

`||T₁||=1`,

`||T₁||₁=1`,

`Tr(T₁)=1`.

## R-SPEC-006 — Параметрична неперервність

Перевірити:

`||T_q−T_r||≤|q−r|`.

Це твердження має аналітичне доведення W27.2. Чисельний тест перевіряє відповідність реалізації формулі.

---

# W28.8. Регресійна група R-FINITE

## R-FIN-001 — Скінченна матриця

Для рівня n перевірити:

`(T_q^(n))_{ij}=b^{-n}q^{ℓ(i,j)}` для i≠j,

`(T_q^(n))_{ii}=b^{-n}q^n c_q`.

## R-FIN-002 — Рядки

Перевірити:

`Σ_j(T_q^(n))_{ij}=c_q`.

## R-FIN-003 — Слід

Перевірити:

`Tr(T_q^(n))=q^n c_q`.

Це скінченний слід проєкції, а не слід нескінченновимірного T_q.

## R-FIN-004 — Спектр

Перевірити:

`Spec(T_q^(n))={c_q,λ₁,…,λ_n}`

із відповідними кратностями.

## R-FIN-005 — Апроксимація

Перевірити:

`||T_q−P_nT_qP_n||=|λ_{n+1}|`.

## R-FIN-006 — Центровані апроксимації

Перевірити окремо:

`P_nT_qP_n−c_qP_n`

і

`P_nT_qP_n−c_qI_H`.

Не допускати підміни сильного зближення операторною збіжністю.

# W28.9. Регресійна група R-STRUCTURE

## R-STRUCT-001 — Fingerprint

Для скінченного кореневого дерева перевірити:

`F(T)=(L,h,a)`.

## R-STRUCT-002 — Еквівалентності

Для кожного рівня k:

`x~_k y ⇔ a(x,y)≥k`.

Перевірити рефлексивність, симетричність і транзитивність.

## R-STRUCT-003 — Unary nodes

Перевірити:
- дерево з одним листком;
- ланцюг із unary-вузлів;
- дерево з unary-ланцюгом перед розгалуженням;
- unary-ланцюги після розгалуження.

## R-STRUCT-004 — Root-only tree

Перевірити:

`L={x}`, `h(x)=0`.

Результат — одновузлове дерево.

## R-STRUCT-005 — Межі реконструкції

Тестувати, що fingerprint не претендує на відновлення:
- порядку дітей;
- міток ребер;
- зовнішніх імен внутрішніх вузлів.

Якщо потрібні ці властивості, вони мають бути додані до fingerprint.

# W28.10. Перевірка залежностей теорем

| Теорема | Необхідні передумови |
|---|---|
| Компактність Tree∞ | Скінченний алфавіт, замкненість умов |
| Banach fixed point | Повнота, самовідображення, коефіцієнт <1 |
| Boundary Lipschitz | Tω⁺, компактність меж, метрики d_F і d_Σ |

| Structural reconstruction | Скінченне кореневе дерево, умови W27.3.2 |

Ця таблиця є обов'язковою перевіркою перед включенням кожної теореми до канонічної специфікації.

# W28.11. Класи тестів і критерії проходження

Тестовий набір поділяється на п'ять класів.

**Class A — Unit tests**

Перевірка окремих функцій і структур.

**Class B — Property-based tests**

Перевірка загальних властивостей на багатьох згенерованих скінченних об'єктах.

**Class C — Boundary tests**

Перевірка граничних параметрів і вироджених структур.

**Class D — Numerical spectral tests**

Порівняння чисельного спектра з аналітичними формулами.

**Class E — Formal proof tests**

Машинна перевірка формалізованих теорем.

PASS у класах A–D не означає PASS у класі E.

Для кожного тесту необхідно зберігати:
- ID;
- версію специфікації;
- вхідні параметри;
- очікуваний результат;
- фактичний результат;
- чисельний допуск;
- статус;
- середовище виконання.

# W28.12. Обов'язкові інваріанти

Перед випуском v0.4 усі реалізації мають зберігати такі інваріанти:

**I-01. Type separation**

Повні, часткові та скінченні дерева не змішуються.

**I-02. Metric separation**

`d_F`, `d_Σ`, `d_T`, `d_H` мають різні області визначення.

**I-03. Boundary domain**

Оператор межі в K(Σ) застосовується лише на Tω⁺.

**I-04. Parameter separation**

`α_v`, `α_w`, `α_s` не ототожнюються без явного відображення.

**I-05. Endpoint separation**

`q=0`, `0<q<1`, `q=1` мають окремі твердження.

**I-06. Trace separation**

Слід нескінченного оператора не змішується зі слідом скінченної проєкції.

**I-07. Approximation separation**

Сильна збіжність не ототожнюється з операторною.

**I-08. Homogeneous versus inhomogeneous**

Спільний спектральний розклад однорідних операторів не переноситься автоматично на неоднорідні.

**I-09. Proof versus computation**

Чисельний результат не видається за загальне доведення.

**I-10. Specification versus implementation**

Математична специфікація не видається за перевірений програмний продукт.
