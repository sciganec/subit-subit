# 1. Мета та межі аудиту

W44 має встановити, чи зберігає консолідована архітектура SUBIT-WARP v0.4 математичні, структурні та обчислювальні властивості, які були зафіксовані в попередній специфікації та тестовій моделі W20.

Аудит спрямований на виявлення чотирьох типів регресій:

1. **Математична регресія** — нове означення суперечить раніше прийнятому математичному твердженню.
2. **Структурна регресія** — нова типізація або нормалізація змінює допустимі об'єкти.
3. **Семантична регресія** — різні стани або контексти помилково зливаються.
4. **Обчислювальна регресія** — зміна специфікації робить попередню реалізацію або тест некоректними.

W44 не є твердженням, що всі історичні тести W20 уже відновлено. Без точного тексту W20 неможливо достовірно встановити повну відповідність між його тестами та новими модулями.

Тому W44 має два рівні:

- **W44-A:** регресійна перевірка положень, які вже зафіксовані у W39–W43;
- **W44-B:** відновлення та перевірка історичної матриці W20 після прямого звірення першоджерела.

# 2. Канонічний baseline для регресій

W44 використовує такі поточні домовленості.

## 2.1. Адресна структура

Нехай:

- b ≥ 2;
- B_b = {1,…,b};
- Pos_b = B_b^{<ω};
- Σ_b = B_b^ℕ;
- ε — коренева адреса.

Для u ∈ Pos_b та i ∈ B_b адреса u·i позначає i-й дочірній слот вузла u.

## 2.2. Кодові стани

S_A = {ABSENT, INTERNAL} ∪ {LEAF(a) : a ∈ A}.

Code_b(A) = S_A^{Pos_b}.

Допустимі коди повинні задовольняти:

- ABSENT closure;
- LEAF closure;
- rootedness для C_Partial;
- full-branching condition для C_Full.

## 2.3. Структурні простори

- PartialTree∞_A^(b) — коіндуктивний простір часткових впорядкованих дерев;
- RootedPartialTree∞_A^(b) — дерева з ненульовим коренем;
- C_Partial(A,b) — допустимі rooted-коди;
- C_Full(A,b) — допустимі rooted-коди без відсутніх дочірніх слотів під INTERNAL.

## 2.4. Метрична структура

Кодова метрика:

d_code(t,s)=2^(−r_code(t,s)),

де r_code — мінімальна глибина адреси, на якій коди відрізняються.

Для однакових кодів:

d_code(t,t)=0.

## 2.5. Нескінченне продовження

IB(u,t) означає, що INTERNAL-вузол u має нескінченне INTERNAL-продовження.

Tω_P =
{t ∈ C_Partial : кожний INTERNAL-вузол має нескінченне INTERNAL-продовження}.

Tω_P⁺ =
{t ∈ Tω_P : t(ε)=INTERNAL}.

## 2.6. Межа

Для t ∈ Tω_P⁺:

∂t =
{ξ ∈ Σ_b : ∀k ≥ 0, t(ξ|k)=INTERNAL}.

## 2.7. Спектральна архітектура

Для спадного ядра:

K_q(ξ,η)=q^{ℓ(ξ,η)}, 0≤q≤1.

Для зростаючого ядра:

K_t(ξ,η)=t^{ℓ(ξ,η)}, t>1.

Порогові результати W42:

- спадне ядро: trace-class на всьому q∈[0,1];
- зростаюче ядро: boundedness і compactness при 1<t<b;
- Hilbert–Schmidt умова: t²<b;
- trace-class для t>1 не виконується;
- для t≥b не існує обмеженого оператора, що реалізує відповідну інтегральну форму на всьому L² за встановленою моделлю.

Цей baseline є робочою консолідацією W39–W43, а не підтвердженням історичної відповідності W20.

# 3. Методика регресійного аудиту

Кожний тест має:

1. ідентифікатор;
2. математичну передумову;
3. очікувану властивість;
4. тип можливої регресії;
5. залежності;
6. статус.

Статуси:

- **SPECIFIED** — тест визначений у цьому документі;
- **PROVED-TEXT** — результат обґрунтований математично на рівні текстового доказу;
- **PENDING-EXECUTION** — потрібне виконання тесту;
- **SOURCE-CHECK** — потрібне зіставлення з історичним першоджерелом;
- **BLOCKED** — тест не можна коректно завершити без відсутнього означення.

Жоден статус SPECIFIED або PROVED-TEXT не означає, що програмний тест уже виконаний.

# 4. Група R1 — адресація та branching factor

## R1.1. Мінімальний branching factor

**W44-R001**

Передумова: b=2.

Очікується:

- B₂={1,2};
- кожний INTERNAL має дві адресовані дочірні позиції;
- адреси різної довжини залишаються різними.

Мета: виявити неявне використання b>2 у формулах або реалізаціях, які повинні працювати для всіх b≥2.

Статус: SPECIFIED.

## R1.2. Загальний branching factor

**W44-R002**

Передумова: довільне скінченне b≥2.

Очікується, що всі визначення, які залежать від кількості дочірніх слотів, параметризовані через b.

Заборонено непомітно замінювати b на 2 або 3.

Статус: SPECIFIED.

## R1.3. Заборона b=1

**W44-R003**

Передумова: b=1.

Очікується явна відмова або окремий режим, якщо теорема використовує b≥2.

Не можна переносити формули, які містять b−1, без окремого аналізу граничного випадку.

Статус: SPECIFIED.

## R1.4. Адресна унікальність

**W44-R004**

Кожний вузол має єдину адресу.

Дві різні дочірні позиції одного INTERNAL-вузла не можуть мати однаковий індекс.

Статус: PROVED-TEXT у межах адресної моделі; виконання тесту очікується.

# 5. Група R2 — кодові стани та closure

## R2.1. ABSENT closure

**W44-R005**

Якщо t(u)=ABSENT, тоді кожний нащадок v адреси u також має ABSENT.

Порушення цієї умови повинно призводити до відхилення коду.

Статус: SPECIFIED.

## R2.2. LEAF closure

**W44-R006**

Якщо t(u)=LEAF(a), усі строгі нащадки u мають ABSENT.

Статус: SPECIFIED.

## R2.3. INTERNAL branching

**W44-R007**

INTERNAL створює рівно b адресованих слотів.

Водночас частковий код може мати менше ніж b зайнятих слотів.

Статус: SPECIFIED.

## R2.4. Rootedness

**W44-R008**

Код належить C_Partial лише тоді, коли:

t(ε)≠ABSENT.

Статус: SPECIFIED.

## R2.5. UNKNOWN не дорівнює ABSENT

**W44-R009**

Якщо система отримує стан невизначеності, він не може неявно декодуватися як ABSENT.

Статус: SPECIFIED.

Ризик: семантична регресія через втрату інформації.

**W44-R017**

# 10. Група R7 — спектральні регресії

Ця група фіксує результати W42 як контрольні інваріанти. Вона не підтверджує автоматично сумісність із W30.

## R7.1. Спадне ядро

**W44-R028**

Для q∈[0,1]:

λ₀(q)=(b−1)/(b−q).

Для j≥1:

λ_j(q)=−(1−q)q^(j−1)/[b^(j−1)(b−q)].

Кратність:

m_j=(b−1)b^(j−1).

Статус: PROVED-TEXT у W42; SOURCE-CHECK для W30.

## R7.2. Крайовий випадок q=0

**W44-R029**

λ₀(0)=(b−1)/b.

λ₁(0)=−1/b.

Вищі wavelet-рівні мають нульові власні значення.

Статус: PROVED-TEXT.

## R7.3. Крайовий випадок q=1

**W44-R030**

T₁=P_const.

Rank(T₁)=1.

Статус: PROVED-TEXT.

## R7.4. Trace-class для спадного ядра

**W44-R031**

Для 0≤q<1:

‖T_q‖₁=2(b−1)/(b−q).

Для q=1:

‖T₁‖₁=1.

Статус: PROVED-TEXT.

## R7.5. Зростаюче ядро

**W44-R032**

Для 1<t<b:

λ₀(t)=(b−1)/(b−t).

λ_j(t)=(t−1)t^(j−1)/[b^(j−1)(b−t)].

Статус: PROVED-TEXT у W42; SOURCE-CHECK для W30.

## R7.6. Пороги оператора

**W44-R033**

Boundedness і compactness: 1<t<b.

Hilbert–Schmidt: t²<b.

Trace-class: не виконується для t>1.

Статус: PROVED-TEXT у W42.

## R7.7. Критична межа t=b

**W44-R034**

Для t≥b інтегральна форма на константній функції має необмежене значення при переході до відповідних усічених ядер.

Отже, не існує обмеженого оператора, який реалізує цю граничну інтегральну форму на всьому L².

Статус: PROVED-TEXT за формулюванням W42.

# 14. Відновлення історичного W20

Цей розділ залишається відкритим до прямого звірення першоджерела.

Потрібно отримати точний текст W20 та встановити:

1. повний перелік тестів;
2. початкові означення об'єктів;
3. прийняті інваріанти;
4. очікувані результати;
5. відомі крайові випадки;
6. попередні виправлення;
7. статус кожного тесту;
8. залежність тестів від конкретних версій WARP.

Після отримання джерела кожний історичний тест має бути зіставлений з одним із варіантів:

- **PRESERVED** — нова модель зберігає початкову властивість;
- **STRENGTHENED** — нова модель посилює початкову властивість без суперечності;
- **REFINED** — властивість уточнено, але змінено її область застосування;
- **REPLACED** — старе означення замінено новим;
- **INCOMPATIBLE** — нова модель суперечить старому тесту;
- **UNRESOLVED** — недостатньо інформації.

Заборонено автоматично позначати всі старі тести як PRESERVED лише тому, що нова архітектура має ширший формальний апарат.

# 15. Пріоритетні регресійні ризики

**RR-001 — Domain drift.**  
Домен функції змінився, але її попередні теореми використовують старий домен.

**RR-002 — Type collapse.**  
ABSENT, UNKNOWN та невизначений стан реалізації злиті в одне значення.

**RR-003 — Root convention drift.**  
Коди з ABSENT-коренем помилково допускаються в rooted-простір.

**RR-004 — Branching drift.**  
Фіксований b замінено змінною кількістю дочірніх вузлів без явного переходу до іншої моделі.

**RR-005 — Infinite-depth truncation.**  
Нескінченне дерево неявно замінюється скінченною апроксимацією.

**RR-006 — Boundary-domain drift.**  
Boundary map застосовується до простору, де межа може бути порожньою.

**RR-007 — Metric substitution.**  
d_code використовується замість d_F без доведеної еквівалентності.

**RR-008 — Spectral formula drift.**  
Формули W42 переносяться на інше ядро або іншу міру без повторного виведення.

**RR-009 — Historical mismatch.**  
W20 або W30 інтерпретується за пізнішою термінологією без перевірки першоджерела.

**RR-010 — Proof-status inflation.**  
Текстове доведення або тестова специфікація позначаються як Lean-verified чи executed.
