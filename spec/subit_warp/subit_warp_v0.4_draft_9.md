**Статус:** DRAFT · COMPUTATIONAL VALIDATION SPECIFICATION

**Залежності:** W7–W19

# 1. Призначення W20

W20 визначає єдину систему обчислювальних тестів для SUBIT-WARP.

Його мета — перевірити, чи узгоджується програмна реалізація з математичними формулами та скінченними моделями, визначеними у W7–W18.

W20 не доводить загальних математичних теорем.

Він перевіряє:

1. правильність обчислення аналітичних формул;
2. правильність побудови скінченних матриць;
3. відповідність числового спектра теоретичному;
4. коректність скінченних апроксимацій;
5. правильність комутаторів;
6. поведінку операторних збурень;
7. реконструкцію скінченних дерев;
8. стабільність обчислень на граничних параметрах.

## 1.1. Принцип доказовості

Встановлюємо три незалежні рівні:

**Mathematical Proof**

Доведення твердження в межах заданих припущень.

**Computational Verification**

Перевірка скінченної кількості обчислювальних випадків.

**Implementation Verification**

Перевірка того, що конкретна програмна реалізація відповідає специфікації.

Наприклад:

Теорема про спектр T_q може мати статус PROVED.

Тест матриці розміру 81×81 може мати статус COMPUTATIONALLY VERIFIED.

Реалізація функції build_operator() може мати статус IMPLEMENTATION VERIFIED лише після проходження відповідних тестів.

Жоден із цих статусів не замінює інший.

# 2. W20.1 — Канонічне тестове середовище

## 2.1. Математичні параметри

Основний набір:

b ∈ {2,3,4,5}.

q ∈ {0,0.2,0.5,0.7,0.9,0.99}.

n ∈ {0,1,2,3,4}.

Основний спектральний набір:

q ∈ (0,1).

Граничний набір:

q=0 та q→1⁻.

Параметри повинні передаватися тестам явно.

Забороняється приховано використовувати глобальні значення b, q або n.

Рекомендовані допуски:

| Тип перевірки              |                    Допуск |
| -------------------------- | ------------------------: |
| Арифметика формул          |                     10⁻¹² |
| Симетричність матриці      |                     10⁻¹² |
| Норма комутатора           |                     10⁻¹⁰ |
| Власні значення            |                     10⁻¹⁰ |

# 3. W20.2 — Канонічний набір математичних функцій

Програмна реалізація повинна містити незалежні функції для аналітичних формул.

## 3.1. Константне власне значення

c_q(b)=(b−1)/(b−q).

## 3.2. Власні значення хвильових рівнів

λⱼ(q,b)=−(1−q)q^(j−1)/[b^(j−1)(b−q)].

Для j≥1.

## 3.3. Кратність

mⱼ(b)=(b−1)b^(j−1).

## 3.4. Центровані власні значення

τⱼ(q,b)=λⱼ(q,b)−c_q(b).

## 3.5. Слідова норма

‖T_q‖₁=2(b−1)/(b−q).

## 3.6. Норма Гільберта—Шмідта

‖T_q‖²_HS=(b−1)/(b−q²).

## 3.7. Норма оператора

‖T_q‖=c_q(b).

## 3.8. Точна похибка апроксимації

εₙ(q,b)=
(1−q)qⁿ/[bⁿ(b−q)].

## 3.9. Перевірка розмірності

1+Σⱼ₌₁ⁿmⱼ(b)=bⁿ.

Усі функції повинні мати перевірку допустимих аргументів.

Для основної моделі:

b≥2, 0<q<1.

Для граничних тестів дозволяється q=0.

q=1 не повинен непомітно проходити як звичайний параметр основної моделі.

# 4. W20.3 — Тести спектральних формул

## TEST W20-SPEC-001 — Спектральні значення

Для кожної пари (b,q) побудувати список:

Sₙ={c_q,λ₁,...,λₙ}.

* усі значення скінченні;

* λⱼ₊₁/λⱼ=q/b;
* |λⱼ₊₁|<|λⱼ|.

Очікуваний результат:

PASS для всіх допустимих параметрів.

## TEST W20-SPEC-002 — Кратності

Для кожного n перевірити:

1+Σⱼ₌₁ⁿmⱼ=bⁿ.

Очікуваний результат:

PASS з точною цілочисельною рівністю.

## TEST W20-SPEC-003 — Центрування

Перевірити:

τⱼ=λⱼ−c_q.

Для константного підпростору:

τ₀=0.

Очікуваний результат:

PASS.

## TEST W20-SPEC-004 — Точка накопичення

Для послідовності τⱼ перевірити:

limⱼ→∞τⱼ=−c_q.

Числовий тест не доводить границю.

Він перевіряє збіжність для скінченної кількості рівнів.

Очікуваний результат:

Tr(T_q⁽ⁿ⁾)

Tr(T_q)=0.

Скінченні часткові суми повинні збігатися до нуля.

Очікуваний результат:

limₙ→∞Tr(T_q⁽ⁿ⁾)=0.

# 5. W20.4 — Побудова скінченної матриці

Для рівня n існує bⁿ циліндрів.

Нехай σ і τ — адреси довжини n.

Позначимо k=ℓ(σ,τ), де для σ=τ маємо k=n.

Для ортонормованого циліндричного базису матриця оператора має елементи:

M⁽ⁿ⁾_στ=

* 3? Ні: загальна b-арна формула нижче.

Для σ≠τ:

M⁽ⁿ⁾_στ=b⁻ⁿqᵏ.

Для σ=τ:

M⁽ⁿ⁾_σσ=b⁻ⁿqⁿc_q.

Отже, загальна формула:

M⁽ⁿ⁾_στ=
{
b⁻ⁿqᵏ, якщо σ≠τ;
b⁻ⁿqⁿc_q, якщо σ=τ.
}

Ця формула є канонічною для b-арної моделі.

## TEST W20-MAT-001 — Розмірність

Перевірити:

shape(M⁽ⁿ⁾)=(bⁿ,bⁿ).

## TEST W20-MAT-002 — Симетричність

Перевірити:

M=Mᵀ.

## TEST W20-MAT-003 — Сума рядків

Для кожного рядка:

ΣτM_στ=c_q.

Допуск: 10⁻¹².

## TEST W20-MAT-004 — Слід

Перевірити:

Tr(M⁽ⁿ⁾)=c_q².

Це випливає з діагональних елементів:

bⁿ·b⁻ⁿqⁿc_q=qⁿc_q.

Отже, правильна формула:

**Tr(M⁽ⁿ⁾)=qⁿc_q.**

Попередній запис c_q² є некоректним і не повинен використовуватися.

## TEST W20-MAT-005 — Найбільше власне значення

Перевірити:

λ_max(M⁽ⁿ⁾)=c_q.

Оскільки матриця симетрична, а суми рядків дорівнюють c_q, вектор констант є власним вектором.

Для канонічної моделі інші власні значення:

λ₁,...,λₙ.

Їхні кратності:

m₁,...,mₙ.

# 9. W20.8 — Перевірка W15: Non-Homogeneous Trees

Використовується контрольна модель із трьома листками.

Матриці:

A=
[[0,0,1],
[0,0,1],
[1,1,0]].

B=
[[0,1,0],
[1,0,0],
[0,0,0]].

T_q=(A+qB)/3.

## TEST W20-NHT-001 — Спектр

Перевірити числові власні значення:

λ₁=−q/3.

λ±=[q±√(q²+8)]/6.

## TEST W20-NHT-002 — Комутатор

Для q₁,q₂:

[T_q₁,T_q₂]
=(q₁−q₂)(BA−AB)/9.

Перевірити матричну рівність.

## TEST W20-NHT-003 — Норма комутатора

Перевірити:

‖[T_q₁,T_q₂]‖₂
=√2|q₁−q₂|/9.

## TEST W20-NHT-004 — Параметрична похибка

Перевірити:

‖T_q−T_r‖₂=|q−r|/3.

## TEST W20-NHT-005 — Комутативність

Якщо q₁=q₂:

[T_q₁,T_q₂]=0.

Якщо q₁≠q₂:

[T_q₁,T_q₂]≠0.

Це твердження стосується саме контрольної моделі W15.

# 11. W20.10 — Перевірка W18: Structural Fingerprint

Цей модуль повинен працювати незалежно від спектрального модуля.

## Вхідна структура

Скінченне кореневе дерево:

X=(V,E,r).

Для кожного листка ξ:

* h(ξ) — глибина;
* ℓ(ξ,η) — глибина найглибшого спільного предка.

## TEST W20-SF-001 — Матриця LCA

Перевірити:

A_LCA=A_LCAᵀ.

Для діагоналі:

A_LCA[i,i]=h(ξᵢ).

Для всіх пар:

0≤A_LCA[i,j]≤min(hᵢ,hⱼ).

## TEST W20-SF-002 — Відстань дерева

Перевірити:

d_T(ξᵢ,ξⱼ)
=hᵢ+hⱼ−2A_LCA[i,j].

Для різних листків:

d_T(ξᵢ,ξⱼ)>0.

## TEST W20-SF-003 — Еквівалентність на рівнях

Для кожного k визначити активні листки:

L_k={ξ:h(ξ)≥k}.

Побудувати:

ξ~ₖη ⇔ A_LCA[ξ,η]≥k.

Перевірити:

* рефлексивність;
* симетричність;
* транзитивність.

## TEST W20-SF-004 — Вкладення класів

Кожен клас рівня k+1 повинен бути вкладений рівно в один клас рівня k.

## TEST W20-SF-005 — Реконструкція

1. Побудувати класи еквівалентності для всіх рівнів.
2. Створити вузли.
3. Побудувати ребра між вкладеними класами.
4. Приєднати листки на їхніх глибинах.
5. Відновити корінь.
6. Перевірити структуру.

Результат:

SF(Reconstruct(SF(X)))≅SF(X).

## TEST W20-SF-006 — Ізоморфізм

Перевірити, що реконструйоване дерево ізоморфне початковому як кореневе дерево.

## TEST W20-SF-007 — Unary Nodes

Окремо перевірити дерева з вузлами арності 1.

Вкладення класів між сусідніми рівнями повинно зберігати такі вузли, навіть якщо множина активних листків не змінюється.

## TEST W20-SF-008 — Листок у корені

Перевірити дерево, де корінь сам є листком.

Це граничний випадок із глибиною 0.

Алгоритм реконструкції повинен обробляти його без створення штучного ребра.

# 12. W20.11 — Контрольні структури для реконструкції

Мінімальний набір повинен містити:

**SF-A:** один корінь — один листок.

**SF-B:** корінь із трьома безпосередніми листками.

**SF-C:** збалансоване бінарне дерево.

**SF-D:** незбалансоване дерево типу comb.

**SF-E:** дерево з unary nodes.

**SF-F:** дерево з листками різної глибини.

**SF-G:** дерево з кількома вузлами однакової глибини.

**SF-H:** дві неізоморфні структури з однаковим набором глибин листків.

**SF-I:** дві структури, що відрізняються внутрішньою топологією.

**SF-J:** дерево з коренем-листком.

Для кожного дерева необхідно зберігати:

* серіалізовану структуру;
* список листків;
* профіль глибин;
* матрицю LCA;
* профіль арності;
* результат реконструкції;
* результат ізоморфізму.

# 14. W20.13 — Property-Based Testing

Крім фіксованих тестів, потрібні генеративні перевірки.

Генератор дерев:

* випадкова кількість вузлів;
* випадкова арність;
* випадкова глибина;
* контрольована кількість листків;
* обов'язкове збереження зв'язності;
* відсутність циклів;
* усі вузли досяжні від кореня.

Для кожного згенерованого дерева:

1. обчислити SF;
2. реконструювати дерево;
3. перевірити ізоморфізм;
4. повторно обчислити SF;
5. порівняти fingerprints.

Інваріант:

Reconstruct(SF(X))≅X.

Додатково:

SF(Reconstruct(SF(X)))=SF(X).

Кількість генеративних тестів:

* мінімум 100 для локального запуску;
* мінімум 1000 для release validation.

Кожен невдалий випадок повинен зберігатися як regression fixture.

# 15. W20.14 — Regression Test Registry

Усі знайдені помилки перетворюються на постійні регресійні тести.

Формат запису:

| Поле           | Опис                     |
| -------------- | ------------------------ |
| test_id        | Унікальний ідентифікатор |
| module         | Модуль                   |
| input          | Вхідні дані              |

Забороняється видаляти регресійний тест лише тому, що його виправлено.

Він залишається в тестовому наборі.

# 20. W20.19 — Виявлена проблема, що потребує окремого контролю

Під час формалізації тестів уточнено одну арифметичну деталь.

Для матриці M⁽ⁿ⁾:

M_σσ=b⁻ⁿqⁿc_q.

Кількість діагональних елементів:

bⁿ.

Тому:

Tr(M⁽ⁿ⁾)=bⁿ·b⁻ⁿqⁿc_q.

Отже:

**Tr(M⁽ⁿ⁾)=qⁿc_q.**

Не c_q².

Це важливий контрольний приклад для всієї процедури W20:

обчислювальний тест повинен перевіряти не тільки реалізацію, а й арифметичну узгодженість самої специфікації.

Якщо тест виявляє суперечність між двома записами, спочатку виправляється математичне джерело, а потім реалізація.
