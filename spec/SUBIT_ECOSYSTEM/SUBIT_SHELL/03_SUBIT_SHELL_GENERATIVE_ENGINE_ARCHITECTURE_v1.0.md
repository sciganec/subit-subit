# 1. Призначення

SUBIT-SHELL GENERATIVE ENGINE — автономний обчислювальний двигун для генерації, дослідження, аналізу та візуалізації морфологічних структур.

Його основне завдання — перетворювати параметричні конфігурації на повноцінні тривимірні геометричні об'єкти.

Система повинна забезпечувати:

1. Генерацію мушель на основі параметрів Раупа.
2. Генерацію 64 базових морфологічних класів.
3. Моделювання послідовного росту.
4. Зміну параметрів у процесі росту.
5. Створення нестандартних геометричних форм.
6. Перевірку геометричної коректності.
7. Порівняння з природними морфологічними зразками.
8. Автоматичне дослідження морфологічного простору.
9. Збереження історії генерації.
10. Інтерактивну тривимірну візуалізацію.

Двигун не повинен залежати від готових моделей мушель або сторонніх генеративних систем.

# 4. RAUP-MODEL

## 4.1. Призначення

RAUP-MODEL реалізує математичну модель спірального росту.

Основні параметри:

W — Whorl Expansion.

D — Distance.

T — Translation.

## 4.2. Обчислення радіуса

```text
function shell_radius(theta, a0, W):

    if W <= 0:
        return INVALID

    exponent = theta * ln(W) / (2 * PI)

    return a0 * exp(exponent)
```

## 4.3. Обчислення центральної лінії

```text
function shell_center(theta, params):

    a = shell_radius(
        theta,
        params.a0,
        params.W
    )

    R = params.D * a

    x = R * cos(theta)
    y = R * sin(theta)

    z = params.z0 +
        params.T * params.a0 * theta / (2 * PI)

    return Vector3(x, y, z)
```

## 4.4. Важлива умова

Реалізація повинна розрізняти:

- геометричну траєкторію;
- форму поперечного перерізу;
- поверхню мушлі;
- матеріальну товщину стінки.

Це різні рівні геометричної моделі.

# 5. GEOMETRY-ENGINE

## 5.1. Призначення

GEOMETRY-ENGINE перетворює центральну лінію на тривимірну поверхню.

## 5.2. Алгоритм

1. Отримати параметри W, D, T.
2. Побудувати центральну лінію.
3. Розрахувати локальний ортонормований базис.
4. Побудувати поперечні перерізи.
5. З'єднати сусідні перерізи.
6. Створити полігональну поверхню.
7. Розрахувати нормалі.
8. Перевірити топологію.
9. Передати геометрію до CONSTRAINT-ENGINE.

## 5.3. Типи геометрії

Початкова версія підтримує:

- круглий переріз;
- еліптичний переріз;
- овальний переріз;
- асиметричний переріз.

Наступні версії можуть додати:

- багатокамерні структури;
- нерегулярні перерізи;
- локальні розширення;
- змінну товщину стінок.

## 5.4. Геометричний алгоритм

Для побудови поверхні необхідно використовувати стабільний локальний базис.

Переважний метод — Parallel Transport Frame.

Це зменшує небажане обертання перерізу вздовж кривої.

# 6. GROWTH-ENGINE

## 6.1. Призначення

GROWTH-ENGINE моделює формування мушлі в часі.

На відміну від звичайного геометричного генератора, він повинен зберігати історію послідовного формування.

## 6.2. Модель росту

```text
GrowthState:
    current_theta
    current_parameters
    previous_geometry
    growth_history
    growth_step
```

## 6.3. Основний алгоритм

```text
function grow_shell(state, delta_theta):

    old_geometry = state.geometry

    new_interval = [
        state.current_theta,
        state.current_theta + delta_theta
    ]

    new_geometry = generate_segment(
        state.parameters,
        new_interval
    )

    state.geometry = append(
        old_geometry,
        new_geometry
    )

    state.current_theta += delta_theta

    record_growth_event(state)

    return state
```

У виробничій реалізації append повинен забезпечувати коректне з'єднання сегментів без щілин, дубльованих граней або некоректної топології.

## 6.4. Адаптивний ріст

Система повинна дозволяти змінювати параметри:

```text
W(theta)
D(theta)
T(theta)
```

Наприклад:

- повільне розширення на початковому етапі;
- прискорене розширення;
- зміна відстані між витками;
- поступовий перехід до баштової форми.

Кожна зміна повинна записуватися в історію.

# 7. SUBIT-64 ENGINE

## 7.1. Призначення

Модуль відповідає за 64 базові морфологічні класи.

## 7.2. Генерація

```text
for w in [0, 1, 2, 3]:

    for d in [0, 1, 2, 3]:

        for t in [0, 1, 2, 3]:

            state = create_shell_state(
                w, d, t
            )

            atlas.add(state)
```

## 7.3. Ідентифікатор

```text
function encode_state(w, d, t):

    return (w << 4) |
           (d << 2) |
           t
```

Усі значення w, d, t повинні належати діапазону 0–3.

## 7.4. Декодування

```text
function decode_state(id):

    w = (id >> 4) & 3
    d = (id >> 2) & 3
    t = id & 3

    return (w, d, t)
```

## 7.5. Важливе обмеження

SUBIT-64 генерує 64 категорії параметричних станів.

Він не гарантує, що всі 64 комбінації відповідають геометрично коректним або біологічно можливим мушлям.

Це завдання CONSTRAINT-ENGINE.

# 9. CONSTRAINT-ENGINE

## 9.1. Призначення

## 9.2. Рівні перевірки

LEVEL 1 — Numerical Validation.

Перевірка числових значень.

LEVEL 2 — Geometric Validation.

Перевірка координат, нормалей та поверхонь.

LEVEL 3 — Topological Validation.

Окреме дослідження потенційної біологічної допустимості.

```text

    structural

    warnings
```

# 10. NOVELTY-ENGINE

## 10.1. Призначення

NOVELTY-ENGINE досліджує морфологічний простір.

Він повинен знаходити форми, які відрізняються від відомих природних зразків.

## 10.2. Стратегії пошуку

GRID SEARCH:

Систематичне сканування параметричного простору.

RANDOM SEARCH:

Випадкова генерація конфігурацій.

BOUNDARY SEARCH:

Дослідження граничних конфігурацій.

ADAPTIVE SEARCH:

Зосередження на областях із високою морфологічною різноманітністю.

## 10.3. Оцінювання новизни

Новизна повинна оцінюватися за:

- геометричними характеристиками;
- топологією;
- просторовими відношеннями;
- параметричною відстанню;
- порівнянням із каталогом природних форм.

## 10.4. Заборона хибних висновків

NOVELTY-ENGINE не повинен стверджувати, що форма ніколи не існувала в природі лише через відсутність відповідного зразка в каталозі.
