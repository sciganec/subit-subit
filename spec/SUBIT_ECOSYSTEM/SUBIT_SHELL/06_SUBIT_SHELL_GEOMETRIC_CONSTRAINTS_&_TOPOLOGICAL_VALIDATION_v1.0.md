Цей документ визначає систему геометричних, топологічних і структурних перевірок для генеративного двигуна SUBIT-SHELL.

- чисельно стабільні;
- геометрично коректні;

**DO NOT COLLAPSE — CONTEXTUALIZE.**

Геометрична помилка, механічна нестабільність і біологічна неможливість — це різні типи обмежень.

Наприклад:

- форма може бути математично визначеною, але мати самоперетини;

# 3. Геометрична основа

## 3.1. Центральна лінія мушлі

Початкова модель Раупа задає центральну лінію трубки:

C(θ) = (x(θ), y(θ), z(θ))

Для базового випадку:

a(θ) = a₀ · exp(kθ)

k = ln(W) / 2π

R(θ) = D(θ) · a(θ)

x(θ) = R(θ) · cos(θ)

y(θ) = R(θ) · sin(θ)

z(θ) = z₀ + ∫₀^θ T(u) · a(u) / 2π du

У найпростішій моделі W, D і T є сталими.

У розширеній моделі вони можуть змінюватися вздовж кута росту.

## 3.2. Перевірка центральної лінії

Центральна лінія повинна задовольняти такі умови:

- усі координати є скінченними;
- похідна C'(θ) визначена;
- швидкість параметризації не дорівнює нулю;
- локальна геометрія не містить числових розривів;
- крок дискретизації достатній для відтворення кривизни.

Норма дотичного вектора:

v(θ) = ‖C'(θ)‖

Необхідна умова регулярності:

v(θ) > 0

Якщо ця умова порушена, локальний ортонормований базис не може бути надійно визначений стандартним способом.

## 3.3. Кривина центральної лінії

Для регулярної кривої:

κ(θ) = ‖C'(θ) × C''(θ)‖ / ‖C'(θ)‖³

де κ — кривина.

Радіус кривини:

ρ(θ) = 1 / κ(θ)

за умови κ(θ) > 0.

Ці величини потрібні для визначення геометричної допустимості трубчастої поверхні.

# 4. Регулярність трубчастої поверхні

## 4.1. Побудова поверхні

Поверхня мушлі формується навколо центральної лінії:

P(θ,φ) = C(θ) + a(θ) · [n(θ)cos(φ) + b(θ)sin(φ)]

де:

- n(θ) — нормаль;
- b(θ) — бінормаль;
- φ — кут поперечного перерізу;
- a(θ) — локальний радіус трубки.

Для побудови базису рекомендується Parallel Transport Frame.

Цей метод зменшує небажане обертання поперечного перерізу вздовж кривої порівняно з наївним використанням локального френетового базису, який може бути нестабільним у точках малої кривини.

## 4.2. Локальна умова регулярності

Для трубки зі сталим локальним радіусом достатньою локальною умовою відсутності фокальних сингулярностей є:

a(θ) · κ(θ) < 1

Для змінного радіуса це співвідношення залишається корисним локальним індикатором, але не є повним критерієм регулярності всієї поверхні.

SUBIT-SHELL повинен обчислювати:

Qκ(θ) = a(θ) · κ(θ)

Інтерпретація:

- Qκ < 1 — локальна умова виконується;
- Qκ ≈ 1 — зона підвищеного геометричного ризику;
- Qκ ≥ 1 — можливе порушення регулярності трубчастої моделі.

Поріг попередження задається конфігурацією.

Важливо: виконання локальної умови не гарантує відсутності глобальних самоперетинів. Віддалені ділянки центральної лінії можуть зближуватися настільки, що трубка перетинає сама себе.

## 4.3. Локальна товщина та змінний переріз

Якщо трубка має змінний переріз:

P(θ,φ) = C(θ) + q₁(θ)cos(φ)n(θ) + q₂(θ)sin(φ)b(θ)

де q₁ і q₂ задають півосі еліптичного перерізу.

У такому випадку система повинна перевіряти обидва напрями деформації.

Майбутні розширення:

- еліптичний переріз;
- асиметричний переріз;
- змінна товщина стінки;
- нерівномірне нарощування матеріалу;
- локальні потовщення та ремонтні структури.

# 5. Виявлення самоперетинів

## 5.1. Визначення

Самоперетин виникає, коли дві геометрично несуміжні частини поверхні займають спільну просторову область або перетинаються.

Для поверхні P:

P(θ₁,φ₁) = P(θ₂,φ₂)

за геометрично несуміжних пар параметрів може вказувати на самоперетин.

Проте зближення двох ділянок саме по собі не завжди означає перетин.

Тому необхідно розрізняти:

1. контакт;
2. перекриття;
3. проникнення;
4. самоперетин;
5. злиття поверхонь.

## 5.2. Дворівневе виявлення

Рекомендується використовувати два етапи.

### Етап A — Broad Phase

Швидке визначення потенційно конфліктних ділянок.

Методи:

- Axis-Aligned Bounding Boxes (AABB);
- Bounding Volume Hierarchy (BVH);
- просторове розбиття;
- інтервальні обмежувальні об'єми.

Мета — не перевіряти всі трикутники попарно.

### Етап B — Narrow Phase

Точна перевірка потенційно конфліктних пар.

Для полігональної поверхні:

- triangle-triangle intersection;
- перевірка відстані між трикутниками;
- визначення спільних точок;
- класифікація типу контакту.

Суміжні трикутники, що мають спільне ребро або вершину, не повинні автоматично класифікуватися як самоперетин.

Водночас не можна виключати всі трикутники, що мають близькі індекси: це може приховати реальні перетини між різними витками.

## 5.3. Результат

Для кожного виявленого конфлікту зберігаються:

- ID першої ділянки;
- ID другої ділянки;
- координати перетину або мінімальної відстані;
- тип конфлікту;
- геометрична серйозність;
- локальний параметр θ;
- відповідний сегмент історії росту.

Самоперетини не повинні просто видалятися з геометрії.

Вони мають залишатися у звіті валідації.

# 6. Перекриття витків — окрема морфологічна властивість

Одна з найважливіших особливостей SUBIT-SHELL полягає в необхідності розрізняти самоперетин і перекриття витків.

У природних мушлях сусідні витки можуть:

- контактувати;
- частково перекриватися;
- щільно прилягати;
- утворювати складну систему швів;
- створювати зовнішню оболонку навколо попередніх витків.

Тому будь-яке перекриття не можна автоматично вважати помилкою.

## 6.1. Параметри перекриття

Визначимо:

O(θ) — локальний індекс перекриття.

S(θ) — мінімальна відстань між сусідніми витками.

C(θ) — коефіцієнт контакту.

Ці метрики мають бути незалежними від бінарного результату самоперетину.

## 6.2. Класифікація

Можливі типи:

- NO_OVERLAP;
- NEAR_CONTACT;
- TANGENTIAL_CONTACT;
- PARTIAL_OVERLAP;
- ENCLOSING_OVERLAP;
- INTERSECTION;
- UNKNOWN.

Перші п'ять категорій можуть бути морфологічно допустимими залежно від типу мушлі та способу побудови поверхні.

INTERSECTION вимагає окремого аналізу.

## 6.3. Морфологічне значення

Перекриття може бути не дефектом, а визначальною ознакою архітектури мушлі.

Тому SUBIT-SHELL повинен використовувати його як класифікаційну характеристику, а не лише як обмеження.

# 7. Топологічна валідація

## 7.1. Основні поняття

Топологічна перевірка відповідає на питання:

Чи утворює згенерована поверхня структурно узгоджений геометричний об'єкт?

Основні характеристики:

- manifoldness;
- watertightness;
- orientability;
- connected components;
- boundary edges;
- non-manifold edges;
- Euler characteristic.

## 7.2. Manifoldness

Двовимірна поверхня є manifold у внутрішній точці, якщо її достатньо мала околиця топологічно еквівалентна диску.

Для точки на межі — півдиску.

Полігональна сітка повинна перевіряти:

- кількість граней на ребро;
- узгодженість сусідніх граней;
- локальну структуру вершин;
- відсутність некоректних розгалужень.

Для звичайної замкненої двовимірної поверхні без меж кожне ребро має належати рівно двом граням.

Для відкритої поверхні ребра на межі можуть належати одній грані.

Ребра, інцидентні більш ніж двом граням, є потенційними non-manifold дефектами.

## 7.3. Watertightness

Watertightness означає, що поверхня утворює замкнену оболонку без відкритих меж.

Перевіряються:

- boundary edges;
- розриви сітки;
- незамкнені контури;
- узгодженість з'єднання сегментів.

Однак не кожна коректна модель мушлі повинна бути watertight.

Наприклад, відкрите устя може бути природною частиною геометрії.

Тому параметр:

ExpectedBoundaryMode ∈ {CLOSED, OPEN_APERTURE, MULTIPLE_BOUNDARIES}

повинен бути заданий контекстом моделі.

## 7.4. Orientability

Поверхня є орієнтовною, якщо можна узгоджено визначити напрямок нормалі на всіх її ділянках.

Для звичайної моделі мушлі це важливо для:

- освітлення;
- визначення внутрішньої та зовнішньої сторін;
- обчислення об'єму;
- аналізу товщини;
- механічного моделювання.

Неузгоджені нормалі повинні фіксуватися як окрема категорія помилки.

## 7.5. Euler characteristic

Для полігональної сітки:

χ = V − E + F

де:

- V — кількість вершин;
- E — кількість ребер;
- F — кількість граней.

Для замкненої, зв'язної, орієнтовної поверхні:

χ = 2 − 2g

де g — рід поверхні.

Важливе обмеження:

Не можна обчислювати рід за цією формулою без перевірки припущень про замкненість, зв'язність і орієнтовність.

Для поверхонь із межами використовується відповідна топологічна характеристика.

# 8. Якість полігональної сітки

## 8.1. Загальні вимоги

Генеративний двигун повинен контролювати:

- вироджені трикутники;
- нульову площу;
- надмірно витягнуті трикутники;
- перевернуті нормалі;
- нерівномірну щільність;
- розриви;
- дубльовані вершини;
- некоректні індекси.

## 8.2. Вироджені грані

Площа трикутника:

A = 0.5 · ‖(B − A) × (C − A)‖

Якщо площа нижча за заданий числовий допуск, грань позначається як DEGENERATE.

Допуск повинен масштабуватися відповідно до характерного розміру моделі.

Не можна використовувати один універсальний абсолютний epsilon для мушель усіх масштабів.

## 8.3. Aspect Ratio

Для кожного трикутника обчислюється співвідношення між найбільшою та найменшою характерними довжинами.

Надмірно витягнуті грані можуть погіршувати:

- стабільність нормалей;
- точність перетинів;
- якість візуалізації;
- подальші механічні розрахунки.

Порогові значення є конфігураційними.

## 8.4. Адаптивна дискретизація

Крок дискретизації θ не повинен бути однаковим за будь-яких умов.

Він залежить від:

- локальної кривини;
- швидкості зміни радіуса;
- зміни D(θ);
- зміни T(θ);
- геометрії перерізу;
- заданої точності апроксимації.

Пропонується:

Δθ = f(κ, a, |da/dθ|, |dD/dθ|, |dT/dθ|, ε)

де ε — допустима похибка апроксимації.

Мета — збільшувати щільність сітки там, де геометрія швидко змінюється, і зменшувати її на гладких ділянках.

# 9. Валідація росту

## 9.1. Принцип накопичувального росту

Базова модель передбачає, що новий матеріал додається до вже сформованої мушлі.

Для дискретних кроків:

Gₙ ⊆ Gₙ₊₁

Цей інваріант застосовується лише до режиму росту без ерозії, ремонту або деформації старого матеріалу.

## 9.2. Перевірка меж сегментів

Кожен новий сегмент повинен:

- мати коректне початкове положення;
- узгоджуватися з попереднім сегментом;
- не створювати небажаних розривів;
- зберігати історію параметрів;
- мати визначений статус інтеграції.

Оператор GROW не повинен просто об'єднувати два масиви вершин.

Він має виконувати геометричне узгодження меж.

## 9.3. Події росту

Кожна операція записується в Growth History:

- INITIALIZATION;
- EXPANSION;
- RADIAL_CHANGE;
- AXIAL_CHANGE;
- CROSS_SECTION_CHANGE;
- GROWTH_PAUSE;
- REPAIR;
- DAMAGE;
- MINERALIZATION;
- TERMINATION.

Це дозволяє відрізняти природний розвиток форми від цифрової деформації, виконаної під час генерації.

## 9.4. Перевірка історичної узгодженості

Система повинна вміти відновити геометричний стан на будь-якому попередньому кроці.

Для цього необхідно зберігати:

- параметри;
- геометричні сегменти;
- часові мітки;
- операції;
- контекст;
- версію алгоритму;

# 10. Фізична та механічна спроможність

Геометрично коректна форма не обов'язково може існувати як матеріальна структура.

Мушля є матеріальним об'єктом із певною товщиною, властивостями матеріалу та навантаженнями.

## 10.1. Параметри матеріалу

Майбутня підсистема повинна підтримувати:

- Young's modulus;
- Poisson's ratio;
- density;
- tensile strength;
- compressive strength;
- fracture toughness;
- wall thickness;
- material anisotropy;
- growth-dependent material properties.

Ці параметри не слід вигадувати для природних видів.

Вони мають надходити з емпіричних джерел або бути явно позначеними як умовні параметри симуляції.

## 10.2. Механічні перевірки

Потенційні механізми відмови:

- локальне руйнування;
- згин;
- стискання;
- втрата стійкості;
- buckling;
- fracture;
- локальне пошкодження;
- надмірна концентрація напружень.

Для відповідних оцінок потрібна механічна модель.

Геометричний модуль SUBIT-SHELL не повинен оголошувати конструкцію механічно стійкою лише на підставі відсутності самоперетинів.

## 10.3. Статус механічної перевірки

Поки механічний розрахунок не реалізований:

Vₘ = NOT_EVALUATED

Якщо є лише часткові параметри матеріалу:

Vₘ = UNKNOWN або CONDITIONAL

# 11. Біологічна правдоподібність

Біологічна допустимість не виводиться безпосередньо з геометрії.

Для оцінки потрібні додаткові відомості:

- таксономічна група;
- спосіб росту;
- фізіологічні обмеження;
- доступність матеріалу;
- середовище;
- функціональна роль мушлі;
- філогенетичний контекст;
- емпіричні спостереження.

## 11.1. Біологічні обмеження

Визначимо:

B = f(G, M, E, P, F)

де:

- G — геометрія;
- M — матеріальні властивості;
- E — середовище;
- P — процес росту;
- F — функціональні характеристики.

Функція f поки не визначена як універсальний біологічний закон.

Вона є концептуальною основою для майбутньої емпіричної моделі.

## 11.2. Таксономічна обережність

Модель Раупа найкраще розглядати як параметричну модель певного класу трубчастих мушель.

Не слід автоматично застосовувати її без змін до:

- Bivalvia;
- Brachiopoda;
- рогів;
- бивнів;
- інших структур, які не є звичайними спіральними трубками.

Для них можуть знадобитися інші генеративні моделі.

# 13. Алгоритм повної валідації

Псевдокод:

```text
FUNCTION VALIDATE_SHELL(shell, context):

    result = CREATE_VALIDATION_RESULT()

    result.numerical =
        CHECK_FINITE_COORDINATES(shell)

    IF result.numerical == INVALID:
        RETURN result

    result.parametric =
        CHECK_PARAMETER_DOMAIN(shell.parameters)

    result.curve =
        CHECK_CENTERLINE_REGULARITY(shell.centerline)

    result.surface =
        CHECK_SURFACE_REGULARITY(shell.surface)

    result.curvature =
        COMPUTE_LOCAL_CURVATURE(shell)

    result.local_tube_risk =
        CHECK_LOCAL_TUBE_REGULARITY(shell)

    result.intersections =
        DETECT_SELF_INTERSECTIONS(
            shell.mesh,
            BVH,
            TRIANGLE_INTERSECTION
        )

    result.overlap =
        ANALYZE_WHORL_OVERLAP(shell)

    result.topology =
        CHECK_TOPOLOGY(shell.mesh)

    result.mesh_quality =
        CHECK_MESH_QUALITY(shell.mesh)

    result.growth_history =
        CHECK_GROWTH_CONSISTENCY(shell.history)

    IF context.material_data_available:
        result.mechanical =
            RUN_MECHANICAL_VALIDATION(shell, context)
    ELSE:
        result.mechanical = NOT_EVALUATED

    IF context.biological_model_available:
        result.biological =
            RUN_BIOLOGICAL_VALIDATION(shell, context)
    ELSE:
        result.biological = NOT_EVALUATED

    IF context.empirical_reference_available:
        result.empirical =
            COMPARE_WITH_REFERENCE(shell, context)
    ELSE:
        result.empirical = NOT_EVALUATED

    result.overall_profile =
        BUILD_MULTIDIMENSIONAL_PROFILE(result)

    SAVE_VALIDATION_PROVENANCE(result)

    RETURN result
```

Важливо: `RUN_MECHANICAL_VALIDATION` і `RUN_BIOLOGICAL_VALIDATION` є інтерфейсами майбутніх підсистем, а не твердженням, що ці обчислення вже реалізовані.

S-004: змінний переріз.

# 15. Інваріанти SUBIT-SHELL VALIDATION

Система повинна гарантувати такі властивості.

**INV-001 — Context Preservation**

Жоден результат геометричної перевірки не повинен знищувати контекст генерації.

**INV-002 — No Silent Repair**

Автоматичне виправлення сітки не повинно відбуватися без запису операції.

**INV-003 — Separate Validity Levels**

Геометрична валідність не повинна автоматично означати біологічну.

**INV-004 — Reproducible Validation**

Для однакових геометрії, конфігурації та версії алгоритму результати повинні бути відтворюваними в межах визначеної числової точності.

**INV-005 — Preserve Invalid States**

Некоректні геометрії не видаляються з атласу. Вони отримують відповідний статус і залишаються доступними для дослідження.

**INV-006 — Distinguish Contact from Intersection**

Контакт або перекриття витків не повинні автоматично трактуватися як самоперетин.

**INV-007 — Provenance Preservation**

Кожна перевірка має зберігати джерело параметрів, версію генератора та конфігурацію перевірки.

**INV-008 — No Unsupported Biological Claims**

Геометричний модуль не повинен робити висновків про біологічну реалізованість без відповідної моделі або емпіричних даних.

# 16. Дослідницька програма: простір можливих мушель

Цей модуль має не лише інженерне, а й теоретичне значення.

Модель Раупа дозволяє розглядати мушлі як область параметричного простору.

SUBIT-SHELL розширює це бачення, розрізняючи декілька множин:

Ω₀ — математично визначені конфігурації.

Ω₁ — конфігурації з регулярною геометрією.

Ω₂ — конфігурації з допустимою топологією.

Ω₃ — конфігурації з потенційною механічною спроможністю.

Ω₄ — біологічно правдоподібні конфігурації.

Ω₅ — емпірично підтверджені форми.

За умови узгоджених критеріїв перевірки:

Ω₅ ⊆ Ω₄ ⊆ Ω₃ ⊆ Ω₂ ⊆ Ω₁ ⊆ Ω₀.

Однак ці включення є методологічною моделлю, а не вже доведеним законом природи. Вони залежать від визначень допустимості та повноти відповідних моделей.

## 16.1. Питання про незаповнені області

Якщо певна область параметричного простору не має відомих природних аналогів, можливі різні пояснення:

1. Геометрична неможливість.
2. Топологічне обмеження.
3. Механічна нестабільність.
4. Біологічна недоцільність.
5. Обмеження середовища.
6. Історична відсутність відповідної еволюційної траєкторії.
7. Недостатність палеонтологічних або сучасних даних.

Ці пояснення не є взаємовиключними.

## 16.2. Рауп і Гулд: обмеження та історична випадковість

SUBIT-SHELL дозволяє сформулювати дослідницьке питання:

Чи визначається розподіл природних мушель переважно обмеженнями простору можливих форм, чи значною мірою історією еволюційних подій?

Для перевірки потрібні:

- карта математично можливих форм;
- карта геометрично допустимих форм;
- карта механічно допустимих форм;
- каталог реальних мушель;
- філогенетична інформація;
- палеонтологічні дані.

Якщо певні області математично можливі, але механічно недопустимі, це підтримуватиме пояснення через фізичні обмеження.

Якщо ж області механічно допустимі, але не представлені в історії життя, необхідно досліджувати еволюційну контингентність.

SUBIT-SHELL не повинен заздалегідь обирати одне з цих пояснень.

Його завдання — створити інструментарій для їх розрізнення.
