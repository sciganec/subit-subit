## WP1.5. §11 (v6.0). Модальна логіка — виправлена редакція

### 11.1. Діагноз v5.2

v5.2 §11 постулює вісім аксіом M1–M8. Аудит (Частина 1, §6.1) показав, що **M4** (`◇A ↔ ¬□¬A`) не виконується в Ω_SUBIT. Крім того, виявилася глибша проблема: **модальності □ і ◇ у v5.2 мають різну арність** — □ визначено для *множин* (`F(A) = A`), ◇ — для *станів* (`∃k: Fᵏ(s) ∈ A`). Це робить формулювання аксіом неоднозначним.

Обидві проблеми виправляються в v6.0.

### 11.2. Узгодження арності

**Означення 11.1 (модальності як предикати станів).** Нехай A ⊆ S_∞ × ℛ — множина (клас). Для ŝ ∈ S_∞ × ℛ:

```
ŝ ⊨ □A   ⟺   ∀n ≥ 0: Fⁿ(ŝ) ∈ A
ŝ ⊨ ◇A   ⟺   ∃n ≥ 0: Fⁿ(ŝ) ∈ A
ŝ ⊨ ◯A   ⟺   ∃k > 1: Fᵏ(ŝ) ∈ A,  і  ŝ ⊨ ◇A,  і  Fᵏ(A) = A для деякого такого k
```

**Твердження 11.1 (зв'язок з множинним Ω).** Для будь-якої A:

```
F(A) = A  ⟹  (A ⊨ □A)  ⟺  (∀ŝ ∈ A: ŝ ⊨ □A)
```

Тобто множинна стабільність (Означення 6.1) і станова модальність □ узгоджені: якщо A — інваріант, то кожен його елемент задовольняє □A.

*Доведення.* Якщо F(A) = A і ŝ ∈ A, то F(ŝ) ∈ A, отже за індукцією Fⁿ(ŝ) ∈ A для всіх n. ∎

**Зауваження 11.1.** Зворотне не виконується: ŝ ⊨ □A для всіх ŝ ∈ A не тягне F(A) = A, якщо A не замкнена. Наприклад, A = {ŝ}, F(ŝ) = ŝ (нерухома точка) — тоді ŝ ⊨ □A, але якщо додати ŝ' ∉ A з F(ŝ') = ŝ, то F(A) = A все одно, але A не «породжує» □A для всіх своїх елементів (лише для ŝ).

### 11.3. Перевірка аксіом

**Твердження 11.2 (M1–M3).** Наступні аксіоми виконуються для всіх ŝ і A, B:

```
(M1)  □A → A
(M2)  □A → □□A
(M3)  □(A → B) → (□A → □B)
```

*Доведення.*

- **(M1):** Якщо ∀n: Fⁿ(ŝ) ∈ A, то зокрема F⁰(ŝ) = ŝ ∈ A. ✅
- **(M2):** Потрібно: □A → □□A. Тут □□A читається як ∀m: Fᵐ(ŝ) ⊨ □A. Еквівалентно ∀m ∀n: Fᵐ⁺ⁿ(ŝ) ∈ A. Це випливає з □A. ✅
- **(M3):** Якщо A ⊆ B (розуміючи A → B як A ⊆ B для предикатів), то □A ⟹ □B. ✅

**Твердження 11.3 (M5–M8).**

```
(M5)  ◯A → ◇A
(M6)  □A → ◯A
(M7)  ◯◯A ↔ ◯A
(M8)  □A ∧ □B → □(A ∧ B)
```

*Доведення (ескіз).*

- **(M5):** За означенням ◯A містить ◇A як кон'юнкт. ✅
- **(M6):** Якщо ∀n: Fⁿ(ŝ) ∈ A, то зокрема F²(ŝ) ∈ A і F²(A) = A (з □A для множин), отже ◯A. ✅
- **(M7):** ◯A означає повернення з періодом k>1; застосування ◯ знову не змінює період. Формально: ◯◯A ⟺ ∃k>1: Fᵏ(A)=A і Fᵏ(ŝ)∈A — те саме, що ◯A. ✅
- **(M8):** □A ∧ □B ⟹ ∀n: Fⁿ(ŝ)∈A і Fⁿ(ŝ)∈B ⟹ ∀n: Fⁿ(ŝ)∈A∩B ⟹ □(A∧B). ✅

### 11.4. M4 — спростовано і замінено

**Твердження 11.4 (M4 не виконується).** Аксіома `◇A ↔ ¬□¬A` не виконується в Ω_SUBIT.

*Контрприклад.* Покладемо A = METASTABLE (як множину станів).

- **Ліва частина:** ◇METASTABLE — існує n ≥ 0: Fⁿ(ŝ) ∈ METASTABLE. На скінченному рівні метастабільність для синглтона неможлива (Означення 6.3), але для множини — можлива. Припустимо, ŝ входить у метастабільну множину.

- **Права частина:** ¬□¬METASTABLE. Обчислимо ¬METASTABLE (у Ω_SUBIT): ¬METASTABLE = CHAOTIC (з таблиці §7 v5.2). Тепер □CHAOTIC: чи є CHAOTIC інваріантом? На скінченному рівні CHAOTIC не реалізується (Твердження 5.1), тому □CHAOTIC = ⊥ (порожня множина). Отже ¬□CHAOTIC = ¬⊥ = STABLE.

- **Висновок:** STABLE ≠ ◇METASTABLE. Отже, M4 спростовано.

**Твердження 11.5 (M4' — інтуїціоністська форма).** Виконується лише одна імплікація:

```
(M4')  ◇A → ¬□¬A
```

*Доведення.* Якщо ◇A, існує n: Fⁿ(ŝ) ∈ A. Припустимо ¬A (у сенсі заперечення як A → ⊥). Тоді □¬A означало б ∀m: Fᵐ(ŝ) ∈ ¬A, зокрема Fⁿ(ŝ) ∈ ¬A, суперечність з Fⁿ(ŝ) ∈ A. Отже, ¬□¬A. ∎

**Зауваження 11.2.** Зворотна імплікація ¬□¬A → ◇A є саме тим, що перетворює інтуїціоністську логіку на класичну (подвійне заперечення). Її відсутність узгоджується з Твердженням 7.1 v5.2 (недосяжність виключеного третього).

### 11.5. Підсумкова таблиця аксіом v6.0

| Аксіома | Формулювання | Статус |
|---|---|---|
| M1 | □A → A | ✅ |
| M2 | □A → □□A | ✅ |
| M3 | □(A → B) → (□A → □B) | ✅ |
| **M4** | **◇A ↔ ¬□¬A** | **❌** (спростовано) |
| M4' | ◇A → ¬□¬A | ✅ |
| M5 | ◯A → ◇A | ✅ |
| M6 | □A → ◯A | ✅ |
| M7 | ◯◯A ↔ ◯A | ✅ |
| M8 | □A ∧ □B → □(A ∧ B) | ✅ |
| M9 (нова) | ¬¬□A → □A | ✅ |

**Твердження 11.6 (M9).** У Ω_SUBIT подвійне заперечення стабільної істини збігається з нею самою: ¬¬□A ↔ □A.

*Доведення.* ¬□A = CHAOTIC (за таблицею §7). ¬¬□A = ¬CHAOTIC = STABLE. Отже, ¬¬□A ⟺ STABLE ⟺ □A. ∎

**Зауваження 11.3.** M9 узгоджується з гейтінговою структурою: у ланцюзі Гейтінга подвійне заперечення не завжди повертає початкове значення (¬¬METASTABLE = ¬CHAOTIC = STABLE ≠ METASTABLE), але для ⊤ і ⊥ воно стабільне.

### 11.6. Відповідність класифікатору Ω

| Ω-клас | Модальна характеристика |
|---|---|
| STABLE | □A |
| METASTABLE | A ∧ ¬□A |
| CYCLIC | ◯A ∧ ¬□A |
| CHAOTIC | ¬◇A |

**Твердження 11.7 (узгодженість з §18.7).** Двоосьова класифікація Ω_traj = (S, Att) вкладається в модальну логіку: S-компонента визначається формулами вище, Att-компонента — окремо (через існування або неіснування моменту досягнення m(ŝ₀)).

## WP1.7. §20 (v6.0). Статуси доказовості

### 20.1. Навіщо цей розділ

Специфікація SUBIT v5.2 змішувала три різні речі: (а) **формальну визначеність** поняття, (б) **доведеність** твердження, (в) **емпіричну підтримку**. Це призводило до ситуацій, коли відкрите питання використовувалося як аксіома на наступному рівні, або коли методологічне застереження плуталося з теоремою.

§20 вводить **нормативну систему статусів** для кожного твердження SUBIT. Це операційний інструмент, не метафора.

### 20.2. Шість статусів

**Означення 20.1.** Кожне твердження SUBIT має рівно один зі шести статусів:

| Позначка | Назва | Значення | Що потрібно для присвоєння |
|---|---|---|---|
| ✅ | Доведено | Є повний доказ із явними передумовами | Доказ, відтворюваний незалежно |
| ⚠️ | Доведено умовно | Доведено за додаткових припущень | Явний список передумов + доказ |
| ❌ | Спростовано | Є контрприклад | Явний контрприклад |
| ❓ | Гіпотеза | Сформульовано, але ні доведено, ні спростовано | Формулювання + спроба доведення/спростування |
| 📊 | Емпірично підтримано | Узгоджується з даними за фіксованим критерієм | Дані + критерій + протокол |
| ⊥ | Невизначено | Недостатньо підстав для висновку | — |

### 20.3. Правила використання статусів

**Правило 20.1 (заборона на аксіоматизацію).** Твердження зі статусом ❓ або ⊥ **не можна** використовувати як аксіому або передумову на наступному рівні ієрархії. Воно або підвищується до ✅/⚠️/❌, або явно позначається як гіпотеза в тексті.

**Правило 20.2 (обов'язковість передумов).** Твердження зі статусом ⚠️ зобов'язане супроводжуватися **явним** списком додаткових передумов. Передумови не можуть бути неявними.

**Правило 20.3 (заборона на змішування).** ❌ не можна трактувати як ❓. ❌ означає наявність контрприкладу; ❓ — його відсутність. Це різні епістемічні стани.

**Правило 20.4 (заборона на підміну).** 📊 не можна трактувати як ✅. Емпірична підтримка не є математичним доказом.

**Правило 20.5 (обов'язковість ⊥).** Якщо обчислювальних ресурсів, даних або формальних підстав недостатньо, статус має бути ⊥. Невизначеність **не можна** автоматично трактувати як хибність або істину.

**Правило 20.6 (промоція та демоція).** Зміна статусу можлива лише за наявності нового артефакту:

| Перехід | Що потрібно |
|---|---|
| ❓ → ✅ | Повний доказ |
| ❓ → ❌ | Контрприклад |
| ⚠️ → ✅ | Усунення додаткових передумов |
| ✅ → ❌ | Виявлення помилки в доказі + контрприклад |
| 📊 → ❌ | Суперечливі дані за тим самим критерієм |
| ⊥ → будь-що | Поява ресурсів/даних/доказів |

**Правило 20.7 (успадкування).** Якщо A має статус ✅ і A ⟹ B, то B може отримати статус ✅ лише після повного доказу B. Імплікація не переносить статус автоматично.

### 20.4. Відношення до чотирьох значень Белнапа

**Застереження 20.1.** Шість статусів доказовості **не слід** ототожнювати з чотирма значеннями Белнапа T, F, B, N з §1.

| Поняття | Область |
|---|---|
| T, F, B, N | Логічне/інформаційне значення стану в білаттисі |
| ✅, ⚠️, ❌, ❓, 📊, ⊥ | Епістемічний статус твердження про SUBIT |

Це різні рівні: перше — внутрішньо-логічне, друге — метатеоретичне. Їхнє поєднання (наприклад, «твердження зі статусом ✅ про стан зі значенням B») можливе, але вимагає окремої формальної семантики, якої v6.0 не вводить.

### 20.5. Формат STATUS.md

**Означення 20.2.** Кожне твердження в STATUS.md має таку структуру:

```json
{
  "id": "6.1",
  "statement": "Ω взаємовиключний і вичерпний",
  "status": "✅",
  "source": "§6 v5.2",
  "dependencies": ["4.1"],
  "premises": [],
  "proof_artifact": "proofs/Subit/Omega.lean#Theorem_6_1",
  "counterexample": null,
  "notes": ""
}
```

Поля `premises`, `proof_artifact`, `counterexample` заповнюються обов'язково відповідно до статусу.
