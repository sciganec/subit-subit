## 0. Резюме релізу

SUBIT v6.0 — перший реліз, який замінює «нашарування рівнів» v5.2 на **перевірюване ядро**. Кожне твердження специфікації має явний статус доказовості. Кожен рівень ієрархії має реалізацію, тести та (де можливо) машинно перевірений доказ.

**Ключові зміни v5.2 → v6.0:**

| Область | v5.2 | v6.0 |
|---|---|---|
| Реєстр статусів тверджень | відсутній | §20, STATUS.md |
| Функція P(τ) | хибно передбачала `m(ŝ₀) < ∞` | виправлено (§18), три типи Attainment |
| Топологія ℛ | відсутня | §21, два класи ℛ₀ / ℛ₁ |
| Класифікатор Ω | 4 значення для множин | Ω_set / Ω_state / Ω_traj (§6, §18.7) |
| Proto-topos | заявлено | понижено до Ω-класифікованої категорії (§9) |

| Докази | відсутні | 7 із 10 теорем у Lean 4 (§Додаток B) |
| Еталонна реалізація | відсутня | `subit-core`, `subit-infinity` |
| Емпіричний протокол | загальний | пілот-01 з критеріями спростування (§Додаток C) |
| Число ❌-тверджень | невідомо | 0 |
| Число ✅-тверджень | — | 61 із 71 (86%) |

**Мета релізу.** Дати досліднику, інженеру або математику повний, самодостатній, незалежно перевірюваний опис SUBIT — від 64-станівного алфавіту до емпіричного протоколу.

## 4. §18 v6.0 — Канонічна побудова P(τ) (повний текст)

*(Включено повністю, бо це найважливіша зміна v5.2 → v6.0.)*

### 18.1. Постановка задачі

Означення 6.1 (Ω для множин) і Означення 15.1 (метрика d_Ω) залишають незамкненою передумову: як від траєкторії τ(ŝ₀) перейти до об'єкта, який класифікує Ω. Потрібна функція

```
P : Траєкторії(S_∞ × ℛ) → Класифіковані об'єкти ∪ {⊥}
```

що задовольняє чотири вимоги:

- **(У0, неколапс)** — P(τ) не повинна апріорно визначати Ω-клас.
- **(У1, узгодженість)** — на скінченному рівні відтворює типологію Твердження 5.1.
- **(У2, інваріантність)** — не залежить від довільних параметрів спостереження.
- **(У3, явність відмови)** — випадок нелокалізованої асимптотичної поведінки позначається явно (⊥).

### 18.2. Незалежна від Ω топологія на S_∞

```
d_S(s, t) := 2^(−δ(s,t))
```

де δ(s, t) — найменша глибина розходження піддерев.

**Твердження 18.1.** d_S — ультраметрика; (S_∞, d_S) — компактний простір.

### 18.3. Топологія простору правил ℛ

**Означення 18.1 (причинна функція).** f : S_∞ → S_∞ причинна, якщо

```
∀s, t:  δ(s, t) ≥ n  ⟹  δ(f(s), f(t)) ≥ n
```

**Означення 18.2.** ℛ₀ := { f : S_∞ → S_∞ \| f причинна }.
**Означення 18.3.** ℛ₁ := { f : S_∞ → S_∞ \| f обчислювана }.

**Теорема 18.2.** ℛ₀ компактний (Lean T6 ✅).

**Наслідок 18.1.** S_∞ × ℛ₀ компактний.

### 18.4. ω-границя

**Означення 18.4.** ω(ŝ₀) := множина точок накопичення траєкторії.

**Твердження 18.3.** ω(ŝ₀) ≠ ∅ для ℛ₀ (Lean T7 ⚠️).

**Твердження 18.4.** F(ω) = ω для неперервного F (Lean T8 ⚠️).

### 18.5. Чому P(τ) := ω(ŝ₀) — неправильна відповідь

**Твердження 18.5 (колапс).** Якщо P(τ) := ω(ŝ₀), то Ω(P(τ)) = STABLE завжди.

### 18.6. Три типи досягнення

**Означення 18.5.** Нехай ω := ω(ŝ₀).

- **(A) ATTAINED** — ∃n: ŝₙ ∈ ω.
- **(B) ASYMPTOTIC** — ∀n: ŝₙ ∉ ω, але dist(ŝₙ, ω) → 0.
- **(C) INDETERMINATE** — ω = ∅, або dist не прямує до 0, або ресурсів бракує.

### 18.7. Двоосьова класифікація

**Означення 18.6.** S-компонента:

| S(τ) | Умова |
|---|---|
| STABLE | ω = {p}, F(p) = p |
| CYCLIC | ω — скінченна орбіта довжини k > 1 |
| METASTABLE | ω ⊊ closure(τ), F(ω) = ω |
| CHAOTIC | ω нескінченна, мінімальна, з додатною топологічною ентропією |

**Означення 18.7.** Ω_traj(τ) := (S(τ), Att(τ)).

### 18.8. Перевірка вимог

**Твердження 18.6 (У0).** Існують траєкторії з різними Ω_traj (Lean T9 ✅).
**Твердження 18.7 (У1).** Узгодженість зі скінченним рівнем.
**Твердження 18.8 (У2).** Інваріантність.
**Твердження 18.9 (У3).** Явність відмови.

### 18.9. Сертифікат класифікації

JSON-схема з полями: `trajectory_hash`, `s_component`, `att_type`, `witness`, `omega_set`, `core_version`, `rule_class`.

### 18.10. Наслідок для протоколу застосування

- **Крок 0 (кодування)** — обґрунтування розбиття.
- **Крок 0' (причинність)** — перевірка, що ρ ∈ ℛ₀.

## 5. §20 v6.0 — Статуси доказовості (повний текст)

### 20.1. Шість статусів

| Позначка | Назва | Значення |
|---|---|---|
| ✅ | Доведено | Повний доказ із явними передумовами |
| ⚠️ | Доведено умовно / структурно | Доведено за припущень або структурно |
| ❌ | Спростовано | Є контрприклад |
| ❓ | Гіпотеза | Ні доведено, ні спростовано |
| 📊 | Емпірично підтримано | Узгоджується з даними за фіксованим критерієм |
| ⊥ | Невизначено | Недостатньо підстав |

### 20.2. Правила використання

1. **Заборона аксіоматизації:** ❓ або ⊥ не можна використовувати як аксіому.
2. **Обов'язковість передумов:** ⚠️ супроводжується явним списком.
3. **Заборона змішування:** ❌ ≠ ❓.
4. **Заборона підміни:** 📊 ≠ ✅.
5. **Обов'язковість ⊥:** невизначеність не можна трактувати як хибність.
6. **Промоція/демоція:** зміна статусу вимагає нового артефакту.

### 20.3. Відношення до Белнапа

Шість статусів доказовості **не ототожнюються** з чотирма значеннями Белнапа. Перше — метатеоретичне, друге — внутрішньо-логічне.

## 8. Додаток C. Емпіричний протокол пілота-01

### 8.1. Крок 0

Розбиття: quantile bins на трійці (log x, Δlog x, Δ²log x).
Альтернативні розбиття: 2, 4, 8 бінів.

**Застереження:** результат класифікації може бути артефактом кодування. Перевіряється стійкістю Ω_traj між розбиттями.

### 8.2. Крок 0'

Усі три правила ρ₁, ρ₂, ρ₃ ∈ ℛ₀ на скінченному S₀. F неперервний автоматично. **Крок 0' пройдено без застережень.**

### 8.3. Гіпотези

| Гіпотеза | Правило | Передбачення |
|---|---|---|
| H₁ | identity | Ω_traj = (STABLE, ATTAINED) |
| H₂ | cycle successor | Ω_traj = (CYCLIC, ATTAINED), cycle = 4 |
| H₃ | empirical table | обчислюється |

### 8.4. Критерій спростування (заздалегідь)

Пілот **провалюється**, якщо:
1. Ω_traj для H₁, H₂, H₃ не відрізняються.
2. Ω_traj нестійкий між розбиттями.
3. Baseline дають той самий поділ.

Пілот **успішний**, якщо:
- Ω_traj(H₁) ≠ Ω_traj(H₂);
- стійкість ≥ 2 із 3 розбиттів;
- baseline не дають того самого поділу.

## 12. Центральна теза v6.0

> Правило належить стану. Істина визначається стабільністю F(P) = P. Відстань між траєкторіями вимірюється горизонтом першої розбіжності. Категорія — Ω-класифікована. Простір станів — дерево з мітками. Класифікатор Ω застосовується не до траєкторії безпосередньо, а до канонічно побудованої множини P(τ).

> Формальна коректність нотації не переносить емпіричного змісту на конкретну систему: висновок «це stable» чи «це chaotic» завжди залишається інтерпретаційним кроком дослідника і починається з явного обґрунтування кодування (Крок 0).
