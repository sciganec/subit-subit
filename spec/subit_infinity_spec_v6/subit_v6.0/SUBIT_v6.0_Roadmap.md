# SUBIT v6.0 — Roadmap

**Від формальної специфікації до перевірюваної обчислювальної теорії**

Цей roadmap враховує результати Conformance Audit (Частина 1) і замінює загальну дорожню карту з файлу v5.2 → v6.0 конкретним планом робіт. Кожен етап має явний вхід, вихід, критерій завершення та залежності.

---

## 0. Принципи планування

| Принцип | Наслідок для плану |
|---|---|
| **Ніяких нових рівнів, поки не закрито старі** | SUBIT-128/256 не розглядаються до завершення Фази 3 |
| **Статус кожного твердження явний** | ✅ / ⚠️ / ❌ / ❓ / 📊 / ⊥ — обов'язковий атрибут |
| **Код не випереджає математику** | ENGINE стартує лише після FORMAL-аудиту ✅-ядра |
| **Емпірія не випереджає код** | EMPIRICAL стартує лише після релізу SUBIT-CORE v1.0 |
| **Кожен етап має сертифікат** | Артефакт, який можна перевірити незалежно |

### 2.1. Мета
Побудувати **SUBIT-CORE v1.0** — виконуване скінченне ядро, яке точно відповідає ✅-твердженням v6.0.

### 2.2. Обсяг (тільки ✅-твердження)

| Модуль | Що реалізує | Джерело |
|---|---|---|
| `alphabet` | 4 примітиви, біграми, гексаграми | §1–2 |

| `rule` | скінченна ℛ, f_ρ : S₀ → S₀ | §3 |
| `evolution` | F(s, ρ) = (f_ρ(s), g(ρ, s)) | §4 |

| `omega` | Ω_set, Ω_state, Ω_traj | §6, §6.3, §22 |
| `lattice` | ∧, ∨, ¬ на Ω (алгебра Гейтінга) | §7 |

### 2.3. Що **не** входить у v1.0
- S_∞ (нескінченні дерева) — Фаза 4.
- d_ω, d_S — Фаза 4 (потребують S_∞).
- Категоріальні експоненціали — Фаза 4.
- Універсальний об'єкт U — Фаза 4.

### 2.4. Deliverables
- **D2.1** Бібліотека `subit-core` з публічним API.
- **D2.2** **Нормативні тестові вектори** (≥ 100): для кожного стану, правила, траєкторії — очікуваний результат.
- **D2.3** **Інваріанти** — машинно перевірювані:
  - тотальність F;
  - замкненість S₀ × ℛ;

  - узгодженість Ω_set / Ω_state (Твердження 4.1);

### 2.5. Критерій завершення
- Два незалежні розробники, реалізуючи специфікацію, отримують **однакові результати** на тестових векторах (вимога відтворюваності з файлу v5.2→v6.0).
- Усі інваріанти проходять у CI.
- Покриття тестами ≥ 90%.

## Фаза 4. INFINITY — розширення на S_∞ (2–3 ітерації)

### 4.1. Мета
Перенести CORE на нескінченний простір S_∞ з коректною топологією.

### 4.2. Робочі пакети

| ID | Пакет | Вихід |
|---|---|---|
| **WP4.1** | Реалізація S_∞ як коалгебри | `subit-infinity` модуль |
| **WP4.2** | Клас ℛ_0 (причинні функції) | компактний простір правил |
| **WP4.3** | Клас ℛ_1 (обчислювані) | з явною межею неперервності |
| **WP4.4** | Метрики d_S, d_ω | ультраметрики на S_∞ |
| **WP4.5** | Функція P(τ) з §2 аудиту | двоосьова класифікація |
| **WP4.6** | ω-границя, m(ŝ₀), Att(τ) | виявлення типу досягнення |
| **WP4.7** | Категорія на S_∞ | перенесення §8 |
| **WP4.8** | Універсальний об'єкт U | ескіз |

### 4.3. Ключовий тест
На траєкторії `x_n = 1/(n+1)`:
- ω = {0} ✅
- m(ŝ₀) **не існує** — коректно повертається `Att = ASYMPTOTIC`
- Ω_traj = (STABLE, ASYMPTOTIC) — не колапсує в константу

### 4.4. Deliverables
- **D4.1** Бібліотека `subit-infinity`.
- **D4.2** Тестові вектори для S_∞ (≥ 50).
- **D4.3** Демонстрація неколапсу Ω_traj на ≥ 4 класах.

### 4.5. Критерій завершення
CHAOTIC реалізується на конкретній траєкторії в S_∞ × ℛ_1; сертифікат містить доказ хаотичності.

## Фаза 5. EMPIRICAL — пілотне дослідження (1–2 ітерації)

### 5.1. Мета
Показати, що SUBIT дає **розрізнювальні передбачення** на реальних даних.

### 5.2. Вибір системи
Одна з трьох (за спаданням простоти):
1. **Нейронні часові ряди** (LFP, spike trains) — природне дискретне кодування.
2. **Екологічні популяційні ряди** — природний WHO/WHERE/WHEN.
3. **Фінансові часові ряди** — вимагає явного Кроку 0.

### 5.3. Протокол (за §19 v6.0)

| Крок | Дія | Артефакт |
|---|---|---|
| **0** | Обґрунтувати розбиття неперервного простору на A | `encoding.md` |
| **0'** | Перевірити причинність обраних ρ (належність ℛ_0) | `causality-check.md` |
| **1** | Визначити систему й питання | `question.md` |
| **2** | Сформулювати конкуруючі ρ₁, ρ₂, … | `hypotheses.md` |
| **3** | Вивести розрізнювальні передбачення | `predictions.md` |
| **4** | Зібрати дані, перевірити передбачення | `results.md` |
| **5** | Присвоїти Ω_traj-клас (після кроку 4) | `classification.json` |
| **6** | Розрізнити формальне / емпіричне / інтерпретаційне | `conclusion.md` |

### 5.4. Контрольні умови
- **Базова модель** — принаймні одна простіша (ARIMA, Markov chain, тощо).
- **Тест чутливості** — Ω_traj при трьох різних розбиттях (грубе / середнє / тонке).
- **Тест спростування** — заздалегідь визначений критерій, за якого гіпотеза відкидається.

### 5.5. Deliverables
- **D5.1** Звіт про пілот (відтворюваний, з кодом).
- **D5.2** Таблиця: SUBIT vs базові моделі за фіксованими метриками.
- **D5.3** Аналіз чутливості до Кроку 0.

### 5.6. Критерій завершення
Або SUBIT показує статистично значущу перевагу, або результат негативний і задокументований. **Негативний результат — теж валідний вихід фази.**

## Зведена діаграма залежностей

```
Фаза 0 (Підготовка)
   │
   ▼
Фаза 1 (FORMAL) ──► виправлена математика
   │
   ▼
Фаза 2 (CORE) ──► скінченне ядро + тести
   │
   ├──► Фаза 3 (PROOFS) ──► формальні докази
   │
   ▼
Фаза 4 (INFINITY) ──► S_∞ + P(τ)
   │
   ▼
Фаза 5 (EMPIRICAL) ──► пілот
   │
   ▼
Фаза 6 (RELEASE) ──► SUBIT v6.0
```

**Правило:** фаза N+1 не стартує, поки фаза N не має закритого критерію завершення. Це — головна відмінність від v5.2, де рівні нашаровувалися без перевірки.
