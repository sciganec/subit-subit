# SUBIT-∞: огляд специфікації v6.11.8

Oct 15, 2026 · @Slavick

## Мотивація

Специфікація SUBIT-∞ (редакція v6.11.8) описує скінченні й нескінченні дискретні динамічні системи над чотиризначним алфавітом. Мета — точна класифікація траєкторій: для кожного класу задано означення, умови й, де це можливо, доведення.

Алфавіт має чотири значення T, B, F, N. Кожне є парою бітів, а координати «хто», «де», «коли» задають позицію в таблиці §1. Порядки істинності й інформації взято з білаттисів Белнапа. Динаміка на них автоматично не переноситься.

Специфікація свідомо розрізняє пари понять, які легко сплутати: стан і траєкторію, нерухому точку і цикл, причинність і обчислюваність (§0.3). Редакція не рецензована, а її формальна перевірка часткова (§0.1).

## Структура

Специфікація будується як ланцюг рівнів, кожен наступний розширює попередній (§0.4):

1. SUBIT-64: алфавіт і скінченний простір станів S₀ = A³ з 64 станами.
2. SUBIT⁺: скінченна динаміка з правилом у стані.
3. SUBIT-CAT: категорія скінченних об'єктів.
4. SUBIT-∞: простір Tree∞ і нескінченні траєкторії.

Зв'язок «ₓ» не гарантує ін'єкцій множин чи вкладень категорій.

| § | Зміст |
| :-- | :-- |
| 1 | Алфавіт A і простір S₀ |
| 2 | SUBIT⁺: скінченна динаміка з правилом у стані |
| 3 | Точкова класифікація траєкторій |
| 4 | Класифікатор множин Classify⁺: OrbitType, InclusionType, ChaosStatus, Min |
| 5 | Алгебра Ω і проєкція π\_Ω |
| 6 | Модальна логіка і динамічна теорія типів |
| 7 | Категорія SUBIT |
| 8 | Dyn як категорія динамічних систем |
| 9 | Простір S∞ = Tree∞ і метрика d\_S |
| 10 | Правила ℛ₀ і ℛ₁, припущення (H), метрики |
| 11 | Класифікація траєкторій: ω-границя, шість класів, d\_Ω\_traj |
| 12–13 | Конформність і Pilot-01 |
| 14 | Протокол змін |
| А–Ж | Гексаграми, план Lean, відкриті питання, журнал, реєстр тверджень, Lean, Rust |

## Основні об'єкти

Динаміка — відображення D на компактному просторі. Траєкторія x має ω-границю ω(x) = ⋂\_N cl{Dⁿ x : n ≥ N}. Непорожність, компактність і D\[ω(x)\] = ω(x) доведено у Lean (D1).

Шість класів траєкторій розрізняються трьома ознаками: розмір ω, мінімальність і ентропія h\_top (§11).

| Клас | Розмір ω | Мінімальність | Ентропія h\_top |
| :-- | :-- | :-- | :-- |
| FIXED | одна точка | так | 0 |
| PERIODIC | скінченна, більше однієї | так | 0 |
| MIN\_ZERO | нескінченна | так | 0 |
| MIN\_POS | нескінченна | так | > 0 |
| NONMIN\_ZERO | нескінченна | ні | 0 |
| NONMIN\_POS | нескінченна | ні | > 0 |

Для скінченних систем лишаються FIXED і PERIODIC: ентропія дорівнює 0 (C7).

Для множин P задано чотиривимірний класифікатор Classify⁺ (§4.5): OrbitType (§4.1), InclusionType з п'ятьма значеннями (§4.2), ChaosStatus і Min (§4.3). ChaosStatus має значення NOT\_APPLICABLE, що не синонімічне NON\_CHAOTIC (застереження 4.3.2).

На 12 кодах чотверок (розмір, Min, ентропія, Att) задано метрику Геммінга d\_Ω\_traj (§11.3).

## Скінченний і нескінченний рівні

Скінченний рівень працює зі станами й точними траєкторіями скінченних систем (див. Додаток Ж). Нескінченний рівень — це простір Tree∞ деревоподібних розміток (§9). Точні перевірки доступні лише для тих об'єктів, де їх можна обчислити.

| Об'єкт | Що перевірено | Де |
| :-- | :-- | :-- |
| Tree∞ (загальний) | компактність; ультраметричність d\_S; база околиць кулами; цілковита обмеженість і повнота | Lean: `Tree`, `TreeMetric` |
| Регулярні дерева (скінченні автомати) | T1–T4 на досяжних станах; d\_S = 2^(−r) через перебір пар станів | Rust: `inf::regular` |
| Одометр на Z₂ | ω — весь простір на кожній глибині; сюр'єктивність mod 2^d | Rust: `inf::odometer` |
| Одометр, ентропія | h\_top = 0 береться з теореми про еквінерсивність; не обчислено | не перевірено в коді |

Не реалізовано: загальні нескінченні дерева, ентропія довільних нескінченних систем, свідки W1–W7. Відповідні твердження присутні лише в тексті специфікації.

## Формальна перевірка

Дві частини: формальне доведення у Lean 4.32.0 (Mathlib v4.32.0) і програмна перевірка у Rust. Кожна має свої межі.

| Частина | Інструмент | Що перевірено | Статус |
| :-- | :-- | :-- | :-- |
| Топологічний блок: D1, D6, T3–T5, лема E | Lean + Mathlib | ω-границя, шість класів, Tree∞, абстракція леми E | перевірено, без sorry |
| Дискретний залишок: C3, C4a, Гейтінг на Ω, χ\_U, гексаграми, P3/P3′, K4 | Lean | підмножинна модель категорій, K2–K5 | перевірено, без sorry |
| Скінчений рівень: A1–A3, P1–P3′, C1–C3, M1, M3, K1–K3, Додаток А | Rust, 47 тестів | тести на станах специфікації і переборі малих систем; не доведення | тестовано частково |
| Min і C3(a), C3(c) для скінченних систем | Rust | вичерпно для n ≤ 4 | тестовано |
| Нескінченний рівень: регулярні дерева, одометр | Rust | точні об'єкти, без загального випадку | тестовано частково |
| Незалежне рецензування Lean-формулювань | — | — | не виконано |

Усі доведені теореми залежать лише від propext, Classical.choice та Quot.sound. Замітка: Lean-перевірку виконав автор з асистентом; незалежної перевірки формулювань не було. Rust-тести написані тим самим автором, що і текст, і вони не є незалежним доведенням.

## Статус тверджень

Редакція «стабільна» означає заморожений текст, а не перевірений текст. Прапорці з §0.1 станом на 6.11.8:

| Прапорець | Стан | Що означає |
| :-- | :-- | :-- |
| DEFINED | так | об'єкти задані явно |
| PROVED ON PAPER | так, лише для DP-f | доведення виписані, але не рецензовані |
| LEAN-CHECKED | частково | лише твердження з Додатку Е |
| RUST-TESTED | частково | 47 тестів та Pilot-01; без загального нескінченного рівня |
| BUILD-PASSED | ні | прапорець стосується всієї специфікації, не окремого крейта |
| AUDITED BY EXECUTION | ні | незалежний аудит не проведено |
| IMPLEMENTED (conformant) | ні | §12 має незакриті пункти |
| EMPIRICALLY SUPPORTED | ні | емпіричних даних про реальні системи немає |

Статус DP-s (схема доведення або посилання на стандартний результат) не є доведенням на папері. Підвищення статусу (DP-s → DP-f, доведено → доведено) дозволене лише після незалежного рецензування або успішної компіляції у Lean (§14).

## Відтворення і джерела

Щоб одержати ті самі результати:

1. Lean: розпакувати `subit-lean-mathlib.tar.gz`, у каталозі `pm` виконати `lake build` (Lean 4.32.0, Mathlib v4.32.0). Збірка без попереджень і без `sorry`.
