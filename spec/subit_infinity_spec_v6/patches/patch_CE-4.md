CE-3 зробив правильний крок — розвів означення і ввів реєстр. Але **його власні докази мають помилки**, які аудит виявив. CE-4 **не змінює архітектуру** SUBIT-∞ і **не переглядає CE-3 у цілому**. Він:

3. Знижує до ⚠️ ті твердження CE-3, чиї докази ще не завершені.
4. Додає реєстр обов'язків доведення (proof obligations).

## CE-4.1. Metric and Causality (K-01)

### Діагноз

У CE-3.1.4 наведено еквівалентність метричної та префіксної причинності. Доведення містить помилку на одиницю в індексації: твердження `δ(s, t) ≥ n ⟹ p_n(s) = p_n(t)` **не виконується** для узгодженої раніше формули `δ(s, t) := min{n : p_n(s) ≠ p_n(t)}`.

**Контрприклад.** Нехай `s, t` розрізняються на глибині `n`: `p_n(s) ≠ p_n(t)`. Тоді `δ(s, t) = n`. За формулюванням CE-3 `δ ≥ n` виконується, але `p_n(s) ≠ p_n(t)`. Отже, імплікація хибна.

### Виправлення

**Означення CE-4.1.1 (нормативна метрика, узгоджена індексація).**

Для `s, t ∈ S_∞`:

```
δ(s, t) := ∞                                     якщо s = t
δ(s, t) := max{ n ≥ 0 : p_n(s) = p_n(t) }        якщо s ≠ t
```

де `p_n : S_∞ → T_n` — проєкція (CE-3.3.7). Іншими словами, `δ(s, t)` — найбільша глибина, на якій `s` і `t` збігаються.

**Метрика:**

```
d_S(s, t) := 2^{−δ(s, t)}        якщо δ(s, t) < ∞
d_S(s, t) := 0                    якщо δ(s, t) = ∞  (тобто s = t)
```

**Застереження CE-4.1.2.** Це еквівалентно `δ'(s,t) := min{n : p_n(s) ≠ p_n(t)}` лише за конвенції `δ(s,t) = δ'(s,t)` для `s ≠ t` і `δ(s,s) = ∞`. Різниця — в індексації множини збігу. Обрана конвенція (`max` збігу) дає чисту відповідність з проєкціями.

**Лема CE-4.1.3 (ключова тотожність).** Для всіх `n ∈ ℕ`:

```
δ(s, t) ≥ n  ⟺  p_n(s) = p_n(t)
```

*Доведення.*

(⟹) Якщо `δ(s, t) ≥ n` і `s ≠ t`, то `max{k : p_k(s) = p_k(t)} ≥ n`, отже `p_n(s) = p_n(t)`.

(⟸) Якщо `p_n(s) = p_n(t)`, то `n` належить множині `{k : p_k(s) = p_k(t)}`, отже `max` цієї множини `≥ n`. ∎

**PROVED ON PAPER.**

**Означення CE-4.1.4 (причинність, префіксна форма).**

```
f причинна  ⟺  ∀n ≥ 0, ∀s, t ∈ S_∞:
                 p_n(s) = p_n(t) ⟹ p_n(f(s)) = p_n(f(t))
```

**Означення CE-4.1.5 (причинність, метрична форма).**

```
f причинна  ⟺  ∀s, t ∈ S_∞:  d_S(f(s), f(t)) ≤ d_S(s, t)
```

**Твердження CE-4.1.6 (еквівалентність).** Означення CE-4.1.4 і CE-4.1.5 еквівалентні.

*Доведення.*

**(CE-4.1.4 ⟹ CE-4.1.5).** Нехай `f` задовольняє CE-4.1.4, `s, t ∈ S_∞`. Треба: `d_S(f(s), f(t)) ≤ d_S(s, t)`.

- Якщо `s = t`: тривіально.
- Якщо `s ≠ t`: нехай `N := δ(s, t)`. За CE-4.1.3, `p_N(s) = p_N(t)`, отже `p_N(f(s)) = p_N(f(t))`, отже `δ(f(s), f(t)) ≥ N = δ(s, t)`. Тому `d_S(f(s), f(t)) ≤ d_S(s, t)`.

**(CE-4.1.5 ⟹ CE-4.1.4).** Нехай `f` задовольняє CE-4.1.5, `p_n(s) = p_n(t)`. За CE-4.1.3, `δ(s, t) ≥ n`. З метричної умови: `δ(f(s), f(t)) ≥ δ(s, t) ≥ n`. Знову за CE-4.1.3: `p_n(f(s)) = p_n(f(t))`. ∎

**PROVED ON PAPER.**

**Наслідок CE-4.1.7.** Твердження CE-3.1.4 (яке мало помилку на одиницю) **відкликано**. Його замінює CE-4.1.6.

**Наслідок CE-4.1.8 (для §21.1.2).** `ℛ₀ ≅ {причинні функції}` — ДОВЕДЕНО НА ПАПЕРІ за CE-4.1.6 (раніше — ⚠️).

## CE-4.2. Finite Dynamical Metric (K-04)

### Діагноз

У CE-3.4.2 стверджувалося: `d_finite` — ультраметрика за умови NF3'. Але:

- `d_finite(x,y) := sup_n 2^{-n} d̂(F^n x, F^n y)`;
- ультраметричність `d_finite` випливає з ультраметричності `d̂`, а не з NF3';
- CE-3.4 не зафіксував ультраметричність `d̂` як **явну передумову**.

**Контрприклад (аудит).** Якщо `d̂` — звичайна метрика, `d_finite` може не бути ультраметрикою.

### Виправлення

**Означення CE-4.2.1 (d̂).**

```
d̂((s, ρ), (t, σ)) := max( d_S(s, t), d_ℛ(ρ, σ) )
```

**Твердження CE-4.2.2 (ультраметричність d̂).** `d̂` — ультраметрика на `S_∞ × ℛ₀`.

*Доведення.*

1. `d_S` — ультраметрика (CE-4.1.1 і стандартне доведення ультраметричності префіксної метрики).
2. `d_ℛ` — ультраметрика (за означенням `2^{-n_0}`, де `n_0` — перший індекс розбіжності).
3. `max` двох ультраметрик — ультраметрика: для `x, y, z`:
   ```
   max(d_1, d_2)(x, z) = max(d_1(x, z), d_2(x, z))
                       ≤ max(max(d_1(x, y), d_1(y, z)), max(d_2(x, y), d_2(y, z)))
                       = max( max(d_1, d_2)(x, y), max(d_1, d_2)(y, z) )
   ```
   ∎

**PROVED ON PAPER.**

**Твердження CE-4.2.3 (ультраметричність d_finite).**

**Передумови:**
1. `d̂` — ультраметрика (CE-4.2.2);
2. `F : S_∞ × ℛ₀ → S_∞ × ℛ₀` з NF3' (`g(ρ, s) ∈ ℛ₀`), отже `F^n(ŝ) ∈ S_∞ × ℛ₀` для всіх `n`.

**Твердження.** `d_finite(ŝ, t̂) := sup_{n ≥ 0} 2^{-n} · d̂(F^n(ŝ), F^n(t̂))` — ультраметрика на `S_∞ × ℛ₀`.

*Доведення.*

**Крок 1.** Для кожного фіксованого `n`: `d_n(ŝ, t̂) := 2^{-n} · d̂(F^n ŝ, F^n t̂)`. `F^n` — детерміноване, `d̂` — ультраметрика, тому `d_n` — ультрапсевдометрика.

**Крок 2.** Супремум сімейства ультрапсевдометрик — ультрапсевдометрика.

Перевірка: для фіксованого `n`: `d_n(ŝ, û) ≤ max(d_n(ŝ, t̂), d_n(t̂, û))`. Супремум по `n`:
```
sup_n d_n(ŝ, û) ≤ sup_n max(d_n(ŝ, t̂), d_n(t̂, û)) = max(sup_n d_n(ŝ, t̂), sup_n d_n(t̂, û))
```

**Крок 3.** Розрізнення точок. Член при `n = 0` дає `d_finite(ŝ, t̂) ≥ d̂(ŝ, t̂)`. Якщо `d_finite(ŝ, t̂) = 0`, то `d̂(ŝ, t̂) = 0`, отже `ŝ = t̂` (бо `d̂` — метрика).

**Крок 4.** Симетрія — тривіально.

Отже, `d_finite` — ультраметрика. ∎

**PROVED ON PAPER.**

**Застереження CE-4.2.4.** Умова NF3' потрібна **не для ультраметричності**, а для **визначеності** `d_finite` (щоб `F^n(ŝ) ∈ S_∞ × ℛ₀` для всіх `n`). У CE-3.4.2 ці дві умови були змішані.

**Наслідок CE-4.2.5.** Якщо `d̂` — **звичайна метрика** (не ультраметрика), твердження CE-4.2.3 не виконується. У SUBIT `d̂` — ультраметрика за побудовою (§15.1.3 і CE-4.2.2), тому вибір `d̂` узгоджений.

**Виправлення:** §15.2.3 переформульовано як `d_finite` — ультраметрика за передумов CE-4.2.3.

## CE-4.3. Inverse-Limit Reconstruction (K-14)

### Діагноз

У CE-3.14.1 крок 1 використовує `state(σ) := t_{|σ|+1}(σ)`, але це визначено лише для позицій `σ`, які **існують** в `t_{|σ|+1}`. Якщо предок σ є листком на глибині `j < |σ|`, позиція σ у дереві `t_{|σ|+1}` не існує, і `t_{|σ|+1}(σ)` не визначене.

### Виправлення

**Означення CE-4.3.1 (позиція).**

`σ ∈ {1, 2, 3}^{<ω}`. `σ` існує в `t ∈ T_n`, якщо `|σ| ≤ n` і всі строгі префікси σ (у позиції глибини `< |σ|`) є внутрішніми вузлами t.

**Означення CE-4.3.2 (частковий state).** Для `(t_n) ∈ lim←(T_n, q_n)` і позиції σ:

```
state(σ) := t_{|σ|+1}(σ)        якщо σ існує в t_{|σ|+1}
state(σ) := ⊥ (позначка невизначеності)   інакше
```

**Застереження CE-4.3.3.** Позначка ⊥ **не плутається** з ⊥-листком із `T_n`; це окремий символ, що означає «позиція не існує».

**Лема CE-4.3.4 (стабілізація для існуючих позицій).** Якщо σ існує в `t_{|σ|+1}`, то:

1. σ існує в `t_n` для всіх `n ≥ |σ| + 1`;
2. `t_n(σ) = t_{n+1}(σ)` для всіх `n ≥ |σ| + 1`;
3. `state(σ) ∈ {leaf(a) : a ∈ A} ∪ {internal}`.

*Доведення.*

**(1)** Усічення `q_n : T_{n+1} → T_n` не зачіпає позиції з глибиною `< n`. Якщо σ існує в `t_n` і `|σ| < n`, то σ існує в `t_{n+1}`. Індукція.

**(2)** Усічення не змінює позицію σ (|σ| < n).

**(3)** `|σ| < |σ| + 1`, отже позиція σ не на фронтирному рівні `|σ| + 1` — там лише ⊥-листки. Тому `t_{|σ|+1}(σ) ≠ ⊥`, отже `state(σ) ∈ {leaf(a), internal}`. ∎

**PROVED ON PAPER.**

**Означення CE-4.3.5 (коалгебра lim←).**

```
out_← : lim←(T_n, q_n) → A ⊔ (lim←(T_n, q_n))³

out_←((t_n)) :=
   a ∈ A                        якщо state(∅) = leaf(a)
   (u^{(1)}, u^{(2)}, u^{(3)})   якщо state(∅) = internal
```

де `u_m^{(i)} := (t_{m+1})|_i` — піддерево `t_{m+1}` на позиції `i` (коректно визначене, бо `state(∅) = internal` тягне `t_{m+1}(∅) = internal` для всіх m ≥ 0).

**Лема CE-4.3.6 (коректність out_←).**

1. `state(∅) ∈ {leaf(a) : a ∈ A} ∪ {internal}` (з CE-4.3.4(3), бо ∅ існує в `t_1`).
2. Для гілки `internal`: `u^{(i)} ∈ lim←(T_m, q_m)`.

*Доведення (2).* Треба: `q_m(u_{m+1}^{(i)}) = u_m^{(i)}`.

Для `t_{m+2}` з `t_{m+2}(∅) = internal`:
`t_{m+2} = node(v_1, v_2, v_3)` з `v_j ∈ T_{m+1}`.

За сумісністю: `t_{m+1} = q_{m+1}(t_{m+2}) = node(q_m(v_1), q_m(v_2), q_m(v_3))`.

Отже, `(t_{m+1})|_i = q_m(v_i) = q_m((t_{m+2})|_i)`, тобто `q_m(u_{m+1}^{(i)}) = u_m^{(i)}`. ∎

**PROVED ON PAPER.**

**Означення CE-4.3.7 (реконструкція s).** За фінальністю `S_∞` існує єдиний морфізм коалгебр `s : (lim←, out_←) → (S_∞, out)`.

**Твердження CE-4.3.8 (p_n(s(t)) = t_n).** Для всіх `n ∈ ℕ` і `t ∈ lim←`: `p_n(s(t)) = t_n`.

*Доведення (індукція за n з універсальною гіпотезою IH(n)).*

**IH(n):** `∀u ∈ lim←: p_n(s(u)) = u_n`.

**База n = 0.**

- Якщо `state(∅) = leaf(a)`: `out(s(t)) = a`, отже `s(t) = leaf(a)`, `p_0(s(t)) = leaf(a)`. З іншого боку, `t_1(∅) = state(∅) = leaf(a)`, отже `t_0 = q_0(t_1) = q_0(leaf(a)) = leaf(a)`. ✓
- Якщо `state(∅) = internal`: `out(s(t)) = (s(u^{(1)}), s(u^{(2)}), s(u^{(3)}))`, отже `s(t) = node(...)`, `p_0(s(t)) = ⊥`. З іншого боку, `t_1(∅) = internal`, `t_1 = node(...)`, `t_0 = q_0(t_1) = ⊥`. ✓

**Крок n → n+1.**

- Якщо `state(∅) = leaf(a)`: `s(t) = leaf(a)`, `p_{n+1}(s(t)) = leaf(a)`. Стабілізація: `t_m(∅) = leaf(a)` для всіх m ≥ 1, зокрема `t_{n+1} = leaf(a)`. ✓
- Якщо `state(∅) = internal`: `s(t) = node(s(u^{(1)}), s(u^{(2)}), s(u^{(3)}))`. Тоді:
  ```
  p_{n+1}(s(t)) = node(p_n(s(u^{(1)})), p_n(s(u^{(2)})), p_n(s(u^{(3)})))
  ```
  За IH(n): `p_n(s(u^{(i)})) = u_n^{(i)} = (t_{n+1})|_i`.
  Отже: `p_{n+1}(s(t)) = node((t_{n+1})|_1, (t_{n+1})|_2, (t_{n+1})|_3)`.
  Оскільки `t_{n+1}(∅) = internal`, `t_{n+1} = node((t_{n+1})|_1, (t_{n+1})|_2, (t_{n+1})|_3)`.
  Отже, `p_{n+1}(s(t)) = t_{n+1}`. ✓

∎

**PROVED ON PAPER.**

**Застереження CE-4.3.9 (виправлення CE-3.14).** У CE-3.14.1 не було розрізнення між існуючими та неіснуючими позиціями. CE-4.3 вводить частковий `state` і доводить, що:
- для існуючих позицій стан стабілізується (CE-4.3.4);
- реконструкція `s` використовує лише існуючі позиції (∅ і далі — рекурсивно).

**Наслідок CE-4.3.10 (сюр'єктивність p).** Для будь-якого `t ∈ lim←`: `p(s(t)) = t`. Отже, `p : S_∞ → lim←` — сюр'єкція.

**Наслідок CE-4.3.11 (бієкція).** Разом із ін'єктивністю (CE-3.14.2, стандартна бісимуляція), `p` — бієкція.

**PROVED ON PAPER.**

**Наслідок CE-4.3.12 (для §13.4.2).** Теорема бієкції — ДОВЕДЕНО НА ПАПЕРІ за CE-4.3.

## CE-4.4. Certification Semantics (K-09)

### Діагноз

У CE-3.9 сформульовано три рівні сертифікації (EXACT_CERTIFIED, APPROXIMATION_CONVERGED, RESOURCE_EXCEEDED) і твердження про монотонність між горизонтами. Але:

- монотонність `COMPUTED_N_1 → COMPUTED_N_2` не випливає з означень;
- узгодженість `APPROXIMATION_CONVERGED_N_1` і `EXACT_CERTIFIED_N_2` — окреме твердження, а не наслідок;
- довший запуск може вичерпати бюджет, а не покращити результат.

### Виправлення

**Означення CE-4.4.1 (рівні сертифікації, остаточно).**

```
EXACT_CERTIFIED
    Результат супроводжується формальним доказовим сертифікатом,
    який незалежна процедура може перевірити без повторного запуску F.
    Гарантія: якщо два EXACT_CERTIFIED запуски обидва коректні, вони
    дають однакову класифікацію Ω_traj.

APPROXIMATION_CONVERGED
    Виконано числовий критерій, зафіксований у конфігурації:
    (наприклад, dist(ŝ_n, ω) < ε для N послідовних кроків).
    Гарантія: класифікація узгоджена з обчисленим критерієм.
    Не гарантується: що при іншому горизонті класифікація буде такою ж.

RESOURCE_EXCEEDED
    Обчислення не завершене в межах бюджету.
```

**Твердження CE-4.4.2 (що виконується).**

1. Два `EXACT_CERTIFIED` запуски для однієї τ дають однакову `Ω_traj` (за умови коректності сертифікатів).
2. `RESOURCE_EXCEEDED` не дає класифікації.
3. `APPROXIMATION_CONVERGED` узгоджений із власним критерієм збіжності.

**Твердження CE-4.4.3 (що НЕ виконується автоматично).**

1. `COMPUTED_N_1 = EXACT_CERTIFIED` **не тягне** `COMPUTED_N_2 = EXACT_CERTIFIED` для `N_2 > N_1`.
2. `APPROXIMATION_CONVERGED_N_1` і `EXACT_CERTIFIED_N_2` **не обов'язково** дають однакову `Ω_traj`.

**Застереження CE-4.4.4.** Ці твердження — **окремі обов'язки доведення** для конкретних алгоритмів. Кожен алгоритм, який претендує на монотонність сертифікації, має довести її для свого класу входів.

**Виправлення:** CE-3.9.2 замінено на CE-4.4.2 і CE-4.4.3.

**Застереження CE-4.4.5 (для §23.2).** Тест монотонності в Implementation Conformance Requirements застосовується **лише** до алгоритмів, які довели свою монотонність. Для решти алгоритмів тест не є обов'язковим; обов'язковим є лише документування рівня сертифікації.

## CE-4.5. Додаткові виправлення

### CE-4.5.1. CE-3.2 — термінологія CHAOTIC

**Діагноз.** CE-3.2 використовує `CHAOTIC` для множин із `h_top > 0` і мінімальних. Це не тотожне «хаотичності» в усіх значеннях.

**Виправлення.** У §18.6.1 до класу CHAOTIC додати:

> CHAOTIC визначається як «мінімальна система з додатною топологічною ентропією». Це не еквівалентно іншим визначенням хаосу (чутливість до початкових умов, перемішування, щільні орбіти). У SUBIT-∞ CHAOTIC не використовується в іншому значенні.

### CE-4.5.2. CE-3.11 — PERIODIC_SET для неін'єктивних F

**Діагноз.** Мінімальність періоду `p` у `PERIODIC_SET(p)` — коректна. Але треба вказати, що `PERIODIC_SET` вимагає `F^p(P) = P`, а не просто `F^p(P) ⊆ P`.

**Виправлення.** У §6.2.1 явно:

> PERIODIC_SET(p): `p := min{ k ≥ 2 : F^k(P) = P }`, причому рівність `F^k(P) = P` — точна (не ⊆). Якщо `F` неін'єктивна і `F^k(P) ⊊ P` для всіх k, то застосовується EVENTUALLY_FIXED або EVENTUALLY_PERIODIC.

### CE-4.5.3. CE-3.17 — емпіричний протокол

**Діагноз.** Критерій не є повним протоколом.

**Виправлення.** Додати до §E.4:

1. **Метрика між класами.** `d_Ω_traj` (CE-3.4) використовується для перевірки стійкості класифікації при перестановках. Відхилення — сума `d_Ω_traj` на парах (оригінал, перестановка) / кількість пар.
2. **Уникнення витоку даних.** Квантильні межі обчислюються виключно на навчальній частині (перші 80 трійок). Тестова частина використовується лише для оцінки.
3. **Baseline.** ARIMA(2, 0, 2) з `statsmodels`; Markov-ланцюг першого порядку на 64 станах. Обидва навчаються на тій самій навчальній частині і оцінюються на тій самій тестовій.
4. **Довірчий інтервал.** Bootstrap з 10000 ресемплів тестової вибірки (для точності H₃). Для ARIMA і Markov — аналогічно.
5. **Критерій.** H₃ успішний, якщо нижня межа 95% ДІ точності H₃ строго перевищує верхню межу 95% ДІ для ARIMA і Markov.

## CE-4.11. Фінальне формулювання

CE-4 виправляє чотири помилки в доказах CE-3:

1. **Індексація метрики** — узгоджена через `δ(s, t) := max{n : p_n(s) = p_n(t)}`.
2. **Ультраметричність d_finite** — виведена з ультраметричності `d̂`, а не з NF3'.
3. **Сертифікація** — розділено математичні гарантії від операційних властивостей алгоритмів.
4. **Реконструкція S_∞** — частковий `state(σ)`, розрізнення існуючих і неіснуючих позицій.

**Головний принцип CE-4:** *кожне твердження PROVED має бути виведене з явно зазначених передумов. Якщо передумови не виконуються — ⚠️ CONDITIONAL.*
