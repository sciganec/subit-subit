## CE-10b.0. Принцип

Аудит CE-10a визнав напрям правильним, але виявив чотири конкретні дефекти:

1. **K-14 (типізація).** `TreeApprox n` задано неявно; рекурсія `truncate` не виписана для загального `n`.
2. **K-14 (стабільність `lim_tree`).** Означення `lim_tree` передбачає однозначність мітки, яку треба спочатку довести.
3. **K-15 (шаблонний хвіст).** У CE-10a.2.2 правила для `|τ| = 0` і `|τ| ≥ 1` суперечать одне одному; Model A має помилку індексації.
4. **K-09 / K-11 (термінологія).** `Φ_EP` названо «extension-preserving», хоча це «existential prefix»; `p_set` не визначено.

CE-10b **не змінює архітектуру** SUBIT-∞. Він закриває ці чотири дефекти точковими виправленнями.

**Правило CE-10b:** спочатку типізувати, потім довести стабільність, потім визначити `lim_tree`, потім використати для бієкції.

## CE-10b.1. TreeApprox, truncate, project — індуктивна типізація (K-14)

### Діагноз

CE-10a.1.1 задав `Leaf : A → TreeApprox n`, `Bottom : TreeApprox n`, `Node : (TreeApprox n)³ → TreeApprox (n+1)` — але рекурсія за n залишена неявною; `truncate_n` для загального n не виписана; базовий рівень не зафіксовано.

### Виправлення

**Означення CE-10b.1.1 (TreeApprox, індуктивне).**

```
TreeApprox : ℕ → Type

TreeApprox 0     := { Leaf(a) : a ∈ A } ∪ { Bottom }
TreeApprox (n+1) := { Leaf(a) : a ∈ A }
                  ∪ { Bottom }
                  ∪ { Node(t₁, t₂, t₃) : t₁, t₂, t₃ ∈ TreeApprox n }
```

**Застереження CE-10b.1.2.** Це **індуктивне** визначення за мета-індексом n. Воно не вимагає окремого конструктора `Node_n`; достатньо одного `Node` на кожному рівні.

**Означення CE-10b.1.3 (truncate, за індукцією).**

```
truncate_0 : TreeApprox 1 → TreeApprox 0
truncate_0 (Leaf a)          := Leaf a
truncate_0 Bottom            := Bottom
truncate_0 (Node _ _ _)      := Bottom

truncate_{n+1} : TreeApprox (n+2) → TreeApprox (n+1)
truncate_{n+1} (Leaf a)          := Leaf a
truncate_{n+1} Bottom            := Bottom
truncate_{n+1} (Node t₁ t₂ t₃)   := Node (truncate_n t₁) (truncate_n t₂) (truncate_n t₃)
```

**Лема CE-10b.1.4 (коректність типів).** `truncate_n(t) ∈ TreeApprox n` для всіх `t ∈ TreeApprox (n+1)`.

*Доведення.* Індукція за n.

- `n = 0`: випадки `Leaf`, `Bottom`, `Node`. Усі повертають елемент `TreeApprox 0 = { Leaf(a) } ∪ { Bottom }`. ✓
- `n + 1`: `Node(t₁, t₂, t₃)` з `tᵢ ∈ TreeApprox (n+1)`. За індукцією `truncate_n(tᵢ) ∈ TreeApprox n`. Отже `Node(truncate_n t₁, truncate_n t₂, truncate_n t₃) ∈ TreeApprox (n+1)`. ✓ ∎

**PROVED ON PAPER.**

**Означення CE-10b.1.5 (project, за індукцією).**

```
project_0 : S_∞ → TreeApprox 0
project_0 (leaf a)      := Leaf a
project_0 (node _ _ _)  := Bottom

project_{n+1} : S_∞ → TreeApprox (n+1)
project_{n+1} (leaf a)          := Leaf a
project_{n+1} (node t₁ t₂ t₃)   := Node (project_n t₁) (project_n t₂) (project_n t₃)
```

**Лема CE-10b.1.6 (рекурсія).** `project_n = truncate_n ∘ project_{n+1}`.

*Доведення.* Структурна індукція за `s ∈ S_∞` з окремими випадками `n = 0` і `n ≥ 1`. ∎

**PROVED ON PAPER.**

### Комутативність усічення з піддеревом

**Лема CE-10b.1.7.** Для `t ∈ TreeApprox (n+1)` з `t = Node(t₁, t₂, t₃)` і `i ∈ {1, 2, 3}`:

```
(truncate_n t)|_i = truncate_{n-1}(t_i)     (для n ≥ 1)
```

*Доведення.* Пряме з означення `truncate_{n}`. ∎

**PROVED ON PAPER.**

## CE-10b.2. Стабільність міток — лема перед визначенням lim_tree (K-14)

### Діагноз

CE-10a.1.7 визначив `lim_tree` через «існує n: t_n(σ) = Leaf(a)», але не довів, що **інші** рівні не дають іншої мітки. CE-10a.1.9 стверджував стабілізацію, але доведення передбачало однозначність `lim_tree`, яку треба спочатку встановити.

### Виправлення

**Лема CE-10b.2.1 (стабільність Leaf).**

Нехай `(t_n) ∈ lim←` і σ — позиція з `|σ| < N`. Якщо `t_N(σ) = Leaf(a)` для деякого `a ∈ A`, то для всіх `m ≥ N`:

- σ існує в `t_m`;
- `t_m(σ) = Leaf(a)`.

*Доведення.*

Індукція за `m ≥ N`.

- **База m = N:** тривіально.
- **Крок m → m+1:** за сумісністю `t_m = truncate_m(t_{m+1})`. Отже `Leaf(a) = t_m(σ) = truncate_m(t_{m+1})(σ)`.

  Розглянемо `t_{m+1}(σ)`:
  - `Leaf(a')`: `truncate_m(Leaf(a')) = Leaf(a')`. Тому `a' = a`. ✓
  - `Bottom`: `truncate_m(Bottom) = Bottom ≠ Leaf(a)`. Суперечність. ✗
  - `Node(...)`: `truncate_m(Node ...) = Node(...) ≠ Leaf(a)` (для `m ≥ 1`) або `truncate_0(Node) = Bottom ≠ Leaf(a)`. Суперечність. ✗

  Отже `t_{m+1}(σ) = Leaf(a)`. Крім того, якщо σ існує в `t_{m+1}` як листок, то σ існує в `t_{m+1}` за припущенням індукції. ✓ ∎

**PROVED ON PAPER.**

**Лема CE-10b.2.2 (стабільність Node).**

Нехай `(t_n) ∈ lim←` і σ — позиція з `|σ| < N`. Якщо `t_N(σ) = Node(t₁, t₂, t₃)`, то для всіх `m ≥ N`: σ існує в `t_m` і `t_m(σ)` є вузлом `Node`.

*Доведення.* Аналогічно до CE-10b.2.1: `truncate_m(Node) = Node` для `m ≥ 1`; для `m = 0` треба окремо перевірити, але `|σ| < 0` неможливо, отже база `m = 0` недосяжна. ∎

**PROVED ON PAPER.**

**Означення CE-10b.2.3 (lim_tree, коректне).** Для `(t_n) ∈ lim←` і позиції σ:

```
lim_tree(σ) :=
   Leaf(a)         якщо ∃N > |σ|: t_N(σ) = Leaf(a)
   Node            якщо ∃N > |σ|: t_N(σ) = Node(t₁, t₂, t₃)
   undefined       інакше (у тому числі якщо σ не існує в жодному t_N з N > |σ|)
```

**Застереження CE-10b.2.4 (коректність).** За CE-10b.2.1 і CE-10b.2.2 значення `lim_tree(σ)` **однозначне**: якщо існує `N > |σ|` з `t_N(σ) = Leaf(a)`, то жодне `M > |σ|` не дає іншої мітки (Leaf або Node).

**PROVED ON PAPER.**

**Лема CE-10b.2.5 (стабілізація, фінальна).** Якщо `lim_tree(σ) = Leaf(a)`, то існує `N_σ` таке, що для всіх `m ≥ N_σ`: `t_m(σ) = Leaf(a)`. Аналогічно для `Node`.

*Доведення.* Пряме з CE-10b.2.1 і CE-10b.2.2. ∎

**PROVED ON PAPER.**

**Наслідок CE-10b.2.6.** CE-10a.1.9 відкликано; замінено CE-10b.2.5. Доведення CE-10a.1.12 (продуктивність) зберігається без змін.

**Наслідок CE-10b.2.7.** K-14 — **PROVED ON PAPER** за CE-10b.1 і CE-10b.2.

## CE-10b.3. Шаблонний хвіст — рекурсивне означення (K-15)

### Діагноз

CE-10a.2.2 містить суперечність:

- для `|τ| = 0` — `Leaf(a₀)`;
- для `|τ| ≥ 1` — `Node(Leaf(a₀), Leaf(a₀), Leaf(a₀))`.

Для `|τ| = 1` друга умова дає нащадку `Node`, але тоді в **його** нащадків (позиція `σ · τ · i` з `|τ| ≥ 1`) друга умова знову дає `Node`, суперечачи тому, що `Node(Leaf, Leaf, Leaf)` має листки.

### Виправлення

**Означення CE-10b.3.1 (шаблон τ₀).**

```
τ₀ := Leaf(a₀) ∈ S_∞,   де a₀ ∈ A — фіксований елемент
```

**Означення CE-10b.3.2 (τ_N(s)).** Для `s ∈ S_∞` і `N ∈ ℕ` визначимо `τ_N(s) ∈ S_∞`:

```
τ_N(s)(σ) :=
   s(σ)                       якщо |σ| < N і s(σ) визначено
   s(σ)                       якщо |σ| = N і s(σ) = Leaf(a) для деякого a
   Node(τ₀, τ₀, τ₀)           якщо |σ| = N і s(σ) = Node
   undefined                  якщо |σ| > N
   undefined                  якщо s(σ) не визначено (предок — листок)
```

**Застереження CE-10b.3.3 (інтерпретація).** `τ_N(s)` — дерево, у якому:
- префікс глибини 0..N збігається з `s`;
- кожен вузол `Node` на глибині `N` замінюється на `Node(Leaf(a₀), Leaf(a₀), Leaf(a₀))`;
- жодні позиції глибини `> N` не визначені.

**Лема CE-10b.3.4 (τ_N(s) ∈ S_∞).** Для кожного `s ∈ S_∞` і `N ∈ ℕ`: `τ_N(s) ∈ S_∞`.

*Доведення.* Кожна позиція або `Leaf(a)`, або `Node(Leaf(a₀), Leaf(a₀), Leaf(a₀))`, або не визначена (що відповідає листку-предку). Усі три випадки узгоджені з `S_∞ = νX.(A ⊔ X³)`. ∎

**PROVED ON PAPER.**

**Означення CE-10b.3.5 (S_∞^{(N)}).**

```
S_∞^{(N)} := { τ_N(s) : s ∈ S_∞ }
```

**Лема CE-10b.3.6 (скінченність).** `|S_∞^{(N)}| < ∞`.

*Доведення.* `τ_N(s)` визначається значеннями `s` на позиціях глибини `< N`, які є `Leaf(a)` або `Node` (2 + |A| варіантів на позицію, плюс «не визначено» якщо предок — листок), і на позиціях глибини `N`, які є `Leaf(a)` або `Node` (2 + |A| варіантів, але з фіксованим `Node(τ₀, τ₀, τ₀)`).

Загальна кількість варіантів ≤ `(|A| + 3)^((3^N − 1)/2) · (|A| + 1)^(3^N)`, що скінченне. ∎

**PROVED ON PAPER.**

**Лема CE-10b.3.7 (збіг префікса).** `p_m(τ_N(s)) = p_m(s)` для всіх `m ≤ N`.

*Доведення.* Пряме з означень CE-10b.3.2 і CE-10b.1.5. ∎

**PROVED ON PAPER.**

**Лема CE-10b.3.8 (ε-мережа).** Для кожного ε > 0 існує N таке, що `S_∞^{(N)}` — ε-мережа для `(S_∞, d_S)`.

*Доведення.*

Нехай ε > 0. Виберемо N так, щоб `2^{-(N+1)} < ε`.

Для будь-якого `s ∈ S_∞` покладемо `s' := τ_N(s) ∈ S_∞^{(N)}`. За CE-10b.3.7: `p_m(s) = p_m(s')` для всіх `m ≤ N`. Отже, `δ(s, s') ≥ N + 1`, і `d_S(s, s') ≤ 2^{-(N+1)} < ε`. ∎

**PROVED ON PAPER.**

**Наслідок CE-10b.3.9.** `(S_∞, d_S)` цілком обмежений; разом із повнотою (CE-10.2.3) — компактний.

**Наслідок CE-10b.3.10.** K-15 — **PROVED ON PAPER** за CE-10b.3.

### Виправлення контрольної моделі A

**Аудит CE-10a виявив помилку індексації.** Для

```
s  = Node(Leaf(a), Leaf(b), Node(Leaf(c), Leaf(d), Leaf(a)))
s' = Node(Leaf(a), Leaf(b), Node(Leaf(c), Leaf(d), Leaf(b)))
```

правильні проекції:

- `p_0(s) = p_0(s') = Bottom` (обидва — внутрішні корені);
- `p_1(s) = p_1(s') = Node(Leaf(a), Leaf(b), Node(Bottom, Bottom, Bottom))`;
- `p_2(s) ≠ p_2(s')` (листок `a` vs `b` на глибині 2).

**Висновок:** `δ(s, s') = 2`, `d_S(s, s') = 2^{-2} = 1/4`.

**Застереження CE-10b.3.11.** CE-10a.5 відкликано в частині `δ = 3`, `d_S = 1/8`. Правильні значення — `δ = 2`, `d_S = 1/4`.

### Виправлення контрольної моделі B

**Аудит CE-10a виявив помилку.** Для нескінченного регулярного дерева `Ω` з `Ω(σ) = Node` для всіх σ:

- `p_0(Ω) = Bottom` (бо `project_0(internal) = Bottom`);
- `p_n(Ω) = Node(...)` для `n ≥ 1`.

**Застереження CE-10b.3.12.** Твердження `p_n(Ω) = Node(...)` має бути обмежене `n ≥ 1`. Для `n = 0` маємо `Bottom`.

## CE-10b.4. Сертифікація: точна термінологія (K-09)

### Діагноз

CE-10a.3 назвав `Φ_EP` «extension-preserving», хоча це «existential prefix». Крім того, твердження «`Φ_PH(N) не тягне Φ_EP(N)`» хибне: якщо `φ(k,τ)` для всіх `k ≤ N` і `N ≥ 0`, то зокрема `φ(0, τ)`, отже `∃k ≤ N: φ(k, τ)`.

### Виправлення

**Означення CE-10b.4.1 (предикати префікса).** Нехай `φ(k, τ)` — предикат, визначений для `k ∈ ℕ` і траєкторії `τ`.

```
Φ_∀(N, τ) := ∀k ≤ N: φ(k, τ)         (universal prefix)
Φ_∃(N, τ) := ∃k ≤ N: φ(k, τ)         (existential prefix)
Φ_k(k, τ) := φ(k, τ)                  (pointwise, fixed k)
Ψ(τ)      := глобальний предикат       (global)
```

**Твердження CE-10b.4.2 (правила перенесення).**

1. **`Φ_∀(N+1) ⟹ Φ_∀(N)`.** Безпосередньо з означення.
2. **`Φ_∀(N) не тягне Φ_∀(M)` для `M > N`** у загальному випадку.
3. **`Φ_∃(N) ⟹ Φ_∃(N+1)`.** Безпосередньо з означення.
4. **`Φ_∃(N+1) не тягне Φ_∃(N)`** у загальному випадку.
5. **`Φ_∀(N) ⟹ Φ_∃(N)`** (для `N ≥ 0`, бо `k = 0 ≤ N`).
6. **`Φ_∃(N) не тягне Φ_∀(N)`** у загальному випадку.
7. **`Φ_k(k)` не тягне `Φ_k(k')` для `k ≠ k'`** у загальному випадку.
8. **`Ψ(τ)` може тягнути `Φ_∀(N)`, `Φ_∃(N)` або `Φ_k(k)`** лише за **явно доведеної** семантичної імплікації для конкретного `φ`. Загального правила за типом немає.

**PROVED ON PAPER.**

**Наслідок CE-10b.4.3.** CE-10a.3.3 відкликано у формулюванні «`Φ_PH(N) не тягне Φ_EP(N)`». Правильне формулювання: `Φ_∀(N) ⟹ Φ_∃(N)`, але `Φ_∃(N) ↛ Φ_∀(N)`.

**Наслідок CE-10b.4.4.** Означення `Φ_EP` у CE-10a.3 замінено на `Φ_∃` з правильною назвою.

**Застереження CE-10b.4.5.** Кожен сертифікат у `P(τ)` повинен містити:

- `predicate_name` — ім'я предиката `φ`;
- `predicate_type ∈ {∀, ∃, k, Ψ}`;
- `horizon` — N для `Φ_∀` / `Φ_∃`, k для `Φ_k`;
- `proof` — посилання на доведення імплікації.

**Наслідок CE-10b.4.6.** K-09 — **PROVED ON PAPER** для предикатів `Φ_∀`, `Φ_∃`, `Φ_k`.

## CE-10b.5. p_set і розділення рівнів (K-11)

### Діагноз

CE-10a.4.7 використовує `p_set(P)`, не визначаючи його. Крім того, треба явно розділити «множинну» та «точкову» динаміку.

### Виправлення

**Означення CE-10b.5.1 (множинна динаміка).** `F : 2^{S_∞ × ℛ} → 2^{S_∞ × ℛ}`, `F(P) := { f(x) : x ∈ P }`.

**Означення CE-10b.5.2 (період множини).**

```
p_set(P) := min{ k ≥ 1 : F^k(P) = P }        якщо P ≠ ∅ і множина непорожня
p_set(P) := ∞                                 якщо P ≠ ∅ і множина порожня
p_set(∅) не визначено                         (∅ виключено з класифікації)
```

**Означення CE-10b.5.3 (μ, π).**

```
μ(P) := min{ m ≥ 0 : ∃n > m: F^m(P) = F^n(P) }     якщо існує
μ(P) := ∞                                           інакше

π(P) := min{ n − μ(P) : n > μ(P), F^n(P) = F^{μ(P)}(P) }    якщо μ < ∞
π(P) := ∞                                                     інакше
```

**Означення CE-10b.5.4 (шість класів, фінально).**

```
INVARIANT_FIXED(P)           ⟺ F(P) = P ∧ ∀x ∈ P: f(x) = x
INVARIANT_DYNAMIC(P)         ⟺ F(P) = P ∧ ∃x ∈ P: f(x) ≠ x
PERIODIC_SET(p)              ⟺ p_set(P) = p ≥ 2
EVENTUALLY_FIXED(μ, π)       ⟺ μ(P) ≥ 1 ∧ π(P) = 1
EVENTUALLY_PERIODIC(μ, π)    ⟺ μ(P) ≥ 1 ∧ π(P) ≥ 2
APERIODIC(P)                 ⟺ μ(P) = ∞
```

**Застереження CE-10b.5.5 (рівні динаміки).**

- `μ(P) = ∞` означає, що **орбіта множини** `F^0(P), F^1(P), …` не має повторень.
- Це **не** означає, що кожна точка `x ∈ P` має неперіодичну точкову орбіту `f^0(x), f^1(x), …`.
- `INVARIANT_DYNAMIC(P)` **не** тягне, що всі точки `P` не періодичні. Приклад: `P = {a, b}`, `f(a) = b, f(b) = a` — обидві точки періодичні (період 2), але `INVARIANT_DYNAMIC` виконується.

**Твердження CE-10b.5.6 (взаємовиключність і вичерпність).** Шість класів попарно не перетинаються і вичерпують `2^{S_∞ × ℛ} ∖ {∅}`.

*Доведення.* Розбиття за `(F(P) = P?, μ(P), π(P))`, як у CE-10a.4.8. ∎

**PROVED ON PAPER.**

**Наслідок CE-10b.5.7.** K-11 — **PROVED ON PAPER** за CE-10b.5.

## CE-10b.8. Фінальне формулювання

CE-10b закриває чотири дефекти аудиту CE-10a:

1. **Індуктивна типізація** `TreeApprox` (CE-10b.1) — `TreeApprox 0` як базова, `TreeApprox (n+1)` через `Node_n`.
2. **Стабільність міток** (CE-10b.2) — доведена **до** визначення `lim_tree`; `lim_tree` тепер коректно визначено.
3. **Шаблонний хвіст** (CE-10b.3) — `τ_N(s)` рекурсивно; модель A виправлено (δ = 2, d_S = 1/4).
4. **Точна термінологія** (CE-10b.4, CE-10b.5) — `Φ_∀ / Φ_∃ / Φ_k / Ψ`; `p_set`, `μ`, `π` формально визначені.

**Головний принцип CE-10b:** *спочатку типізувати, потім довести стабільність, потім визначити `lim_tree`, потім будувати бієкцію. Кожен крок спирається на попередній, а не передбачає його.*

**Наступний крок** — консолідація **v6.8.25** як нормалізованої редакції з явним поділом:

- доведені твердження (PROVED ON PAPER за передумов);
- умовні теореми (CONDITIONAL);
- протоколи (PROTOCOL DRAFT);
- відкриті питання (Q1–Q29).
