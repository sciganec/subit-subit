## CE-9.0. Принцип

Аудит CE-8 виявив **фундаментальний контрприклад** до бієкції `S_∞ ≅ lim←(T_n, q_n)`: послідовність `(Bottom₀, Bottom₁, Bottom₂, …)` належить `lim←`, але не належить `p(S_∞)`. Це доводить, що `p` не сюр'єктивне.

CE-9 **не змінює архітектуру** SUBIT-∞. Він:

1. Відкликає CE-8.2.8 і CE-5.3.17 (бієкція на повній `lim←`).
2. Вводить **продуктивне підпростірство** `L_prod ⊊ lim←`.
3. Доводить `S_∞ ≅ L_prod` (правильна форма).
4. Позначає топологічні наслідки (гомеоморфізм, компактність) як `CONDITIONAL` до завершення доказу замкненості `L_prod`.
5. Уточнює K-09, K-11, K-18 відповідно до зауважень аудиту.

**Ключове розрізнення.** `lim←(T_n, q_n)` **більший** за `S_∞`. Це та сама проблема, що виявлена в v6.8.10 (Patch U), де рішення було у відокремленні `Comp` від `{причинні функції Adm → Adm}`. CE-5–CE-8 намагалися відновити бієкцію і повернулися до помилки.

## CE-9.1. Продуктивне підпростірство L_prod

### Означення CE-9.1.1 (позиція, reachable)

Для `(t_n) ∈ lim←(T_n, q_n)` і `σ ∈ {1,2,3}^{<ω}`:
- **σ досяжна в t_n** ⟺ `|σ| ≤ n` і для всіх `j < |σ|`: `t_n((i₁,…,i_j)) = Node_{...}` (внутрішній вузол, не Bottom, не Leaf).
- **σ досяжна в (t_n)** ⟺ `∃n: σ` досяжна в `t_n`.

**Застереження CE-9.1.2 (спадковість).** Якщо σ досяжна в `t_n`, то σ досяжна в `t_m` для всіх `m ≥ n`. *Доведення.* За (P2): `t_n = truncate_n(t_{n+1})`. Якщо `t_n(σ)` — вузол, то `t_{n+1}(σ)` теж вузол (усічення не перетворює Node на Bottom при `|σ| < n`). ∎

### Означення CE-9.1.3 (граничне дерево)

Для `(t_n) ∈ lim←` означимо часткову структуру `lim_tree((t_n))`:

```
lim_tree(σ) := Leaf(a)      якщо ∃n: t_n(σ) = Leaf(a)
lim_tree(σ) := Node         якщо ∃n: t_n(σ) = Node_{...}
lim_tree(σ) := undefined    інакше
```

### Означення CE-9.1.4 (L_prod)

```
L_prod := { (t_n) ∈ lim← : lim_tree((t_n)) ∈ S_∞ }
```

**Твердження CE-9.1.5 (характеризація).** `(t_n) ∈ L_prod` тоді й лише тоді, коли:

- **(i)** `lim_tree(∅)` визначено (корінь існує);
- **(ii)** для кожного σ з `lim_tree(σ) = Node` і кожного `i ∈ {1,2,3}`: `lim_tree(σ·i)` визначено.

*Доведення.* Пряме з означень `L_prod` і `S_∞ = νX.(A ⊔ X³)`. ∎

**Контрприклад (аудит CE-8).** `b := (Bottom₀, Bottom₁, …)`:

- `lim_tree(∅)` не визначено (усі `t_n(∅) = Bottom_n`), отже `b ∉ L_prod`.
- Але `truncate_n(Bottom_{n+1}) = Bottom_n`, отже `b ∈ lim←`.
- Отже, `L_prod ⊊ lim←`. ✓

**Твердження CE-9.1.6 (непорожність L_prod \ lim←).** `L_prod ≠ ∅` і `L_prod ≠ lim←`.

*Доведення.* `L_prod ∋ p(s)` для будь-якого `s ∈ S_∞`; `lim← \ L_prod ∋ b`. ∎

**DEFINED.**

## CE-9.2. Бієкція S_∞ ≅ L_prod (виправлення CE-8.2)

### Виправлення твердження

**Твердження CE-9.2.1 (p : S_∞ → L_prod — бієкція).** Відображення `p : S_∞ → L_prod`, `p(s) := (p_n(s))_{n ∈ ℕ}`, є бієкцією.

**Доведення.**

**Добре визначене.** `p(s) ∈ lim←` за CE-7.2.6. Крім того, `lim_tree(p(s)) = s ∈ S_∞`, отже `p(s) ∈ L_prod`.

**Ін'єктивність.** Як у CE-8.2.6: якщо `p(s) = p(t)`, то `p_n(s) = p_n(t)` для всіх n, отже `s = t` за бісимуляцією (P3).

**Сюр'єктивність.** Нехай `(t_n) ∈ L_prod`. Покладемо `s := lim_tree((t_n)) ∈ S_∞`. Треба: `p(s) = (t_n)`.

**Індукція за рівнем n.**

**База n = 0.**
- `lim_tree(∅) = Leaf(a)`: `t_1(∅) = Leaf(a)`, отже `t_0 = truncate_0(t_1) = Leaf(a) = p_0(leaf(a)) = p_0(s)`. ✓
- `lim_tree(∅) = Node`: `t_1(∅) = Node_0(...)`, отже `t_0 = truncate_0(t_1) = Bottom_0 = p_0(node(...)) = p_0(s)`. ✓

**Крок n → n+1.** Нехай `lim_tree(∅) = Leaf(a)`. Тоді для всіх `m ≥ 1`, `t_m(∅) = Leaf(a)` (бо Leaf є термінальним у S_∞). Отже, `t_{n+1} = Leaf(a) = p_{n+1}(leaf(a)) = p_{n+1}(s)`. ✓

Нехай `lim_tree(∅) = Node`. Тоді `s = node(s₁, s₂, s₃)` з `s_i := lim_tree((u_m^{(i)})_m)`, де `u_m^{(i)} := (t_{m+1})|_i`. Треба довести, що `(u_m^{(i)})_m ∈ L_prod` — це випливає з (ii) характеристики CE-9.1.5: якщо `lim_tree(∅) = Node`, то для кожного i `lim_tree((i))` визначено, отже `(u_m^{(i)})_m ∈ L_prod`.

За індукційною гіпотезою `p_n(s_i) = u_n^{(i)}`. Отже:

```
p_{n+1}(s) = Node_n(p_n(s_1), p_n(s_2), p_n(s_3)) = Node_n(u_n^{(1)}, u_n^{(2)}, u_n^{(3)}) = t_{n+1}
```

(остання рівність — за узгодженістю `t_{n+1} = Node_n((t_{n+1})|_1, (t_{n+1})|_2, (t_{n+1})|_3)` і означенням `u_n^{(i)} = (t_{n+1})|_i`). ∎

**PROVED ON PAPER.**

**Застереження CE-9.2.2.** Доведення не використовує сюр'єктивності `p` на всій `lim←`; воно працює лише на `L_prod`, де кожне обмеження на рівні `t_{n+1} = Node_n(...)` тягне за собою продовження на всіх дочірніх підпослідовностях.

**Відкликано:** CE-8.2.8 (бієкція на `lim←`), CE-5.3.17 (бієкція на `lim←`).

**Статус K-14:** **PROVED ON PAPER** (з виправленим цільовим простором `L_prod`).

## CE-9.5. Компактність L_prod і S_∞ (уточнення CE-8.3.5)

### Діагноз

Компактність `lim←` доводиться легко (замкнений підпростір добутку скінченних дискретних). Але `L_prod ⊊ lim←` — чи замкнене `L_prod` у `lim←`?

### Аналіз

`L_prod = { (t_n) ∈ lim← : (i) ∧ (ii) }` (CE-9.1.5).

**Умова (i):** `lim_tree(∅)` визначено.

```
(t_n) задовольняє (i) ⟺ ∃N, ∀m ≥ N: t_m(∅) ∈ {Leaf(a) : a ∈ A} ∪ {Node_{...}}
```

Це `⋃_N ⋂_{m ≥ N} (...)`, тобто **F_σ**-множина, не замкнена в загальному випадку.

**Умова (ii):** аналогічно, для кожної σ.

**Застереження CE-9.5.1.** `L_prod` може бути **не замкненим** у `lim←`. Отже, компактність `L_prod` **не випливає** безпосередньо з компактності `lim←`.

### Виправлення

**Твердження CE-9.5.2 (компактність S_∞).** `(S_∞, d_S)` компактний.

**Статус:** окремий обов'язок доведення. Пропонуються два шляхи.

**Шлях A (через d_S).** Довести повноту і цілковиту обмеженість `(S_∞, d_S)` безпосередньо:

- **Повнота:** стандартна для ультраметрики першого розходження (послідовність Коші стабілізується на кожному рівні).
- **Цілковита обмеженість:** для кожного ε > 0 скінченне ε-покриття `S_∞` скінченними кулями `B_ε(s)` з представниками `s ∈ S_∞^{(N)}` для достатньо великого N.

Тоді `S_∞` компактний за теоремою Гейне–Бореля для метричних просторів.

**Шлях B (через канонічне вкладення).** Побудувати ін'єкцію `ι : S_∞ → ∏_n T_n` з замкненим образом. Образ `ι(S_∞)` = `L_prod` — замкнена підмножина добутку? Це потребує доведення, але з іншим вибором топології (наприклад, компактно-відкрита топологія на кожному `T_n`).

**Рекомендація CE-9.5.3.** Приймається **Шлях A** — прямий доказ повноти і цілковитої обмеженості. Це дає компактність без використання `L_prod` як замкненого підпростору.

**Статус K-15:** **CONDITIONAL** до завершення доказу (Шлях A або B).

**Застереження CE-9.5.4.** Твердження CE-7.4.2 (компактність через Тихонова) **відкликано** — воно використовує бієкцію `S_∞ ≅ lim←`, яка хибна.

## CE-9.6. Сертифікація — правила перенесення (K-09)

### Діагноз

Аудит правильно зауважує: не можна стверджувати безумовно, що `PREFIX_CERTIFIED(N₁)` не тягне `PREFIX_CERTIFIED(N₂)`. Це залежить від того, **яку саме властивість** сертифіковано.

### Виправлення

**Означення CE-9.6.1 (типи властивостей).**

- **Монотонні (MP).** Властивість `P` префікса така, що `P(N) ⟹ P(N+1)`. Приклади: «перші N кроків не повторюються», «на кроці k ∈ [1, N] виконується умова X».
- **Точкові (PP).** Властивість, що стосується конкретного моменту: `P(k)` для фіксованого k. Не монотонна за N.
- **Глобальні (GP).** Властивість всієї траєкторії, наприклад «траєкторія входить у цикл довжини p».

**Твердження CE-9.6.2 (правила перенесення).**

1. **MP(N) ⟹ MP(M) для M ≥ N.** Доводиться безпосередньо з означення MP.
2. **MP(N) не тягне MP(M) для M < N** (в загальному випадку).
3. **PP(k) не тягне PP(k') для k ≠ k'.**
4. **GP (глобальна) не випливає з жодного MP(N) чи PP(N).**
5. **GP ⟹ MP(N) для будь-якого N**, якщо MP(N) є наслідком GP.

**PROVED ON PAPER.**

**Наслідок CE-9.6.3.** Кожен сертифікат у `P(τ)` має містити:

- `cert_level ∈ {PREFIX, GLOBAL, APPROXIMATION}`
- `property_type ∈ {MP, PP, GP}`

Тоді перенесення між горизонтами дозволено лише за CE-9.6.2.

**Статус K-09:** **CONDITIONAL** (потребує специфікації типів властивостей у кожному алгоритмі).

## CE-9.7. Динамічні класи — лема про орбіту (K-11)

### Виправлення

**Лема CE-9.7.1 (орбітальна класифікація).**

Нехай `P ≠ ∅`, і нехай орбіта множин `P, F(P), F²(P), …` визначена для всіх n (тобто `F` тотальне на відповідному просторі множин). Тоді:

**(a)** Існує `k ≥ 1` з `F^k(P) = P` ⟺ `PERIODIC_SET(p)` або `INVARIANT_*`.

**(b)** `F(P) = P` розпадається на `INVARIANT_FIXED` (усі точки нерухомі) і `INVARIANT_DYNAMIC` (не всі).

**(c)** `F(P) ≠ P` і `∃m ≥ 1: F^{m+1}(P) = F^m(P) ≠ P` — `EVENTUALLY_FIXED(m)` за умови, що m мінімальне і `∀k ≥ 1: F^k(P) ≠ P`.

**(d)** `F(P) ≠ P` і `∃m ≥ 1, p ≥ 2: p_set(F^m(P)) = p` — `EVENTUALLY_PERIODIC(m, p)` за умови, що m мінімальне і `∀k ≥ 1: F^k(P) ≠ P`.

**(e)** Жоден з випадків (a)–(d) не виконується — `APERIODIC(P)`.

*Доведення.*

За детермінованістю `F`, орбіта `P, F(P), F²(P), …` — це послідовність множин. Застосуємо принцип Діріхле: якщо простір множин скінченний (на скінченному рівні S₀ × ℛ), то повторення обов'язкове. На нескінченному рівні:

- Якщо `∃k ≥ 1: F^k(P) = P` — випадок (a) (з подальшим розділенням (b)).
- Інакше `∀k ≥ 1: F^k(P) ≠ P`. Розглянемо послідовність `(F^n(P))_{n ≥ 0}`:
  - Якщо `∃m: F^{m+1}(P) = F^m(P)` з мінімальним m — випадок (c).
  - Якщо `∃m, p ≥ 2: F^{m+p}(P) = F^m(P)` — випадок (d).
  - Інакше — випадок (e).

Випадки (a)–(e) покривають усі можливості за побудовою. Взаємовиключність — за означеннями. ∎

**PROVED ON PAPER.**

**Застереження CE-9.7.2 (область визначення).** `Classify⁺(P)` визначене лише для `P ≠ ∅`. Порожня множина класифікується окремо як `EMPTY` або виключається з області.

**Твердження CE-9.7.3 (вичерпність і взаємовиключність).** За CE-9.7.1 шість класів + `EMPTY` утворюють розбиття простору `2^{S_∞ × ℛ} ∖ {∅}`.

**PROVED ON PAPER.**

**Застереження CE-9.7.4 (INVARIANT_DYNAMIC і періодичність).** Контрприклад CE-8.4.7 виправляється: правильне твердження — «`INVARIANT_DYNAMIC(P)` не тягне періодичності **кожної** точки `P`». Абстрактний контрприклад: `P = ℕ`, `F(n) = max(n − 1, 0)`. Явний контрприклад у `S_∞ × ℛ₀` залишається **Q28 (❓)**.

**Статус K-11:** **PROVED ON PAPER**.

## CE-9.8. Статистичний протокол — парний bootstrap (K-18)

### Виправлення

**Означення CE-9.8.1 (навчальні приклади).** Нехай `ŝ_1, …, ŝ_112` — кодована послідовність трійок (CE-8.6.1). Навчальні приклади для H₃:

- Для кожного `t ∈ {1, …, 79}` (бо `t+1 ≤ 80`): пара `(ŝ_t, ŝ_{t+1})`.

Прогноз для H₃ у момент `t`: `ρ₃(ŝ_t)` використовує лише `ŝ_t` (не майбутні значення).

**Означення CE-9.8.2 (парний bootstrap).**

Для кожного тестового моменту `t ∈ T_test = {81, …, 111}`:

```
Δ_t := 1[ρ₃(ŝ_t) = ŝ_{t+1}] − 1[B(ŝ_t) = ŝ_{t+1}]     B ∈ {ARIMA, Markov}
```

**Процедура блочного bootstrap (рухомі блоки):**

- Довжина блоку `L = 5`.
- `K = |T_test| − L + 1 = 27` можливих блоків.
- Для кожної репліки: вибір `⌈31/5⌉ = 7` випадкових блоків із `K` (з поверненням).
- `Δ_B`-репліка := середнє `Δ_t` на ресемплованих даних.

**Квантиль.** Нижня межа 97.5%: `L_B := Δ_{(250)}` — 250-та порядкова статистика з 10000 реплік.

**Критерій.** `L_B > 0` для обох B ∈ {ARIMA, Markov}.

**Застереження CE-9.8.3 (навчально-тестове перекриття).** Блоки не перетинають межу 80/81 — ресемплінг здійснюється виключно в тестовому інтервалі.

**Застереження CE-9.8.4 (обґрунтування L).** Вибір L = 5 — попередній; аналіз чутливості з L ∈ {3, 5, 10} звітується окремо. Фактичні автокореляції ряду не перевірені — Q27 (❓).

## CE-9.12. Фінальне формулювання

CE-9 закриває критичний дефект CE-8 (і, ретроспективно, CE-5 – CE-7):

1. **K-14** — цільовий простір бієкції змінено з `lim←` на `L_prod` (продуктивне підпростірство); бієкція `S_∞ ≅ L_prod` доведена.
2. **K-09** — правила перенесення сертифікатів сформульовані через типи властивостей (MP, PP, GP).
3. **K-11** — додана лема про орбіту; вичерпність і взаємовиключність шістьох класів доведені.
4. **K-18** — парний блочний bootstrap; квантиль 250/10000.
5. **K-15** — позначено як CONDITIONAL; два шляхи доведення компактності.

**Головний принцип CE-9:** *обернена границя `lim←` скінченних апроксимацій **більша** за фінальну коалгебру `S_∞`; різниця — «заморожені» послідовності з постійним Bottom. Правильна теорема: `S_∞ ≅ L_prod`, а не `S_∞ ≅ lim←`.*

Це узгоджується з відомим результатом теорії доменів: обернена границя скінченних апроксимацій коалгебри дає «ідеальне поповнення» коалгебри, яке зазвичай строго більше за неї, якщо функтор не має спеціальної властивості «насиченості».

**Наступний крок** — контрольна модель D (Bottom-послідовність) як обов'язкова перевірка CE-9.2.1, потім A–C, потім v6.8.25.
