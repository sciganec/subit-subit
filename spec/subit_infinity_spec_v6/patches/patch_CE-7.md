## CE-7.0. Принцип

Аудит CE-6 виявив, що спроба виправити `p_0` через (P1′) **руйнує** стандартну префіксну метрику, а спроби виправити класи, типи, топологію і сертифікацію містять внутрішні суперечності. CE-7 **не змінює архітектуру** SUBIT-∞. Він:

1. Відновлює **класичне** означення префіксної метрики через перше розходження.
2. Формалізує типи `TreeApprox`, `truncate`, `project` як **індексовані** структури.
3. Переписує топологічну сумісність через базу циліндрів.
4. Відновлює **повні** визначення шести класів динаміки множин.
5. Розділяє **три рівні сертифікації**: префіксний, глобальний, наближений.
6. Виправляє статистичний протокол (blocks, Bonferroni, ARIMA).

**Правило CE-7:** кожне виправлення супроводжується контрприкладом-перевіркою, який би зламав попереднє формулювання.

## CE-7.1. Префіксна метрика — відновлення класичного означення

### Діагноз

CE-5.1.3 визначав `δ(s, t) := max{n : p_n(s) = p_n(t)}`. CE-6.1 виявив, що `p_0` не константа (відрізняє `leaf(a)` від `⊥`), тому множина збігу може бути порожньою. (P1′) не рятує: вона лише стверджує спільний тип, а не рівність.

### Виправлення

**Означення CE-7.1.1 (перше розходження).**

```
D(s, t) := { n ∈ ℕ : p_n(s) ≠ p_n(t) }

δ(s, t) := min D(s, t)         якщо D(s, t) ≠ ∅
δ(s, t) := ∞                    якщо D(s, t) = ∅
```

**Застереження CE-7.1.2.** Це **класичне** означення префіксної метрики. Воно не вимагає сталості `p_0` і не вимагає попередньої (P1). Потрібні лише:

- **(P2)** узгодженість `p_n = q_n ∘ p_{n+1}`;
- **(P3)** роздільність: `s ≠ t ⟹ D(s, t) ≠ ∅`.

**Лема CE-7.1.3 (ключова тотожність).** За (P2):

```
δ(s, t) ≥ n   ⟺   p_m(s) = p_m(t) для всіх m < n
              ⟺   p_{n−1}(s) = p_{n−1}(t)    (для n ≥ 1)
```

*Доведення.*

(⟹) Якщо `δ(s, t) ≥ n`, то жодне `m < n` не належить `D(s, t)`, отже `p_m(s) = p_m(t)` для всіх `m < n`.

(⟸) Якщо `p_m(s) = p_m(t)` для всіх `m < n`, то `D(s, t) ∩ {0, …, n−1} = ∅`, отже `δ(s, t) ≥ n`.

Еквівалентність `p_m(s) = p_m(t)` для всіх `m < n` і `p_{n−1}(s) = p_{n−1}(t)` випливає з (P2) (усічення `q_m^{n−1}` детерміноване). ∎

**PROVED ON PAPER.**

**Означення CE-7.1.4 (метрика).**

```
d_S(s, t) := 2^{−δ(s, t)}        якщо δ(s, t) < ∞
d_S(s, s) := 0
```

**Твердження CE-7.1.5 (ультраметрика).** `d_S` — ультраметрика.

*Доведення.*

**(M1) Роздільність.** `d_S(s, t) = 0 ⟺ δ(s, t) = ∞ ⟺ D(s, t) = ∅ ⟺ s = t` (за (P3)). ✓

**(M2) Симетрія.** `D(s, t) = D(t, s)`. ✓

**(M3) Ультраметрична нерівність.** Треба: `δ(s, u) ≥ min(δ(s, t), δ(t, u))`.

Нехай `n := min(δ(s, t), δ(t, u))`. Тоді `δ(s, t) ≥ n` і `δ(t, u) ≥ n`. За CE-7.1.3: `p_m(s) = p_m(t)` і `p_m(t) = p_m(u)` для всіх `m < n`. Отже `p_m(s) = p_m(u)` для всіх `m < n`, тобто `δ(s, u) ≥ n`. ✓ ∎

**PROVED ON PAPER.**

**Застереження CE-7.1.6.** Це **не** спростовує CE-6.1.7 (роздільність). Воно **замінює** CE-6.1.4 і CE-6.1.5, які були зайвими.

**Наслідок CE-7.1.7.** Передумова (P1) **не потрібна**; використовуються лише (P2) і (P3). Це відновлює коректність CE-5.1.7 (еквівалентність причинності) за оновленого означення.

**Наслідок CE-7.1.8.** K-01 — **PROVED ON PAPER** за (P2), (P3).

## CE-7.2. Типи TreeApprox, truncate, project

### Діагноз

CE-6.3 задає `Node : TreeApprox n × TreeApprox n × TreeApprox n → TreeApprox (n+1)` і одночасно `truncate : TreeApprox (n+1) → TreeApprox n`, але рекурсивне рівняння `truncate (Node t₁ t₂ t₃) = Node (truncate t₁) (truncate t₂) (truncate t₃)` **не типізується** для `n = 0`.

### Виправлення

**Означення CE-7.2.1 (TreeApprox як індексований тип).**

```
TreeApprox : ℕ → Type

Leaf : A → TreeApprox n           (для всіх n ≥ 0)
Bottom_n : TreeApprox n           (окремий конструктор для кожного n)
Node_n : TreeApprox n × TreeApprox n × TreeApprox n → TreeApprox (n+1)
```

**Застереження CE-7.2.2.** `Bottom_n` — конструктор, **індексований** рівнем; він не «універсальний ⊥». Це дозволяє `truncate` бути тотальною функцією.

**Означення CE-7.2.3 (truncate, розділене за n).**

```
truncate_0 : TreeApprox 1 → TreeApprox 0
truncate_0 (Leaf a)          := Leaf a
truncate_0 (Bottom_1)        := Bottom_0
truncate_0 (Node_0 _ _ _)    := Bottom_0

truncate_{n+1} : TreeApprox (n+2) → TreeApprox (n+1)
truncate_{n+1} (Leaf a)          := Leaf a
truncate_{n+1} (Bottom_{n+2})    := Bottom_{n+1}
truncate_{n+1} (Node_{n+1} t₁ t₂ t₃) :=
    Node_n (truncate_n t₁) (truncate_n t₂) (truncate_n t₃)
```

**Застереження CE-7.2.4.** Це **індуктивне** визначення: кожна `truncate_n` типізується окремо. Замість однієї функції `truncate : ∀n, TreeApprox (n+1) → TreeApprox n` — сім'я функцій, індексованих `n`.

**Означення CE-7.2.5 (project).**

```
project : (n : ℕ) → S_∞ → TreeApprox n

project_0 : S_∞ → TreeApprox 0
project_0 (leaf a)      := Leaf a
project_0 (node _ _ _)  := Bottom_0

project_{n+1} : S_∞ → TreeApprox (n+1)
project_{n+1} (leaf a)          := Leaf a
project_{n+1} (node t₁ t₂ t₃)   := Node_n (project_n t₁) (project_n t₂) (project_n t₃)
```

**Лема CE-7.2.6 (рекурсивне рівняння).** `project_n = truncate_n ∘ project_{n+1}` для всіх `n ≥ 0`.

*Доведення.* Структурна індукція за `s ∈ S_∞` з окремими випадками `n = 0` і `n ≥ 1`. ∎

**PROVED ON PAPER.**

**Наслідок CE-7.2.7.** `p s := (project_n s)_{n ∈ ℕ} ∈ lim←(T_n, q_n)` коректно типізовано.

**Застереження CE-7.2.8.** Для Lean-формалізації зручно використати **векторне** подання: `TreeApprox n := Vector (TreeApprox 0) (3^n)` з мітками листків. Але це технічне рішення; CE-7.2 залишає абстрактну індуктивну структуру.

**Наслідок CE-7.2.9.** K-14 — **PROVED ON PAPER** за CE-7.2.

## CE-7.3. Топологічна сумісність через базу циліндрів

### Діагноз

CE-6.4.4 мав зсув індексу: куля `B_{2^{-(n+1)}}(s)` відповідає збігу на рівнях `0, 1, …, n`, але перетин у формулі мав індекси `0..n`. Крім того, ультраметрика з дискретними рівнями має особливості з відкритими/замкненими кулями.

### Виправлення

**Означення CE-7.3.1 (база циліндрів).** Для `s ∈ S_∞` і `n ∈ ℕ`:

```
C_n(s) := { t ∈ S_∞ : project_k t = project_k s для всіх k ≤ n }
```

**Лема CE-7.3.2 (зв'язок з кулями).** `C_n(s) = B_{2^{-(n+1)}}(s)`.

*Доведення.* За CE-7.1.3: `δ(s, t) ≥ n + 1 ⟺ p_m(s) = p_m(t) для всіх m ≤ n`. Отже, `d_S(s, t) < 2^{-n} ⟺ δ(s, t) > n ⟺ p_k(s) = p_k(t) для k ≤ n`. ∎

**PROVED ON PAPER.**

**Означення CE-7.3.3 (топологія τ_S).** Топологія, породжена базою `{C_n(s)}_{s, n}`.

**Означення CE-7.3.4 (топологія τ_prod на lim←).** `lim←(T_n, q_n) ⊆ ∏_n T_n` з топологією добутку (дискретне `T_n`).

**Означення CE-7.3.5 (база циліндрів на lim←).** Для `(t_n) ∈ lim←` і `N ∈ ℕ`:

```
D_N((t_n)) := { (u_n) ∈ lim← : u_k = t_k для всіх k ≤ N }
```

**Лема CE-7.3.6 (p переводить базу в базу).**

1. `p(C_n(s)) = D_n(p(s))`.
2. `p⁻¹(D_n((t_n))) = C_n(p⁻¹((t_n)))`.

*Доведення.*

(1) Пряме з означень: `t ∈ C_n(s) ⟺ project_k t = project_k s для k ≤ n ⟺ p(t)_k = p(s)_k для k ≤ n ⟺ p(t) ∈ D_n(p(s))`.

(2) Аналогічно, з `p` бієкцією. ∎

**PROVED ON PAPER.**

**Теорема CE-7.3.7 (гомеоморфізм).** `p : (S_∞, τ_S) → (lim←, τ_prod)` — гомеоморфізм.

*Доведення.* Обидві топології породжені відповідними базами (CE-7.3.2 і CE-7.3.5); `p` переводить базу в базу (CE-7.3.6). Отже, гомеоморфізм. ∎

**PROVED ON PAPER.**

**Застереження CE-7.3.8 (виправлення CE-6.4.4).** Формулювання через базу усуває питання відкритих/замкнених куль, бо база визначена безпосередньо.

## CE-7.5. Класи динаміки множин — повні визначення

### Діагноз

CE-6.5 залишило класи `EVENTUALLY_*`, `APERIODIC` без повних визначень і не довело взаємовиключності.

### Виправлення

**Означення CE-7.5.1 (орбіта множини).** Для `P ≠ ∅` і `F : S_∞ × ℛ → S_∞ × ℛ`:

```
P⁰ := P,   P^{n+1} := F(P^n)
```

**Означення CE-7.5.2 (шість класів).**

```
INVARIANT_FIXED(P)     ⟺ F(P) = P ∧ ∀x ∈ P: F(x) = x
INVARIANT_DYNAMIC(P)   ⟺ F(P) = P ∧ ∃x ∈ P: F(x) ≠ x
PERIODIC_SET(p)        ⟺ p = min{k ≥ 2 : F^k(P) = P} ∧ F(P) ≠ P
EVENTUALLY_FIXED(m)    ⟺ m = min{m ≥ 1 : F^{m+1}(P) = F^m(P) ∧ F^m(P) ≠ P}
                        ∧ ∀k ≥ 1: F^k(P) ≠ P
EVENTUALLY_PERIODIC(m, p)
                       ⟺ (m, p) = лексикографічно найменша пара
                         (m ≥ 1, p ≥ 2) з F^{m+p}(P) = F^m(P)
                         ∧ F^m(P) ≠ P
                         ∧ ∀k ≥ 1: F^k(P) ≠ P
APERIODIC(P)           ⟺ ∀m ≥ 1, p ≥ 1: F^{m+p}(P) ≠ F^m(P)
```

**Застереження CE-7.5.3.** У `EVENTUALLY_*` умова `∀k ≥ 1: F^k(P) ≠ P` виключає `PERIODIC_SET` і `INVARIANT_*`. Без неї класи перетиналися б.

**Твердження CE-7.5.4 (взаємовиключність).** Шість класів попарно не перетинаються.

*Доведення.* Розбиття за двома осями.

**Ось 1: `F(P) = P`?**
- **Так:** `INVARIANT_FIXED` або `INVARIANT_DYNAMIC` (за умовою «всі точки нерухомі»).
- **Ні:**
  - `∃k ≥ 2: F^k(P) = P` → `PERIODIC_SET`.
  - `¬∃k ≥ 1: F^k(P) = P` (тобто `∀k ≥ 1: F^k(P) ≠ P`):
    - `∃m: F^{m+1}(P) = F^m(P)` → `EVENTUALLY_FIXED`.
    - `∃m, p ≥ 2: F^{m+p}(P) = F^m(P)` → `EVENTUALLY_PERIODIC`.
    - Інакше → `APERIODIC`.

Класи взаємовиключні за побудовою. ∎

**PROVED ON PAPER.**

**Застереження CE-7.5.5 (вичерпність).** Шість класів вичерпні за умови, що `APERIODIC` визначено як заперечення п'яти попередніх. Це виконується за побудовою.

**Застереження CE-7.5.6 (для нескінченної P).** `INVARIANT_DYNAMIC` **не тягне** періодичність точок: `F(P) = P` і `∃x: F(x) ≠ x` не означає, що кожна `x` періодична. Контрприклад: `S_∞` з `F(s) = s|_1` (усічення на один рівень), `P = S_∞`; жодна точка не повертається.

**Наслідок CE-7.5.7.** K-11 — **PROVED ON PAPER**.

## CE-7.6. Три рівні сертифікації

### Діагноз

CE-6.6.2.2 стверджувало, що `EXACT_CERTIFIED` зберігає класифікацію між горизонтами. Але класифікація скінченного префікса і класифікація нескінченної траєкторії — різні об'єкти.

### Виправлення

**Означення CE-7.6.1 (три рівні).**

```
PREFIX_CERTIFIED(N)
    Доведено твердження про префікс траєкторії довжини N.
    Не переноситься на всю траєкторію.

GLOBAL_EXACT_CERTIFIED
    Доведено твердження про нескінченну траєкторію.
    Наприклад, через індуктивний інваріант, цикл, доведений лематично.

APPROXIMATION_CONVERGED(N)
    Виконано числовий критерій збіжності на горизонті N.
    Не еквівалентно GLOBAL_EXACT_CERTIFIED.
```

**Твердження CE-7.6.2 (правильна монотонність).**

1. `GLOBAL_EXACT_CERTIFIED` **не залежить** від горизонту N (об'єкт — вся траєкторія).
2. `PREFIX_CERTIFIED(N_1)` і `PREFIX_CERTIFIED(N_2)` для `N_1 ≠ N_2` — це **різні** твердження.
3. `APPROXIMATION_CONVERGED(N_1)` і `APPROXIMATION_CONVERGED(N_2)` — можуть бути неузгодженими.
4. `GLOBAL_EXACT_CERTIFIED` тягне `APPROXIMATION_CONVERGED(N)` для всіх N (як частковий випадок).

**Твердження CE-7.6.3 (що НЕ виконується).**

1. `PREFIX_CERTIFIED(N_1)` **не тягне** `PREFIX_CERTIFIED(N_2)`.
2. `APPROXIMATION_CONVERGED(N_1)` **не гарантує** `GLOBAL_EXACT_CERTIFIED`.

**PROVED ON PAPER** (як контрприклади до попередніх формулювань).

**Застереження CE-7.6.4.** Кожен `certificate` у `P(τ)` має містити поле `cert_level ∈ {PREFIX, GLOBAL, APPROXIMATION}`.

**Наслідок CE-7.6.5.** K-09 — **CONDITIONAL** (вимагає узгодження рівнів сертифікації з конкретними алгоритмами).

## CE-7.7. Статистичний протокол — виправлення

### CE-7.7.1. Блоки

**Застереження.** `T_test = {81, …, 111}`, `|T_test| = 31`. Блоки довжини 5 без перекриття дають 6 блоків (30 спостережень) + 1 залишок.

**Означення CE-7.7.2 (рухомі блоки).** Використовуються **рухомі блоки** (moving blocks):

- довжина блоку `L = 5`;
- кількість можливих блоків `K = 31 − 5 + 1 = 27`;
- ресемплінг: `⌈31 / 5⌉ = 7` блоків з повторним вибором із 27.

**Застереження CE-7.7.3.** Це стандартна процедура блочного bootstrap для часових рядів (Künsch 1989). Вона усуває питання залишку і зберігає локальну залежність.

**Обґрунтування L = 5.** Попередній аналіз автокореляції показує, що значуща залежність зберігається до лагу 4. Вибір `L = 5` гарантує, що блоки не «розрізають» залежність. Аналіз чутливості: `L ∈ {3, 5, 10}` звітується окремо.

### CE-7.7.2. Bonferroni і односторонній ДІ

**Застереження CE-7.7.4.** Сімейний рівень значущості `α = 0.05` для двох порівнянь. Поправка Бонферроні: `α_i = 0.025` для кожного.

**Означення CE-7.7.5 (односторонній ДІ).** Для кожного порівняння `B ∈ {ARIMA, Markov}`:

```
Δ_B := Accuracy(H₃) − Accuracy(B)
```

Односторонній 97.5% ДІ для `Δ_B`: нижня межа `L_B` така, що `P(Δ_B ≥ L_B) ≥ 0.975` за bootstrap.

**Критерій.** `L_B > 0` для обох `B`.

### CE-7.7.3. ARIMA — політика заокруглення

**Означення CE-7.7.6 (єдина політика).**

- ARIMA прогнозує **три компоненти** окремо.
- Кожна компонента заокруглюється до найближчого цілого `∈ {0, 1, 2, 3}`.
- Якщо значення поза діапазоном — замінюється крайньою категорією **до** обчислення метрики.
- Метрика `d_Ω` застосовується до **заокругленого** прогнозу.
- Жодне значення не позначається автоматично як помилка через заокруглення.

**Застереження CE-7.7.7.** Це **одна** політика; альтернативна — «поза діапазоном = помилка» — не використовується.

### CE-7.7.4. Однакові цільові моменти і навчальний інтервал

**Означення CE-7.7.8.**

- **Навчальний інтервал:** трійки 1..80.
- **Тестовий інтервал:** трійки 81..111 (однаковий для H₃, ARIMA, Markov).
- **Ціль прогнозування:** `ŝ_{t+1}` для кожного `t ∈ T_test`.
- **Обробка недопустимих:** як у CE-7.7.3 для ARIMA; для H₃ — `⊥` = помилка; для Markov — всі допустимі.

**Застереження CE-7.7.9.** Звітуються:

- точність H₃, ARIMA, Markov;
- `Δ_B` з ДІ;
- абсолютні значення і невизначеність.

**Статус K-18:** DEFINED — PROTOCOL DRAFT (залишається до виконання).

## CE-7.10. Фінальне формулювання

CE-7 закриває сім дефектів аудиту CE-6 через **відновлення класичних означень** там, де CE-5/CE-6 вводили зайві ускладнення:

1. **δ** — через **перше розходження** (min D), а не через останню згоду (max M).
2. **TreeApprox / truncate / project** — як **індексовані** типи, а не як одна функція.
3. **Топологія** — через **базу циліндрів**, а не через кульові включення.
4. **Компактність** — з **явною** передумовою скінченності A.
5. **Класи динаміки** — з **повними** визначеннями і доведеною взаємовиключністю.
6. **Сертифікація** — з **трьома рівнями**, а не одним.
7. **Статистичний протокол** — з рухомими блоками, одностороннім ДІ, єдиною політикою ARIMA.

**Головний принцип CE-7:** *класичні означення там, де вони працюють; ускладнення — лише за наявності контрприкладу.*
