## CE-10c.0. Принцип

Аудит CE-10b визнав напрям правильним, але виявив три конкретні дефекти:

1. **K-14 (локальна проєкція).** `(truncate_n t)|_i = truncate_{n-1}(t_i)` не типізовано; стабільність міток має приховану передумову про визначеність позиції; `lim_tree` дає лише мітку, а не структуру.
2. **K-15 (шаблон τ_N).** Означення CE-10b.3.2 суперечить самому собі: правило «undefined для всіх |σ| > N» і «Node(Leaf(a₀), Leaf(a₀), Leaf(a₀)) на глибині N» несумісні, бо діти цього Node лежать на глибині N+1.
3. **K-11 (орбітальна класифікація).** `μ`, `π` визначено, але доказ розбиття потребує п'яти допоміжних лем.

CE-10c — **точковий** patch. Він не змінює архітектуру SUBIT-∞; він доповнює CE-10b явними означеннями, лемами й виправленням шаблону.

**Правило CE-10c:** спочатку типізувати локальні операції, потім довести їхні властивості, потім будувати глобальні об'єкти.

## CE-10c.1. Локальні проєкції та стабільність міток (K-14)

### Означення CE-10c.1.1 (TreeApprox, остаточно)

```
TreeApprox : ℕ → Type

-- Індуктивне визначення за рівнем n:
-- TreeApprox 0     := { Leaf(a) : a ∈ A } ∪ { Bottom }
-- TreeApprox (n+1) := { Leaf(a) : a ∈ A }
--                   ∪ { Bottom }
--                   ∪ { Node(t₁, t₂, t₃) : tᵢ ∈ TreeApprox n }
--
-- Конструктори:
Leaf   : A → TreeApprox n           (для всіх n ≥ 0)
Bottom : TreeApprox n                (для всіх n ≥ 0)
Node   : TreeApprox n × TreeApprox n × TreeApprox n → TreeApprox (n+1)
```

**Застереження CE-10c.1.2.** `TreeApprox` — не вкладена сім'я: `TreeApprox n ⊄ TreeApprox (n+1)`. Перехід між рівнями — лише через `truncate` і `project`.

### Означення CE-10c.1.3 (локальне виділення піддерева)

Для `t ∈ TreeApprox (n+1)` і `i ∈ {1, 2, 3}` визначимо **часткову** операцію:

```
t|_i : TreeApprox n            якщо t = Node(t₁, t₂, t₃)
t|_i := t_i

t|_i : undefined               якщо t = Leaf(a) або t = Bottom
```

**Застереження CE-10c.1.4.** `|_i` — не функція `TreeApprox (n+1) → TreeApprox n`, а **часткова** функція. Вона визначена лише на `Node`. Це узгоджується з природою дерев: у листка немає нащадків.

### Лема CE-10c.1.5 (комутативність усічення з локальним виділенням)

Для `t = Node(t₁, t₂, t₃) ∈ TreeApprox (n+1)`:

```
(truncate_n t)|_i = truncate_{n-1}(t_i)        (для n ≥ 1)
```

*Доведення.* За означенням CE-10b.1.3:

```
truncate_n(Node(t₁, t₂, t₃)) = Node(truncate_{n-1}(t₁), truncate_{n-1}(t₂), truncate_{n-1}(t₃))
```

Тоді за CE-10c.1.3:

```
(truncate_n t)|_i = truncate_{n-1}(t_i)
```

∎

**PROVED ON PAPER.**

**Застереження CE-10c.1.6.** Для `n = 0` формула недосяжна, бо `truncate_0 : TreeApprox 1 → TreeApprox 0`, а `TreeApprox 0` не містить `Node`. Отже, `(truncate_0 t)|_i` не визначене за CE-10c.1.3. Твердження CE-10b.1.7 стосувалося лише `n ≥ 1` — це виправлено.

### Лема CE-10c.1.7 (покомпонентне усічення)

Для `t, t' ∈ TreeApprox (n+1)`:

```
truncate_n(t) = truncate_n(t') ⟺ t = t' ∨ (t, t' ∈ {Leaf(a), Bottom})
```

*Доведення.*

(⟸) Якщо `t = t'` — тривіально. Якщо `t, t' ∈ {Leaf(a), Bottom}` — за означенням `truncate_n` зберігає `Leaf(a)` і `Bottom`. ✓

(⟹) Нехай `truncate_n(t) = truncate_n(t')`. Розглянемо випадки:
- `t = Leaf(a)`: `truncate_n(t) = Leaf(a)`. Отже, `truncate_n(t') = Leaf(a)`. Можливі випадки: `t' = Leaf(a)` або (`t' = Node(...)` при `n = 0` — неможливо, бо `t' ∈ TreeApprox 1`). Отже, `t' = Leaf(a) = t`. ✓
- `t = Bottom`: аналогічно. ✓
- `t = Node(t₁, t₂, t₃)`, `t' = Node(t'₁, t'₂, t'₃)`: `Node(truncate_{n-1}(t_i)) = Node(truncate_{n-1}(t'_i))`, отже `truncate_{n-1}(t_i) = truncate_{n-1}(t'_i)`. За індукцією: `t_i = t'_i` для всіх i (або випадок `n - 1 = 0` з `t_i, t'_i ∈ {Leaf, Bottom}`). В обох випадках `t = t'`. ✓
- `t = Node(...)`, `t' = Leaf(a)` або `Bottom`: `truncate_n(t) = Node(...)` (для n ≥ 1) ≠ `Leaf(a)` або `Bottom`. Суперечність. ✓

∎

**PROVED ON PAPER** за індукцією.

### Лема CE-10c.1.8 (стабільність міток)

Нехай `(t_n) ∈ lim←(T_n, q_n)` і σ — позиція з `|σ| < N`. Тоді:

1. Якщо σ існує в `t_N`, то σ існує в `t_m` для всіх `m ≥ N`.
2. Якщо `t_N(σ) = Leaf(a)`, то `t_m(σ) = Leaf(a)` для всіх `m ≥ N`.
3. Якщо `t_N(σ) = Node_{...}`, то `t_m(σ)` — вузол `Node` для всіх `m ≥ N`.

*Доведення.*

**Крок 1 (визначеність позиції).** Індукція за `|σ|`.

**База `σ = ∅`.** `t_N(∅)` визначене за означенням `T_N`. За сумісністю `t_N = truncate_N(t_{N+1})`. Розглянемо випадки:
- `t_N(∅) = Leaf(a)`: `t_{N+1}(∅) = Leaf(a)` (за CE-10c.1.7 з урахуванням `t_N(∅) = truncate_N(t_{N+1})(∅)`). ✓
- `t_N(∅) = Bottom`: `t_{N+1}(∅) ∈ {Bottom, Node(...)}` (бо `truncate_N` на `Node` при `N = 0` дає `Bottom`, але при `N ≥ 1` — `Node`). Але `t_N(∅) = Bottom` з `t_{N+1}(∅) = Node(...)` суперечить `truncate_N(Node) = Node` (для `N ≥ 1`). Отже, `t_{N+1}(∅) = Bottom`. ✓
- `t_N(∅) = Node(...)`: `t_{N+1}(∅) = Node(...)`. ✓

**Крок 2 (мітки).** Пряме з кроку 1 і CE-10c.1.7.

**Крок 3 (позиції σ з |σ| > 0).** Індукція за `|σ|`: якщо σ існує в `t_N`, то `t_N(σ)` лежить у піддереві `t_N(σ₀)|_{σ_k}`. За кроком 2 (для префікса σ₀) відповідне піддерево стабілізується; далі застосовуємо крок 1 до піддерева.

∎

**PROVED ON PAPER** за індукцією за `|σ|` і `m − N`.

**Наслідок CE-10c.1.9.** `lim_tree(σ)`, визначене CE-10b.2.3, **однозначне**: не може бути `Leaf(a)` і `Node` одночасно; не може бути різних `Leaf(a)`, `Leaf(a')`.

**PROVED ON PAPER.**

### Означення CE-10c.1.10 (продуктивність граничного дерева)

Для `(t_n) ∈ lim←` визначимо часткову структуру `tree_lim((t_n))` рекурсивно за позицією:

```
tree_lim(σ) :=
   Leaf(a)          якщо lim_tree(σ) = Leaf(a)
   (tree_lim(σ·1), tree_lim(σ·2), tree_lim(σ·3))   якщо lim_tree(σ) = Node
                      і lim_tree(σ·i) визначено для всіх i
   undefined         інакше
```

**Лема CE-10c.1.11 (tree_lim ∈ S_∞ для продуктивних послідовностей).**

Якщо `(t_n) ∈ L_prod` (CE-10a.1.11), то `tree_lim((t_n)) ∈ S_∞`.

*Доведення.* За (i)–(iii) з CE-10a.1.11, кожна позиція σ у `tree_lim` або `Leaf(a)`, або `Node` з трьома визначеними дочірніми позиціями. Індукція за структурою дає `tree_lim((t_n)) ∈ S_∞`. ∎

**PROVED ON PAPER.**

### Оновлена лема продуктивності

**Лема CE-10c.1.12 (продуктивність, фінальна).**

Нехай `(t_n) ∈ L_prod` і σ — позиція з `lim_tree(σ) = Node`. Тоді:

**(a)** Для кожного `i ∈ {1, 2, 3}`: `lim_tree(σ · i)` визначено.

**(b)** Послідовність `u^{(σ, i)} := ((t_{m+|σ|+1})|_{σ·i})_m` ∈ `lim←`.

**(c)** `u^{(σ, i)} ∈ L_prod`.

*Доведення.*

**(a)** Пряме з (ii) CE-10a.1.11.

**(b)** Сумісність: для кожного m:
```
truncate_m(u^{(σ, i)}_{m+1}) = truncate_m((t_{m+|σ|+2})|_{σ·i})
                              = (truncate_{m+|σ|+1}(t_{m+|σ|+2}))|_{σ·i}     (CE-10c.1.5)
```

✓

**(c)** Треба (i)–(iii) для `u^{(σ, i)}`.

∎

**PROVED ON PAPER.**

## CE-10c.2. Шаблон τ_N — рекурсивне означення (K-15)

### Діагноз

CE-10b.3.2 містить суперечність:

- правило «`undefined` якщо |σ| > N»;
- правило «`Node(Leaf(a₀), Leaf(a₀), Leaf(a₀))` якщо |σ| = N і s(σ) = Node».

Правило `Node` на глибині N породжує три визначені позиції на глибині N+1, що суперечить першому правилу.

### Виправлення

**Означення CE-10c.2.1 (шаблонний хвіст τ_N(s), рекурсивне).**

Для `s ∈ S_∞` і `N ∈ ℕ` визначимо `τ_N(s) ∈ S_∞` рекурсивно за структурою позиції:

**Випадок σ = ∅:**

- `s = leaf(a)`: `τ_N(s) := leaf(a)` для всіх N.
- `s = node(t₁, t₂, t₃)`:
  - `N = 0`: `τ_0(s) := node(τ₀, τ₀, τ₀)`, де `τ₀ := leaf(a₀)`.
  - `N ≥ 1`: `τ_N(s) := node(τ_{N-1}(t₁), τ_{N-1}(t₂), τ_{N-1}(t₃))`.

**Застереження CE-10c.2.2.** Позицій глибини `> N+1` у `τ_N(s)` не визначено, бо всі листки, породжені шаблоном `τ₀`, є листками без нащадків.

**Лема CE-10c.2.3 (τ_N(s) ∈ S_∞).** Для кожного `s ∈ S_∞` і `N ∈ ℕ`: `τ_N(s) ∈ S_∞`.

*Доведення.* Індукція за N.

- `N = 0`, `s = leaf(a)`: тривіально. `s = node(...)`: `τ_0(s) = node(τ₀, τ₀, τ₀)`, де `τ₀ = leaf(a₀) ∈ S_∞`. ✓
- `N ≥ 1`: за індукцією `τ_{N-1}(tᵢ) ∈ S_∞`; `node` з трьох елементів `S_∞` — елемент `S_∞`. ✓

∎

**PROVED ON PAPER.**

**Лема CE-10c.2.4 (збіг префікса).** Для всіх `m ≤ N`: `p_m(τ_N(s)) = p_m(s)`.

*Доведення.* Індукція за `m` з використанням рекурсивного означення CE-10c.2.1 і факторизації проєкцій. ∎

**PROVED ON PAPER.**

**Лема CE-10c.2.5 (скінченність).** `|S_∞^{(N)}| < ∞`, де `S_∞^{(N)} := { τ_N(s) : s ∈ S_∞ }`.

*Доведення.* `τ_N(s)` визначається за префіксом `s` глибини `≤ N`:
- позиції глибини `< N`: `Leaf(a)` або `Node` (з піддеревами);
- позиції глибини `= N`: `Leaf(a)` або замінене на `Node(τ₀, τ₀, τ₀)`.

Кількість позицій глибини `< N` скінченна: `(3^N − 1)/2`. Кількість можливих значень на позиції ≤ `|A| + 1`. Отже:

```
|S_∞^{(N)}| ≤ (|A| + 1)^{(3^N − 1)/2} · (|A| + 1)^{3^{N − 1}}     (верхня межа)
```

∎

**PROVED ON PAPER.**

**Лема CE-10c.2.6 (ε-мережа).** Для кожного ε > 0 існує N, для якого `S_∞^{(N)}` — ε-мережа `(S_∞, d_S)`.

*Доведення.* Виберемо N так, щоб `2^{-(N+1)} < ε`. Для будь-якого `s ∈ S_∞`: `p_m(s) = p_m(τ_N(s))` для `m ≤ N` (CE-10c.2.4). Отже, `δ(s, τ_N(s)) ≥ N+1` і `d_S(s, τ_N(s)) ≤ 2^{-(N+1)} < ε`. ∎

**PROVED ON PAPER.**

**Наслідок CE-10c.2.7.** `(S_∞, d_S)` цілком обмежений; разом із повнотою (CE-10.2.3) — компактний.

**Наслідок CE-10c.2.8.** K-15 — **PROVED ON PAPER**.

### Виправлення контрольних моделей

**Model A (остаточно).**

```
s  = Node(Leaf(a), Leaf(b), Node(Leaf(c), Leaf(d), Leaf(a)))
s' = Node(Leaf(a), Leaf(b), Node(Leaf(c), Leaf(d), Leaf(b)))
```

- `p_0(s) = p_0(s') = Bottom`;
- `p_1(s) = p_1(s') = Node(Leaf(a), Leaf(b), Node(Bottom, Bottom, Bottom))`;
- `p_2(s) ≠ p_2(s')` (листок `a` vs `b` на глибині 2);
- `δ(s, s') = 2`, `d_S(s, s') = 1/4`.

**Model B (остаточно).**

Для нескінченного регулярного дерева `Ω` з `Ω(σ) = Node` для всіх σ:

- `p_0(Ω) = Bottom`;
- `p_n(Ω) = Node(...)` для `n ≥ 1`;
- `truncate_n(p_{n+1}(Ω)) = p_n(Ω)` для `n ≥ 0`;
- `lim_tree(Ω) = Ω`;
- `d_S(Ω, Ω) = 0`.

## CE-10c.3. Орбітальна класифікація — п'ять лем (K-11)

### Означення CE-10c.3.1 (множинна динаміка)

```
F : 2^{S_∞ × ℛ} → 2^{S_∞ × ℛ}
F(P) := { f(x) : x ∈ P }
```

**Застереження CE-10c.3.2.** `F(∅) = ∅`.

### Означення CE-10c.3.3 (μ, π, p_set)

```
μ(P) := min{ m ≥ 0 : ∃n > m: F^m(P) = F^n(P) }     якщо існує
μ(P) := ∞                                            інакше

π(P) := min{ n − μ(P) : n > μ(P), F^n(P) = F^{μ(P)}(P) }    якщо μ < ∞
π(P) := ∞                                                     інакше

p_set(P) := min{ k ≥ 1 : F^k(P) = P }                 якщо існує
p_set(P) := ∞                                          інакше
```

### Лема CE-10c.3.4 (випадок `F(P) = P`)

Якщо `F(P) = P`, то `μ(P) = 0` і `π(P) = 1`.

*Доведення.* `F^0(P) = P = F^1(P)`, отже `μ(P) = 0`. Далі `π(P) = min{n − 0 : n > 0, F^n(P) = F^0(P)} = min{n : n > 0, F^n(P) = P}`. При `F(P) = P`: `F^n(P) = P` для всіх n, тому `π(P) = 1`. ∎

**PROVED ON PAPER.**

### Лема CE-10c.3.5 (випадок `p_set(P) = p ≥ 2`)

Якщо `p_set(P) = p ≥ 2` (тобто `F^p(P) = P`, але `F(P) ≠ P`), то `μ(P) = 0` і `π(P) = p`.

*Доведення.* `F^0(P) = P = F^p(P)`, отже `μ(P) = 0`. Тоді `π(P) = min{n : n > 0, F^n(P) = P} = p_set(P) = p`. ∎

**PROVED ON PAPER.**

### Лема CE-10c.3.6 (випадок `μ(P) ≥ 1`, `π(P) = 1`)

Якщо `μ(P) ≥ 1` і `π(P) = 1`, то `F^μ(P) ≠ P` для всіх `k < μ` і `F^μ(P) = F^{μ+1}(P) ≠ P`.

*Доведення.* `π(P) = 1` означає `F^{μ(P) + 1}(P) = F^{μ(P)}(P)`. За означенням μ: `F^m(P) ≠ F^n(P)` для всіх `m < n < μ`; отже, `F^μ(P) ≠ P` (бо інакше `F^μ(P) = F^0(P)` з `μ > 0`). ∎

**PROVED ON PAPER.**

### Лема CE-10c.3.7 (випадок `μ(P) ≥ 1`, `π(P) ≥ 2`)

Якщо `μ(P) ≥ 1` і `π(P) = p ≥ 2`, то `F^μ(P), F^{μ+1}(P), …, F^{μ+p-1}(P)` — цикл довжини p у просторі множин, і `F^k(P) ≠ P` для всіх `k ≥ 1`.

*Доведення.* За означенням π: `F^{μ+p}(P) = F^μ(P)`, і `p` мінімальне таке. Значить, `F^{μ+i}(P) ≠ F^{μ+j}(P)` для `0 ≤ i < j < p`. Крім того, `F^k(P) ≠ P` для `k ≥ 1` за означенням μ ≥ 1 (як у CE-10c.3.6). ∎

**PROVED ON PAPER.**

### Лема CE-10c.3.8 (випадок `μ(P) = ∞`)

Якщо `μ(P) = ∞`, то всі `F^m(P)` попарно різні.

*Доведення.* Пряме з означення μ. ∎

**PROVED ON PAPER.**

### Твердження CE-10c.3.9 (розбиття)

Шість класів (CE-10a.4.7) попарно не перетинаються і вичерпують `2^{S_∞ × ℛ} ∖ {∅}`.

*Доведення.*

Нехай `P ≠ ∅`. Розглянемо `(F(P) = P?, μ(P), π(P))`.

**Випадок 1: `F(P) = P`.**
- `∀x ∈ P: f(x) = x` → `INVARIANT_FIXED`.
- `∃x ∈ P: f(x) ≠ x` → `INVARIANT_DYNAMIC`.

**Випадок 2: `F(P) ≠ P`, `μ(P) = 0`.**
За CE-10c.3.5: `F^k(P) = P` для деякого `k ≥ 2`, отже `p_set(P) ≥ 2` → `PERIODIC_SET(p_set(P))`.

**Випадок 3: `F(P) ≠ P`, `μ(P) ≥ 1`.**
За CE-10c.3.6 і CE-10c.3.7:
- `π(P) = 1` → `EVENTUALLY_FIXED(μ, 1)`.
- `π(P) ≥ 2` → `EVENTUALLY_PERIODIC(μ, π)`.

**Випадок 4: `F(P) ≠ P`, `μ(P) = ∞`.**
За CE-10c.3.8 → `APERIODIC`.

Взаємовиключність — за означеннями (кожен клас визначає різні комбінації `(F(P) = P, μ, π)`). Вичерпність — усі випадки покрито. ∎

**PROVED ON PAPER.**

**Наслідок CE-10c.3.10.** K-11 — **PROVED ON PAPER**.

**Застереження CE-10c.3.11.** Класифікація — для **множинної** динаміки `F`. Точкова динаміка `f` не класифікується цими шістьма класами. Q28 (❓) залишається відкритим.
