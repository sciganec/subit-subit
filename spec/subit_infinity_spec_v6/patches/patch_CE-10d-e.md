## CE-10d.1. Локальні проєкції та стабільність (K-14)

### Відкликані твердження

**Відкликано:**

- CE-10c.1.7 (покомпонентне усічення) — **хибна**.
- CE-10c.1.8 (стабільність) — залежить від хибної 1.7; переписана нижче.

**Контрприклад до CE-10c.1.7.** Нехай `t = Leaf(a)`, `t' = Bottom`. Тоді `truncate_n(t) = Leaf(a) ≠ Bottom = truncate_n(t')`, але права частина CE-10c.1.7 допускала `t, t' ∈ {Leaf(a), Bottom}` як рівність.

**Сильніший контрприклад (аудит CE-10c, §4).** Для `n = 1`:
```
t  = Node(Node(u₁,u₂,u₃), a₁, a₂)
t' = Node(Node(v₁,v₂,v₃), a₁, a₂),   де u ≠ v
```
`truncate_1(t) = truncate_1(t') = Node(Bottom, Leaf(a₁), Leaf(a₂))`, хоча `t ≠ t'`.

**Застереження CE-10d.1.0.** Усічення **не є ін'єктивним** на жодному рівні — це його призначення. Спроба CE-10c.1.7 сформулювати бієктивність була помилкою; правильною є лише **слабка** форма: збереження конструкторів.

### Заміна CE-10c.1.7

**Лема CE-10d.1.1 (збереження Leaf).** Для всіх `n ≥ 0` і `a ∈ A`:

```
truncate_n(Leaf(a)) = Leaf(a)
```

*Доведення.* Пряме з означення CE-10b.1.3. ∎

**PROVED ON PAPER.**

**Лема CE-10d.1.2 (збереження Bottom).** Для всіх `n ≥ 0`:

```
truncate_n(Bottom) = Bottom
```

*Доведення.* Пряме з означення CE-10b.1.3. ∎

**PROVED ON PAPER.**

**Лема CE-10d.1.3 (розпізнавання Node).** Для `n ≥ 1` і `t ∈ TreeApprox (n+1)`:

```
truncate_n(t) = Node(t'₁, t'₂, t'₃)   ⟹   t = Node(t₁, t₂, t₃) 
                                          і t'_i = truncate_{n-1}(t_i)
```

*Доведення.* За означенням CE-10b.1.3: `truncate_n` повертає `Node` лише коли аргумент — `Node`. Отже, `t = Node(t₁, t₂, t₃)`, і `truncate_n(t) = Node(truncate_{n-1}(t₁), truncate_{n-1}(t₂), truncate_{n-1}(t₃))`. Порівняння покомпонентно дає `t'_i = truncate_{n-1}(t_i)`. ∎

**PROVED ON PAPER.**

**Наслідок CE-10d.1.4.** Ін'єктивність усічення **не потрібна**; для стабільності міток достатньо збереження конструкторів (CE-10d.1.1, CE-10d.1.2) і розпізнавання (CE-10d.1.3).

### Семантика Bottom

**Застереження CE-10d.1.5.** `Bottom` має дві семантичні ролі:

- **Bottom як справжня мітка повного дерева**: дерево, що складається з одного листка з міткою `⊥`. Це елемент `S_∞`? **Ні** — `⊥ ∉ A` (CE-3.3.1), отже таке дерево не є елементом `S_∞`. Bottom — **лише** елемент `TreeApprox n`.
- **Bottom як маркер усічення в апроксимації**: елемент `TreeApprox n`, що позначає «глибше не дивимося».

**Твердження CE-10d.1.6.** `Bottom ∈ TreeApprox n` для всіх n, але `Bottom ∉ project_n(S_∞)` **не завжди** — для `n = 0` і `s = node(...)` маємо `project_0(s) = Bottom`, але `Bottom` виникає як результат, не як елемент `S_∞`.

**Застереження CE-10d.1.7.** Тому **стабільність Bottom не можна доводити аналогічно до Leaf/Node**: Bottom у `t_n` може на рівні `n+1` стати `Node` (якщо апроксимація уточнюється) або `Leaf(a)`.

**Приклад.** `s = node(t₁, t₂, t₃)`, `project_0(s) = Bottom`, але `project_1(s) = Node(Bottom, Bottom, Bottom)`. Отже, Bottom на рівні 0 «розкривається» на рівні 1.

### Переписана стабільність

**Лема CE-10d.1.8 (стабільність Leaf/Node).**

Нехай `(t_n) ∈ lim←` і σ — позиція з `|σ| < N`. Тоді:

1. Якщо `t_N(σ) = Leaf(a)`, то `t_m(σ) = Leaf(a)` для всіх `m ≥ N`.
2. Якщо `t_N(σ) = Node_{...}`, то `t_m(σ)` є `Node` для всіх `m ≥ N`.

*Доведення.*

**Випадок Leaf.** Індукція за `m ≥ N`.

- **База m = N.** Тривіально.
- **Крок m → m+1.** За сумісністю `t_m = truncate_m(t_{m+1})`. Отже `Leaf(a) = t_m(σ) = truncate_m(t_{m+1})(σ)`. Розглянемо `t_{m+1}(σ)`:
  - `Leaf(a')`: `truncate_m(Leaf(a')) = Leaf(a')` (CE-10d.1.1). Отже `a' = a`. ✓
  - `Bottom`: `truncate_m(Bottom) = Bottom ≠ Leaf(a)` (CE-10d.1.2). ✗
  - `Node(t'₁, t'₂, t'₃)`: `truncate_m(Node...) = Node(...)` для `m ≥ 1`, `truncate_0(Node) = Bottom` для `m = 0`. Обидва ≠ `Leaf(a)`. ✗
  Отже `t_{m+1}(σ) = Leaf(a)`. ✓

**Випадок Node.** Аналогічно:

- `Leaf(a')`: суперечність.
- `Bottom`: суперечність.
- `Node(t'₁, t'₂, t'₃)`: за CE-10d.1.3, `truncate_m(Node...) = Node(...)` для `m ≥ 1`. Для `m = 0` — але `|σ| < 0` недосяжно, отже база `m = 0` не виникає.

∎

**PROVED ON PAPER.**

**Наслідок CE-10d.1.9.** `lim_tree(σ)` (CE-10b.2.3) однозначно визначене для Leaf і Node. Випадок Bottom у `lim_tree` окремо не виникає: якщо на всіх рівнях `t_N(σ) = Bottom`, то `lim_tree(σ) = undefined`.

**Застереження CE-10d.1.10.** Стабільність **не поширюється** на Bottom: Bottom на рівні N може стати `Node` на рівні N+1. Це узгоджується з роллю Bottom як маркера усічення.

### Продуктивність (переписана)

**Лема CE-10d.1.11 (продуктивність граничного дерева).**

Нехай `(t_n) ∈ L_prod` і σ — позиція з `lim_tree(σ) = Node`. Тоді:

**(a)** Для кожного `i ∈ {1, 2, 3}`: `lim_tree(σ · i)` визначено.

**(b)** Послідовність `u^{(σ, i)} := ((t_{m+|σ|+1})|_{σ·i})_m` ∈ `lim←`.

**(c)** `u^{(σ, i)} ∈ L_prod`.

*Доведення.*

**(a)** Пряме з (ii) CE-10a.1.11.

**(b)** Сумісність: за CE-10d.1.3, для `t = Node(...)` маємо `(truncate_m t)|_i = truncate_{m-1}(t_i)`. Застосуємо до `t = t_{m+|σ|+2}`:

```
truncate_m(u^{(σ, i)}_{m+1}) = truncate_m((t_{m+|σ|+2})|_{σ·i})
                              = (truncate_{m+|σ|+1}(t_{m+|σ|+2}))|_{σ·i}
                              = (t_{m+|σ|+1})|_{σ·i}
                              = u^{(σ, i)}_m
```

(друга рівність — комутативність CE-10c.1.5, виправлена CE-10d.1.3).

**(c)** Треба (i)–(iii) CE-10a.1.11 для `u^{(σ, i)}`:
- (i) — з (a);
- (ii) — з (ii) вихідної послідовності для `σ · i · τ`;
- (iii) — аналогічно.

∎

**PROVED ON PAPER.**

**Наслідок CE-10d.1.12.** Бієкція `p : S_∞ → L_prod` (CE-10.1.3) доведена.

**Наслідок CE-10d.1.13.** K-14 — **PROVED ON PAPER**.

## CE-10d.2. Верхня межа і збіг префікса (K-15)

### Відкликані твердження

**Відкликано:** CE-10c.2.5 (верхня межа) — показник містить помилку.

### Виправлена верхня межа

**Лема CE-10d.2.1 (верхня межа).**

```
|S_∞^{(N)}| ≤ (|A| + 1)^{(3^N − 1)/2 + 3^N}
```

*Доведення.* `τ_N(s)` визначається значеннями `s` на всіх позиціях глибини `≤ N`. Кількість таких позицій:

```
1 + 3 + 3² + … + 3^N = (3^{N+1} − 1)/2 = (3^N − 1)/2 + 3^N
```

На кожній позиції значення — `Leaf(a)` (|A| варіантів) або `Node` (1 варіант), тобто `|A| + 1` значень. Отже:

```
|S_∞^{(N)}| ≤ (|A| + 1)^{(3^N − 1)/2 + 3^N}
```

∎

**PROVED ON PAPER.**

**Застереження CE-10d.2.2.** Це **груба верхня межа**; вона не є точною кількістю допустимих дерев. Для доведення цілковитої обмеженості достатньо скінченності для кожного N.

### Явний доказ збігу префікса

**Лема CE-10d.2.3 (збіг префікса).** Для всіх `s ∈ S_∞` і `N ∈ ℕ`:

```
p_m(τ_N(s)) = p_m(s),   для всіх 0 ≤ m ≤ N
```

*Доведення (індукція за m).*

**База m = 0.**

- `s = leaf(a)`: `τ_N(s) = leaf(a)` для всіх N (CE-10c.2.1). `p_0(τ_N(s)) = p_0(leaf(a)) = Leaf(a) = p_0(s)`. ✓
- `s = node(t₁, t₂, t₃)`:
  - `N = 0`: `τ_0(s) = node(τ₀, τ₀, τ₀)`, отже `p_0(τ_0(s)) = Bottom = p_0(s)`. ✓
  - `N ≥ 1`: `τ_N(s) = node(τ_{N-1}(t₁), τ_{N-1}(t₂), τ_{N-1}(t₃))`, отже `p_0(τ_N(s)) = Bottom = p_0(s)`. ✓

**Крок m → m+1** (для `m+1 ≤ N`).

- `s = leaf(a)`: `τ_N(s) = leaf(a)`, `p_{m+1}(τ_N(s)) = Leaf(a) = p_{m+1}(s)` (проєкція листка). ✓
- `s = node(t₁, t₂, t₃)`:
  - `N ≥ m+2`: `τ_N(s) = node(τ_{N-1}(t₁), …)`, отже `p_{m+1}(τ_N(s)) = Node(p_m(τ_{N-1}(t₁)), p_m(τ_{N-1}(t₂)), p_m(τ_{N-1}(t₃)))`. За індукційною гіпотезою для `N-1 ≥ m`: `p_m(τ_{N-1}(t_i)) = p_m(t_i)`. Отже `p_{m+1}(τ_N(s)) = Node(p_m(t₁), p_m(t₂), p_m(t₃)) = p_{m+1}(s)`. ✓
  - `N = m+1`: `τ_N(s) = node(τ_0(t₁), τ_0(t₂), τ_0(t₃))`, отже `p_{m+1}(τ_N(s)) = Node(p_m(τ_0(t₁)), p_m(τ_0(t₂)), p_m(τ_0(t₃)))`. За індукційною гіпотезою для `m = N-1`: `p_m(τ_0(t_i)) = p_m(t_i)` **лише якщо** `m ≤ 0`, тобто `m = 0`. Для `m ≥ 1` застосовуємо індукцію за структурою t_i.

Повний доказ для випадку `N = m+1` вимагає індукції за структурою `t`: `p_m(τ_0(t)) = p_m(t)` для всіх `t` і `m ≥ 0` (бо `τ_0` замінює лише листки шаблоном, не змінюючи префікс глибини `≥ 1`... але це складно).

**Простіше формулювання.** Замість `τ_0(t_i)` використаємо індукцію за N: `p_m(τ_{N-1}(t)) = p_m(t)` для `m ≤ N-1`. Тоді випадок `N = m+1` дає `m ≤ N-1`, отже `p_m(τ_{N-1}(t_i)) = p_m(t_i)`. Але `τ_0` замінює листки на рівні 0, а не `τ_{N-1}`. Отже, випадок `N = m+1` зводиться до `τ_{N-1} = τ_0` при `m = 0`:

- `m = 0, N = 1`: `τ_0(t_i)` на рівні 0. `p_0(τ_0(t_i)) = p_0(t_i)` (база CE-10d.2.3 для m=0). ✓

Для `m ≥ 1, N = m+1 ≥ 2`: `τ_{N-1}(t_i) = τ_m(t_i)`, і за індукційною гіпотезою для `m` (з `τ_m` на позиціях `≤ m`): `p_m(τ_m(t_i)) = p_m(t_i)`. ✓

Отже, індукція за m працює.

∎

**PROVED ON PAPER.**

**Застереження CE-10d.2.4.** Доказ використовує **подвійну індукцію**: за m і за N (через індукційну гіпотезу для `τ_{N-1}`). Явне формулювання:

`IH(m, N): p_m(τ_N(s)) = p_m(s)` для всіх `s` і `m ≤ N`.

- База `m = 0`: CE-10d.2.3 (перший випадок).
- Крок `m → m+1`: використовує `IH(m, N-1)`, що виконується для `m ≤ N-1`, тобто `m+1 ≤ N`. ✓

**Наслідок CE-10d.2.5.** Лема CE-10c.2.4 (збіг префікса) доведена.

**Наслідок CE-10d.2.6.** ε-мережа (CE-10c.2.6) доведена; разом із повнотою (CE-10.2.3) — компактність.

**Наслідок CE-10d.2.7.** K-15 — **PROVED ON PAPER**.

## CE-10d.3. Орбітальна класифікація (K-11)

### Відкликані твердження

**Відкликано:** CE-10c.3.6 у частині формулювання «`F^k(P) ≠ P` для всіх k < μ» з плутаними індексами.

### Виправлення CE-10c.3.6

**Лема CE-10d.3.1 (випадок `μ ≥ 1`, `π = 1`).**

Нехай `P ≠ ∅`, `F(P) ≠ P`, `μ(P) ≥ 1`, `π(P) = 1`. Тоді:

1. `F^m(P) ≠ F^n(P)` для всіх `0 ≤ m < n < μ(P)`.
2. `F^{μ(P)}(P) ≠ P` (і `F^k(P) ≠ P` для всіх `1 ≤ k ≤ μ(P)`).
3. `F^{μ(P)+1}(P) = F^{μ(P)}(P)`.

*Доведення.*

**(1)** За означенням `μ(P) = min{m ≥ 0 : ∃n > m: F^m(P) = F^n(P)}`. Отже, для `m < μ(P)` не існує `n > m` з рівністю.

**(2)** `F^{μ(P)}(P) ≠ P` — бо інакше `F^{μ(P)}(P) = F^0(P)` з `μ(P) ≥ 1`, суперечність з мінімальністю μ. Отже, `F^k(P) ≠ P` для всіх `k ≥ 1` з `k ≤ μ(P)` (зокрема, `F(P) ≠ P` вже дано).

**(3)** `π(P) = 1` означає `min{n − μ(P) : n > μ(P), F^n(P) = F^{μ(P)}(P)} = 1`, отже `F^{μ(P)+1}(P) = F^{μ(P)}(P)`. ✓

∎

**PROVED ON PAPER.**

**Застереження CE-10d.3.2.** Виправлено індексну помилку CE-10c.3.6: замість «`F^k(P) ≠ P` для всіх `k < μ`» правильно «`F^k(P) ≠ P` для всіх `1 ≤ k ≤ μ`».

### Явна випадкова перевірка розбиття

**Твердження CE-10d.3.3 (розбиття, повний доказ).**

Шість класів (CE-10a.4.7) попарно не перетинаються і вичерпують `2^{S_∞ × ℛ} ∖ {∅}`.

*Доведення.*

Нехай `P ≠ ∅`. Розглянемо `(F(P) = P?, μ(P), π(P))`.

**Випадок 1: `F(P) = P`.**
- `∀x ∈ P: f(x) = x` → `INVARIANT_FIXED` (CE-10a.4.7).
- `∃x ∈ P: f(x) ≠ x` → `INVARIANT_DYNAMIC`.

**Випадок 2: `F(P) ≠ P`, `μ(P) = 0`.**
Означення `μ(P) = 0` означає: `∃n > 0: F^0(P) = F^n(P)`, тобто `F^n(P) = P` для деякого `n ≥ 1`. Оскільки `F(P) ≠ P`, маємо `n ≥ 2`. Отже `p_set(P) ≥ 2` і `F^{p_set(P)}(P) = P` → `PERIODIC_SET(p_set(P))`.

**Випадок 3: `F(P) ≠ P`, `μ(P) ≥ 1`.**
- `F^k(P) ≠ P` для всіх `k ≥ 1` (CE-10d.3.1(2) і CE-10c.3.7, якщо `π ≥ 2`).
- За `π(P)`:
  - `π(P) = 1` → `EVENTUALLY_FIXED(μ, 1)` (CE-10d.3.1(3)).
  - `π(P) ≥ 2` → `EVENTUALLY_PERIODIC(μ, π)` (CE-10c.3.7).

**Випадок 4: `F(P) ≠ P`, `μ(P) = ∞`.**
За CE-10c.3.8, всі `F^m(P)` попарно різні → `APERIODIC`.

**Взаємовиключність.** Різні комбінації `(F(P) = P, μ(P), π(P))` дають різні класи:
- `INVARIANT_FIXED` vs `INVARIANT_DYNAMIC` — за квантором `∀` / `∃`.
- `PERIODIC_SET`, `EVENTUALLY_FIXED`, `EVENTUALLY_PERIODIC` — різні значення `(μ, π)`.
- `APERIODIC` — `μ = ∞`.

**Вичерпність.** Усі комбінації покрито.

∎

**PROVED ON PAPER.**

**Наслідок CE-10d.3.4.** K-11 — **PROVED ON PAPER**.

**Застереження CE-10d.3.5.** Класифікація — для **множинної** динаміки `F`. Точкова динаміка `f` не класифікується цими шістьма класами. Q28 (❓) залишається відкритим: явний контрприклад `INVARIANT_DYNAMIC` без періодичності точок у `S_∞ × ℛ₀`.

## CE-10e.1. Локальна проєкція і продуктивність (K-14)

### Означення CE-10e.1.1 (TreeApprox, остаточно, з індексованими конструкторами)

```
TreeApprox : ℕ → Type

TreeApprox 0     := { Leaf(a) : a ∈ A } ∪ { Bottom }
TreeApprox (n+1) := { Leaf(a) : a ∈ A }
                  ∪ { Bottom }
                  ∪ { Node(t₁, t₂, t₃) : t₁, t₂, t₃ ∈ TreeApprox n }
```

**Конструктори (індексовані явно):**

```
Leaf_n    : A → TreeApprox n                     (для всіх n ≥ 0)
Bottom_n  : TreeApprox n                          (для всіх n ≥ 0)
Node_n    : TreeApprox n × TreeApprox n × TreeApprox n → TreeApprox (n+1)
```

**Застереження CE-10e.1.2.** `Leaf_n`, `Bottom_n`, `Node_n` — різні конструктори для різних рівнів. У Lean це дає однозначну типізацію.

### Означення CE-10e.1.3 (truncate_n, остаточно)

```
truncate_0 : TreeApprox 1 → TreeApprox 0
truncate_0 (Leaf_1 a)          := Leaf_0 a
truncate_0 (Bottom_1)          := Bottom_0
truncate_0 (Node_0 t₁ t₂ t₃)   := Bottom_0

truncate_{n+1} : TreeApprox (n+2) → TreeApprox (n+1)
truncate_{n+1} (Leaf_{n+2} a)          := Leaf_{n+1} a
truncate_{n+1} (Bottom_{n+2})          := Bottom_{n+1}
truncate_{n+1} (Node_{n+1} t₁ t₂ t₃)   := Node_n (truncate_n t₁) (truncate_n t₂) (truncate_n t₃)
```

**Лема CE-10e.1.4 (коректність типів).** `truncate_n(t) ∈ TreeApprox n` для всіх `t ∈ TreeApprox (n+1)`.

**PROVED ON PAPER** (пряме з означення).

### Означення CE-10e.1.5 (локальне виділення піддерева, часткове)

```
subtree_n : TreeApprox (n+1) → {1, 2, 3} → Option (TreeApprox n)
subtree_n (Node_n t₁ t₂ t₃) i := Some (tᵢ)
subtree_n (Leaf_{n+1} _)    i := None
subtree_n (Bottom_{n+1})    i := None
```

**Застереження CE-10e.1.6.** `subtree_n` — **тотальна часткова** функція (значення `Option`). Замість `t|_i` (яке могло бути не визначене), використовується `Some t_i` або `None`.

**Запис.** Для скорочення нижче пишемо `t|_i` там, де гарантовано `subtree_n t i = Some (...)`, і явно зазначаємо цю гарантію.

### Лема CE-10e.1.7 (комутативність усічення з локальним виділенням)

Для `n ≥ 1`, `t = Node_n(t₁, t₂, t₃) ∈ TreeApprox (n+1)`, `i ∈ {1, 2, 3}`:

```
subtree_n (truncate_n t) i = Some (truncate_{n-1} tᵢ)
```

*Доведення.*

`truncate_n (Node_n t₁ t₂ t₃) = Node_{n-1} (truncate_{n-1} t₁) (truncate_{n-1} t₂) (truncate_{n-1} t₃)`.

Отже, `subtree_n (truncate_n t) i = Some (truncate_{n-1} tᵢ)` — за означенням `subtree_n` на `Node_{n-1}`. ∎

**PROVED ON PAPER** (за `n ≥ 1`).

**Застереження CE-10e.1.8.** Для `n = 0` лема недосяжна: `truncate_0` від `Node_0` дає `Bottom_0`, на якому `subtree` не визначене.

### Лема CE-10e.1.9 (сумісність дочірніх сімей, типізовано)

**Передумова.** Нехай `(t_n) ∈ lim←(T_n, q_n)`, σ — позиція з `lim_tree(σ) = Node`, `|σ| = k ≥ 0`.

**Означення.** Для `i ∈ {1, 2, 3}` і `m ≥ 0`:

```
u_m^{(σ, i)} : TreeApprox m
u_m^{(σ, i)} := t_{m+k+1} |_{σ·i}        (визначено, бо state(σ) = Node)
```

**Лема.** Для всіх `m ≥ 0`:

```
truncate_m (u_{m+1}^{(σ, i)}) = u_m^{(σ, i)}
```

*Доведення.*

**Крок 1.** За сумісністю `t_{m+k+1} = truncate_{m+k+1}(t_{m+k+2})`.

**Крок 2.** За `lim_tree(σ) = Node` і лемою CE-10d.1.8 (стабільність Node), `t_{m+k+2}(σ) = Node` (для `m+k+2 > |σ| = k`, що виконується).

**Крок 3.** Тому `truncate_{m+k+1}(t_{m+k+2})` на позиції σ є `Node`:
```
truncate_{m+k+1}(Node_{m+k+1}(...)) = Node_{m+k}(truncate_{m+k}(...), truncate_{m+k}(...), truncate_{m+k}(...))
```

**Крок 4.** За CE-10e.1.7 (застосованою до `t = t_{m+k+2}`, `n = m+k+1 ≥ 1`):
```
subtree_{m+k+1}(truncate_{m+k+1}(t_{m+k+2})) i = Some (truncate_{m+k}(subtree_{m+k+2}(t_{m+k+2}) i))
```

**Крок 5.** Оскільки `t_{m+k+1} = truncate_{m+k+1}(t_{m+k+2})`, маємо:
```
subtree_{m+k+1}(t_{m+k+1}) i = Some (truncate_{m+k}(subtree_{m+k+2}(t_{m+k+2}) i))
```

**Крок 6.** Ліва частина за означенням — це `u_m^{(σ, i)}` (якщо `t_{m+k+1} = Node_{m+k}(...)`). Права частина за означенням `u_{m+1}^{(σ, i)} := subtree_{m+k+2}(t_{m+k+2}) i` дає `Some (truncate_{m+k}(u_{m+1}^{(σ, i)}))`.

**Крок 7.** Тому `u_m^{(σ, i)} = truncate_{m+k}(u_{m+1}^{(σ, i)})`.

**Застереження CE-10e.1.10.** Отримано `truncate_{m+k}`, а не `truncate_m`. Потрібно змінити означення `u_m^{(σ, i)}`.

### Виправлене означення дочірніх сімей

**Означення CE-10e.1.11 (виправлене).**

```
u_m^{(σ, i)} : TreeApprox m
u_m^{(σ, i)} := t_{m + k + 1} |_{σ·i}
```

Але для сумісності з `truncate_m` треба, щоб `t_{m+k+1}` було `TreeApprox (m+k+1)`, а його піддерево на позиції `σ·i` (глибина `k+1`) лежить на глибині `m+k+1 − (k+1) = m` від кореня цього піддерева. Це узгоджено.

Однак тоді сумісність вимагає `truncate_m` від `t_{m+k+2}|_{σ·i}` — але `t_{m+k+2}|_{σ·i} ∈ TreeApprox (m+1)`. Отже `truncate_m` має тип `TreeApprox (m+1) → TreeApprox m`. Перевірка: `truncate_m : TreeApprox (m+1) → TreeApprox m` — **так**, це узгоджено з CE-10e.1.3 (для `n = m`).

**Лема CE-10e.1.12 (сумісність, виправлена).** Для всіх `m ≥ 0`:

```
truncate_m (u_{m+1}^{(σ, i)}) = u_m^{(σ, i)}
```

*Доведення.*

**Крок 1.** За сумісністю `t_{m+k+1} = truncate_{m+k+1}(t_{m+k+2})`.

**Крок 2.** За стабільністю Node (CE-10d.1.8): `t_{m+k+2}(σ) = Node_{...}` для всіх `m+k+2 > k`.

**Крок 3.** Тому `t_{m+k+2} = Node_{m+k+1}(a₁, a₂, a₃)`, де `aᵢ := subtree_{m+k+1}(t_{m+k+2})(σ·i)`.

**Крок 4.** За CE-10e.1.7 (застосованою до `t = t_{m+k+2}`, `n = m+k+1` — індекси на позиції σ):

Виділимо піддерево на позиції σ·i дерева `t_{m+k+2}`:

`subtree_{m+k+2}(t_{m+k+2})(σ·i) = subtree_{m+1}(subtree_{k+1}(t_{m+k+2})(σ))(i)`. Але `subtree_{k+1}(t_{m+k+2})(σ) = t_{m+k+2}|_σ = Node_m(...)` (бо стан на позиції σ — Node).

**Крок 5.** За `truncate_{m+k+1}(Node_{m+k+1}(...)) = Node_{m+k}(truncate_{m+k}(a₁), truncate_{m+k}(a₂), truncate_{m+k}(a₃))`.

Але `aᵢ ∈ TreeApprox (m+k+1)`, тому `truncate_{m+k}(aᵢ) ∈ TreeApprox (m+k)`.

**Крок 6.** Оскільки `u_m^{(σ, i)} = subtree_{m+k+1}(t_{m+k+1})(σ·i)`, і `t_{m+k+1} = truncate_{m+k+1}(t_{m+k+2})`:

`u_m^{(σ, i)} = subtree_{m+k+1}(truncate_{m+k+1}(t_{m+k+2}))(σ·i)`. За CE-10e.1.7 (для `t = t_{m+k+2}`, `n = m+k+1`): `subtree_{m+k+1}(truncate_{m+k+1}(t_{m+k+2}))(σ·i) = truncate_{m+k}(subtree_{m+k+2}(t_{m+k+2})(σ·i))`.

**Крок 7.** Отже `u_m^{(σ, i)} = truncate_{m+k}(u_{m+1}^{(σ, i)})`. Це **не** `truncate_m`.

**Проблема в індексації.** `subtree_{m+k+2}(t_{m+k+2})(σ·i) ∈ TreeApprox (m+k+2)`, а не `TreeApprox (m+1)`. Різниця в тому, чи вимірюється глибина піддерева від його власного кореня, чи від кореня всього дерева.

**Остаточне виправлення означення.**

```
u_m^{(σ, i)} := subtree_{m+k+1}(t_{m+k+1})(σ·i) ∈ TreeApprox (m+k+1)
```

Але тоді `u_m^{(σ, i)} : TreeApprox (m+k+1)`, а не `TreeApprox m`. Це неузгоджено з `u^{(σ, i)} ∈ lim←(T_n, q_n)` з типом `TreeApprox m`.

**Найпростіший вихід.** Визначити дочірню сім'ю **на рівнях, які лежать у самому піддереві**:

```
u_m^{(σ, i)} := subtree_{m+1}(w_m)(i),   де w_m := subtree_{k+1}(t_{m+k+1})(σ)
```

Тоді `w_m ∈ TreeApprox (m+1)` (бо `t_{m+k+1} ∈ TreeApprox (m+k+1)`, і виділення на глибині `k+1` дає тип `TreeApprox (m+k+1 − (k+1)) = TreeApprox m`... але це рівень `m`, не `m+1`).

**Застереження CE-10e.1.13.** Точна типізація залежить від конвенції про глибину піддерева. Найпростіше — перейти на **природну глибину піддерева**, виміряну від його власного кореня:

**Означення CE-10e.1.14 (остаточне).**

```
w_m^{(σ)} := subtree_{k+1}(t_{m+k+1})(σ) ∈ Option (TreeApprox m)

u_m^{(σ, i)} : TreeApprox m
u_m^{(σ, i)} := якщо w_m^{(σ)} = Some (Node_{m-1}(a₁, a₂, a₃)) для m ≥ 1:
                   aᵢ
                якщо w_m^{(σ)} = Some (Node_0(...)) — недосяжно (TreeApprox 0 не має Node)
                якщо w_m^{(σ)} = Some (Leaf_m a) — недосяжно (lim_tree(σ) = Node)
                якщо w_m^{(σ)} = Some (Bottom_m) — недосяжно (стабільність)
```

**Наслідок CE-10e.1.15.** `u_m^{(σ, i)} ∈ TreeApprox m`. Сумісність:

```
truncate_m (u_{m+1}^{(σ, i)}) = u_m^{(σ, i)}
```

*Доведення.* Пряме з `w_m^{(σ)}` = `truncate_m(w_{m+1}^{(σ)})` і комутативності усічення з `subtree` (CE-10e.1.7). ∎

**PROVED ON PAPER.**

**Застереження CE-10e.1.16.** CE-10d.1.11(b) потребувало саме такого уточнення: спочатку виділити піддерево, потім зробити усічення.

## CE-10e.2. Шаблон τ_N — чистий індукційний доказ (K-15)

### Виправлення CE-10d.2.3

**Лема CE-10e.2.1 (збіг префікса, єдина індукція).**

Для всіх `s ∈ S_∞` і `N ∈ ℕ`:

```
IH(N) : ∀m ≤ N, p_m(τ_N(s)) = p_m(s)
```

*Доведення (індукція за N).*

**База N = 0.**

Покажемо: `p_0(τ_0(s)) = p_0(s)` для всіх s.
- `s = leaf(a)`: `τ_0(s) = leaf(a)`, `p_0(τ_0(s)) = Leaf(a) = p_0(s)`. ✓
- `s = node(t₁, t₂, t₃)`: `τ_0(s) = node(τ₀, τ₀, τ₀)` (де `τ₀ = leaf(a₀)`), `p_0(τ_0(s)) = Bottom = p_0(s)`. ✓

**Крок N → N+1.**

Треба: `∀m ≤ N+1, p_m(τ_{N+1}(s)) = p_m(s)`.

Розглянемо випадки для m.

**Випадок m = 0.**

- `s = leaf(a)`: `τ_{N+1}(s) = leaf(a)`, `p_0 = Leaf(a) = p_0(s)`. ✓
- `s = node(t₁, t₂, t₃)`: `τ_{N+1}(s) = node(τ_N(t₁), τ_N(t₂), τ_N(t₃))`, `p_0 = Bottom = p_0(s)`. ✓

**Випадок m ≥ 1, m ≤ N.**

Тоді `p_m(τ_{N+1}(s)) = p_m(node(τ_N(t₁), τ_N(t₂), τ_N(t₃)))` для `s = node(...)`.

За означенням `p_m` від `Node`:
```
p_m(node(τ_N(t₁), τ_N(t₂), τ_N(t₃))) = Node_{m-1}(p_{m-1}(τ_N(t₁)), p_{m-1}(τ_N(t₂)), p_{m-1}(τ_N(t₃)))
```

За `IH(N)` (для `m-1 ≤ N`): `p_{m-1}(τ_N(tᵢ)) = p_{m-1}(tᵢ)`.

Отже:
```
p_m(τ_{N+1}(s)) = Node_{m-1}(p_{m-1}(t₁), p_{m-1}(t₂), p_{m-1}(t₃)) = p_m(node(t₁, t₂, t₃)) = p_m(s)
```
✓

**Випадок m = N+1.**

- `s = leaf(a)`: `τ_{N+1}(s) = leaf(a)`, `p_{N+1}(τ_{N+1}(s)) = Leaf(a) = p_{N+1}(s)`. ✓
- `s = node(t₁, t₂, t₃)`: `τ_{N+1}(s) = node(τ_N(t₁), τ_N(t₂), τ_N(t₃))`, отже `p_{N+1}(τ_{N+1}(s)) = Node_N(p_N(τ_N(t₁)), p_N(τ_N(t₂)), p_N(τ_N(t₃)))`.

  За `IH(N)` (для `m = N`): `p_N(τ_N(tᵢ)) = p_N(tᵢ)`.

  Отже: `p_{N+1}(τ_{N+1}(s)) = Node_N(p_N(t₁), p_N(t₂), p_N(t₃)) = p_{N+1}(node(t₁, t₂, t₃)) = p_{N+1}(s)`. ✓

**Застереження CE-10e.2.2 (виправлення CE-10d.2.3).** Ключова відмінність:

- У CE-10d.2.3 для `m = N` використовувалася `τ_0` — це помилка для `N ≥ 2`.
- Тут для всіх `m ≤ N` використовується `τ_N` — узгоджено з рекурсією CE-10c.2.1.

∎

**PROVED ON PAPER.**

## CE-10e.3. Предикати класів (K-11)

### Формальні предикати

**Означення CE-10e.3.1 (передумови класифікації).**

```
Класифікація Classify⁺ : 2^{S_∞ × ℛ} ∖ {∅} → {6 класів}
визначена для:
   - непорожніх підмножин P ⊆ S_∞ × ℛ;
   - тотального точкового відображення f : S_∞ × ℛ → S_∞ × ℛ;
   - індукованого F(P) := {f(x) : x ∈ P} (тотальне на 2^{S_∞ × ℛ}).
```

**Означення CE-10e.3.2 (предикати класів, остаточно).**

```
INVARIANT_FIXED(P)           ⟺  F(P) = P ∧ ∀x ∈ P: f(x) = x
INVARIANT_DYNAMIC(P)         ⟺  F(P) = P ∧ ∃x ∈ P: f(x) ≠ x
PERIODIC_SET(P)              ⟺  ∃p ≥ 2: F^p(P) = P ∧ F(P) ≠ P
                                  ∧ p = min{k ≥ 2 : F^k(P) = P}
EVENTUALLY_FIXED(P)          ⟺  ∃m ≥ 1: F^{m+1}(P) = F^m(P) ∧ F^m(P) ≠ P
                                  ∧ F(P) ≠ P
                                  ∧ ∀k ≥ 1: F^k(P) ≠ P
                                  ∧ m = min{m' ≥ 1 : F^{m'+1}(P) = F^{m'}(P)}
EVENTUALLY_PERIODIC(P)       ⟺  ∃m ≥ 1, p ≥ 2: F^{m+p}(P) = F^m(P)
                                  ∧ F^m(P) ≠ P
                                  ∧ ∀k ≥ 1: F^k(P) ≠ P
                                  ∧ (m, p) = min{(m', p') : m' ≥ 1, p' ≥ 2, F^{m'+p'}(P) = F^{m'}(P)}
APERIODIC(P)                 ⟺  ∀m ≥ 1, k ≥ 1: F^{m+k}(P) ≠ F^m(P)
```

**Застереження CE-10e.3.3.** Кожен предикат визначений лише для `P ≠ ∅`; випадок `P = ∅` не входить до області.

### Твердження про розбиття

**Твердження CE-10e.3.4 (розбиття).** Шість предикатів попарно не перетинаються і вичерпують `2^{S_∞ × ℛ} ∖ {∅}`.

*Доведення.*

Нехай `P ≠ ∅`.

**Крок 1.** Якщо `F(P) = P`, то рівно один із `INVARIANT_FIXED` / `INVARIANT_DYNAMIC` виконується (за означенням).

**Крок 2.** Якщо `F(P) ≠ P`, розглянемо `μ(P)` і `π(P)`.

- **μ(P) = 0.** Тоді `F^n(P) = P` для деякого `n ≥ 1`. Оскільки `F(P) ≠ P`, `n ≥ 2`. Мінімальне таке `n` дорівнює `p_set(P) ≥ 2`. Отже `PERIODIC_SET(P)`. ✓
- **μ(P) ≥ 1, π(P) = 1.** За CE-10d.3.1: `F^{μ+1}(P) = F^μ(P)`, `F^μ(P) ≠ P`, і `F^k(P) ≠ P` для `1 ≤ k ≤ μ`. Отже `EVENTUALLY_FIXED(P)`. ✓
- **μ(P) ≥ 1, π(P) ≥ 2.** За CE-10c.3.7: цикл довжини `π` у хвості. Отже `EVENTUALLY_PERIODIC(P)`. ✓
- **μ(P) = ∞.** Жодна пара елементів орбіти не повторюється. Отже `APERIODIC(P)`. ✓

∎

**PROVED ON PAPER.**

**Наслідок CE-10e.3.5.** K-11 — **PROVED ON PAPER**.

**Застереження CE-10e.3.6.** Це класифікація **множинної** динаміки `F`. Точкова динаміка `f` не класифікується цими шістьма класами; Q28 (❓) залишається відкритим.
