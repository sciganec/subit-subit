## CE-10a.0. Принцип

Аудит CE-10 визнав напрям правильним, але виявив чотири конкретні прогалини:

1. **K-14.** Домен і індексація `p_n`, `lim_tree`, базовий рівень не зафіксовані явно; лема CE-10.1.2(a) частково передбачає те, що має довести.
2. **K-15.** Означення `S_∞^{(N)}` неоднозначне; скінченність і ε-мережність потребують формального доведення з правильними границями.
3. **K-09.** Твердження «GP не тягне EP(N)» — надто категоричне; типологія потребує прив'язки до конкретних предикатів.
4. **K-11.** Означення `F` для множин і `f` для точок треба розділити; `INVARIANT_*` не можна визначати через поведінку точок без явної конструкції.

CE-10a — **точковий** patch. Він не змінює архітектуру SUBIT-∞ і не відкликає CE-10 загалом. Він уточнює чотири конкретні місця.

**Правило CE-10a:** кожне уточнення супроводжується явною передумовою або контрприкладом.

## CE-10a.1. Домен, індексація, базовий рівень (K-14)

### Діагноз

CE-7.2 означило `TreeApprox : ℕ → Type`, `truncate : TreeApprox (n+1) → TreeApprox n`, `project : (n : ℕ) → S_∞ → TreeApprox n`. Але:

- базова конвенція `project_0` не зафіксована явно щодо типів кореня;
- `lim_tree` визначено на позиціях, які **можуть не існувати** у скінченній апроксимації `t_n`;
- лема CE-10.1.2(a) використовує умову (ii) з CE-9.1.5 у доведенні того, що й так міститься в (ii).

### Виправлення

**Означення CE-10a.1.1 (TreeApprox, остаточно).**

```
TreeApprox : ℕ → Type

Leaf   : A → TreeApprox n           (для всіх n ≥ 0)
Bottom : TreeApprox n                (для всіх n ≥ 0)
Node   : TreeApprox n × TreeApprox n × TreeApprox n → TreeApprox (n+1)
```

**Означення CE-10a.1.2 (truncate, узгоджене).**

```
truncate_0 : TreeApprox 1 → TreeApprox 0
truncate_0 (Leaf a)              := Leaf a
truncate_0 Bottom                := Bottom
truncate_0 (Node _ _ _)          := Bottom

truncate_{n+1} : TreeApprox (n+2) → TreeApprox (n+1)
truncate_{n+1} (Leaf a)              := Leaf a
truncate_{n+1} Bottom                := Bottom
truncate_{n+1} (Node t₁ t₂ t₃)       := Node (truncate_n t₁) (truncate_n t₂) (truncate_n t₃)
```

**Означення CE-10a.1.3 (project, базова конвенція).**

```
project_0 : S_∞ → TreeApprox 0
project_0 (leaf a)      := Leaf a
project_0 (node _ _ _)  := Bottom

project_{n+1} : S_∞ → TreeApprox (n+1)
project_{n+1} (leaf a)          := Leaf a
project_{n+1} (node t₁ t₂ t₃)   := Node (project_n t₁) (project_n t₂) (project_n t₃)
```

**Застереження CE-10a.1.4.** У базовій конвенції: `project_0(internal) = Bottom`. Це не «дефект», а маркер, що «на рівні 0 внутрішній вузол не розрізняється від обрізаного». Узгоджено з `truncate_0(Node _ _ _) = Bottom`.

**Лема CE-10a.1.5 (рекурсія).** `project_n = truncate_n ∘ project_{n+1}`.

*Доведення.* Структурна індукція за `s ∈ S_∞` з окремими випадками `n = 0` і `n ≥ 1`. ∎

**PROVED ON PAPER.**

### Індексація позицій

**Означення CE-10a.1.6 (позиція, з існуванням).** Для `t ∈ TreeApprox n` і `σ ∈ {1, 2, 3}^{<ω}`:

```
t(σ) — визначене ⟺ |σ| ≤ n і всі строгі префікси σ у t — вузли Node
```

**Означення CE-10a.1.7 (lim_tree, з явною областю).** Для `(t_n) ∈ lim←(T_n, q_n)`:

```
lim_tree(σ) := Leaf(a)      якщо ∃n: σ існує в t_n, |σ| < n і t_n(σ) = Leaf(a)
lim_tree(σ) := Node         якщо ∃n: σ існує в t_n, |σ| < n і t_n(σ) = Node_{...}
lim_tree(σ) := undefined    інакше
```

**Застереження CE-10a.1.8.** Умова `|σ| < n` **обов'язкова**: на рівні `|σ| = n` позиція σ завжди може бути `Bottom` (фронтирна мітка). Для «граничного» значення треба дивитися **суворо глибші** рівні.

**Лема CE-10a.1.9 (стабілізація).** Якщо `lim_tree(σ)` визначено, то `∃N_σ: ∀n ≥ N_σ: t_n(σ) = lim_tree(σ)`.

*Доведення.* За означенням `lim_tree`. Для `|σ| < n` усічення `truncate_n` не змінює позицію σ (бо вона не на фронтирі). Отже, значення стабілізується. ∎

**PROVED ON PAPER.**

### Продуктивність (виправлення CE-10.1.2)

**Означення CE-10a.1.10 (L_prod).**

```
L_prod := { (t_n) ∈ lim← : lim_tree((t_n)) ∈ S_∞ }
```

**Лема CE-10a.1.11 (характеризація, формальна).** `(t_n) ∈ L_prod` тоді й лише тоді, коли:

- **(i)** `lim_tree(∅)` визначено;
- **(ii)** для будь-якої позиції σ, якщо `lim_tree(σ) = Node`, то `lim_tree(σ · i)` визначено для всіх `i ∈ {1, 2, 3}`;
- **(iii)** для будь-якої позиції σ з `lim_tree(σ) = Leaf(a)`, не існує `i` з `lim_tree(σ · i)` визначеним.

*Доведення.* Пряме з означення `S_∞ = νX.(A ⊔ X³)` і `lim_tree` (CE-10a.1.7). ∎

**PROVED ON PAPER.**

**Лема CE-10a.1.12 (продуктивність дочірніх послідовностей).**

Нехай `(t_n) ∈ L_prod` і σ — позиція з `lim_tree(σ) = Node`. Тоді для кожного `i ∈ {1, 2, 3}`:

**(a)** `lim_tree(σ · i)` визначено.

**(b)** Послідовність `u^{(σ, i)} := ((t_{m+|σ|+1})|_{σ·i})_m` належить `lim←`.

**(c)** `u^{(σ, i)} ∈ L_prod`.

*Доведення.*

**(a)** Пряме з (ii) CE-10a.1.11. Це **не** приховує циклічності, бо `L_prod` визначено через (i)–(iii), а (ii) — це означення, а не наслідок. Лема CE-10a.1.11 перевіряє, що (i)–(iii) еквівалентні приналежності `L_prod`.

**(b)** Сумісність. Для кожного m:

```
truncate_m(u^{(σ, i)}_{m+1}) = truncate_m((t_{m+|σ|+2})|_{σ·i})
                              = (truncate_{m+|σ|+1}(t_{m+|σ|+2}))|_{σ·i}
                              = (t_{m+|σ|+1})|_{σ·i}
                              = u^{(σ, i)}_m
```

(використано CE-10a.1.2 і комутативність усічення з виділенням піддерева).

**(c)** Треба (i)–(iii) для `u^{(σ, i)}`.
- **(i)** `lim_tree` для `u^{(σ, i)}` — це `lim_tree(σ · i)` у вихідній послідовності, визначено за (a). ✓
- **(ii)** Для будь-якої позиції τ у `u^{(σ, i)}` з `lim_tree(τ) = Node`: це відповідає `lim_tree(σ · i · τ) = Node` у вихідній послідовності. За (ii) вихідної послідовності, `lim_tree(σ · i · τ · j)` визначено для всіх j. Отже, у `u^{(σ, i)}` всі дочірні гілки визначені. ✓
- **(iii)** Аналогічно. ✓

∎

**PROVED ON PAPER.**

**Наслідок CE-10a.1.13.** Сюр'єктивність `p : S_∞ → L_prod` (CE-10.1.3) коректна.

**Статус K-14:** PROVED ON PAPER.

## CE-10a.2. Скінченні ε-мережі (K-15)

### Діагноз

Означення CE-10.2.4 `S_∞^{(N)} := { s : depth(s) ≤ N або усі гілки s глибини N вже встановлені }` **не є формальним**: друга частина умови не має чіткого означення членства.

### Виправлення

**Означення CE-10a.2.1 (шаблон τ₀).**

```
τ₀ := leaf(a₀) ∈ S_∞
```

де `a₀ ∈ A` — фіксований елемент (наприклад, `a₀ = 00`).

**Означення CE-10a.2.2 (S_∞^{(N)}, формальне).**

`S_∞^{(N)}` — множина `s ∈ S_∞` таких, що:

- для всіх позицій σ з `|σ| ≤ N`: значення `s(σ)` довільне (`Leaf(a)`, `Node`, або не визначене у випадку, коли предок — листок);
- для всіх позицій σ з `|σ| = N`: якщо `s(σ)` не визначене (бо предок — листок), то нічого не накладається; якщо `s(σ) = Node`, то для всіх позицій `σ · τ` з `|τ| ≥ 1`: `s(σ · τ)` визначається шаблоном `τ₀` рекурсивно:

```
для кожної позиції σ · τ · i з |σ| = N, |τ| ≥ 0:
    s(σ · τ · i) := 
        Leaf(a₀)   якщо |τ| = 0
        Node(Leaf(a₀), Leaf(a₀), Leaf(a₀))   якщо |τ| ≥ 1
```

**Застереження CE-10a.2.3 (неформальна інтерпретація).** `S_∞^{(N)}` — це дерева, у яких «хвіст» глибше рівня N замінено на фіксований шаблон: листок `leaf(a₀)` на глибині N, і далі — стандартне продовження.

**Лема CE-10a.2.4 (S_∞^{(N)} ⊆ S_∞).** Для кожного N: `S_∞^{(N)} ⊆ S_∞`.

*Доведення.* Кожне `s ∈ S_∞^{(N)}` — це або скінченне дерево глибини ≤ N (якщо на глибині N усі листки), або дерево з фіксованим шаблонним хвостом. Обидва випадки дають елемент `S_∞`. ∎

**PROVED ON PAPER.**

**Лема CE-10a.2.5 (скінченність).** `|S_∞^{(N)}| < ∞`.

*Доведення.* Дерево `s ∈ S_∞^{(N)}` визначається:
- вибором для кожної позиції σ з `|σ| < N`: `Leaf(a)` (для `|A|` = 4 варіантів), `Node` (1 варіант), або «не визначене» (1 варіант). Усього `|A| + 2` варіантів на позицію;
- хвіст за рівнем N фіксований.

Загальна кількість: `(|A| + 2)^{(3^N − 1)/2}` — скінченне. ∎

**PROVED ON PAPER.**

**Лема CE-10a.2.6 (ε-мережа).** Для кожного ε > 0 існує N ∈ ℕ таке, що `S_∞^{(N)}` — ε-мережа для `(S_∞, d_S)`.

*Доведення.*

Нехай ε > 0. Виберемо N так, щоб `2^{-(N+1)} < ε` (тобто `N + 1 > log₂(1/ε)`).

Для будь-якого `s ∈ S_∞` побудуємо `s' ∈ S_∞^{(N)}`:

- для позицій σ з `|σ| ≤ N`: `s'(σ) := s(σ)` (збіг);
- для позицій σ з `|σ| = N` з `s(σ) = Node`: хвіст `s'` заповнюється за шаблоном CE-10a.2.2;
- для позицій σ з `|σ| < N` з `s(σ) = Leaf(a)`: `s'(σ · i) := undefined` для всіх i (тобто листок успадковується).

Тоді для всіх `m ≤ N`: `p_m(s) = p_m(s')`. Отже, `δ(s, s') ≥ N + 1`, і `d_S(s, s') ≤ 2^{-(N+1)} < ε`. ✓

Отже, `S_∞^{(N)}` — скінченна ε-мережа. ∎

**PROVED ON PAPER.**

**Теорема CE-10a.2.7 (цілковита обмеженість).** `(S_∞, d_S)` цілком обмежений.

*Доведення.* Для кожного ε > 0 існує скінченна ε-мережа (CE-10a.2.6). ∎

**PROVED ON PAPER** за передумов CE-10a.1 (метрика) і CE-10a.2.2 (означення `S_∞^{(N)}`).

**Наслідок CE-10a.2.8.** Разом із повнотою (CE-10.2.3) отримуємо компактність `S_∞`.

**Статус K-15:** PROVED ON PAPER.

**Застереження CE-10a.2.9.** Доведення компактності **не** залежить від компактності `lim←`. Воно використовує лише метричну структуру `S_∞` і шаблон `τ₀`.

**Застереження CE-10a.2.10.** Якщо `A` нескінченний, `|A| + 2` нескінченне, і доказ не працює. Це **Q26 (❓)**.

## CE-10a.3. Сертифікати: прив'язка до предикатів (K-09)

### Діагноз

CE-10.3.2.6 — надто категоричне: «GP не тягне EP(N) для жодного N». Це **не універсальне** твердження; залежить від конкретних предикатів.

### Виправлення

**Означення CE-10a.3.1 (предикат префікса).** Нехай `φ(k, τ)` — предикат, визначений для `k ∈ ℕ` і траєкторії `τ`. Визначимо:

```
Φ_PH(N, τ) := ∀k ≤ N: φ(k, τ)         (префіксний, універсальний за k ≤ N)
Φ_PP(k, τ) := φ(k, τ)                  (точковий)
Φ_EP(N, τ) := ∃k ≤ N: φ(k, τ)         (префіксний, екзистенційний за k ≤ N)
```

**Твердження CE-10a.3.2 (правила перенесення).**

1. **PH:** `Φ_PH(N+1, τ) ⟹ Φ_PH(N, τ)`. **Не** навпаки в загальному випадку.
2. **EP:** `Φ_EP(N, τ) ⟹ Φ_EP(N+1, τ)` (бо множина k ≤ N розширюється). **Не** навпаки в загальному випадку.
3. **PP:** `Φ_PP(k, τ)` не тягне `Φ_PP(k', τ)` для `k' ≠ k` **у загальному випадку**; але може тягнути для конкретних `φ`, якщо `φ(k, τ) ⟹ φ(k', τ)` доведено.
4. **GP:** власне глобальний предикат `Ψ(τ)` (не залежить від N). `Ψ(τ)` може тягнути `Φ_PH(N, τ)` або `Φ_EP(N, τ)` **для конкретних предикатів**, якщо це логічно випливає з семантики `Ψ`.

**Твердження CE-10a.3.3 (що НЕ виконується автоматично).** Тип предиката (PH / EP / PP / GP) **не** визначає напрямків імплікації між різними типами. Наприклад:

- PH-предикат `Φ_PH(N, τ) := ∀k ≤ N: φ(k, τ)` не тягне EP-предикат `Φ_EP(N, τ) := ∃k ≤ N: φ(k, τ)` (для довільного φ).
- GP-предикат `Ψ(τ)` може тягнути `Φ_EP(N, τ)` **лише** за явної семантичної імплікації.

**Приклад (аудит CE-10).** Нехай `Ψ(τ) := "траєкторія відвідує всі 64 стани"` і `Φ_EP(N, τ) := "на кроці ≤ N досягнуто повне покриття"`. Тоді `Ψ(τ) ⟹ Φ_EP(N_0, τ)` для деякого скінченного `N_0` (моменту повного покриття), але не для всіх N. Однак `Φ_EP(N_0, τ) ⟹ Φ_EP(N, τ)` для всіх `N ≥ N_0` (монотонність EP).

**Твердження CE-10a.3.4 (правильне правило).** Кожен алгоритм класифікації повинен:

1. Зафіксувати предикати `φ(k, τ)` і їхні типи (PH / EP / PP);
2. Довести конкретні імплікації між сертифікатами різних горизонтів (або позначити їх як відсутні);
3. Не покладатися на універсальні правила за типом.

**PROVED ON PAPER.**

**Наслідок CE-10a.3.5.** CE-10.3.2.6 відкликається. Правильне формулювання — CE-10a.3.3 і CE-10a.3.4.

**Наслідок CE-10a.3.6.** Формат сертифіката (CE-9.8) має містити:

- `predicate_name` — ім'я предиката;
- `predicate_type ∈ {PH, EP, PP}`;
- `horizon` — N для префіксних;
- `proof` — доказ імплікації або посилання на нього.

**Статус K-09:** PROVED ON PAPER.

## CE-10a.4. Множинна vs точкова динаміка (K-11)

### Діагноз

Означення CE-10.4.2(a) змішує `F(P) = P` (множинна динаміка) з поведінкою точок всередині `P`. Це призводить до неоднозначності в `INVARIANT_FIXED` і `INVARIANT_DYNAMIC`.

### Виправлення

**Означення CE-10a.4.1 (точкова динаміка).** `f : S_∞ × ℛ → S_∞ × ℛ` — точкова динаміка (оператор `F` в SUBIT).

**Означення CE-10a.4.2 (множинна динаміка).** Індукована дія на підмножинах:

```
F : 2^{S_∞ × ℛ} → 2^{S_∞ × ℛ}
F(P) := { f(x) : x ∈ P }     (прямий образ)
```

**Застереження CE-10a.4.3.** Це **не** те саме, що `f`, розширене на множини точково. `F` діє **на рівні множин**. Рівність `F(P) = P` означає, що `f(P) = P` як множини.

**Означення CE-10a.4.4 (INVARIANT_FIXED, INVARIANT_DYNAMIC).**

```
INVARIANT_FIXED(P)     ⟺ F(P) = P ∧ ∀x ∈ P: f(x) = x
INVARIANT_DYNAMIC(P)   ⟺ F(P) = P ∧ ∃x ∈ P: f(x) ≠ x
```

**Застереження CE-10a.4.5 (розрізнення).** Ці класи одночасно описують:

- **множинну інваріантність:** `F(P) = P`;
- **поведінку точок:** усі нерухомі / є рухомі.

**Контрприклад (аудит CE-10).** `P = {a, b}`, `f(a) = b`, `f(b) = a`.

- `F(P) = {f(a), f(b)} = {b, a} = P` — множинна інваріантність;
- жодна точка не нерухома (`f(a) = b ≠ a`, `f(b) = a ≠ b`);
- отже, `INVARIANT_DYNAMIC(P)`. ✓

**Це не приклад** інваріантної множини без періодичних точок — обидві точки періодичні (період 2). Це приклад інваріантної множини без **нерухомих** точок.

**Застереження CE-10a.4.6 (альтернативне розрізнення).** Якщо потрібен клас «інваріантна множина без періодичних точок», це окремий предикат:

```
INVARIANT_APERIODIC_POINTS(P) ⟺ F(P) = P ∧ ∀x ∈ P: ¬PERIODIC(x)
```

Але `PERIODIC(x)` — властивість точкової динаміки `f`, не множинної `F`.

### Означення CE-10a.4.7 (шість класів, остаточно)

```
INVARIANT_FIXED(P)           ⟺ F(P) = P ∧ ∀x ∈ P: f(x) = x
INVARIANT_DYNAMIC(P)         ⟺ F(P) = P ∧ ∃x ∈ P: f(x) ≠ x
PERIODIC_SET(p)              ⟺ p_set(P) = p ≥ 2
EVENTUALLY_FIXED(μ, π)       ⟺ μ(P) ≥ 1 ∧ π(P) = 1
EVENTUALLY_PERIODIC(μ, π)    ⟺ μ(P) ≥ 1 ∧ π(P) ≥ 2
APERIODIC(P)                 ⟺ μ(P) = ∞
```

де `μ(P), π(P)` визначені як у CE-10.4.1 на **множинній** динаміці `F`.

**Твердження CE-10a.4.8 (взаємовиключність і вичерпність).** Шість класів попарно не перетинаються і вичерпують `2^{S_∞ × ℛ} ∖ {∅}`.

*Доведення.*

Розбиття за `(F(P) = P?, μ(P), π(P))`:

- `F(P) = P`:
  - `∀x ∈ P: f(x) = x` → `INVARIANT_FIXED`.
  - `∃x ∈ P: f(x) ≠ x` → `INVARIANT_DYNAMIC`.
- `F(P) ≠ P`:
  - `μ(P) = 0` (тобто `∃n > 0: F^n(P) = P` з мінімальним μ = 0): `PERIODIC_SET(p)` для `p = π(P) ≥ 2`.
  - `μ(P) ≥ 1`:
    - `π(P) = 1` → `EVENTUALLY_FIXED(μ, 1)`.
    - `π(P) ≥ 2` → `EVENTUALLY_PERIODIC(μ, π)`.
  - `μ(P) = ∞` → `APERIODIC`.

Взаємовиключність — за означеннями. ∎

**PROVED ON PAPER.**

**Застереження CE-10a.4.9.** Порівняння `INVARIANT_DYNAMIC` з `INVARIANT_APERIODIC_POINTS` — **окреме питання**. Перший клас не гарантує, що всі точки `P` не періодичні, а лише, що не всі точки нерухомі.

**Приклад (аудит CE-10, §5).** `P = {a, b}`, `f(a) = b`, `f(b) = a`: `INVARIANT_DYNAMIC(P)` виконується, але обидві точки періодичні.

**Приклад.** `P = ℕ`, `f(n) = max(n − 1, 0)`: `F(P) = P`, `f(1) = 0 ≠ 1`, отже `INVARIANT_DYNAMIC(P)`. Але точка `1` не періодична (`f^k(1) = 0` для `k ≥ 1`). Це **абстрактний** приклад; явний контрприклад у `S_∞ × ℛ₀` — Q28 (❓).

**Статус K-11:** PROVED ON PAPER.

## CE-10a.5. Контрольні моделі A, B, C (за аудитом CE-10)

**Модель A (аудит CE-10, §6).** Кінцеве дерево `s = Node(Leaf(a), Leaf(b), Node(Leaf(c), Leaf(d), Leaf(a)))` і `s'`, змінений у третьому листку.

Перевірки:

- `project_n(Ω) = Node(...)` (усі вузли);
- `truncate_n(project_{n+1}(Ω)) = project_n(Ω)`;
- `lim_tree(Ω) = Ω`;
- `d_S(Ω, Ω) = 0`.

**Модель C.** Три системи (за CE-10.4):

1. `f(p) = q, f(q) = r, f(r) = q`. Орбіта p: `μ(p) = 1, π(p) = 2` → `EVENTUALLY_PERIODIC(1, 2)`.
2. `f(p) = q, f(q) = r, f(r) = r`. Орбіта p: `μ(p) = 2, π(p) = 1` → `EVENTUALLY_FIXED(2, 1)`.
3. `f(n) = n + 1` на `ℕ`. `μ(p) = ∞` → `APERIODIC`.
