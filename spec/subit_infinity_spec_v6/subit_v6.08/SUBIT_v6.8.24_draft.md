## Анотація

SUBIT-∞ — формальна нотаційна система для опису станів, переходів, правил еволюції та метаеволюції динамічних систем. Архітектура кумулятивна:

```
SUBIT-64  ⊂  SUBIT⁺  ⊂  SUBIT-CAT  ⊂  SUBIT-∞
```

Основний принцип — розділяти стан системи, правило переходу, динаміку траєкторії, топологічну структуру та епістемічний статус результату. Ці рівні не можна ототожнювати лише через спільну термінологію.

У консолідованій версії розмежовуються **три класифікатори**:

- **Ω_set** — класи поведінки множин під дією F;
- **Ω_point** — класи окремих станів;
- **S(τ)** — класи ω-граничної поведінки траєкторій.

Двоосьова класифікація **Ω_traj** додає до класу ω-граничної поведінки математичний тип досягнення. Обчислювальний статус фіксується окремо.

Специфікація розрізняє причинні правила ℛ₀ та правила зі скінченним обчислюваним описом ℛ₁. Вона також розрізняє категорію динамічних систем Dyn (з відомою топосною інтерпретацією) і ширшу категорію SUBIT (топосна структура якої не встановлена).

**Обмеження.** Наведені математичні означення не означають, що всі заявлені теореми формально доведені в Lean 4. Статус «доведено на папері» не еквівалентний машинно перевіреному доказу.

# Частина I. SUBIT-64 — скінченний алфавіт станів

## 1. Алфавіт примітивів

### 1.1. Єдиний базовий алфавіт

**Означення 1.1.**

```
A = {00, 01, 10, 11},   |A| = 4
```

Алфавіт має дві рівноправні інтерпретації.

**Семантична інтерпретація:**

- WHO = {ME, WE, YOU, THEY}
- WHERE = {EAST, SOUTH, WEST, NORTH}
- WHEN = {SPRING, SUMMER, AUTUMN, WINTER}

**Логічна інтерпретація (чотиризначний алфавіт Белнапа):**

```
𝔸 = {T, F, B, N}
```

**Відповідність двобітних кодів:**

| Код | Логічна | Семантична мітка |
|---|---|---|
| 10 | T | ME / EAST / SPRING |
| 11 | B | WE / SOUTH / SUMMER |
| 01 | F | YOU / WEST / AUTUMN |
| 00 | N | THEY / NORTH / WINTER |

Це одне й те саме чотириелементне кодування, а не твердження про фізичну тотожність різних семантичних понять.

### 1.2. Білаттисна структура

На `𝔸` задані два часткові порядки.

**Порядок істинності:**

- F ≤ₜ N ≤ₜ T
- F ≤ₜ B ≤ₜ T

**Порядок інформації:**

- N ≤ᵢ F ≤ᵢ B
- N ≤ᵢ T ≤ᵢ B

Ця структура може використовуватися для логічних операцій. Її властивості **не переносяться автоматично** на динаміку `S_∞`.

**Статус:** базова алгебраїчна структура визначена; прикладні інтерпретації не є емпіричними фактами.

## 2. Простір станів S₀

**Означення 2.1.**

```
S₀ = A × A × A
|S₀| = 4³ = 64
```

Кожен стан — трійка:

```
s = (α, β, γ)
```

6-бітний код:

```
b₁b₂ b₃b₄ b₅b₆
```

де:

- `b₁b₂` — WHO (ME = 10, WE = 11, YOU = 01, THEY = 00);
- `b₃b₄` — WHERE (EAST = 10, SOUTH = 11, WEST = 01, NORTH = 00);
- `b₅b₆` — WHEN (SPRING = 10, SUMMER = 11, AUTUMN = 01, WINTER = 00).

**Числове кодування:**

```
code6(s) := 32·w₂ + 16·w₁ + 8·h₂ + 4·h₁ + 2·t₂ + t₁ ∈ [0, 63]
```

**Приклади:**

- 101010 = ME / EAST / SPRING = 42;
- 111111 = WE / SOUTH / SUMMER = 63;
- 010001 = YOU / NORTH / AUTUMN = 17.

### 2.1. Статус рівня SUBIT-64

SUBIT-64 — статичний алфавіт. Він не містить оператора переходу, не визначає траєкторій і не гарантує жодної динамічної поведінки.

Гексаграмне кодування І-Цзін (Додаток A) — додаткова система індексації 64 станів. Це нотаційна відповідність; традиційна символічна інтерпретація гексаграм не є аксіомою SUBIT.

**Статус:** потужність простору та двобітне кодування визначені.

# Частина II. SUBIT⁺ — скінченна самореферентна динаміка

## 3. Простір правил і розширений стан

**Означення 3.1.** Нехай `ℛ` — непорожня скінченна множина правил:

```
ℛ = {ρ₁, …, ρₙ},   ρᵢ : S₀ → S₀
```

**Означення 3.2.** Розширений стан:

```
ŝ = (s, ρ) ∈ S₀ × ℛ
```

Правило є **частиною** розширеного стану. Це дозволяє представляти зміну правила всередині траєкторії, але саме по собі не доводить сильнішої обчислювальної виразності.

**Застереження 3.3.** Розділення `ℛ₀` (причинні правила) і `ℛ₁` (обчислювані правила) застосовується **лише** на рівні `SUBIT-∞` (§21), де `S_∞` нескінченне. У скінченній моделі `SUBIT⁺` всі правила належать одному класу.

## 4. Оператор еволюції та метаеволюція

**Означення 4.1.**

```
F : S₀ × ℛ → S₀ × ℛ
F(s, ρ) = ( f_ρ(s), g(ρ, s) )
```

де:

- `f_ρ : S₀ → S₀` — новий стан;
- `g : ℛ × S₀ → ℛ` — нове правило або параметр правила.

**Аксіома 4.2 (тотальність).** У базовій детермінованій моделі `F` — тотальна функція.

Якщо реалізація допускає невизначені переходи, помилки виконання чи ресурсне переривання, їх слід представляти окремим шаром обчислювального статусу. Не можна мовчки трактувати частковий оператор як тотальний.

### 4.1. Рівні опису

- **Рівень 0:** базовий стан `s`.
- **Рівень 1:** розширений стан `ŝ = (s, ρ)`.
- **Рівень 2:** перехід `F(ŝ)`.
- **Рівень 3:** метаеволюція `g(ρ, s)`.

Це різні способи опису однієї динамічної архітектури, а не автоматична ієрархія обчислювальної потужності.

### 4.2. Межа твердження про самореференцію

SUBIT⁺ з фіксованим скінченним простором еквівалентний автономному детермінованому скінченному автомату з відповідним простором конфігурацій. Теза «правило належить стану» є структурною зміною представлення, а не доведенням сильнішої виразності.

**Статус:** еквівалентність зі скінченним автономним автоматом — **ДОВЕДЕНО НА ПАПЕРІ**. Сильніша теза про самореферентну обчислювальну перевагу — **не встановлена**.

## 5. Траєкторії у скінченному просторі

**Означення 5.1.**

```
τ(ŝ₀) = (ŝ₀, ŝ₁, ŝ₂, …),   ŝₙ₊₁ = F(ŝₙ)
```

### 5.1. Скінченна періодичність

Якщо `S₀ × ℛ` скінченний, а `F` тотальний, то для кожного `ŝ₀` існують `m ≥ 0` і `k ≥ 1` такі, що:

```
ŝ_{m+k} = ŝ_m
```

Це наслідок принципу Діріхле.

**Статус:** ДОВЕДЕНО НА ПАПЕРІ.

### 5.2. Точкова категорія (скінченний рівень)

**Означення 5.2.1.** Для `ŝ ∈ S₀ × ℛ`:

```
Ω_point(ŝ) :=
   FIXED           якщо F(ŝ) = ŝ
   PERIODIC(p)     якщо p := min{ k > 1 : Fᵏ(ŝ) = ŝ } існує
   PREPERIODIC     інакше
```

**Застереження 5.2.2 (CE-1).** Клас `PREPERIODIC` — формальна назва передперіодичної точки. Термін `TRANSIENT` **не використовується** у формальному означенні; його можна вживати лише як неформальний синонім, якщо семантика збігається.

FIXED і PERIODIC(p) не перетинаються (p = 1 виключено).

### 5.3. Точкова категорія (нескінченний рівень)

**Означення 5.3.1.** Для `ŝ ∈ S_∞ × ℛ` визначимо чотири **незалежні предикати**:

```
P_FIXED(ŝ)                ⟺  F(ŝ) = ŝ

P_PERIODIC(ŝ)             ⟺  F(ŝ) ≠ ŝ
                              ∧ ∃p > 1: Fᵖ(ŝ) = ŝ

P_EVENTUALLY_PERIODIC(ŝ)  ⟺  F(ŝ) ≠ ŝ
                              ∧ ¬∃p > 1: Fᵖ(ŝ) = ŝ
                              ∧ ∃m ≥ 1, p ≥ 1: F^{m+p}(ŝ) = Fᵐ(ŝ)

P_APERIODIC(ŝ)            ⟺  ¬P_FIXED(ŝ)
                              ∧ ¬P_PERIODIC(ŝ)
                              ∧ ¬P_EVENTUALLY_PERIODIC(ŝ)
```

**Твердження 5.3.2.** Чотири предикати взаємовиключні.

**Означення 5.3.3.**

```
Ω_point^∞(ŝ) :=
   FIXED                       якщо P_FIXED(ŝ)
   PERIODIC(p*)                якщо P_PERIODIC(ŝ)
   EVENTUALLY_PERIODIC(m*,p*)  якщо P_EVENTUALLY_PERIODIC(ŝ)
   APERIODIC                   якщо P_APERIODIC(ŝ)
```

де `p* := min{k > 1 : Fᵏ(ŝ) = ŝ}`, `m* := min{m ≥ 1 : ∃p ≥ 1, F^{m+p}(ŝ) = Fᵐ(ŝ)}`, `p* := min{p ≥ 1 : F^{m*+p}(ŝ) = F^{m*}(ŝ)}`.

**Статус:** ДОВЕДЕНО НА ПАПЕРІ.

### 5.4. Алгоритм скінченної класифікації

```
Вхід: ŝ₀, горизонт N_max
Вихід: PointClass(ŝ₀) := (category, m, p, attractor_cycle, certificate)

visited : Map<State, ℕ> ← ∅
для n = 0, 1, …, N_max:
    якщо ŝₙ ∈ visited:
        m ← visited[ŝₙ]
        p ← n − m
        attractor_cycle ← [ŝ_m, …, ŝ_{n-1}]
        category ← FIXED / PERIODIC(p) / PREPERIODIC
        повернути
    visited[ŝₙ] ← n
    ŝₙ₊₁ ← F(ŝₙ)
повернути RESOURCE_EXCEEDED
```

Для гарантії знаходження повторення в скінченній моделі достатньо `N_max ≥ |S₀ × ℛ|`.

### 5.5. Відкликане ототожнення

**ВІДКЛИКАНО:** ототожнення `PREPERIODIC` із `CHAOTIC`. Передперіодичність — звичайна поведінка скінченного автомата. «Хаотичність» у SUBIT-∞ має окреме визначення через властивості ω-граничної динаміки (§18.6).

# Частина III. SUBIT-CAT — категорія, класифікатори та логіка

## 6. Три класифікатори

Класифікатори визначаються на **різних математичних об'єктах**. Їх не можна використовувати як взаємозамінні позначення.

### 6.1. Точна класифікація множин

**Означення 6.1.1.**

```
Classify⁺(P) := ( OrbitType(P), InclusionType(P), Chaos(P) )
```

Три незалежні складові.

### 6.2. OrbitType

**Означення 6.2.1 (пріоритетний порядок).**

```
OrbitType(P) :=
   1. INVARIANT_FIXED
         якщо F(P) = P ∧ ∀x ∈ P: F(x) = x
   2. INVARIANT_DYNAMIC
         якщо F(P) = P ∧ ¬(∀x ∈ P: F(x) = x)
   3. PERIODIC_SET(p)
         якщо ∃p ≥ 2: Fᵖ(P) = P ∧ F(P) ≠ P
   4. EVENTUALLY_FIXED(m)
         якщо ∃m ≥ 1: F^{m+1}(P) = Fᵐ(P) ∧ Fᵐ(P) ≠ P
                     ∧ ∀k ≥ 1: Fᵏ(P) ≠ P
   5. EVENTUALLY_PERIODIC(m, p)
         якщо ∃m ≥ 1, p ≥ 2: F^{m+p}(P) = Fᵐ(P)
                              ∧ F^{m+1}(P) ≠ Fᵐ(P)
                              ∧ ∀k ≥ 1: Fᵏ(P) ≠ P
   6. APERIODIC
         інакше
```

**Твердження 6.2.2 (вичерпність і взаємовиключність).** Шість класів вичерпні й взаємовиключні.

**Статус:** ДОВЕДЕНО НА ПАПЕРІ.

### 6.3. InclusionType

**Означення 6.3.1 (пріоритетний порядок).**

```
InclusionType(P) :=
   1. EQUAL_IMAGE                якщо F(P) = P
   2. DISJOINT_IMAGE             якщо F(P) ∩ P = ∅
   3. STRICT_SUBIMAGE            якщо F(P) ⊊ P
   4. STRICT_SUPERIMAGE          якщо P ⊊ F(P)
   5. OVERLAPPING_NONCOMPARABLE  інакше
```

**Твердження 6.3.2.** InclusionType утворює розбиття множини всіх `P ⊆ S_∞ × ℛ₀`.

**Статус:** ДОВЕДЕНО НА ПАПЕРІ.

### 6.4. Chaos — окремий предикат

**Означення 6.4.1.** `P` хаотична, якщо:

1. `P ≠ ∅`;
2. `P` компактна в топології `d̂`;
3. `F(P) = P`;
4. `F|_P : P → P` **неперервна**;
5. `P` мінімальна: не містить власної непорожньої замкненої F-інваріантної підмножини;
6. `h_top(P, F|_P) > 0`.

**Застереження 6.4.2.** CHAOTIC — **предикат**, не значення OrbitType і не клітинка Ω. Може співіснувати лише з OrbitType, для якого `P` інваріантна.

**Твердження 6.4.3.** На скінченному рівні SUBIT⁺ хаотичних множин немає.

**Статус:** ДОВЕДЕНО НА ПАПЕРІ.

### 6.5. Зв'язок точкової та множинної класифікації

**Твердження 6.5.1.** Для скінченної `P`: `F(P) = P` ⟹ `∀ŝ ∈ P: Ω_point(ŝ) ∈ {FIXED, PERIODIC}`.

**Твердження 6.5.2.** На `S_∞` твердження 6.5.1 **хибне**. Контрприклад: `X = ℤ`, `F(n) = n+1`, `P = ℤ`.

### 6.6. Classify⁺ vs Ω — розділення понять

**Означення 6.6.1 (домен проєкції).**

```
D_class := { Classify⁺(P) : P ⊆ S_∞ × ℛ₀ }
```

**Означення 6.6.2 (проєкція π_Ω).**

```
π_Ω : D_class → Ω
π_Ω((O, I, C)) :=
   CHAOTIC                  якщо C = ⊤
   APERIODIC_NON_CHAOTIC    якщо O = APERIODIC ∧ C = ⊥
   EVENTUALLY_PERIODIC      якщо O ∈ {EVENTUALLY_FIXED, EVENTUALLY_PERIODIC} ∧ C = ⊥
   PERIODIC_SET             якщо O = PERIODIC_SET ∧ C = ⊥
   INVARIANT_DYNAMIC        якщо O = INVARIANT_DYNAMIC ∧ C = ⊥
   INVARIANT_FIXED          якщо O = INVARIANT_FIXED ∧ C = ⊥
```

**Твердження 6.6.3 (тотальність).** `π_Ω` визначена на всьому `D_class`.

**Статус:** ДОВЕДЕНО НА ПАПЕРІ.

**Застереження 6.6.4 (втратність).** `π_Ω` **втратна**:

- `π_Ω((EVENTUALLY_FIXED(1), STRICT_SUBIMAGE, ⊥)) = π_Ω((EVENTUALLY_PERIODIC(1,2), DISJOINT_IMAGE, ⊥))`;
- параметри `m`, `p`, InclusionType, Chaos не зберігаються.

**Застереження 6.6.5.** `π_Ω(Classify⁺(A ∩ B)) ≠ π_Ω(Classify⁺(A)) ∧ π_Ω(Classify⁺(B))` у загальному випадку — через втратність.

## 7. Алгебра Ω

**Означення 7.1.** Ω — 6-елементний ланцюг:

```
CHAOTIC
  < APERIODIC_NON_CHAOTIC
  < EVENTUALLY_PERIODIC
  < PERIODIC_SET
  < INVARIANT_DYNAMIC
  < INVARIANT_FIXED
```

**Застереження 7.2 (CE-1).** Це **синтаксичний** інструмент Ґратінгової алгебри. Він **не є** класифікацією об'єктів SUBIT — для класифікації використовується `Classify⁺` (§6.1), а `Ω` виникає як втратна проєкція `π_Ω`.

**Твердження 7.3.** Ω із `∧ = min`, `∨ = max`, `→` (релятивне псевдодоповнення), `¬a := a → ⊥` утворює **алгебру Гейтінга**.

**Статус:** ДОВЕДЕНО НА ПАПЕРІ (будь-який скінченний ланцюг є алгеброю Гейтінга).

**Твердження 7.4 (недосяжність виключеного третього).**

```
EVENTUALLY_PERIODIC ∨ ¬EVENTUALLY_PERIODIC
  = EVENTUALLY_PERIODIC ≠ INVARIANT_FIXED
```

**Застереження 7.5.** Ω — самостійна алгебра; не пов'язана формально з білаттисом Белнапа на `𝔸`.

## 8. Категорія SUBIT

### 8.1. Об'єкти

**Означення 8.1.1.**

```
X = (S_X, ℛ_X, F_X, g_X)
```

де:

- `S_X` — простір станів;
- `ℛ_X` — допустимі правила;
- `F_X : S_X × ℛ_X → S_X × ℛ_X` — оператор переходу;
- `g_X : ℛ_X × S_X → ℛ_X` — компонент метаеволюції.

### 8.2. Морфізми

**Означення 8.2.1 (проєкції).**

```
p_S : S_X × ℛ_X → S_X,    p_S(s, ρ) := s
p_ℛ : S_X × ℛ_X → ℛ_X,    p_ℛ(s, ρ) := ρ
```

**Означення 8.2.2 (морфізм SUBIT).** Пара `φ = (φ_S, φ_ℛ)`, де `φ_S : S_X → S_Y`, `φ_ℛ : ℛ_X → ℛ_Y`, що задовольняє **умову динамічної сумісності**:

```
∀(s, ρ) ∈ S_X × ℛ_X:
   φ_S( p_S( F_X(s, ρ) ) ) = p_S( F_Y( φ_S(s), φ_ℛ(ρ) ) )
```

**Застереження 8.2.3.** Умова стосується **лише S-компоненти** F. Компонента `g_X` **не входить** до умови морфізму SUBIT.

**Застереження 8.2.4 (що ігнорується).** Два об'єкти з однаковими `(S, ℛ, F)` і різними `g` **ізоморфні** в SUBIT.

### 8.3. SUBIT і SUBIT_full

**Означення 8.3.1 (SUBIT_full).** Широка підкатегорія SUBIT: ті самі об'єкти; морфізми задовольняють **додатково**:

```
∀(s, ρ) ∈ S_X × ℛ_X:
   φ_ℛ( g_X(ρ, s) ) = g_Y( φ_ℛ(ρ), φ_S(s) )
```

**Твердження 8.3.2.** SUBIT_full — категорія.

**Статус:** ДОВЕДЕНО НА ПАПЕРІ.

**Застереження 8.3.3.** SUBIT_full — **широка** (wide) підкатегорія (ті самі об'єкти), а не повна.

### 8.4. Категоріальні властивості

**Твердження 8.4.1 (термінальний об'єкт).** `1 = ({∗}, {id}, F_triv, g_triv)`, де `F_triv(∗, id) := (∗, id)`, `g_triv(id, ∗) := id` — термінальний об'єкт SUBIT.

**Твердження 8.4.2 (добуток).** `X × Y` визначається покомпонентно; універсальна властивість виконується.

**Застереження 8.4.3 (CCC).**

- Для об'єктів із `g ≡ id` — декартова замкненість **встановлена** на підкатегорії оборотних F;
- Для об'єктів із нетривіальною `g` — CCC **не встановлена**;
- Для SUBIT_full як категорії з `g`-сумісними морфізмами — CCC-структура **невідома**;
- Загальний випадок — **Q1 (❓)**.

**Статус:** означення морфізму відновлено; повна декартова замкненість — **ВІДКРИТО**.

## 9. Dyn як категорія динамічних систем

### 9.1. Означення Dyn

**Означення 9.1.1.** Об'єкт Dyn — пара `(S, f)`, `f : S → S`.

**Означення 9.1.2.** Морфізм `φ : (S, f) → (T, g)` — функція `φ : S → T` з `φ ∘ f = g ∘ φ`.

### 9.2. Зв'язок із Fun(ℕ, Set)

**Твердження 9.2.1.** Dyn ≅ Fun(ℕ, Set), де `ℕ` — моноїд як категорія з одним об'єктом.

**Статус:** ДОВЕДЕНО НА ПАПЕРІ (стандартний результат).

### 9.3. Субоб'єкти Dyn

**Означення 9.3.1.** `U ⊆ S` — підоб'єкт, якщо `f(U) ⊆ U`.

**Означення 9.3.2 (час входу).**

```
χ_U(x) := min{ n ≥ 0 : fⁿ(x) ∈ U }   якщо існує
χ_U(x) := ∞                           інакше
```

**Означення 9.3.3.** `Ω_Dyn := ℕ ∪ {∞}`; дія моноїда: `n · k := max(n − k, 0)`, `∞ · k := ∞`.

**Твердження 9.3.4 (χ_U — морфізм).** Для підоб'єкта `U`: `χ_U(f(x)) = max(χ_U(x) − 1, 0)`.

**Твердження 9.3.5 (універсальна властивість).** Для будь-якого морфізма `ψ : X → Ω_Dyn` існує єдиний підоб'єкт `U ⊆ X` із `χ_U = ψ`.

**Твердження 9.3.6 (бієкція).** `Sub_Dyn(X) ≅ Hom_Dyn(X, Ω_Dyn)`.

**Твердження 9.3.7.** Dyn — топос із класифікатором `Ω_Dyn`.

**Статус:** ДОВЕДЕНО НА ПАПЕРІ (стандартний результат для топосу прешейвів).

### 9.4. Обмеження щодо топосної структури SUBIT

**Застереження 9.4.1.** Не можна робити висновок, що повна категорія SUBIT є топосом, лише тому що Dyn має топосну інтерпретацію.

**Відкрите питання Q2′ (❓).** Чи існує категорія `C`, така що `Dyn ⊆ C ⊆ SUBIT`, яка є топосом і зберігає нетривіальну метаеволюцію?

## 10. Динамічна теорія типів

**Судження.** `Γ ⊢ t : A @ τ` — у контексті `Γ` терм `t` має тип `A` у часовому стані `τ`.

**Базові правила:**

```
Рефлексивність:
   Γ, x:A@τ ⊢ x : A@τ

Еволюція:
   Γ ⊢ t:A@τ     F(A) ⊆ B
   ─────────────────────────
   Γ ⊢ F(t) : B @ (τ+1)

Стабільність:
   Γ ⊢ t:A@τ     F(A) = A
   ─────────────────────────
   Γ ⊢ t : □A @ τ

Потенційність:
   Γ ⊢ t:A@τ     ∃k: Fᵏ(A) ⊆ B
   ────────────────────────────
   Γ ⊢ t : ◇B @ τ
```

**Статус:** схема визначена; повна метатеорія збереження та повноти — **не підтверджена**.

## 11. Модальна логіка: дві різні семантики

### 11.A. LTL-подібна семантика траєкторій

**Означення 11.A.1.**

```
ŝ ⊨ X A       ⟺   F(ŝ) ∈ A                    (наступний крок)
ŝ ⊨ ◇ A       ⟺   ∃n ≥ 0: Fⁿ(ŝ) ∈ A            (колись)
ŝ ⊨ ◇⁺ A      ⟺   ∃n ≥ 1: Fⁿ(ŝ) ∈ A            (колись у майбутньому)
ŝ ⊨ □ A       ⟺   ∀n ≥ 0: Fⁿ(ŝ) ∈ A            (завжди)
ŝ ⊨ ↺ A       ⟺   ∃k > 1: Fᵏ(ŝ) ∈ A            (повернення через k > 1)
```

**Застереження 11.A.2 (CE-1).** Оператор `X` (наступний крок) — **примітивний** і **не ототожнюється** з `↺` (повернення через k > 1). Це різні поняття.

**Твердження 11.A.3 (аксіоми).**

```
(X1)   X A → ◇⁺A
(X2)   X A ∧ X B ↔ X(A ∧ B)
(X3)   X A ∨ X B ↔ X(A ∨ B)
(D1)   ◇A ↔ A ∨ X ◇A
(D2)   ◇⁺A ↔ X ◇A
(D3)   ◇A ↔ A ∨ ◇⁺A
(B1)   □A ↔ A ∧ X □A
(B2)   □A → A
(B3)   □A → X □A
(B4)   □A → ◇A
(B5)   □(A → B) → (□A → □B)
(R1)   ↺A ↔ ◇⁺(X A)
(R2)   ↺A → ◇⁺A
(M4)   ◇A ↔ ¬□¬A   (класична LTL-дуальність)
```

**Твердження 11.A.4 (M6).** `□A → ↺A` виконується без додаткових умов.

*Доведення.* □A в `ŝ` тягне `F²(ŝ) ∈ A`, отже `∃k = 2 > 1: Fᵏ(ŝ) ∈ A`. ∎

**Статус:** ДОВЕДЕНО НА ПАПЕРІ.

### 11.B. Гейтінгова семантика

**Означення 11.B.1.**

```
(□_H A)(ŝ) := ⋀_{n ≥ 0} A(Fⁿŝ)
(◇_H A)(ŝ) := ⋁_{n ≥ 0} A(Fⁿŝ)
```

де `⋀`, `⋁` — у Ґратці Ω (§7).

**Твердження 11.B.2 (M4_H не виконується).** `◇_H A ↔ ¬_H □_H ¬_H A` — хибне.

*Контрмодель.* `X = {a, b}`, `F(a) = b`, `F(b) = b`, `A(a) := EVENTUALLY_PERIODIC`, `A(b) := CHAOTIC`.

- `□_H ¬_H A(a) = CHAOTIC`;
- `¬_H □_H ¬_H A(a) = INVARIANT_FIXED`;
- `◇_H A(a) = EVENTUALLY_PERIODIC`;
- `INVARIANT_FIXED ≠ EVENTUALLY_PERIODIC`.

**Статус:** ДОВЕДЕНО НА ПАПЕРІ (загальне порушення класичної дуальності в логіці Геделя–Даммета).

### 11.C. Узгодження

§11.A — про траєкторії; §11.B — про алгебраїчні значення. Не змішуються.

## 12. Межі симуляції

**Твердження 12.1 (слабке).** Автономний скінченний автомат із `|Q| ≤ 64` може бути закодований у SUBIT-64 на рівні множини станів.

**Твердження 12.2 (вкладення переходів).** Кожен автономний скінченний автомат `(Q, δ)`, `|Q| ≤ 64`, вкладається в SUBIT⁺ як **сім'я траєкторій**: існує ін'єкція `ι : Q → S₀` і правило `ρ : S₀ → S₀` такі, що для всіх `q ∈ Q`: `ρ(ι(q)) = ι(δ(q))`.

**Статус:** ДОВЕДЕНО НА ПАПЕРІ.

**ВІДКЛИКАНО:** універсальний принцип симуляції DFA, твердження про універсальний об'єкт, автоматичне ототожнення SUBIT із λ-інтерпретатором.

# Частина IV. SUBIT-∞ — нескінченний простір рекурсивних дерев

## 13. Простір станів S∞

### 13.1. Коалгебраїчне означення

**Означення 13.1.1.**

```
S_∞ = νX. (A ⊔ X³)
```

**Інтерпретація.** Елементи `S_∞` (позначаємо також `Adm`) — дерева, які мають або листок із міткою з `A`, або внутрішній вузол із рівно трьома впорядкованими піддеревами. Дозволено скінченні й нескінченні дерева.

**Застереження 13.1.2.** Дерева, бісимілярні щодо визначеної структури, розглядаються як однакові лише за умови, що сама модель задає відповідне факторизування.

### 13.2. Вкладення S₀ у S∞

**Означення 13.2.1.**

```
e : A³ → S_∞,   e(a, b, c) := node(leaf(a), leaf(b), leaf(c))
```

**Твердження 13.2.2.** `e` ін'єктивне; `e(A³) ⊆ S_∞` — дерева глибини 1.

**Статус:** ДОВЕДЕНО НА ПАПЕРІ.

### 13.3. Скінченні апроксимації

**Означення 13.3.1 (гранична мітка).** Вводимо `⊥ ∉ A` — технічну мітку усічення.

**Означення 13.3.2 (T_n).**

```
T_n := { скінченні дерева t :
         (а) кожен листок t позначений A ∪ {⊥};
         (б) кожен внутрішній вузол має рівно трьох нащадків;
         (в) кожен ⊥-листок розташований на глибині рівно n;
         (г) depth(t) ≤ n }
```

**Застереження 13.3.3.** `T_n ⊄ T_{n+1}` (наприклад, `⊥ ∈ T_0`, але `⊥ ∉ T_1`).

**Означення 13.3.4 (усічення q_n).**

```
q_0 : T_1 → T_0
q_0(leaf(a))          := leaf(a)
q_0(node(t₁,t₂,t₃))   := ⊥

q_n : T_{n+1} → T_n     (n ≥ 1)
q_n(leaf(a))          := leaf(a)
q_n(node(t₁,t₂,t₃))   := node(q_{n-1}(t₁), q_{n-1}(t₂), q_{n-1}(t₃))
```

**Лема 13.3.5.** `q_n(t) ∈ T_n`.

**Означення 13.3.6 (проєкції p_n).**

```
p_0 : S_∞ → T_0
p_0(leaf(a))          := leaf(a)
p_0(node(t₁,t₂,t₃))   := ⊥

p_{n+1} : S_∞ → T_{n+1}
p_{n+1}(leaf(a))          := leaf(a)
p_{n+1}(node(t₁,t₂,t₃))   := node(p_n(t₁), p_n(t₂), p_n(t₃))
```

**Лема 13.3.7 (факторизація).** `q_n(p_{n+1}(s)) = p_n(s)`.

**Статус:** ДОВЕДЕНО НА ПАПЕРІ.

### 13.4. Обернена границя

**Означення 13.4.1.**

```
lim←(T_n, q_n) := { (t_n) ∈ ∏_n T_n : q_n(t_{n+1}) = t_n для всіх n }
```

**Теорема 13.4.2 (бієкція).** `p : S_∞ → lim←(T_n, q_n)`, `s ↦ (p_n(s))_{n ∈ ℕ}`, є бієкцією.

**Схема доведення:**

1. **Коректність p.** Факторизація (Лема 13.3.7).
2. **Ін'єктивність.** Бісимуляція `R := {(s, s') : p_n(s) = p_n(s') ∀n}`; коіндукція для фінальної коалгебри `S_∞`.
3. **Сюр'єктивність.** Для `(t_n) ∈ lim←`:
   - `state(σ) := t_{|σ|+1}(σ)`;
   - `u_m^{(i)} := (t_{m+1})|_i`;
   - `out_← : lim← → A ⊔ (lim←)³`;
   - реконструкція `s : lim← → S_∞` через фінальність;
   - індукція за рівнем: `p_n(s(t)) = t_n`.

**Статус:** ДОВЕДЕНО НА ПАПЕРІ.

### 13.5. Топологічна інтерпретація

**Означення 13.5.1 (структурна ультраметрика).** Для `s, t ∈ S_∞`:

```
δ(s, t) := ∞                                   якщо s = t
δ(s, t) := 0                                   якщо різні типи коренів (leaf vs node)
δ(s, t) := 0                                   якщо листки мають різні мітки
δ(s, t) := 1 + min(δ(s_i, t_i))                якщо s, t — внутрішні вузли

d_S(s, t) := 2^{−δ(s, t)}   (0 якщо s = t)
```

**Твердження 13.5.2.** `d_S` — ультраметрика.

**Лема 13.5.3 (діаметр циліндра).** Для `u ∈ C_n(t) := {u : p_n(u) = p_n(t)}`: `d_S(t, u) ≤ 2^{−(n+1)}`.

**Теорема 13.5.4 (гомеоморфізм).** Топології, індуковані `d_S` і проєкціями `p_n`, збігаються. Отже, `p : S_∞ → lim←(T_n, q_n)` — гомеоморфізм.

**Теорема 13.5.5 (компактність).** `S_∞` компактний у `d_S`.

**Статус:** ДОВЕДЕНО НА ПАПЕРІ.

## 14. Динаміка та категорія на рівні S∞

**Означення 14.1.1.** Розширений простір `Ŝ = S_∞ × ℛ`.

**Означення 14.1.2.** Динаміка: `F(s, ρ) = (f_ρ(s), g(ρ, s))`.

**Означення 14.1.3 (нерухомі точки).**

```
Fix(F) = { ŝ ∈ Ŝ : F(ŝ) = ŝ }
```

Це **найбільша** множина нерухомих точок; **не** «найменша стабільна множина».

**Застереження 14.1.4.** Категоріальні означення §8 переносяться на `S_∞` лише за умови, що функції переходу, морфізми та умови сумісності мають ті самі типи. Нескінченність простору сама по собі не гарантує існування добутків, експоненціалів або субоб'єктного класифікатора.

## 15. Метрики

### 15.1. d_S, d_ℛ, d̂

**Означення 15.1.1 (d_S).** Як у §13.5.1.

**Означення 15.1.2 (d_ℛ).** Для `f, g ∈ ℛ₀`:

```
n₀(f, g) := min{ n : f_n ≠ g_n }
d_ℛ(f, g) := 2^{−n₀(f, g)}   (0 якщо n₀ = ∞)
```

**Означення 15.1.3 (d̂).**

```
d̂((s, ρ), (t, σ)) := max( d_S(s, t), d_ℛ(ρ, σ) )
```

**Твердження 15.1.4.** `d_S`, `d_ℛ`, `d̂` — ультраметрики.

**Твердження 15.1.5.** `(S_∞ × ℛ₀, d̂)` компактний гаусдорфовий.

**Статус:** ДОВЕДЕНО НА ПАПЕРІ.

### 15.2. Локальна метрика чутливості d_finite

**Означення 15.2.1.** Для `ŝ, t̂ ∈ S_∞ × ℛ₀`:

```
d_finite(ŝ, t̂) := sup_{n ≥ 0} 2^{-n} · d̂(Fⁿ(ŝ), Fⁿ(t̂))
```

**Застереження 15.2.2 (NF3').** Метрика визначена за умови:

```
(NF3') g(ρ, s) ∈ ℛ₀   для всіх ρ ∈ ℛ₀, s ∈ S_∞
```

**Твердження 15.2.3.** `d_finite` — **ультраметрика** на `S_∞ × ℛ₀`.

**Статус:** ДОВЕДЕНО НА ПАПЕРІ (супремум зважених ультрапсевдометрик + доданок n = 0 гарантує розрізнення).

**Застереження 15.2.4.** `d_finite` вимірює локальну чутливість; **не узгоджена** з асимптотикою в загальному випадку.

### 15.3. Асимптотична метрика d_ω

**Означення 15.3.1.** Для `ŝ, t̂ ∈ S_∞ × ℛ₀` з непорожніми компактними ω-границями:

```
d_ω(ŝ, t̂) := d_Hausdorff( ω(ŝ), ω(t̂) )
```

**Твердження 15.3.2.** `d_ω` — псевдометрика на `S_∞ × ℛ₀`; стає метрикою на факторі `(S_∞ × ℛ₀) / ~_ω`, де `ŝ ~_ω t̂ ⟺ ω(ŝ) = ω(t̂)`.

**Застереження 15.3.3.** Узгодженість `d_finite` і `d_ω` залежить від `F`. Для структурно стійких `F` — узгоджені; для нестійких — можлива неузгодженість (Q12 ❓).

### 15.4. Метрика Ω_traj

**Означення 15.4.1.**

```
Ω_ω := { FIXED_POINT, PERIODIC, MINIMAL_ZERO_ENTROPY,
         CHAOTIC, NON_MINIMAL }
Att := { ATTAINED, ASYMPTOTIC }
Ω_traj := Ω_ω × Att     (10 класів)
```

**Означення 15.4.2 (дискретна метрика).**

```
d_Ω_traj((D₁, A₁), (D₂, A₂)) :=
   0                                  якщо D₁ = D₂ і A₁ = A₂
   1/2                                якщо D₁ = D₂ і A₁ ≠ A₂
   1                                  якщо D₁ ≠ D₂ і A₁ = A₂
   3/2                                якщо D₁ ≠ D₂ і A₁ ≠ A₂
```

**Твердження 15.4.3.** `d_Ω_traj` — метрика на `Ω_traj`.

## 16. Метатеоретичні властивості

**Застереження 16.1.** Побудова `S_∞` як коалгебраїчного об'єкта **не доводить** несуперечності всієї системи аксіом SUBIT. Слід розділяти:

- існування математичного простору дерев;
- несуперечність обраної формальної теорії;
- несуперечність модальної семантики;
- коректність конкретної реалізації.

**Відкрите питання Q9 (❓).** Несуперечність Ω_SUBIT разом з аксіомами LTL-семантики.

**Ієрархія рівнів:**

| Рівень | Додає |
|---|---|
| SUBIT-64 | Скінченний статичний алфавіт |
| SUBIT⁺ | Скінченна динаміка з правилом у розширеному стані |
| SUBIT-CAT | Категоріальний опис об'єктів і морфізмів |
| SUBIT-∞ | Рекурсивний простір дерев і нескінченні динамічні системи |

**Застереження 16.2.** Ця ієрархія є архітектурною. Вона **не доводить**, що кожен наступний рівень строго сильніший за попередній у сенсі обчислювальної виразності.

## 18. Канонічна класифікація траєкторій P(τ)

### 18.1. Вимоги

- **У0 (неколапс):** гранична множина не повинна наперед визначати всі поля класифікації.
- **У1 (узгодженість):** на скінченному рівні результат має бути сумісним із класифікацією скінченних траєкторій.
- **У2 (інваріантність):** математичний клас не залежить від обчислювального горизонту.
- **У3 (прозорість):** обчислювальні обмеження відображаються окремо.

### 18.2. ω-гранична множина

**Означення 18.2.1.**

```
ω(ŝ₀) := { x ∈ X : ∃ nₖ → ∞, ŝ_{nₖ} → x }
```

**Статус:** умовно доведено за компактності простору та неперервності F.

### 18.3. Чому P(τ) не може бути лише ω(τ)

**Застереження 18.3.1.** За неперервної динаміки `F(ω(ŝ₀)) = ω(ŝ₀)`. Тому якщо визначити `P(τ) := ω(ŝ₀)`, класифікатор множин може втратити інформацію про шлях до границі.

### 18.4. Тип досягнення Att

**Означення 18.4.1.**

```
ATTAINED      ⟺  ∃n ≥ 0: ŝₙ ∈ ω(ŝ₀)
ASYMPTOTIC    ⟺  ∀n: ŝₙ ∉ ω(ŝ₀) ∧ dist(ŝₙ, ω(ŝ₀)) → 0
```

**Застереження 18.4.2.** Це математичні властивості траєкторії, а не результат обмеження часу обчислення.

### 18.5. Обчислювальний статус

**Означення 18.5.1.**

- **COMPUTED** — класифікація завершена в межах заданої процедури;
- **RESOURCE_EXCEEDED** — вичерпано горизонт або ресурс.

`RESOURCE_EXCEEDED` **не є** математичним класом траєкторії й не додається до `Att`.

### 18.6. П'ять класів S(τ)

**Означення 18.6.1.**

```
FIXED_POINT
   ω(ŝ₀) = {p}, F(p) = p

PERIODIC
   ω(ŝ₀) скінченна, |ω(ŝ₀)| > 1

MINIMAL_ZERO_ENTROPY
   ω(ŝ₀) нескінченна й мінімальна, h_top(F|_ω) = 0

CHAOTIC
   ω(ŝ₀) нескінченна й мінімальна, h_top(F|_ω) > 0

NON_MINIMAL
   ω(ŝ₀) нескінченна й не мінімальна
```

**Застереження 18.6.2 (CE-1).** Клас `MINIMAL_ZERO_ENTROPY` **замінює** `MINIMAL_CANTOR` у канонічній редакції. Обґрунтування: нескінченна мінімальна ω-границя з нульовою ентропією не обов'язково має топологію Кантора (наприклад, ірраціональне обертання кола, одометр). `MINIMAL_CANTOR` можна використовувати **лише** як уточнювальну підкатегорію за додаткової топологічної умови.

**Межа вичерпності (⚠️).** Ці п'ять умов не є автоматично вичерпними для довільних компактних динамічних систем. Для оголошення п'яти класів вичерпними потрібно довести, що допустимий клас ω-граничних множин SUBIT-∞ виключає решту випадків, або розширити класифікатор.

### 18.7. CHAOTIC і причинні правила ℛ₀

**Означення 18.7.1 (причинність).** `f : S_∞ → S_∞` причинна, якщо:

```
d_S(f(s), f(t)) ≤ d_S(s, t)     для всіх s, t ∈ S_∞
```

**Означення 18.7.2.** `ℛ₀ := { f : S_∞ → S_∞ : f причинна }`.

**Твердження 18.7.3.** Якщо `X` компактний і `f` 1-ліпшицева, то `h_top(f) = 0`.

**Наслідок 18.7.4.** Клас `CHAOTIC` **не реалізується** для траєкторій під правилами з ℛ₀ за фіксованого правила.

**Статус:** УМОВНО (залежить від топологічних передумов і точного визначення динаміки на ω-граничній множині).

### 18.8. Підсумкова функція

```
P(τ) := ( ω(ŝ₀), Ω_traj(τ), certificate )
Ω_traj(τ) := ( S(τ), Att(τ) )
```

### 18.9. Сертифікати

**Сертифікат ATTAINED** містить:

- індекс входження `m`;
- опис скінченної ω-граничної множини (cycle);
- клас `S`;
- `att_type = ATTAINED`.

**Сертифікат ASYMPTOTIC** містить:

- послідовність усічень граничної множини;
- оцінки відстані до ω-граничної множини;
- свідчення збіжності (модуль, якщо доступний).

**Сертифікат CHAOTIC** має обґрунтовувати `h_top > 0`, наприклад через нижню оцінку зростання кількості розділених орбіт.

**Статус:** структура визначена; поліноміальна складність не гарантована без обмежень на розмір входу.

# Частина V. Застосування та методологія

## 19. Епістемологічний статус

### 19.1. Природа формальних результатів

Теореми SUBIT є твердженнями про визначену формальну систему. Вони **не доводять** автоматично, що певна фізична, біологічна, соціальна чи психологічна система має саме ту структуру, яку дослідник їй приписав. Формальна коректність кодування не є доказом емпіричної істинності моделі.

### 19.2. Призначення

SUBIT використовується для:

- класифікації станів;
- представлення переходів;
- формалізації гіпотез про динаміку;
- порівняння різних правил;
- аналізу граничної поведінки;
- побудови відтворюваних сертифікатів;
- явного відокремлення невизначеності від математичного результату.

### 19.3. Протокол застосування

**Крок 0 (кодування).** Обґрунтувати, як об'єкт або дані відображаються в алфавіт `A`. Для неперервних даних зафіксувати процедуру дискретизації, пороги, нормалізацію та аналіз чутливості.

**Крок 0′ (клас правил).** Визначити, чи належить правило до `ℛ₀`, `ℛ₁` або їхнього перетину. Не робити висновку про причинність лише з того, що алгоритм обчислюваний.

**Крок 1.** Визначити простір станів `S₀` або `S_∞`, включно з кодуванням.

**Крок 2.** Задати `F`, `f_ρ`, `g` з точними типами.

**Крок 3.** Перевірити тотальність, неперервність, причинність та інші потрібні припущення.

**Крок 4.** Обчислити траєкторію з явним горизонтом і політикою зупинки.

**Крок 5.** Застосувати відповідний класифікатор, не змішуючи `Ω_point`, `Ω_set` і `S`.

**Крок 6.** Перевірити чутливість до кодування, альтернативних правил і параметрів спостереження.

## 20. Статуси доказовості та контроль змін

### 20.1. Обов'язкові поля твердження

Кожне нетривіальне твердження специфікації має супроводжуватися:

- ідентифікатором;
- точним формулюванням;
- областю застосування;
- необхідними припущеннями;
- статусом;
- посиланням на доказ або протокол перевірки;
- записом про зміни.

### 20.2. Статус не замінює доказ

Позначка ✅ **не є** самостійним математичним обґрунтуванням. Вона означає лише той рівень підтвердження, який зазначено в реєстрі.

### 20.3. Протокол зміни статусу

Кожна зміна статусу має бути зафіксована в журналі змін разом із причиною, датою та наслідками для залежних тверджень.

## 21. Топологія простору правил ℛ

### 21.1. ℛ₀ := Comp

**Означення 21.1.1.**

```
ℛ₀ := Comp := { (f_n)_{n ∈ ℕ} : ∀n, f_n : T_n → T_n,
                                 q_n ∘ f_{n+1} = f_n ∘ q_n }
```

**Твердження 21.1.2.** `ℛ₀ ≅ { f : S_∞ → S_∞ : f причинна }` (через бієкцію §13.4).

**Статус:** ДОВЕДЕНО НА ПАПЕРІ.

**Лема 21.1.3.** `ℛ₀` замкнене в `∏_n (T_n)^{T_n}`.

**Теорема 21.1.4 (компактність ℛ₀).** `(ℛ₀, d_ℛ)` — компактний гаусдорфовий простір.

**Статус:** ДОВЕДЕНО НА ПАПЕРІ.

### 21.2. Класифікація правил

| Клас | Компактність | CHAOTIC досяжний |
|---|---|---|
| ℛ₀, g ≡ id | ✅ | ⛔ |
| ℛ₀, g ≠ id | ✅ | ❓ (Q10) |
| ℛ₁ ∩ C(S_∞) | ❓ | ⚠️ |

### 21.3. Обчислювані правила ℛ₁

**Означення 21.3.1.** `ℛ₁` — клас функцій `S_∞ → S_∞`, заданих скінченним описом у фіксованій моделі обчислень. Модель обчислень, кодування дерев і семантика виконання є частиною означення.

**Застереження 21.3.2.** Причинність і обчислюваність **не тотожні**. Відношення `ℛ₀` та `ℛ₁` — **Q1, Q20 (❓)**.

### 21.4. Потужності просторів правил

**Застереження 21.4.1.** Твердження `|ℛ₀| = 2^ℵ₀`, `|ℛ₁| = ℵ₀` не є безумовними наслідками означень і позначені як ❓.

## 22. Двоосьова класифікація Ω_traj

**Означення 22.1.**

```
Ω_traj := S(τ) × Att(τ)
```

Якщо `S` має 5 класів, а `Att` — 2, формальний добуток містить 10 пар. Це **не доводить**, що всі 10 комбінацій реалізуються математично допустимими траєкторіями.

**Означення 22.2.** Порівняння траєкторій може використовувати `d_ω` або `d_Ω_traj`.

**Означення 22.3.** `COMPUTED` і `RESOURCE_EXCEEDED` — обчислювальні статуси, які **не входять** до `Ω_traj`.

**Заплановані демонстрації:**

| Правило | Передбачений клас | Att | Статус |
|---|---|---|---|
| `identity` | FIXED_POINT | ATTAINED | Потребує тесту реалізації |
| `cycle_leaf` | PERIODIC | ATTAINED | Потребує тесту реалізації |
| `grow_chain` | FIXED_POINT | ASYMPTOTIC | Потребує точного означення |
| `shift_spine` | MINIMAL_ZERO_ENTROPY / CHAOTIC | ASYMPTOTIC | Умовна гіпотеза |

## Додаток B. Коректність коалгебраїчної конструкції

**B.1.** Для функтора `Φ'(X) = X³` кінцева коалгебра — одноелементна: `νX.X³ ≅ 1`. Додавання `A` як базового конструктора забезпечує розрізнення листків із різними мітками.

**B.2.** `νX.(A ⊔ X³) ≠ 1` при `|A| > 1`.

**B.3 (ін'єктивність).** Якщо `π_n(s) = π_n(t)` для всіх `n`, то `s = t`. Аргумент через коіндукцію: усічення розрізняє листок і внутрішній вузол; рівність усічень дає рівність відповідних піддерев за індуктивною гіпотезою.

**Статус:** ДОВЕДЕНО НА ПАПЕРІ за коректного означення `π_n` і `⊥`.

## Додаток E. Емпіричний протокол pilot-01

**E.1. Об'єкт.** Часовий ряд канадської рисі Hudson Bay (Elton & Nicholson, 1942). Це **запропонований** емпіричний приклад; факт існування ряду не підтверджує жодної конкретної класифікації SUBIT.

**E.2. Кодування.** WHO = квантиль `log(x_t)`; WHERE = квантиль `Δlog(x_t)`; WHEN = квантиль `Δ²log(x_t)`. 4 біни; квантильні межі — лише на навчальній частині. Чутливість до перестановок квантилів перевіряється.

**E.3. Гіпотези.**

- **H₁:** `ρ₁ = identity`;
- **H₂:** `ρ₂` = циклічний зсув на 1 у кожній координаті (mod 4);
- **H₃:** `ρ₃(s) := argmax_t count(s → t)` у навчальній вибірці, tie-breaking — найменший `code6`.

**E.4. Критерій спростування.** Пілот **провалюється**, якщо H₃ не відрізняється від H₁ і H₂ за заздалегідь визначеним критерієм, або дає нестійку класифікацію за допустимих варіантів кодування.

**Статус:** протокол запропонований; емпіричний результат — **НЕ ПІДТВЕРДЖЕНО**.

- **Що доведено:** конкретні математичні твердження за явно зазначених умов.
- **Що ще потрібно перевірити:** формальні докази Lean, відповідність реалізацій, вичерпність класифікаторів, емпіричні гіпотези.
