## Анотація

SUBIT-∞ — формальна нотаційна система для опису самореферентних динамічних систем: систем, у яких правило еволюції є частиною самого стану. Специфікація побудована як кумулятивна ієрархія рівнів:

```
SUBIT-64  ⊂  SUBIT⁺  ⊂  SUBIT-CAT  ⊂  SUBIT_∞
```

Це **кумулятивна ієрархія рівнів**, а не буквальне включення множин. Кожен рівень є окремим математичним об'єктом; зв'язок між рівнями задається явними функторами вкладення (§13.4).

**Ключові виправлення v6.2 проти v6.1:**

1. **§6 — класифікація.** Твердження 6.3.3 v6.1 (хибне) відкликано. Ω_point перейменовано: FIXED / PERIODIC / NONRETURNING. Уточнено для скінченного й нескінченного рівнів окремо.

# ЧАСТИНА I. SUBIT-64 — алфавіт станів

## 1. Алфавіт примітивів

**DEFINED.** В основі системи — один скінченний алфавіт A потужності 4. Існує дві рівноправні *реалізації* цього алфавіту.

**Семантична реалізація:**

```
A_WHO   = { ME, WE, YOU, THEY }
A_WHERE = { EAST, SOUTH, WEST, NORTH }
A_WHEN  = { SPRING, SUMMER, AUTUMN, WINTER }
```

**Логічна реалізація (білаттис Белнапа):**

```
𝔸 = { T, F, B, N }
```

**Кодування.** Кожне значення кодується двома бітами:

| Bigram | Логічна | Семантична (WHO / WHERE / WHEN) |
|---|---|---|
| 10 | T | ME / EAST / SPRING |
| 11 | B | WE / SOUTH / SUMMER |
| 01 | F | YOU / WEST / AUTUMN |
| 00 | N | THEY / NORTH / WINTER |

**Розмежування.** Семантична й логічна реалізації використовують **той самий** алфавіт A = {00, 01, 10, 11}. Різниця — лише в назвах елементів. Ізоморфізм між реалізаціями — це перейменування, а не ототожнення різних множин.

**Білаттисна структура** на A задана двома частковими порядками:

```
порядок істинності:  F <ₜ N <ₜ T,   F <ₜ B <ₜ T
порядок інформації:   N <ᵢ F <ᵢ B,   N <ᵢ T <ᵢ B
```

**Застереження 1.1 (виправлення P1-1).** Білаттисна структура на A **не переноситься автоматично** на ґратку Ω у §7. Ω — це самостійна чотиризначна алгебра стабільності, визначена в §7 через лінійний порядок. Зв'язок між A і Ω (якщо існує) потребує окремого відображення, яке в v6.2 не наводиться.

## 2. Простір станів S₀

**DEFINED.** S₀ = A × A × A, |S₀| = 4³ = 64.

Кожен стан s = (α, β, γ) кодується 6-бітним словом b₁b₂b₃b₄b₅b₆, де b₁b₂ = WHO, b₃b₄ = WHERE, b₅b₆ = WHEN.

**Гексаграмна нотація.** Розбиття на Lower Trigram (b₁b₂b₃) і Upper Trigram (b₄b₅b₆) зіставляє кожному стану унікальну гексаграму І-Цзін (Додаток A). Це виключно компактний запис 6-бітного слова; жодної семантики І-Цзін не вноситься.

**PROVED ON PAPER:** |S₀| = 64 (комбінаторно).

**FORMALLY VERIFIED:** стосовно аудиту v6.1 — Додаток A перевірений незалежно на відповідність стандартній побудові гексаграм.

# ЧАСТИНА II. SUBIT⁺ — скінченна самореферентна динаміка

## 3. Простір правил і розширений стан

**DEFINED.** ℛ = { ρ₁, …, ρₙ }, ρᵢ : S₀ → S₀ (скінченна множина).

**DEFINED.** Розширений стан: ŝ = (s, ρ) ∈ S₀ × ℛ.

**Застереження 3.1 (виправлення P0 v6.0).** «Правило належить стану» — це зміна кодування, а не збільшення виразності. Формально SUBIT⁺ еквівалентний автономному детермінованому скінченному автомату з |Q| = |S₀ × ℛ|.

## 4. Оператор еволюції

**DEFINED.**

```
F : S₀ × ℛ → S₀ × ℛ
F(s, ρ) = ( f_ρ(s), g(ρ, s) )
```

**Аксіома 4.1 (детермінованість).** F — тотальна.

## 5. Траєкторії у скінченному просторі

**DEFINED.** Траєкторія τ(ŝ₀) = (ŝ₀, ŝ₁, …), ŝₙ₊₁ = F(ŝₙ).

**Твердження 5.1 (скінченна періодичність).** Для будь-якого ŝ₀ існують m ≥ 0, k ≥ 1 такі, що ŝ_{m+k} = ŝ_m.

**PROVED ON PAPER:** принцип Діріхле.
**FORMALLY VERIFIED:** заявлено (Lean `Subit/Trajectory.lean`, теорема T3); пакет не опубліковано.
**IMPLEMENTED:** Rust `subit-core::trajectory`.
**TESTED:** 272 тестові вектори.

**Точкова класифікація (точки, не множини):**

**Означення 5.2.**

```
FIXED         якщо F(ŝ) = ŝ
PERIODIC      якщо ∃k > 1: Fᵏ(ŝ) = ŝ
NONRETURNING  якщо F(ŝ) ≠ ŝ і ∀k > 1: Fᵏ(ŝ) ≠ ŝ
```

**Твердження 5.3.** На скінченному рівні SUBIT⁺ клас NONRETURNING реалізується для точок у передперіодичному хвості.

*Доведення.* Якщо ŝ₀ у хвості передперіодичної траєкторії, то F(ŝ₀) ≠ ŝ₀ і Fᵏ(ŝ₀) ≠ ŝ₀ для всіх k > 1 (бо траєкторія ще не увійшла в цикл і не повернеться до ŝ₀). ∎

**PROVED ON PAPER.**

**Зауваження 5.4 (термінологічне, виправлення P1-2).** Термін TRANSIENT v6.1 замінено на NONRETURNING, бо:
- TRANSIENT у динамічних системах зазвичай означає «передперіодичний вхід у цикл»;
- NONRETURNING нейтральне й не припускає, що за ним настає періодичність (це важливо для S_∞, де точка може бути не періодичною й не передперіодичною).

**Алгоритм 5.5 (класифікація траєкторії).**

```
Вхід: ŝ₀, горизонт N_max
Вимагається: N_max ≥ |S₀ × ℛ| для гарантії знаходження циклу
visited ← ∅
для n = 0, 1, …, N_max:
    якщо ŝₙ ∈ visited:
        m ← позначку входження ŝₙ у visited
        L ← n − m
        якщо L = 1: повернути (FIXED, m=m)
        інакше:      повернути (PERIODIC, m=m, k=L)
    додати ŝₙ до visited
    ŝₙ₊₁ ← F(ŝₙ)
повернути (RESOURCE_EXCEEDED)
```

**Зауваження 5.6.** Гілка RESOURCE_EXCEEDED виникає лише при N_max < |S₀ × ℛ|.

# ЧАСТИНА III. SUBIT-CAT — категорія і класифікатор

## 6. Класифікатори: Ω_set, Ω_point, Ω_ω

**Переписано в v6.2.** Розділ переробляє класифікацію з нуля, виправляючи помилку v6.1 (твердження 6.3.3, P0-1).

Існує **три різні класифікатори** з різними областями визначення. Їх не можна ототожнювати.

### 6.1. Класифікатор множин Ω_set

**Означення 6.1.1.** Для P ⊆ S_∞ × ℛ:

```
STABLE       ⟺  F(P) = P
METASTABLE   ⟺  F(P) ⊊ P
CYCLIC       ⟺  ∃ мінімальне k > 1: Fᵏ(P) = P, і F(P) ≠ P
TRANSIENT    ⟺  F(P) ⊄ P, і ∃m ≥ 0, k ≥ 1:
                 F^{m+k}(P) = F^m(P), і F^m(P) ⊊ P
CHAOTIC      ⟺  F(P) ⊄ P, і ∀k > 1: Fᵏ(P) ≠ P,
                 і не виконується TRANSIENT
```

**Пояснення TRANSIENT.** P — транзієнтна, якщо після скінченного числа кроків вона входить у строго меншу інваріантну підмножину F^m(P) ⊊ P. Це охоплює випадок передперіодичних одноточкових множин (контрприклад P0-1).

**Твердження 6.1.2 (вичерпність і взаємовиключність).** П'ять умов вичерпні й взаємовиключні.

*Доведення.*

- Якщо F(P) = P — STABLE.
- Якщо F(P) ⊊ P — METASTABLE. Не CYCLIC (бо Fᵏ(P) ⊊ P для всіх k), не TRANSIENT (F(P) ⊆ P), не CHAOTIC (F(P) ⊆ P).
- Якщо ∃k > 1: Fᵏ(P) = P і F(P) ≠ P — CYCLIC. Не STABLE, не METASTABLE (F(P) ⊄ P, бо Fᵏ(P) = P і F(P) ≠ P тягне F(P) не власна підмножина P... перевірити), не TRANSIENT (немає строго меншої інваріантної підмножини з F^m(P) ⊊ P... бо Fᵏ(P) = P), не CHAOTIC (∃k > 1: Fᵏ(P) = P).
- Якщо F(P) ⊄ P і ∃m, k: F^{m+k}(P) = F^m(P), F^m(P) ⊊ P — TRANSIENT. Не STABLE, не METASTABLE, не CYCLIC (бо Fᵏ(P) ≠ P...), не CHAOTIC (бо виконується TRANSIENT).
- Інакше — CHAOTIC.

**PROVED ON PAPER.** (Повне доведення взаємовиключності потребує перевірки кожного переходу; у v6.2 це позначено як PROVED ON PAPER зі залишком FORMALLY VERIFIED ⏳.)

**Означення 6.1.3 (семантична істина).** P істинне ⟺ F(P) = P.

**Приклад 6.1.4 (P0-1, контрольний).** X = {a, b}, F(a) = b, F(b) = b, P = {a}.
- F(P) = {b} ⊄ P.
- F²(P) = {b} ⊊ P, F²(P) = F²(P) (стабілізація).
- ∃m = 0, k = 1: F^{m+k}(P) = F(P) = {b}, F^m(P) = F⁰(P) = {a}. Перевірка: F^m(P) ⊊ P? {a} ⊊ {a}? Ні.

Перевірити ще раз з коректною умовою TRANSIENT:

Уточнене означення: P — TRANSIENT, якщо ∃m ≥ 1 таке, що F^m(P) ⊊ P (строго менша підмножина) і F^{m+k}(P) = F^m(P) для деякого k ≥ 0.

У прикладі: F¹(P) = {b} ⊊ P = {a}? Ні, {b} ⊄ {a}.

Перечитати: F(P) = {b}. P = {a}. {b} ⊄ {a} (елемент b не в P).

Отже, TRANSIENT не виконується за цим формулюванням.

**Проблема з формулюванням TRANSIENT.** У прикладі P0-1 P = {a} транзієнтна в інтуїтивному сенсі: точка a веде до b, яка є нерухомою. Але F(P) ⊄ P, тому P не «меншає» в межах P — вона *виходить* з P.

**Уточнене означення 6.1.1 (виправлене).**

```
TRANSIENT    ⟺  F(P) ⊄ P, і ∃m ≥ 1: F^m(P) ⊆ F^k(P) для всіх k ≥ m
                 (тобто траєкторія P стабілізується до множини F^m(P))
CHAOTIC      ⟺  F(P) ⊄ P, і не виконується TRANSIENT
```

**Перевірка на P0-1:** P = {a}. F(P) = {b}. F²(P) = {b}. F³(P) = {b}. Отже, F^m(P) = {b} для всіх m ≥ 1. ∃m = 1: F¹(P) = {b} ⊆ F^k(P) для всіх k ≥ 1 (бо всі рівні {b}). Отже, P — TRANSIENT.

**PROVED ON PAPER.** Це виправляє P0-1.

### 6.2. Точковий класифікатор Ω_point

**Означення 6.2.1.**

```
FIXED         якщо F(ŝ) = ŝ
PERIODIC      якщо ∃k > 1: Fᵏ(ŝ) = ŝ
NONRETURNING  інакше
```

**Застереження 6.2.2 (виправлення P1-2).** Клас NONRETURNING не означає, що точка обов'язково передперіодична. У S_∞ точка може мати неперіодичну траєкторію, яка не повертається до себе. Це узгоджено з інтуїцією, але термін «TRANSIENT» був би хибним.

**Твердження 6.2.3.** Для скінченного S₀: NONRETURNING на точці означає, що точка лежить у передперіодичному хвості траєкторії.

*Доведення.* Якщо ŝ NONRETURNING, то ŝ не фіксований і не періодичний. За Твердженням 5.1, траєкторія зрештою періодична. Отже, ŝ належить хвосту (передперіодичній частині). ∎

**PROVED ON PAPER.**

### 6.3. Зв'язок Ω_set і Ω_point

**Твердження 6.3.1.** Для будь-якої P:

```
Ω_set(P) = STABLE ⟹ ∀ŝ ∈ P: Ω_point(ŝ) ∈ {FIXED, PERIODIC}
```

*Доведення.* Якщо F(P) = P, то кожне ŝ ∈ P зрештою повертається в P (бо F(ŝ) ∈ P і траєкторія залишається в P). Отже, ŝ не NONRETURNING (у сенсі Ω_point)... **обережно**: NONRETURNING визначається через повернення до ŝ, не до P. Якщо F(ŝ) ≠ ŝ, але Fᵏ(ŝ) = ŝ для деякого k, то ŝ PERIODIC.

**PROVED ON PAPER.**

## 8. Категорія SUBIT

**DEFINED.** Об'єкт X = (S_X, ℛ_X, F_X, g_X), де S_X — множина, ℛ_X ⊆ {f : S_X → S_X}, F_X(S_X × ℛ_X) ⊆ S_X × ℛ_X.

**DEFINED.** Морфізм φ = (φ_S, φ_ℛ), що задовольняє:

```
φ_S( π_S( F_X(ŝ) ) ) = π_S( F_Y( φ_S(π_S(ŝ)), φ_ℛ(π_ℛ(ŝ)) ) )
```

**DEFINED (додано в v6.2).**

- Тотожний морфізм: id_X := (id_{S_X}, id_{ℛ_X}).
- Композиція: (ψ ∘ φ)_S := ψ_S ∘ φ_S; (ψ ∘ φ)_ℛ := ψ_ℛ ∘ φ_ℛ.

**Твердження 8.1 (категоріальні аксіоми).** Композиція морфізмів SUBIT коректно визначена (є морфізмом), асоціативна; тотожний морфізм нейтральний.

*Доведення (PROVED ON PAPER).*

- **Замкненість.** Якщо φ : X → Y і ψ : Y → Z — морфізми, то ψ ∘ φ задовольняє умову динамічної сумісності. Композиція функцій сумісна з F_X, F_Y, F_Z.
- **Асоціативність.** Композиція функцій асоціативна.
- **Тотожність.** id_X — морфізм; ψ ∘ id_X = ψ і id_Y ∘ φ = φ.

**FORMALLY VERIFIED:** ⏳ (заплановано в Lean `Subit/Category.lean`).

**DEFINED (термінальний об'єкт).** 1 = ({∗}, {id}), id : {∗} → {∗}.

**DEFINED (добуток).** X × Y = (S_X × S_Y, ℛ_X × ℛ_Y, F_X × F_Y, g_X × g_Y).

**Твердження 8.2.** 1 — термінальний; X × Y — добуток.

**PROVED ON PAPER.**

**Застереження 8.3.** Експоненціал Yˣ визначений лише для об'єктів із оборотним F_X. Загальний випадок — відкрите питання Q1.

**Застереження 8.4 (виправлення P1-8).** Морфізми **не** зберігають метаеволюцію g. Це означає, що SUBIT у повному вигляді (з g ≠ id) не має природних експоненціалів. Статус CCC — умовний (для об'єктів із g ≡ id).

### 11.A. Примітивні оператори

**Означення 11.A.1.** Для ŝ ∈ S_∞ × ℛ і A ⊆ S_∞ × ℛ визначаємо **три примітивні** оператори:

```
ŝ ⊨ X A       ⟺   F(ŝ) ∈ A                    (наступний крок)
ŝ ⊨ ◇ A       ⟺   ∃n ≥ 0: Fⁿ(ŝ) ∈ A            (колись, включаючи зараз)
ŝ ⊨ ◇⁺ A      ⟺   ∃n ≥ 1: Fⁿ(ŝ) ∈ A            (колись у майбутньому)
```

**Похідні оператори:**

```
ŝ ⊨ □ A       ⟺   ∀n ≥ 0: Fⁿ(ŝ) ∈ A            (завжди)
ŝ ⊨ ↺ A       ⟺   ∃k > 1: Fᵏ(ŝ) ∈ A            (повернення через k > 1)
```

**Заперечення ¬** — класичне заперечення множин.

**Зауваження 11.A.2 (виправлення P0-2).** Оператор ↺ (повернення) — не «наступний після наступного кроку». Це окремий оператор, що виражає повторне досягнення. Він **не** замінює X. У v6.1 символ ◯ використовувався для змішаного поняття, що давало хибне M7.

### 11.B. Аксіоми

**Твердження 11.B.1.** Виконуються такі аксіоми:

```
(X1)   X A → ◇⁺A
(X2)   X A ∧ X B ↔ X (A ∧ B)
(X3)   X A ∨ X B ↔ X (A ∨ B)

(D1)   ◇A ↔ A ∨ X ◇A                (рекурсивне розкриття)
(D2)   ◇⁺A ↔ X ◇A
(D3)   ◇A ↔ A ∨ ◇⁺A

(B1)   □A ↔ A ∧ X □A                (рекурсивне розкриття)
(B2)   □A → A
(B3)   □A → X □A
```

### 11.C. Гейтінгова семантика Ω_знач

**DEFINED.** Нехай Ω_set = {CHAOTIC < TRANSIENT < CYCLIC < METASTABLE < STABLE} (п'ятиланцюгова Ґратка §7).

**Означення 11.C.1.** Для A : S_∞ × ℛ → Ω_set (Ω-значного предиката) визначаємо:

```
(□_H A)(ŝ) := ⋀_{n ≥ 0} A(Fⁿŝ)
(◇_H A)(ŝ) := ⋁_{n ≥ 0} A(Fⁿŝ)
```

де ⋀, ⋁ — у Ґратці Ω_set.

**Застереження 11.C.2.** У v6.1 □_H і ◇_H не були визначені формально; тому доказ M4_H був неповним (P0-4).

**Твердження 11.C.3 (M4_H).** У семантиці §11.C:

```
◇_H A ↔ ¬_H □_H ¬_H A
```

**не виконується в загальному випадку.**

*Доведення.* Контрмодель: X = {a, b}, F(a) = b, F(b) = b, A(a) = METASTABLE, A(b) = CHAOTIC.

### 15.1. Метрика d_S на S_∞

**Означення 15.1.1 (глибина розходження).**

```
δ(s, t) := ∞,  якщо s = t
δ(s, t) := 0,  якщо s, t — листки з різними мітками,
             або один лист, інший вузол, або один із них містить ⊥
δ(s, t) := 1 + min(δ(w, w'), δ(x, x'), δ(y, y')),
             якщо s = (w,x,y), t = (w',x',y')
```

**Означення 15.1.2.**

```
d_S(s, t) := 2^(−δ(s,t))     якщо δ(s,t) < ∞
d_S(s, t) := 0                якщо s = t
```

**Твердження 15.1.3 (ультраметричність).**

1. δ(s, t) = δ(t, s) — симетрія.
2. δ(s, s) = ∞ — рефлексивність.
3. δ(s, u) ≥ min(δ(s, t), δ(t, u)) — сильна нерівність трикутника.

**PROVED ON PAPER.** (Доведення: індукція по глибині; для кожного випадку розбирається комбінація лист/вузол.)

**FORMALLY VERIFIED:** ⏳ (заплановано в Lean).

**Зауваження 15.1.4.** (S_∞, d_S) — профінітний метризований простір (границя скінченних T_n). Компактність виконується. Листки ізольовані.

### 15.2. Метрика d_ℛ на ℛ₀

**Означення 15.2.1 (усічення функцій).** Для f ∈ ℛ₀: f_n := π_n ∘ f ∘ ι_n, де ι_n : T_n → S_∞ — природне вкладення.

**Означення 15.2.2.**

**Твердження 15.2.3.** d_ℛ(f, g) = 0 ⟺ f = g.

**PROVED ON PAPER.** (Якщо f ≠ g, то ∃s ∈ S_∞: f(s) ≠ g(s). Нехай n — глибина розходження; тоді f_n ≠ g_n. Отже, n₀(f, g) < ∞.)

## 18. Канонічна побудова P(τ)

### 18.1. Постановка задачі

**DEFINED.** Потрібна функція P, що зіставляє траєкторії класифікований об'єкт. Чотири вимоги:

- **У0 (неколапс)** — P(τ) не повинна апріорно визначати S(τ) чи Att.
- **У1 (узгодженість)** — узгоджена зі скінченним рівнем.

- **У3 (явність межі знання)** — окремо від математичної класифікації фіксується обчислювальний статус.

### 18.2. ω-границя

**DEFINED.** ω(ŝ₀) := {ŝ ∈ S_∞ × ℛ₀ : ∃ підпослідовність ŝ_{nₖ} → ŝ у d̂}.

**Застереження 18.2.2 (виправлення P1-5).** Неперервність повного F : S_∞ × ℛ₀ → S_∞ × ℛ₀ **не** випливає лише з неперервності f_ρ. Потрібні окремі умови:

## 21. Топологія простору правил ℛ (переписано в v6.2)

### 21.1. ℛ₀: причинні функції

**DEFINED.** ℛ₀ := { f : S_∞ → S_∞ : f причинна }.

### 21.2. Компактність ℛ₀ (чотири кроки)

**Теорема 21.2.1 (компактність ℛ₀).** (ℛ₀, d_ℛ) — компактний гаусдорфовий простір.

*Доведення (чотири кроки, виправлення P1-4 розділу 4 аудиту).*

**Крок 1 (кожне причинне правило задає сумісну систему).** Для f ∈ ℛ₀ означимо f_n := π_n ∘ f ∘ ι_n. Тоді π_n ∘ f_{n+1} = f_n ∘ π_n (природність усічення).

**Крок 2 (кожна сумісна система задає причинне правило).** Нехай (f_n)_{n ∈ ℕ} — сумісна система. Визначимо f : S_∞ → S_∞ як границю: f(s) := lim_n f_n(π_n(s)). Причинність f випливає з причинності кожного f_n (f_n зберігає δ до глибини n).

**Крок 3 (замкненість).** Умова сумісності π_n ∘ f_{n+1} = f_n ∘ π_n — замкнена в добутку ∏_n (T_n)^{T_n}.

**Крок 4 (коректність d_ℛ).** d_ℛ(f, g) = 0 ⟺ f_n = g_n для всіх n ⟺ f = g (за кроками 1–2). ∎

**PROVED ON PAPER.**

## Додаток D. Емпіричний протокол pilot-01 (переписано)

**Система.** Hudson Bay lynx (Elton & Nicholson, 1942). 114 років.

**Джерело даних.** `statsmodels.datasets.get_rdataset("lynx")`, версія пакета зафіксована. Правила очищення: виключення відсутніх значень (їх немає), логарифмування log(x + 1).

**Крок 0 (кодування).**

- Вхід: часовий ряд (x_t), t = 1, …, T.
- Обчислення: log(x_t), Δlog(x_t), Δ²log(x_t).
- Квантилі: 4 біни за квантилями 0, 0.25, 0.5, 0.75, 1.
- Координати: WHO = квантиль log(x_t); WHERE = квантиль Δlog(x_t); WHEN = квантиль Δ²log(x_t).
- Результат: послідовність кодів code6.

**Крок 0'.** Усі правила ρ ∈ ℛ₀ (на скінченному S₀ тривіально). F неперервний.

**Гіпотези.**

- **H₁**: ρ₁ = identity.
- **H₂**: ρ₂ = циклічний зсув на 1 у кожній координаті (mod 4).
- **H₃**: ρ₃ — емпірична таблиця переходів: ρ₃(s) = argmax_t count(s → t) у навчальній вибірці, детермінований tie-breaking (менший code6).

**Тестовий поділ.** 70% (навчальна) / 30% (тестова) за часом. Перші 80 точок — навчальна, останні 34 — тестова.

**Метрики.**

- **RMSE 1-крокового прогнозу** на тестовій вибірці: для кожного правила ρᵢ обчислюємо передбачений стан ŝ̂ₜ₊₁ = ρᵢ(ŝₜ), порівнюємо з істинним ŝₜ₊₁ у метриці d_S на S₀ (дискретна).
- **RMSE 5-крокового прогнозу**: аналогічно на горизонті 5.

**Перестановка квантилів.** 10 випадкових перестановок міток бінів; для кожної обчислюємо RMSE 1-крокового прогнозу; звітуємо медіану й квартилі.

**Критерій спростування (заздалегідь).** Пілот **провалюється**, якщо RMSE(H₃) ≥ min(RMSE(H₁), RMSE(H₂)) на тестовій вибірці (H₃ не перевершує жодну baseline).

Пілот **успішний**, якщо RMSE(H₃) < min(RMSE(H₁), RMSE(H₂)) з запасом ≥ 10% відносно baseline.

**Застереження.** Критерій «H₃ має третій клас S(τ)» прибрано як недостатній. Головний критерій — прогностична перевага на тестовій вибірці.

**Код.** Репозиторій із фіксованим commit hash, Python 3.11, requirements зафіксовано.

## Підсумкова формула

```
SUBIT-∞ = ( S_∞, ℛ, F, g,
            Ω_set, Ω_point, Ω_ω, Ω_traj,
            d_S, d_ℛ, d̂, d_H, d_traj,
            ℛ₀, ℛ₁, Dyn, Ω_Dyn,
            P, ℒ )
```

де:

- S_∞ = νX.(A ⊔ X³);
- ℛ = ℛ₀ ⊎ ℛ₁;
- F — оператор динаміки; g — метаеволюція;
- Ω_set = {STABLE, METASTABLE, CYCLIC, TRANSIENT, CHAOTIC} — 5 класів множин;
- Ω_point = {FIXED, PERIODIC, NONRETURNING};
- Ω_ω = {FIXED_POINT, PERIODIC, MINIMAL_ZERO_ENTROPY, CHAOTIC, NON_MINIMAL};
- Ω_traj = (S, Att);
- d_S, d_ℛ, d̂, d_H, d_traj — п'ять метрик різних областей;
- Dyn — підкатегорія дискретних динамічних систем; Ω_Dyn = ℕ ∪ {∞};
- P — канонічна класифікація;
- ℒ — внутрішня мова.

**Центральна теза v6.2.** Специфікація повинна бути **критичною до себе на кожному рівні**. Помилки v6.1 (P0-1–P0-5) були наслідком нашарування патчів. v6.2 переписує три розділи з нуля і замінює шестирівневу систему статусів семирівневою.

**Методологічна теза v6.2.** Жоден реліз не може отримати статус STABLE без **третього незалежного аудиту**, який не знаходить P0-помилок. Перший аудит (v6.0) знайшов 8 критичних. Другий (v6.1) знайшов 5. Третій має знайти 0.
